# RDMA 第五章：iWARP——基于 TCP/UDP 的 RDMA 协议

> [!abstract] 核心要点
> iWARP（internet Wide Area RDMA Protocol）是另一条将 RDMA 语义跑在 Ethernet 上的技术路线。与 RoCE 不同，iWARP 使用 TCP 或 SCTP 作为底层可靠传输，架构更接近传统网络堆栈。本章详解 DDP、RDMAP、MPA 三层协议，以及 iWARP 的数据平面和控制平面。

---

## 1. iWARP 设计动机

RoCE 将 IB 传输层封装在 UDP 上——这需要无损网络（PFC + ECN）才能可靠工作。在某些场景下：

- 网络设备不支持 DCB
- 需要穿越路由器（WAN）
- 不希望配置复杂的无损网络

iWARP 应运而生——它**利用 TCP 的可靠传输能力**，在普通 IP 网络上提供 RDMA 功能。

核心区别：

| 协议 | 可靠传输层 | 网络要求 |
|------|-----------|----------|
| **RoCE v2** | UDP（自己管理可靠性：ECN/CNP） | 无损网络（PFC+ECN） |
| **iWARP** | TCP/SCTP（内置重传、排序） | 标准 IP 网络即可 |

## 2. iWARP 协议栈

```
┌─────────────────────────────────────────────────────────────┐
│                   Application                              │
├─────────────────────────────────────────────────────────────┤
│                 libibverbs / librdmacm                     │
├─────────────────────────────────────────────────────────────┤
│                 RDMA Operations (Read/Write/Send/Atomic)   │
├─────────────────────────────────────────────────────────────┤
│                 RDMAP (RDMA Protocol)                       │
├─────────────────────────────────────────────────────────────┤
│                 DDP (Direct Data Placement)                │
├─────────────────────────────────────────────────────────────┤
│                 MPA (Marker PDU Aligned Framing)           │
├─────────────────────────────────────────────────────────────┤
│                 TCP / SCTP                                 │
├─────────────────────────────────────────────────────────────┤
│                 IP                                          │
└─────────────────────────────────────────────────────────────┘
```

三层专用协议：**RDMAP → DDP → MPA**

---

## 3. DDP（Direct Data Placement）

### 3.1 DDP 的核心思想

DDP 允许将数据直接放置（DMA）到最终目标的内存中，无需中间缓冲或复制。这与 IB 传输层的"直接放置"语义一致。

### 3.2 DDP 概念

DDP 引入了两个重要概念：

| 概念 | 说明 |
|------|------|
| **Tagged Buffer** | 有明确地址/长度标识的缓冲区，用于 RDMA Read/Write |
| **Untagged Buffer** | 无地址标识，用于 Send/Recv，依赖序号关联 |

### 3.3 DDP 数据包格式

```
┌─────────────────────────────────────────────────────────────┐
│ DDP Header                                                   │
│  ┌────────────────────────────────────────────────────────┐ │
│  │ 流的 (12): Reserved (RDMA), STag (32), TO (64)        │ │
│  │          或 序号 (32) + MSGLENGTH (32)                │ │
│  └────────────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────────────┤
│  DDP Payload (数据)                                         │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 DDP vs IB 传输层

DDP 本质上是 IB 传输层的一个简化变体，保留了 RDMA 的"直接放置"语义，但适配了 TCP 的流式传输模型。

---

## 4. RDMAP（RDMA Protocol）

### 4.1 RDMAP 的角色

RDMAP 在 DDP 之上添加 RDMA 操作语义——它定义了哪些 DDP 报文构成一个完整的 RDMA 操作。

### 4.2 RDMA 操作映射

| RDMA 操作 | RDMAP 层 |
|-----------|----------|
| **RDMA Write** | 一个或多个 RDMAP Write 请求 + RTU |
| **RDMA Read** | RDMAP Read Request + RDMAP Read Response |
| **Send** | 一个或多个 RDMAP Send + 无确认 |
| **Atomic** | RDMAP Fetch-Add / Compare-Swap |

### 4.3 RDMAP 消息类型

```
RDMAP 消息类型（Opcode）：
  0x00 - Write RDMA
  0x01 - Read Request
  0x02 - Read Response (First)
  0x03 - Read Response (Middle/Last)
  0x04 - Read Response (Last)
  0x05 - Send
  0x06 - Send with Invalidate
  0x07 - Fetch Add
  0x08 - Compare Swap
  0x09 - Terminate
```

## 5. MPA（Marker PDU Aligned Framing）

### 5.1 为什么需要 MPA

TCP 是流式协议，没有内置的边界标记。应用程序的数据包可能在 TCP 层被拆分或合并（粘包/拆包）。

MPA 在 DDP/RDMAP 报文之间插入 **Marker**（标记字节），使得接收方能够识别完整的 DDP PDU：

```
┌────────┬────────────────┬────────┬────────────────┬────────┐
│ Marker │ DDP/RDMAP PDU  │ Marker │ DDP/RDMAP PDU  │ ...    │
└────────┴────────────────┴────────┴────────────────┴────────┘
     ↑ 每 64 字节插入 marker（或在 PDU 边界）                  ↑
```

MPA 是可选的：
- 使用 TCP 时：通常启用 MPA（用于边界对齐）
- 使用 SCTP 时：SCTP 本身是消息式的，不需要 MPA

### 5.2 MPA 帧格式

```
┌─────────────────────────────────────────────────────────────┐
│  FPDU (Framed PDU)：                                        │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  Markers (0-64 bytes) + DDP/RDMAP Header + Payload    │ │
│  └────────────────────────────────────────────────────────┘ │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  CRC-32 (4 bytes)                                      │ │
│  └────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 MPA 与 DDP 的协作

```
发送方：
  App Data → RDMAP → DDP → MPA Framing → TCP → IP

接收方：
  IP → TCP → MPA Deframing → DDP → RDMAP → App Buffer
                  ↑
           从 Marker 还原 PDU 边界
```

## 6. iWARP 端口使用

| 端口 | 协议 | 用途 |
|------|------|------|
| **3240** | TCP/SCTP | iWARP 默认控制端口 |
| **4791** | — | RoCE v2（注意：iWARP 不同） |
| **动态** | TCP (ephemeral) | iWARP 数据连接（发起方端口） |

iWARP 监听 TCP 3240，连接建立后使用 TCP 流进行数据传输。

---

## 7. iWARP 与 TCP 的关系

### 7.1 为什么选择 TCP

TCP 的特性恰好满足 RDMA 可靠传输的需求：

| TCP 特性 | 对 RDMA 的意义 |
|----------|---------------|
| **可靠传输** | 不需要像 RoCE 那样自己管理重传 |
| **排序** | TCP 保证字节顺序，不需要 RDMA 层重新排序 |
| **流控** | TCP 内置流控 |
| **拥塞控制** | TCP CUBIC/etc. 自动管理拥塞 |

### 7.2 iWARP 的代价

TCP 的可靠性是以性能为代价的：

| 问题 | 影响 |
|------|------|
| **TCP 头部开销** | 20 字节 IP + 20 字节 TCP = 40 字节/包 |
| **TCP Offload** | 需要 TOE（TCP Offload Engine）否则 CPU 参与处理 |
| **Nagle 算法** | 可能引入小包延迟 |
| **拥塞控制** | TCP 拥塞算法与 RDMA 流量特性不完全匹配 |
| **Head-of-Line Blocking** | TCP 排序可能导致同连接内阻塞 |

### 7.3 TOE（TCP Offload Engine）

为减少 TCP 处理开销，iWARP 网卡通常内置 TOE，将 TCP 处理下沉到网卡：

```
无 TOE：TCP 协议处理由 CPU 完成
有 TOE：TCP 处理由网卡硬件完成
```

TOE 可以显著降低 CPU 占用，但增加了网卡复杂度。

## 8. iWARP vs RoCE 架构对比

```
RoCE v2：
┌─────────────────────────────────────────────────────────────┐
│ IB Transport (RC)                                           │
├─────────────────────────────────────────────────────────────┤
│ UDP (4791)                                                  │
├─────────────────────────────────────────────────────────────┤
│ IP                                                           │
├─────────────────────────────────────────────────────────────┤
│ Ethernet + VLAN + PFC/ECN                                   │
└─────────────────────────────────────────────────────────────┘

iWARP：
┌─────────────────────────────────────────────────────────────┐
│ IB Transport (RC)  ← (语义相同)                             │
├─────────────────────────────────────────────────────────────┤
│ RDMAP                                                        │
├─────────────────────────────────────────────────────────────┤
│ DDP                                                          │
├─────────────────────────────────────────────────────────────┤
│ MPA (TCP) 或 SCTP                                           │
├─────────────────────────────────────────────────────────────┤
│ TCP/SCTP                                                     │
├─────────────────────────────────────────────────────────────┤
│ IP                                                           │
├─────────────────────────────────────────────────────────────┤
│ Ethernet                                                     │
└─────────────────────────────────────────────────────────────┘
```

关键差异：iWARP 在 IB 传输层和 IP 之间多了 **RDMAP + DDP + MPA** 三层。

---

## 9. iWARP 支持的传输类型

| 类型 | 说明 | iWARP 支持 |
|------|------|-----------|
| **RC** | Reliable Connection | 支持 |
| **UC** | Unreliable Connection | 支持（可选） |
| **UD** | Unreliable Datagram | 不支持 |
| **RD** | Reliable Datagram | 不支持 |

注意：**iWARP 不支持 UD**。这与 RoCE 和 IB 不同——iWARP 没有不可靠数据报模式。

---

## 10. iWARP 的使用场景

| 场景 | 适用性 |
|------|--------|
| **标准 Ethernet 网络** | ✓ 不需要 DCB/PFC |
| **WAN 穿越** | ✓ TCP 可路由 |
| **不支持 TOE 的网卡** | ✗ TCP 处理会消耗 CPU |
| **超低延迟 HPC 集群** | ✗ 延迟高于 IB/RoCE |
| **云环境** | △ 需要特殊网卡（如 Chelsio iWARP） |

---

## 11. 主流 iWARP 网卡

| 厂商 | 网卡 | 备注 |
|------|------|------|
| **Chelsio** | T6 系列 | 完整 iWARP + TOE |
| **Intel** | E810 (部分) | iWARP 支持 |
| **Cisco** | usNIC | 思科专有的用户空间 iWARP |

注意：Mellanox/NVIDIA 网卡**不支持 iWARP**，仅支持 InfiniBand 和 RoCE。

---

## 12. 总结

iWARP 协议栈的关键层次：

| 层次 | 作用 |
|------|------|
| **RDMAP** | 定义 RDMA 操作（Read/Write/Send/Atomic） |
| **DDP** | 直接数据放置，将数据 DMA 到最终内存 |
| **MPA** | 为 TCP 添加 PDU 边界标记（TCP 上需要，SCTP 不需要） |
| **TCP/SCTP** | 可靠传输 |

iWARP 的核心优势：
- **不需要无损网络**——TCP 自带可靠传输
- **可穿越路由器**——基于标准 IP

代价：
- **更高延迟**——TCP 协议栈和 MPA 开销
- **需要 TOE**——否则 CPU 负担重
- **不支持 UD**——无法使用多播
