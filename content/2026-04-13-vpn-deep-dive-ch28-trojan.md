## 1. 概述：Trojan 设计理念

**Trojan** 是 trojan-gfw 项目于 2017 年开发的翻墙协议，核心设计理念是**伪装成真实 TLS 连接**。Trojan 不使用自定义加密协议，而是直接使用 TLS，理论上与正常 HTTPS 网站无法区分。

```
Trojan 核心思想：

┌─────────────────────────────────────────────────────────────────┐
│                  Trojan vs 其他翻墙协议                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  传统翻墙协议：                                                  │
│  ├─ Shadowsocks：自定义加密，SOCKS5 代理                        │
│  ├─ V2Ray VMess：自定义加密协议                                 │
│  └─ 问题：都有独特的协议特征，可被 DPI 检测                      │
│                                                                 │
│  Trojan：                                                        │
│  ├─ 直接使用 TLS 1.2/1.3                                        │
│  ├─ 不使用自定义加密                                            │
│  ├─ 流量与真实 HTTPS 网站完全一致                                │
│  └─ GFW 无法通过协议特征检测                                     │
│                                                                 │
│  设计原则：                                                      │
│  "如果它看起来像 HTTPS，它就是 HTTPS"                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.1 Trojan vs Shadowsocks vs V2Ray

```
协议对比表：

┌─────────────────────────────────────────────────────────────────┐
│                        协议对比                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  特征           │ Trojan      │ Shadowsocks │ V2Ray(VLESS)   │
│  ───────────────┼─────────────┼─────────────┼────────────────  │
│  加密           │ TLS（标准） │ AEAD        │ TLS（标准）     │
│  协议特征       │ 无          │ 可检测      │ 极小            │
│  SNI 隐藏       │ 无（明文）  │ 可混淆      │ 可用 XTLS       │
│  证书           │ 真实        │ 无          │ 可真实          │
│  性能           │ 高          │ 高          │ 高              │
│  多用户         │ 支持        │ 需插件      │ 支持            │
│  WebSocket      │ Trojan-Go   │ 支持        │ 原生支持        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 2. Trojan 协议详解

### 2.1 协议工作流程

Trojan 使用 TLS 握手后的 Application Data 传输数据：

```
Trojan 工作原理：

┌─────────────────────────────────────────────────────────────────┐
│                      Trojan 连接流程                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. TCP 握手                                                     │
│                                                                 │
│  Client ──── SYN ──────────────────────────────▶ Server         │
│  Client ◀─── SYN+ACK ─────────────────────────── Server          │
│  Client ──── ACK ──────────────────────────────▶ Server         │
│                                                                 │
│  2. TLS 握手（完全标准的 TLS）                                    │
│                                                                 │
│  Client ──── ClientHello ────────────────────────────────────▶  │
│            │                                                   │
│            │ SNI: example.com（伪装域名）                        │
│            │ 证书: example.com（真实证书）                        │
│            │ TLS 版本: 1.2 或 1.3                                │
│            │ 密码套件: 标准                                      │
│            │                                                   │
│  Client ◀─── ServerHello + Certificate + ServerHelloDone ─────│
│                                                                 │
│  Client ──── ClientKeyExchange + ChangeCipherSpec ──────────▶  │
│  Client ──── Finished ────────────────────────────────────────▶  │
│  Client ◀─── ChangeCipherSpec + Finished ─────────────────────│
│                                                                 │
│  3. Trojan 协议（伪装在 TLS Application Data 中）                 │
│                                                                 │
│  Client ──── [Trojan Header + Data] ────────────────────────▶  │
│            │                                                   │
│            │ ⚠️ 这部分完全加密，GFW 无法解析                      │
│            │                                                   │
│  Client ◀─── [Trojan Response] ────────────────────────────────│
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 Trojan 协议头

Trojan 协议在 TLS 加密后传输：

```
Trojan 请求格式：

┌─────────────────────────────────────────────────────────────────┐
│                    Trojan 数据包结构                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  TLS Record Layer:                                              │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ [5 bytes]  Trojan Header                                 │   │
│  │ [N bytes]  Payload（加密）                                │   │
│  │ [16 bytes] Auth Tag（AEAD 模式）                          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  Trojan Header 详解：                                           │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ [1 byte]   Command                                       │   │
│  │            ├─ 0x01: TCP 连接                             │   │
│  │            └─ 0x02: UDP 转发                             │   │
│  │ [1 byte]   保留                                          │   │
│  │ [2 bytes]  目标端口（Big Endian）                        │   │
│  │ [N bytes]  目标地址（域名或 IP）                          │   │
│  │ [1 byte]   \r (0x0D)                                     │   │
│  │ [1 byte]   \n (0x0A)                                     │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  域名格式：                                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ [1 byte]   域名长度                                       │   │
│  │ [N bytes]  域名（不含结尾 .）                             │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 认证机制

Trojan 使用密码进行认证：

```
Trojan 认证流程：

┌─────────────────────────────────────────────────────────────────┐
│                    Trojan 认证机制                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  认证方式：                                                      │
│  ├─ 共享密码（pre-shared key）                                  │
│  └─ 密码在连接时进行验证                                         │
│                                                                 │
│  认证过程：                                                      │
│                                                                 │
│  Client                                                         │
│  │                                                              │
│  │  密码（用于加密 header）                                     │
│  ▼                                                              │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  使用密码加密 Trojan Header                              │    │
│  │  使用 AES-128-GCM 或 ChaCha20-Poly1305                  │    │
│  └─────────────────────────────────────────────────────────┘    │
│  │                                                              │
│  │  加密的请求                                                  │
│  ▼                                                              │
│  Server                                                         │
│  │                                                              │
│  │  尝试用各用户的密码解密                                      │
│  │  如果 HMAC 验证失败 ──▶ 拒绝连接                            │
│  │  如果验证成功 ──▶ 处理请求                                  │
│  │                                                              │
│  ▼                                                              │
│  响应（同样加密）                                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 Trojan-Go 新特性

```

   ├─ 可通过 WebSocket 传输
```

## 5. TLS 伪装详解

### 5.1 TLS 伪装原理

Trojan 的核心优势是完美的 TLS 伪装：

```
TLS 伪装层次：

┌─────────────────────────────────────────────────────────────────┐
│                    Trojan TLS 伪装                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  正常 HTTPS 网站：                                               │
│                                                                 │
│  Client ──▶ TLS ──▶ Nginx/Apache ──▶ Web App                   │
│                  │                                             │
│                  └── 真实服务                                   │
│                                                                 │
│  Trojan 服务器（伪装成 HTTPS 网站）：                            │
│                                                                 │
│  Client ──▶ TLS ──▶ Trojan Server ──▶ (分流)                   │
│                  │                    │                        │
│                  │                    ├─ 伪装 Web 服务          │
│                  │                    │   (返回正常页面)          │
│                  │                    │                        │
│                  │                    └─ Trojan 协议处理         │
│                  │                        (处理代理请求)        │
│                  │                                             │
│                  └── GFW 视角：只是普通 HTTPS                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 证书配置

```
TLS 证书选择：

1. 使用真实证书（推荐）：
   ├─ Let's Encrypt 免费证书
   ├─ 证书链完整
   ├─ OCSP 验证通过
   └─ 最难被检测

2. 自签名证书：
   ├─ 需要客户端信任
   ├─ 可能被检测
   └─ 仅用于测试

3. 证书配置示例（Let's Encrypt）：

   # 使用 certbot 获取证书
   certbot certonly --nginx -d example.com

   # 证书路径
   /etc/letsencrypt/live/example.com/fullchain.pem
   /etc/letsencrypt/live/example.com/privkey.pem

证书自动续期：
├─ Let's Encrypt 90 天有效期
├─ 添加 crontab 自动续期
└─ certbot renew --quiet
```

### 5.3 SNI 与 Host 头

```
SNI 伪装配置：

服务器端：
{
    "ssl": {
        "sni": "example.com"
    }
}

客户端：
{
    "ssl": {
        "sni": "example.com"
    }
}

效果：
├─ TLS ClientHello 中的 SNI 字段是 example.com
├─ HTTP Host 头也可以是 example.com
└─ GFW 无法区分真实访问还是 Trojan 流量

注意：
├─ 域名需要在 DNS 上正确解析到服务器 IP
├─ 服务器 IP 不能被直接封锁
└─ 证书的 CN/SAN 需要包含该域名
```

## 6. 安全考量

### 6.1 Trojan 的优势

```
Trojan 安全优势：

1. 协议不可检测：
   ├─ 使用标准 TLS
   ├─ 无自定义协议特征
   └─ 流量与 HTTPS 无法区分

2. 证书验证：
   ├─ 使用真实 TLS 证书
   ├─ 证书链完整验证
   └─ 防止中间人攻击

3. 加密强度：
   ├─ TLS 1.2/1.3
   ├─ 强密码套件
   └─ PFS（完美前向保密）

4. 认证机制：
   ├─ 密码认证
   ├─ HMAC 验证
   └─ 防重放（session ticket）
```

### 6.2 潜在风险

```
Trojan 现存问题：

1. SNI 泄露：
   ├─ TLS 1.2 SNI 是明文
   ├─ gfw 可以看到访问的域名
   └─ TLS 1.3 ECH 可解决（尚未普及）

2. 证书关联：
   ├─ Trojan 服务器 IP 与证书关联
   ├─ 如果证书被封，IP 可能被识别
   └─ 需要配合 CDN 或域前置

3. 被动检测局限：
   ├─ Trojan 对抗被动 DPI 很强
   ├─ 但主动探测可能仍可识别
   └─ 建议配合其他安全措施

4. 性能考虑：
   ├─ TLS 握手开销
   ├─ Trojan-Go WebSocket 额外开销
   └─ 选择合适的数据中心
```

## 8. 总结

```
Trojan 核心要点：

┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  设计理念：                                                      │
│  ├─ 伪装成真实 TLS 连接                                        │
│  ├─ 不使用自定义加密层                                         │
│  └─ 流量与 HTTPS 无法区分                                       │
│                                                                 │
│  技术特点：                                                      │
│  ├─ 标准 TLS 1.2/1.3                                          │
│  ├─ 真实 TLS 证书                                              │
│  ├─ 支持多用户                                                 │
│  ├─ Trojan-Go 支持 WebSocket                                   │
│  └─ 完善的路由和负载均衡                                        │
│                                                                 │
│  优势：                                                          │
│  ├─ 完美的协议伪装                                              │
│  ├─ 使用广泛验证的 TLS 协议                                     │
│  ├─ 证书可选真实                                            │
│  └─ 性能优秀                                                   │
│                                                                 │
│  局限：                                                          │
│  ├─ SNI 在 TLS 1.2 中明文                                      │
│  ├─ 需要域名和证书基础设施                                      │
│  └─ 服务器 IP 需要未被封锁                                      │
│                                                                 │
│  最佳使用场景：                                                  │
│  ├─ 有稳定域名和证书的情况下                                    │
│  ├─ 作为翻墙方案的主力                                         │
│  └─ 配合 CDN 提高抗封锁能力                                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

Trojan 代表了翻墙技术的一个重要流派：**利用标准协议进行伪装**。其设计理念影响了后续的 VLESS、XTLS 等协议。对于有技术能力维护域名和证书的用户，Trojan 是一个非常安全可靠的选择。
