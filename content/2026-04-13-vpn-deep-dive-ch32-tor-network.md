## 1. 概述：Tor 的设计目标

**Tor（The Onion Router）** 是美国海军研究实验室于 1990 年代中期开发、2000 年代初开源的**洋葱路由匿名通信系统**。与翻墙不同，Tor 的核心设计目标是** anonymity（匿名性）**，而非仅仅绕过审查。

```
Tor vs 其他翻墙技术：

┌─────────────────────────────────────────────────────────────────┐
│                      目标对比                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  传统翻墙（Shadowsocks/V2Ray/Trojan）：                          │
│  ├─ 目标：绕过 GFW 访问互联网                                   │
│  ├─ 重点：协议伪装、抗检测                                       │
│  ├─ 隐私：保护流量不被窃听                                       │
│  └─ 匿名：有限（服务器知道你的 IP）                              │
│                                                                 │
│  Tor：                                                          │
│  ├─ 目标：匿名通信                                             │
│  ├─ 重点：多层加密、路由混淆                                     │
│  ├─ 隐私：没人知道谁在通信                                      │
│  └─ 匿名：服务器不知道你的 IP（理论上）                          │
│                                                                 │
│  Tor 额外价值：                                                │
│  ├─ 防止流量分析                                                │
│  ├─ 隐藏通信双方身份                                            │
│  ├─ 提供 .onion 隐藏服务                                        │
│  └─ 新闻记者、维权人士的重要工具                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 洋葱路由原理

### 2.1 三层加密架构

Tor 的核心是**三层加密（Onion Encryption）**：

```
Tor 三层加密：

┌─────────────────────────────────────────────────────────────────┐
│                    洋葱路由加密                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  客户端创建 3 层加密（每层对应一个节点）：                       │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ Layer 3（Exit Node 加密层）                             │   │
│  │  ┌─────────────────────────────────────────────────┐   │   │
│  │  │ Layer 2（Middle Node 加密层）                   │   │   │
│  │  │  ┌─────────────────────────────────────────┐   │   │   │
│  │  │  │ Layer 1（Entry Node 加密层）            │   │   │   │
│  │  │  │  ┌─────────────────────────────────┐   │   │   │   │
│  │  │  │  │      原始数据                    │   │   │   │   │
│  │  │  │  └─────────────────────────────────┘   │   │   │   │
│  │  │  │  解密 Key: Exit Node 公钥              │   │   │   │
│  │  │  └─────────────────────────────────────────┘   │   │   │
│  │  │  解密 Key: Middle Node 公钥                     │   │   │
│  │  └─────────────────────────────────────────────────┘   │   │
│  │  解密 Key: Entry Node 公钥                             │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  发送流程：                                                      │
│                                                                 │
│  Client ◀── Layer 3 加密 ──┐                                   │
│           │                  │                                  │
│           │ Layer 2 加密    │                                  │
│           ▼                  │                                  │
│  Entry ◀──┼─────────────────┤                                  │
│           │ Layer 1 加密     │                                  │
│           ▼                 │                                  │
│  Middle ◀─┼─────────────────┼─────── 数据包传递                 │
│           │                 │                                  │
│           ▼                 ▼                                  │
│  Exit ◀───┴─────────────────┘                                  │
│           │                                                    │
│           │ 解密 Layer 3                                       │
│           ▼                                                    │
│  Internet ──▶ 目标服务器                                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 电路建立过程

```
Tor 电路建立：

┌─────────────────────────────────────────────────────────────────┐
│                    Tor 电路建立                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. Directory 获取（获取节点列表）                               │
│                                                                 │
│  Client ──── Directory Request ────────────────────▶ Directory   │
│            │ (HTTPS)                                          │
│  Client ◀─── Node List + Consensus ──────────────────── Server  │
│            │ (所有 Relay 的信息)                              │
│                                                                 │
│  2. 密钥交换（为每个节点生成会话密钥）                           │
│                                                                 │
│  Client ──── TLS + Tor Handshake ────────────▶ Entry Node     │
│            │ 创建电路                                         │
│  Client ◀─── Relay Extend ─────────────────────── Entry Node  │
│            │                                                   │
│  Entry ──── TLS + Handshake ─────────────────▶ Middle Node    │
│            │ Relay Extend                                      │
│  Entry ◀─── Relay Extended ──────────────────── Middle Node   │
│            │                                                   │
│  Middle ─── TLS + Handshake ─────────────────▶ Exit Node     │
│            │ Relay Extend                                      │
│  Middle ◀── Relay Extended ──────────────────── Exit Node     │
│            │                                                   │
│  Client ◀─── 电路建立完成 ────────────────────────────          │
│                                                                 │
│  3. 应用数据通过电路传输                                        │
│                                                                 │
│  Client ◀───▶ Exit ◀───▶ 目标服务器                            │
│           加密隧道                                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 关键特性

```
Tor 匿名性关键：

┌─────────────────────────────────────────────────────────────────┐
│                      匿名性保障                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 路由混淆：                                                  │
│  ├─ 每个节点只知道前后节点                                      │
│  ├─ Entry Node 不知道 Exit Node                                │
│  └─ Exit Node 不知道 Client IP                                 │
│                                                                 │
│  2. 密钥派生：                                                  │
│  ├─ DH 密钥交换                                                │
│  ├─ 每段使用不同密钥                                            │
│  └─ 定期轮换                                                    │
│                                                                 │
│  3. 流量padding：                                               │
│  ├─ 固定大小数据包                                             │
│  ├─ 定期发送空数据包                                            │
│  └─ 防止流量分析                                                │
│                                                                 │
│  4. 电路切换：                                                  │
│  ├─ 10 分钟自动切换电路                                        │
│  └─ 减少长期关联                                                │
│                                                                 │
│  局限性：                                                      │
│  ├─ 对 HTTPS 中间人无效                                        │
│  ├─ 流量模式分析                                              │
│  ├─ 出口节点可看明文（如果目标不支持 TLS）                       │
│  └─ 时间关联攻击                                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 3. Tor 网络组件

### 3.1 Relay 节点类型

```
Tor Relay 类型：

┌─────────────────────────────────────────────────────────────────┐
│                      Relay 类型                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. Guard/Entry Node（入口节点）：                              │
│     ├─ 第一个接触用户的节点                                     │
│     ├─ 长期在线（稳定节点）                                      │
│     ├─ 需要较好带宽                                            │
│     └─ 容易受到定位攻击                                         │
│                                                                 │
│  2. Middle Node（中间节点）：                                   │
│     ├─ 连接 Entry 和 Exit                                       │
│     ├─ 不直接暴露给用户                                        │
│     └─ 带宽要求中等                                             │
│                                                                 │
│  3. Exit Node（出口节点）：                                     │
│     ├─ 最后一个节点，连接目标服务器                              │
│     ├─ 承担最多法律风险（用户行为=节点行为）                      │
│     ├─ 需要配置出口策略                                          │
│     └─ 最容易受到监控                                           │
│                                                                 │
│  4. Bridge（网桥）：                                            │
│     ├─ 未公开列出的 Entry Node                                  │
│     ├─ 用于绕过审查                                            │
│     ├─ 需单独获取地址                                           │
│     └─ 可配合混淆协议（obfs4）                                   │
│                                                                 │
│  5. Directory Authority（目录服务器）：                          │
│     ├─ 维护全网 Relay 列表                                      │
│     ├─ 只有约 10 个                                             │
│     └─ 选举机制决定共识                                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 4. Hidden Services

### 4.1 .onion 原理

Tor **Hidden Services（隐藏服务）** 允许提供完全匿名的网络服务：

```
.onion 隐藏服务：

┌─────────────────────────────────────────────────────────────────┐
│                    隐藏服务工作原理                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  传统服务 vs 隐藏服务：                                         │
│                                                                 │
│  传统服务：                                                     │
│  ├─ Server IP 公开发布                                          │
│  ├─ 用户直接访问 IP/域名                                        │
│  └─ 服务器知道用户 IP                                           │
│                                                                 │
│  隐藏服务：                                                     │
│  ├─ Server .onion 地址自动生成                                  │
│  ├─ 服务端隐藏在一个 6 节点 Rendezvous 系统中                    │
│  └─ 用户和服务端都不知道对方真实 IP                               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

.onion 地址生成：

┌─────────────────────────────────────────────────────────────────┐
│                    Onion 地址生成                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  地址格式：                                                     │
│  ├─ v2: 16 字符 Base32（例：expyuzz3hqw22cx.onion）           │
│  └─ v3: 56 字符 Base32（例：p4fhj5dhu6qh7r2yvljspqvmxayb...）│
│                                                                 │
│  v3 地址特性：                                                 │
│  ├─ 更安全（ed25519 密钥）                                      │
│  ├─ 更好的隐私保护                                             │
│  ├─ 更长的生命周期                                              │
│  └─ 推荐使用 v3                                                  │
│                                                                 │
│  生成过程：                                                     │
│  1. 生成密钥对（私钥 + 公钥）                                   │
│  2. 公钥哈希 → Base32 → .onion 地址                            │
│  3. 私钥必须保密（丢失 = 地址丢失）                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 Hidden Service 协议

```
隐藏服务协议流程：

┌─────────────────────────────────────────────────────────────────┐
│                    隐藏服务连接流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 服务端建立 Introductory Points（引入点）                     │
│                                                                 │
│  Server ──▶ 生成密钥对                                        │
│  Server ──▶ 建立多条到 Introduction Points 的连接               │
│  Server ◀─── 保存 .onion 地址和 HSDir 位置                     │
│                                                                 │
│  2. 客户端获取 .onion 地址（通过某个渠道）                       │
│                                                                 │
│  Client ──▶ 查询 HSDir 获取 .onion 地址                        │
│            │ 的服务描述符                                       │
│  Client ◀─── 服务描述符（含公钥和引入点列表）                   │
│                                                                 │
│  3. 客户端建立 Rendezvous Point（会合点）                        │
│                                                                 │
│  Client ──▶ 随机选择 Rendezvous Point（RP）                     │
│  Client ──▶ 通过 Tor 电路发送 RV cookie 给 RP                   │
│                                                                 │
│  4. 客户端连接到引入点                                          │
│                                                                 │
│  Client ──▶ 通过 Tor 连接 Introduction Point                   │
│  Client ──▶ 发送 Introduce1（包含 RP 地址和加密的 RV cookie）   │
│                                                                 │
│  5. 服务端处理引入请求                                          │
│                                                                 │
│  Server ◀─── Introduce1                                        │
│  Server ──▶ 解密，确认是给自己的                                 │
│  Server ──▶ 通过 Tor 连接到 RP                                  │
│  Server ──▶ 发送 RV cookie 给 RP                               │
│                                                                 │
│  6. RP 将会合双方连接                                          │
│                                                                 │
│  RP ◀─── RV cookie from Client                                 │
│  RP ◀─── RV cookie from Server                                │
│  RP ──── 验证 cookie，连接双方                                  │
│                                                                 │
│  7. 加密电路建立，通信开始                                       │
│                                                                 │
│  Client ◀──▶ RP ◀──▶ Server                                   │
│              加密隧道                                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 5. 在中国使用 Tor

### 5.1 封锁现状

```
GFW 对 Tor 的封锁：

┌─────────────────────────────────────────────────────────────────┐
│                      Tor 封锁情况                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  直接封锁：                                                      │
│  ├─ Tor Directory Authority 服务器 IP 黑名单                     │
│  ├─ 已知的 Exit Node IP 封锁                                    │
│  └─ Tor 协议特征检测                                           │
│                                                                 │
│  检测方式：                                                     │
│  ├─ DPI 检测 Tor TLS 握手特征                                   │
│  ├─ 主动探测网桥                                               │
│  └─ 机器学习流量分析                                           │
│                                                                 │
│  影响：                                                         │
│  ├─ 直接连接 Tor 网络几乎不可能                                 │
│  ├─ 公开的网桥也被封锁                                         │
│  └─ 需要使用混淆协议                                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 网桥获取

```
获取 Tor 网桥：

1. 官方渠道：
   ├─ https://bridges.torproject.org/
   ├─ 邮件获取：bridges@torproject.org
   └─ Telegram bot：@TorBrowserBot
   注意：邮件获取在中国可能不可用

2. 自建网桥（Snowflake）：
   Snowflake 代理：
   ├─ 在国外服务器部署 Snowflake proxy                            │
   ├─ 提供给你在中国使用                                           │
   └─ 需要可用的域名或 IP

3. 获取 meek 网桥：
   ├─ 通过 Azure 或 Google App Engine 部署                       │
   ├─ Domain fronted 版本                                         │
   └─ 域前置混淆

4. 获取 obfs4 网桥：
   ├─ 在国外服务器运行 obfs4proxy                                 │
   ├─ 提供网桥地址和证书指纹                                       │
   └─ 手动添加到 Tor Browser                                      │
```

### 5.3 配置示例

```
Tor + obfs4 + meek 配置：

1. 配置文件 torrc：

# 基本配置
SocksPort 9150
ControlPort 9051
HashedControlPassword xxxxxxxxx

# 网桥配置
UseBridges 1

# obfs4 网桥（手动添加）
Bridge obfs4 <IP>:<PORT> <FINGERPRINT> cert=<CERT> iat-mode=0

# meek 网桥（域前置）
Bridge meek_lite 0.0.2.0:1?Front=xxxxxxxx.cloudfront.net

# 混淆插件
ClientTransportPlugin meek_lite exec ./meek-client
ClientTransportPlugin obfs4 exec ./obfs4proxy

2. 启动 Tor Browser

3. 连接设置：
   ├─ 连接类型：选择"网桥"
   ├─ 配置 IPv4 网桥：添加 obfs4 网桥
   ├─ 或选择" meek tactics"
   └─ 等待连接建立

4. 验证连接：
   ├─ 检查 https://check.torproject.org/
   └─ 显示 "Congratulations" 表示成功
```

## 6. Tor 与翻墙的结合

### 6.1 Tor 作为翻墙工具

```
Tor 翻墙可行性：

┌─────────────────────────────────────────────────────────────────┐
│                      Tor 翻墙评估                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  优势：                                                         │
│  ├─ 完全免费                                                    │
│  ├─ 强大的匿名性                                                │
│  ├─ .onion 服务可用                                            │
│  └─ 全球数千节点                                                │
│                                                                 │
│  劣势：                                                         │
│  ├─ 速度极慢（3 层路由）                                       │
│  ├─ GFW 封锁严重，需要混淆                                      │
│  ├─ 出口节点可能被封锁                                          │
│  └─ 不适合流媒体等大流量应用                                     │
│                                                                 │
│  适用场景：                                                     │
│  ├─ 临时紧急访问                                               │
│  ├─ 高隐私要求的通信                                            │
│  ├─ 访问 .onion 服务                                            │
│  └─ 作为备用方案                                                │
│                                                                 │
│  不适合场景：                                                   │
│  ├─ 日常浏览（速度太慢）                                        │
│  ├─ 视频/下载（大流量）                                        │
│  └─ 游戏（延迟要求高）                                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 6.2 先 Tor 再翻墙

```
混合方案：Tor + 翻墙代理：

架构：

Client ──▶ Tor ──▶ Bridge Proxy ──▶ 翻墙服务器 ──▶ 目标

原理：
├─ Tor 连接到境外的翻墙服务器（作为 Tor 网桥）
├─ 在境外服务器上解密 Tor 流量
└─ 转发到其他翻墙服务

配置示例：

境外服务器（作为 Tor 网桥）：
# 安装 obfs4proxy
apt install obfs4proxy

# torrc 配置
BridgeRelay 1
OrPort 9001
ExtORPort 9002
Obfs4BindAddress 0.0.0.0:8443
ContactInfo your@email.com
Nickname MyBridge

# 将此服务器添加到你的翻墙服务

客户端：
├─ 配置 Tor Browser 使用此网桥
└─ 或者在翻墙客户端中配置 Tor upstream proxy
```

## 7. 安全考量

### 7.1 Tor 的局限性

```
Tor 安全边界：

┌─────────────────────────────────────────────────────────────────┐
│                      Tor 局限性                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 出口节点监控：                                             │
│  ├─ Exit Node 可以看到明文 HTTP                                │
│  ├─ HTTPS 仍然加密（端到端）                                    │
│  └─ 建议：始终使用 HTTPS                                       │
│                                                                 │
│  2. 流量分析：                                                 │
│  ├─ 流量大小和时间模式可被分析                                  │
│  ├─ 网站指纹识别                                               │
│  └─ 建议：Tor Browser 的防指纹功能                             │
│                                                                 │
│  3. 节点勾结：                                                 │
│  ├─ 如果 Entry 和 Exit 被同一攻击者控制                         │
│  └─ 可以关联用户身份（低概率但可能）                            │
│                                                                 │
│  4. 协议泄露：                                                 │
│  ├─ DNS 查询可能泄露                                            │
│  ├─ WebRTC 可能泄露 IP                                         │
│  └─ 建议：使用 Tor Browser，禁用 WebRTC                       │
│                                                                 │
│  5. 恶意节点：                                                 │
│  ├─ 约 3-5% 节点可能是恶意的                                   │
│  ├─ Exit Node 可能记录流量                                     │
│  └─ 建议：敏感操作使用 HTTPS                                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 7.2 最佳实践

```

┌─────────────────────────────────────────────────────────────────┐

│                                                                 │
│  浏览器设置：                                                  │
```

## 9. 总结

```
Tor 核心要点：

┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  设计目标：                                                     │
│  ├─ 匿名通信（而非仅仅翻墙）                                    │
│  ├─ 三层洋葱路由加密                                           │
│  └─ 多节点分布式                                            │
│                                                                 │
│  核心组件：                                                     │
│  ├─ Relay（Guard/Middle/Exit）                                 │
│  ├─ Bridge（封锁地区的入口）                                    │
│  ├─ Hidden Services（.onion）                                 │
│  ├─ Pluggable Transport（obfs4/meek）                          │
│  └─ Tor Browser                                                │
│                                                                 │
│  在中国的使用：                                                 │
│  ├─ GFW 已封锁直接连接                                         │
│  ├─ 需要使用 obfs4/meek 网桥                                   │
│  ├─ 自建网桥最可靠                                             │
│  └─ 速度慢，适合特定场景                                        │
│                                                                 │
│  安全考量：                                                     │
│  ├─ 出口节点可看明文（HTTP）                                   │
│  ├─ 流量分析可识别                                             │
│  ├─ 始终使用 HTTPS                                             │
│  └─ 使用 Tor Browser 的安全功能                                │
│                                                                 │
│  与翻墙技术的关系：                                             │
│  ├─ 不是最佳的翻墙方案（速度慢）                                │
│  ├─ 可作为备用方案                                             │
│  ├─ 可配合翻墙服务混合使用                                      │
│  └─ 适合高隐私需求                                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

Tor 代表了一种独特的匿名通信理念，其洋葱路由设计影响深远。虽然在翻墙场景下有其局限性，但 Tor 仍然是追求高匿名性和抗审查的重要工具。理解 Tor 的工作原理，对于设计安全的网络通信系统也有重要参考价值。
