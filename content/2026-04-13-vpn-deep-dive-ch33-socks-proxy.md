## 1. 概述：SOCKS 协议定位

**SOCKS**（Socket Secure）是一种网络协议，设计用于在代理服务器上转发客户端与服务器之间的网络流量。与 HTTP 代理不同，SOCKS 工作在**会话层**（OSI 第 5 层），不关心上层协议内容，只转发原始数据包。

```
SOCKS 协议在网络模型中的位置：

┌─────────────────────────────────────────────────────────────────┐
│                        OSI 七层模型                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  7. 应用层     │ HTTP, FTP, SMTP, DNS                           │
│  6. 表示层     │ SSL/TLS, ASCII, JPEG                           │
│  5. 会话层     │ SOCKS, PPTP, L2TP, NetBIOS                     │◀── SOCKS 在此
│  4. 传输层     │ TCP, UDP                                        │
│  3. 网络层     │ IP, ICMP, IPSec                                │
│  2. 数据链路层 │ Ethernet, PPP, ATM                             │
│  1. 物理层     │ 光纤, 铜缆, 无线                               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

SOCKS vs HTTP 代理：
├─ SOCKS5：通用代理，不解析协议内容，支持 TCP + UDP
├─ HTTP Proxy：只支持 HTTP/HTTPS，专门解析 HTTP 头
└─ SOCKS 更底层，应用范围更广
```

SOCKS 协议有多个版本：**SOCKS4**、**SOCKS4A**（SOCKS4 扩展）、**SOCKS5**。当前主流是 SOCKS5，提供认证和 UDP 支持。

## 2. SOCKS4 协议详解

### 2.1 SOCKS4 连接流程

SOCKS4 是最早的版本，只支持 TCP 连接，不支持认证：

```
SOCKS4 连接建立：

┌─────────────────────────────────────────────────────────────────┐
│                    SOCKS4 TCP 连接                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 连接请求（Client → Proxy）：                                  │
│                                                                 │
│     ┌─────────────────────────────────────────────────────────┐  │
│     │ VER    │ CMD    │ DSTPORT    │ DSTIP      │ USERID   │  │
│     │ 1 byte │ 1 byte │ 2 bytes    │ 4 bytes    │ Variable │  │
│     │ 0x04   │ 0x01   │ 端口号      │ IP 地址    │ 用户名    │  │
│     └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│     CMD: 0x01 = TCP 连接（CONNECT）                              │
│          0x02 = TCP 绑定（BIND）                                 │
│                                                                 │
│  2. 回复（Proxy → Client）：                                     │
│                                                                 │
│     ┌────────────────────────────┐                               │
│     │ VER    │ CMD    │ DSTPORT  │ DSTIP                         │
│     │ 1 byte │ 1 byte │ 2 bytes  │ 4 bytes                      │
│     │ 0x04   │ 回复码  │ 绑定端口  │ 绑定 IP                       │
│     └────────────────────────────┘                               │
│                                                                 │
│     回复码：                                                      │
│     ├─ 0x5A：请求批准（GRANTED）                                 │
│     ├─ 0x5B：请求被拒绝（REJECTED）                              │
│     └─ 0x5C：无法建立连接（CANNOT_CONNECT）                       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 SOCKS4 局限性

SOCKS4 存在明显局限：

```
SOCKS4 缺点：

1. 不支持域名解析
   ├─ 客户端必须知道目标 IP 地址
   └─ 无法通过域名连接

2. 无认证机制
   ├─ 任何客户端都可以使用代理
   └─ 安全风险

3. 不支持 UDP
   ├─ 只能转发 TCP 流量
   └─ DNS 解析等 UDP 需求无法满足
```

### 2.3 SOCKS4A 扩展

SOCKS4A 是 SOCKS4 的简单扩展，解决域名解析问题：

```
SOCKS4A 域名解析：

客户端发送：
┌────────────────────────────────────────────────────────────┐
│ VER  │ CMD  │ DSTPORT │ DSTIP    │ USERID │ NULL │ HOSTNAME │
│ 0x04 │ 0x01 │ 2 bytes │ 0.0.0.1  │ ...    │ 0x00 │ 目标域名  │
└────────────────────────────────────────────────────────────┘
         │                       │
         │                       └── IP = 0.0.0.1 表示是域名
         └── 连接命令

代理服务器收到后：
1. 解析 HOSTNAME
2. 连接解析后的 IP
3. 返回结果给客户端
```

## 3. SOCKS5 协议详解

### 3.1 SOCKS5 协议工作流程

SOCKS5 是当前主流版本，支持多种认证方式和 UDP 关联：

```
SOCKS5 连接建立完整流程：

┌─────────────────────────────────────────────────────────────────┐
│                    SOCKS5 完整握手                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  阶段一：版本与认证方法协商                                        │
│                                                                 │
│  Client ──── VER(0x05) + NMETHODS + METHODS ────────────▶ Server│
│             │                                                 │
│             │ 0x05 = SOCKS5                                    │
│             │ NMETHODS = 支持的认证方法数量                      │
│             │ METHODS = [0x00, 0x01, 0x02]                    │
│             │   0x00 = 无认证（GSSAPI 未列出，简化实现）          │
│             │   0x01 = GSSAPI                                  │
│             │   0x02 = 用户名/密码                              │
│             │   0x03~0x7F = IANA 分配                           │
│             │   0x80~0xFE = 私有方法                            │
│                                                                 │
│  Server ◀─── VER(0x05) + METHOD ─────────────────────── Client │
│             │                                                 │
│             │ 选择的认证方法                                    │
│                                                                 │
│  阶段二：认证（取决于选择的 METHOD）                              │
│                                                                 │
│  无认证（METHOD=0x00）：直接进入阶段三                            │
│                                                                 │
│  用户名/密码（METHOD=0x02）：                                    │
│                                                                 │
│  Client ──── VERSION + ID_LEN + ID + PW_LEN + PW ────▶ Server  │
│             │                                                 │
│             │ VERSION = 0x01                                  │
│             │ ID = 用户名                                      │
│             │ PW = 密码                                        │
│                                                                 │
│  Server ◀─── VERSION + STATUS ──────────────────────── Client  │
│             │                                                 │
│             │ STATUS: 0x00 = 成功，0x01 = 失败                  │
│                                                                 │
│  阶段三：连接请求                                                │
│                                                                 │
│  Client ──── VER + CMD + RSV + ATYP + DST.ADDR + DST.PORT ──▶  │
│             │                                                 │
│             │ CMD:                                             │
│             │   0x01 = CONNECT（TCP 连接）                      │
│             │   0x02 = BIND（TCP 绑定）                         │
│             │   0x03 = UDP ASSOCIATE（UDP 关联）               │
│             │ RSV: 0x00（保留）                                 │
│             │ ATYP: 地址类型                                   │
│             │   0x01 = IPv4（4 字节）                          │
│             │   0x03 = 域名（变长）                            │
│             │   0x04 = IPv6（16 字节）                         │
│                                                                 │
│  Server ◀─── VER + REP + RSV + ATYP + BND.ADDR + BND.PORT ──  │
│             │                                                 │
│             │ REP（回复码）：                                   │
│             │   0x00 = 成功                                     │
│             │   0x01 = 普通错误                                 │
│             │   0x02 = 规则不允许                               │
│             │   0x03 = 网络不可达                               │
│             │   0x04 = 主机不可达                               │
│             │   0x05 = 连接被拒绝                               │
│             │   0x06 = TTL 过期                                 │
│             │   0x07 = 命令不支持                               │
│             │   0x08 = 地址类型不支持                           │
│             │   0x09~0xFF = 未分配                              │
│                                                                 │
│  BND.ADDR/BND.PORT：代理服务器绑定地址（用于 BIND/UDP）           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 地址类型详解

```
SOCKS5 地址格式（ATYP）：

1. IPv4（ATYP = 0x01）：
   ┌────────────┬────────────┬────────────┐
   │ ATYP(0x01) │ IPv4(4B)  │ PORT(2B)   │
   └────────────┴────────────┴────────────┘

2. 域名（ATYP = 0x03）：
   ┌────────────┬──────────────┬────────────┐
   │ ATYP(0x03) │ LEN(1B)     │ DOMAIN(L)  │
   │            │ 域名长度     │ 域名字节   │
   │            └──────────────┴────────────┤
   │                         PORT(2B)       │
   └─────────────────────────────────────────┘
   说明：域名长度 + 域名内容 + 端口

3. IPv6（ATYP = 0x04）：
   ┌────────────┬─────────────────────────────┬────────────┐
   │ ATYP(0x04) │ IPv6(16B)                  │ PORT(2B)   │
   └────────────┴─────────────────────────────┴────────────┘
```

## 4. UDP ASSOCIATE 机制

### 4.1 UDP 转发原理

SOCKS5 的 UDP ASSOCIATE 命令用于建立 UDP 代理会话：

```
UDP ASSOCIATE 流程：

┌─────────────────────────────────────────────────────────────────┐
│                    UDP ASSOCIATE 完整流程                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 建立 TCP 控制连接                                             │
│                                                                 │
│  Client ──── TCP 连接 ────────────────────────────▶ Proxy       │
│             (到代理的 UDP ASSOC 端口，通常是 1080)                │
│                                                                 │
│  2. 发送 UDP ASSOCIATE 请求                                       │
│                                                                 │
│  Client ──── VER(0x05) + CMD(0x03) + RSV + ATYP + DST ────▶     │
│             │                                                 │
│             │ DST.ADDR = 0.0.0.0（客户端监听地址）               │
│             │ DST.PORT = 0（由代理指定）                         │
│                                                                 │
│  3. 代理回复绑定地址                                               │
│                                                                 │
│  Proxy ◀─── VER(0x05) + REP(0x00) + RSV + ATYP + BND ──── Client│
│             │                                                 │
│             │ BND.ADDR = 代理分配的 UDP 监听地址                 │
│             │ BND.PORT = 代理分配的 UDP 端口                     │
│             │                                                 │
│             │ 例如: 203.0.113.50:40001                          │
│                                                                 │
│  4. 客户端开始 UDP 通信                                           │
│                                                                 │
│  Client ──── UDP 数据报 ──────────────────────▶ Proxy            │
│             │                                                  │
│             │ 到 BND.ADDR:BND.PORT                             │
│             │                                                  │
│  Proxy ──── UDP 数据报 ──────────────────────▶ 目标服务器       │
│             │                                                  │
│             │ 代理替换源地址为代理服务器地址                      │
│             │                                                  │
│  目标 ──── UDP 响应 ────────────────────────────▶ Proxy          │
│             │                                                  │
│  Proxy ──── UDP 数据报 ──────────────────────▶ Client            │
│             │                                                  │
│             │ 通过 TCP 控制连接建立的 UDP 通道                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 UDP 数据报格式

```
SOCKS5 UDP 数据报格式：

┌─────────────────────────────────────────────────────────────────┐
│                    UDP 转发数据报格式                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────┬───────┬──────────┬───────────┬───────────────┐   │
│  │ RSV      │ FRAG  │ ATYP     │ DST.ADDR  │ DST.PORT      │   │
│  │ 2 bytes  │ 1 byte│ 1 byte   │ Variable  │ 2 bytes       │   │
│  ├──────────┼───────┼──────────┼───────────┼───────────────┤   │
│  │ 0x0000   │ 片段号 │ 地址类型  │ 目标地址   │ 目标端口       │   │
│  └──────────┴───────┴──────────┴───────────┴───────────────┘   │
│  │                          │                                   │
│  │ UDP 头部（代理添加）      │ 应用数据                          │
│  └──────────────────────────┴───────────────────────────────────┘
│                                                                 │
│  FRAG（片段号）：                                                │
│  ├─ 0x00 = 这是一个完整的 UDP 数据报                             │
│  ├─ 1~127 = 片段编号                                            │
│  └─ SOCKS5 支持分片传输（实际很少用）                              │
│                                                                 │
│  注意：每个 UDP 数据报都包含完整的目标地址，                        │
│  代理根据地址转发数据报                                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.3 UDP ASSOCIATE 使用场景

```
UDP ASSOCIATE 典型应用：

1. DNS 解析：
   Client ──── DNS 请求（UDP）───▶ Proxy ────▶ 8.8.8.8:53
   Client ◀─── DNS 响应（UDP）◀─── Proxy ◀─── 8.8.8.8:53

2. VoIP（如 Telegram 语音）：
   实时 UDP 传输需要 SOCKS5 UDP 支持

3. 在线游戏：
   很多游戏使用 UDP 进行实时通信

4. BitTorrent：
   虽然 BT 是 TCP 友好，但 uTP 等协议使用 UDP

限制：
├─ 代理服务器可能不支持 UDP
├─ UDP 无连接状态，代理可能超时断开
└─ 防火墙可能阻止 UDP 流量
```

## 5. GSSAPI 认证机制

### 5.1 GSSAPI 认证流程

SOCKS5 支持 GSSAPI（Generic Security Services Application Program Interface）认证：

```
GSSAPI 认证（SOCKS5）：

┌─────────────────────────────────────────────────────────────────┐
│                    GSSAPI 认证流程                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Client ──── VERSION(0x01) + AUTHTYPE(GSSAPI) ────▶ Server     │
│             │                                                 │
│             │ 通知服务器使用 GSSAPI                             │
│                                                                 │
│  Server ◀─── VERSION(0x01) + CTIME(GSS token) ──── Client      │
│             │                                                 │
│             │ 包含 GSSAPI 初始化 token                         │
│                                                                 │
│  ┌── 反复交换直到认证完成 ──┐                                    │
│  │                          │                                    │
│  │  Client ◀── GSS token ◀──│◀── Server                         │
│  │         │                                                  │
│  │         └──▶ Client 验证 token                              │
│  │                │                                           │
│  │                └──▶ 回复自己的 token                         │
│  │                          │                                   │
│  └──────────────────────────┘                                    │
│                                                                 │
│  Client ──── VERSION(0x01) + STATUS ────▶ Server               │
│             │                                                 │
│             │ STATUS: 0x00 = 认证成功                          │
│             │        0x01 = 认证失败                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

GSSAPI 优点：
├─ 基于 Kerberos 的强认证
├─ 不在网上传输明文密码
└─ 适合企业 Windows 环境（NTLM/Kerberos）
```

## 6. SOCKS5 实战配置

### 6.1 常用客户端配置

```
常见 SOCKS5 客户端配置：

1. 命令行 curl：
   curl --socks5 127.0.0.1:1080 http://example.com
   curl --socks5-hostname 127.0.0.1:1080 http://example.com
                          └── 使用域名解析通过代理

2. Firefox 浏览器：
   设置 → 常规 → 网络设置 → 手动配置代理
   SOCKS Host: 127.0.0.1
   Port: 1080
   SOCKS v5: ✓
   DNS 通过代理: ✓（推荐）

3. SSH SOCKS5 代理：
   ssh -D 1080 user@server
   │
   │  SSH 创建本地 SOCKS5 代理
   │  所有流量通过 SSH 隧道转发
   │
   └─ -D: 动态端口转发（本地 SOCKS5 代理）

4. shadowsocks-libev ss-local：
   {
       "server": "203.0.113.1",
       "server_port": 8388,
       "local_address": "127.0.0.1",
       "local_port": 1080,
       "password": "password",
       "method": "chacha20-ietf-poly1305",
       "mode": "tcp_and_udp"
   }
```

### 6.2 协议特征与检测

```
SOCKS5 流量特征：

1. 握手特征：
   ├─ 首次包：0x05（版本号）
   ├─ 方法协商：NMETHODS > 0
   └─ 无认证版本是 0x05 0x00

2. 连接请求特征：
   ├─ CMD 字段：0x01(CONNECT), 0x02(BIND), 0x03(UDP ASSOC)
   └─ ATYP 字段区分地址类型

3. 时序特征：
   ├─ 连接建立快速（无加密开销）
   └─ 没有 TLS 握手特征

检测方法：
├─ DPI 识别 SOCKS5 握手模式
├─ 检测无 TLS 的 TCP 代理流量
└─ 连接目标端口与协议不符（如 443 端口的 SOCKS）

对抗检测：
├─ 在 TLS 隧道内封装 SOCKS5
├─ 使用 SOCKS5 over TLS
└─ 配合混淆插件
```

## 7. SOCKS 协议与其他协议对比

```
SOCKS5 vs HTTP CONNECT vs WireGuard：

┌─────────────────┬───────────────┬───────────────┬───────────────┐
│ 特性            │ SOCKS5        │ HTTP CONNECT  │ WireGuard     │
├─────────────────┼───────────────┼───────────────┼───────────────┤
│ 层级            │ 会话层        │ 应用层        │ 网络层        │
│ TCP 支持        │ ✓             │ ✓             │ ✓             │
│ UDP 支持        │ ✓             │ ✗             │ ✓             │
│ 认证            │ 多种          │ Basic/Digest  │ 公钥          │
│ 加密            │ 无（可叠加）   │ TLS（可选）    │ ChaCha20      │
│ 代理协议        │ 通用          │ HTTP 专用     │ VPN 隧道      │
│ DNS 泄露风险    │ 取决于配置    │ 无            │ 无            │
│ MTU 处理        │ 应用负责      │ 应用负责      │ 自动分片      │
│ 典型用途        │ 翻墙、穿透    │ HTTPS 代理    │ 远程接入      │
│ 性能开销        │ 低            │ 中            │ 低            │
└─────────────────┴───────────────┴───────────────┴───────────────┘

选择建议：
├─ 需要通用代理（任何协议）：SOCKS5
├─ 只需 HTTP/HTTPS 代理：HTTP CONNECT
├─ 需要完整 VPN 隧道：WireGuard
└─ 企业内网穿透：SOCKS5 + TLS
```

## 8. 常见问题与解决方案

```
SOCKS5 常见问题：

1. DNS 泄露：
   问题：DNS 查询走本地 DNS，不经过代理
   解决：
   ├─ Firefox: network.proxy.socks_remote_dns = true
   ├─ 使用 --socks5-hostname（curl）
   └─ 系统级代理可能无法避免 DNS 泄露

2. UDP 不工作：
   检查：
   ├─ 代理服务器是否支持 UDP
   ├─ 防火墙是否放行 UDP 端口
   └─ 客户端是否正确处理 UDP RELAY

3. 连接被拒绝：
   ├─ 认证信息错误
   ├─ 代理服务器不允许该目标地址
   └─ 代理达到连接上限

4. SOCKS 与 HTTP 混淆：
   有些应用只支持 HTTP 代理
   解决：使用 redsocks 将 HTTP 流量转发到 SOCKS5

   Client → SOCKS1 → SOCKS2 → Target
```
