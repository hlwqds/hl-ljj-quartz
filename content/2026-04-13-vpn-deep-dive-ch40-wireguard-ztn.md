## 1. 概述：WireGuard 的零信任潜力

WireGuard 本身是一个轻量、安全的隧道协议，但默认配置下更像传统 VPN（网络层全通）。零信任需要在 WireGuard 基础上叠加身份层和策略层。

```
WireGuard + 零信任：

┌─────────────────────────────────────────────────────────────────┐
│                    WireGuard 零信任架构                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  WireGuard 基础层：                                            │
│  ├─ 加密隧道（ChaCha20-Poly1305）                              │
│  ├─ 身份标识：公钥                                              │
│  └─ 路由：AllowedIPs                                           │
│                                                                 │
│  零信任增强层：                                                │
│  ├─ 身份层：公钥绑定用户/设备身份                               │
│  ├─ 策略层：nftables 基于身份的访问控制                        │
│  ├─ 验证层：持续验证设备状态                                    │
│  └─ 日志层：访问审计                                            │
│                                                                 │
│  组合价值：                                                    │
│  ├─ 保留 WireGuard 性能优势                                     │
│  ├─ 增加零信任细粒度控制                                        │
│  └─ 消除「一旦接入可访问全网」风险                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.1 传统 WireGuard 的局限

```
传统 WireGuard vs 零信任：

┌─────────────────────────────────────────────────────────────────┐
│                    WireGuard 默认局限                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  传统 WireGuard 模型：                                         │
│                                                                 │
│    Client (公钥A) ──── WireGuard ──── Server                   │
│         │                                    │                   │
│         │         AllowedIPs = 0.0.0.0/0   │                   │
│         │         (全量路由)                │                   │
│         │                                    ▼                   │
│         │                              整个内网                  │
│         │                              10.0.0.0/8               │
│         │                                                            │
│  问题：                                                        │
│  ├─ 接入后可访问 AllowedIPs 内的所有地址                        │
│  ├─ 缺少基于用户/角色的访问控制                                │
│  ├─ 缺少设备状态验证                                            │
│  └─ 无微分段隔离                                                │
│                                                                 │
│  零信任 WireGuard：                                            │
│                                                                 │
│    Client (公钥A) ──── WireGuard ──── nftables ──> 精确策略   │
│         │                                    │                   │
│         │         AllowedIPs = 指定子网    │                   │
│         │         + 身份绑定              │                   │
│         │                                    ▼                   │
│         │                              仅允许访问的服务          │
│         │                              (基于策略)                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 2. WireGuard 身份绑定

### 2.1 公钥作为身份

WireGuard 使用 Curve25519 公钥作为设备标识：

```
WireGuard 身份模型：

┌─────────────────────────────────────────────────────────────────┐
│                    WireGuard 身份机制                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  身份表示：                                                    │
│  ├─ 公钥指纹：设备唯一标识（32 字节）                          │
│  ├─ 私钥：设备持有，永不外传                                   │
│  └─ 对等体配置：公钥 + 允许的 IP                               │
│                                                                 │
│  WireGuard 接口配置示例：                                      │
│                                                                 │
│  [Interface]                                                   │
│  PrivateKey = <private-key>                                   │
│  Address = 10.0.0.2/32                                        │
│                                                                 │
│  [Peer]                                                        │
│  PublicKey = <server-public-key>                              │
│  Endpoint = vpn.example.com:51820                             │
│  AllowedIPs = 10.0.0.0/24                                    │
│                                                                 │
│  问题：公钥本身不携带业务身份信息                               │
│                                                                 │
│  解决思路：                                                    │
│  ├─ 方案 1：公钥 → 用户/设备 ID 映射表                        │
│  ├─ 方案 2：公钥 → LDAP/IdP 查询                             │
│  └─ 方案 3：公钥 → SPIFFE ID（自定义扩展）                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

│  └─ 查询接口返回权限                                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
````

## 3. nftables 策略控制

### 3.1 nftables 基础

nftables 是 iptables 的现代替代，提供更灵活的规则管理：

```
nftables 优势：

┌─────────────────────────────────────────────────────────────────┐
│                    nftables vs iptables                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  nftables 优势：                                               │
│  ├─ 单一工具管理 IPv4/IPv6/ARP                                 │
│  ├─ 内置集合（set）和映射（map）                              │
│  ├─ 原子规则更新（无需锁）                                     │
│  ├─ 更好的性能                                                 │
│  └─ 更清晰的语法                                               │
│                                                                 │
│  iptables 局限：                                               │
│  ├─ IPv4 和 IPv6 分开管理                                     │
│  ├─ 规则逐一添加                                               │
│  ├─ 锁竞争问题                                                  │
│  └─ 语法复杂                                                   │
│                                                                 │
│  WireGuard + nftables 场景：                                  │
│  ├─ 基于公钥的流量标记                                         │
│  ├─ 基于身份的访问控制                                         │
│  ├─ 精细化微分段                                              │
│  └─ 与身份系统联动                                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 WireGuard 流量标记

````
nftables + WireGuard 流量标记：

┌─────────────────────────────────────────────────────────────────┐
│                    基于 WireGuard 公钥的标记                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  思路：                                                        │
│  1. WireGuard 接口接收流量时，标记来源 Peer                     │
│  2. 基于标记，应用 nftables 策略                               │
│  3. 实现基于身份的访问控制                                      │
│                                                                 │
│  实现步骤：                                                    │
│                                                                 │
│  1. 创建 WireGuard 接口：                                      │
│  ip link add dev wg0 type wireguard                           │
│  ip addr add 10.0.0.1/24 dev wg0                              │
│                                                                 │
│  2. 添加 Peer 并标记：                                         │
│  wg set wg0 peer <peer-public-key> \                          │
│      allowed-ips 10.0.0.2/32                                   │
│                                                                 │
│  3. nftables 标记规则：                                        │
│  ```                                                           │
│  # 在 prerouting 链标记来自特定 Peer 的流量                    │
│  chain prerouting {                                            │
│      type filter hook prerouting priority -100;               │
│                                                                 │
│      # 标记来自 Peer 的流量                                     │
│      meta iifname "wg0" \                                      │
│          ip saddr 10.0.0.2 \                                   │
│          meta mark set 0x1                                    │
│  }                                                             │
│                                                                 │
│  # 或使用 conntrack 标记                                       │
│  table inet wireguard {                                        │
│      chain forward {                                            │
│          ct state new meta mark set 0x1 \                      │
│              iifname "wg0" ip saddr 10.0.0.2                  │
│      }                                                         │
│  }                                                             │
│  ```                                                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
````

### 3.3 基于身份的访问控制

````
nftables 身份策略配置：

┌─────────────────────────────────────────────────────────────────┐
│                    nftables 零信任策略                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  场景：只有 engineering 部门的用户可以访问 10.0.0.10:8080      │
│                                                                 │
│  1. 定义地址集合：                                             │
│  ```                                                           │
│  nft add set inet filters engineering_ips {                    │
│      type ipv4_addr                                            │
│      elements = { 10.0.0.10, 10.0.0.11 }                      │
│  }                                                             │
│                                                                 │
│  nft add set inet filters finance_ips {                       │
│      type ipv4_addr                                            │
│      elements = { 10.0.0.20, 10.0.0.21 }                      │
│  }                                                             │
│                                                                 │
│  # engineering 部门的 WireGuard 客户端 IP                      │
│  nft add set inet filters engineering_peers {                 │
│      type ipv4_addr                                            │
│      elements = { 10.0.0.2, 10.0.0.3 }                        │
│  }                                                             │
│  ```                                                           │
│                                                                 │
│  2. 定义过滤规则：                                              │
│  ```                                                           │
│  table inet filter {                                           │
│      chain access_control {                                    │
│          # 允许 engineering 访问 engineering_ips                │
│          iifname "wg0" ip saddr @engineering_peers \          │
│              ip daddr @engineering_ips \                       │
│              tcp dport 8080 counter accept                     │
│                                                                 │
│          # 允许 finance 访问 finance_ips                         │
│          iifname "wg0" ip saddr @finance_peers \               │
│              ip daddr @finance_ips \                            │
│              tcp dport 8080 counter accept                      │
│                                                                 │
│          # 默认拒绝                                              │
│          counter drop                                           │
│      }                                                         │
│  }                                                             │
│  ```                                                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
````

## 4. NetBird 实践

### 4.1 NetBird 简介

NetBird 是基于 WireGuard 的零信任网络方案，提供身份驱动的网络策略：

```
NetBird 架构：

┌─────────────────────────────────────────────────────────────────┐
│                    NetBird 概述                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  定位：                                                         │
│  ├─ Zero-Config VPN alternative                               │
│  ├─ 基于 WireGuard                                              │
│  ├─ 内置身份和访问控制                                         │
│  └─ 开源（Apache 2.0）                                          │
│                                                                 │
│  核心功能：                                                     │
│  ├─ 自动 WireGuard 隧道建立                                    │
│  ├─ 基于用户的访问策略                                         │
│  ├─ 单包授权（类似 SDP）                                      │
│  ├─ 设备安全状态检查                                           │
│  ├─ DNS 分流                                                   │
│  └─ Web UI 管理                                                │
│                                                                 │
│  vs Tailscale：                                                │
│  ├─ Tailscale：依赖 DERP 中继，有退出节点限制                  │
│  ├─ NetBird：支持纯 P2P，支持自建信号服务器                    │
│  └─ 两者都基于 WireGuard                                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 ZeroTier 联邦

````
ZeroTier 地球（Planet）+ 叶片（Leaf）：

┌─────────────────────────────────────────────────────────────────┐
│                    ZeroTier 网络拓扑                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  核心概念：                                                    │
│  ├─ Node（节点）：每个设备的 ZeroTier 接口                      │
│  ├─ Moon（卫星）：自建的根服务器                               │
│  ├─ Planet（地球）：ZeroTier 官方根服务器                       │
│  └─ Root：根节点列表                                           │
│                                                                 │
│  流量路径：                                                    │
│                                                                 │
│  Node A ───────┐                                           │
│       │  ZeroTier 隧道加密                                     │
│       │                                                        │
│       └──────> Moon A ───────> Moon B ───────> Node B        │
│                                                                 │
│  自建 Moon：                                                  │
│  ├─ 部署自己的根服务器                                         │
│  ├─ 流量完全自主可控                                          │
│  └─ 适合企业内网                                               │
│                                                                 │
│  Moon 部署示例：                                               │
│  ```                                                           │
│  # 生成 Moon 配置文件                                          │
│  zerotier-idtool genmoon moon.json                            │
│                                                                 │
