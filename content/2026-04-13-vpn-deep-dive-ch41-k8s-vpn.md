## 1. 概述：Kubernetes 网络与 VPN

Kubernetes 默认使用 CNI（Container Network Interface）实现容器网络，但原生的 Kubernetes 网络模型假设一个可信的内部网络。在多集群、混合云、边缘计算场景下，需要 VPN 技术来实现跨网络的安全通信。

```
Kubernetes VPN 需求场景：

┌─────────────────────────────────────────────────────────────────┐
│                    Kubernetes VPN 场景                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  场景 1：多集群互联                                              │
│  ├─ 多个 K8s 集群分布在不同网络/云                                │
│  ├─ 需要安全通信                                                 │
│  └─ 方案：Cluster Federation / Direct Peering                  │
│                                                                 │
│  场景 2：混合云                                                  │
│  ├─ On-Premise + Cloud K8s                                     │
│  ├─ 跨越公网通信                                                 │
│  └─ 方案：WireGuard VPN Tunnel                                 │
│                                                                 │
│  场景 3：边缘计算                                                │
│  ├─ Edge K8s 节点在受限网络                                      │
│  ├─ 需要安全接入                                                 │
│  └─ 方案：WireGuard VPN + K8s API Server                      │
│                                                                 │
│  场景 4：开发者接入                                              │
│  ├─ 开发者的 laptop 接入 K8s 集群                                │
│  ├─ 访问内部服务                                                 │
│  └─ 方案：WireGuard VPN + kubeconfig                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

```

## 2. CNI VPN 方案

### 2.1 CNI 基础回顾

CNI（Container Network Interface）是 Kubernetes 容器网络的接口标准：

```
CNI 工作流程：

┌─────────────────────────────────────────────────────────────────┐
│                    CNI 工作流程                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Pod 创建时：                                                    │
│                                                                 │
│  1. kubelet 调用 CNI 插件（默认路径：/opt/cni/bin/）            │
│                                                                 │
│  2. CNI 插件执行：                                              │
│     ├─ 创建网络命名空间（netns）                                │
│     ├─ 创建 veth pair                                           │
│     ├─ 分配 IP（通过 IPAM 插件）                                │
│     └─ 配置网络命名空间的网络接口                                │
│                                                                 │
│  3. CNI 插件调用 flannel/calico 等网络插件：                    │
│     ├─ 配置路由                                                 │
│     └─ 配置网络策略                                             │
│                                                                 │
│  4. Pod 获得网络连接                                            │
│                                                                 │
│  关键接口：                                                     │
│  ├─ ADD：添加容器到网络                                         │
│  ├─ DEL：从网络删除容器                                         │
│  └─ CHECK：检查网络配置                                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 Calico-WireGuard 集成

Calico 是最流行的 CNI 插件之一，支持与 WireGuard 集成实现流量加密：

```
Calico-WireGuard 架构：

┌─────────────────────────────────────────────────────────────────┐
│                    Calico-WireGuard 集成                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │                    Kubernetes Cluster                      │  │
│  │                                                          │  │
│  │   Node A ────────────────────────── Node B              │  │
│  │      │                                    │               │  │
│  │      │  WireGuard 隧道（UDP 51820）      │               │  │
│  │      │  ════════════════════════════════│               │  │
│  │      ▼                                    ▼               │  │
│  │   Pod:10.1.1.10 ───────────────────> Pod:10.1.2.20       │  │
│  │                                                          │  │
│  │   ┌──────────────────────────────────────────────────┐   │  │
│  │   │  Calico CNI + WireGuard Encryption              │   │  │
│  │   │  ├─ Felix（CNI 插件）                            │   │  │
│  │   │  ├─ BIRD（ BGP 客户端）                         │   │  │
│  │   │  └─ WireGuard（内核模块）                       │   │  │
│  │   └──────────────────────────────────────────────────┘   │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                 │
│  优势：                                                          │
│  ├─ 性能优于 IPsec（WireGuard vs IPsec）                        │
│  ├─ 配置简单（相比 IPsec）                                      │
│  ├─ 保持 Calico 的所有功能（BGP、Network Policy）              │
│  └─ 自动密钥管理                                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 3. Cluster Federation（集群联邦）

### 3.1 KubeFed 概述

Kubernetes Federation（KubeFed）用于管理多个 Kubernetes 集群：

```
KubeFed 架构：

┌─────────────────────────────────────────────────────────────────┐
│                    KubeFed 集群联邦                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │                  KubeFed Control Plane                     │  │
│  │                                                          │  │
│  │  ┌─────────────────────────────────────────────────────┐ │  │
│  │  │                   KubeFed Controller                 │ │  │
│  │  │  ├─ ResourceSyncController                         │ │  │
│  │  │  ├─ ServiceDNSController                           │ │  │
│  │  │  ├─ ReplicaSchedulingController                     │ │  │
│  │  │  └─ DNSController                                   │ │  │
│  │  └─────────────────────────────────────────────────────┘ │  │
│  │                           │                               │  │
│  │  ┌───────────┐  ┌───────────┐  ┌───────────┐            │  │
│  │  │ Host Clus │  │ Member 1  │  │ Member 2  │            │  │

## 4. Direct Peering（直接对等）

### 4.1 概念解析

Direct Peering 是在网络层建立集群间的直接连接，不经过第三方中转：

```
Direct Peering 模型：

┌─────────────────────────────────────────────────────────────────┐
│                    Direct Peering vs 中转                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  传统中转模型：                                                  │
│                                                                 │
│  Cluster A ────────────── VPN GW ────────────── Cluster B        │
│                    │                │                            │
│                    └──────┬─────────┘                            │
│                             │                                    │
│                        第三方节点                                │
│                     （增加延迟和成本）                           │
│                                                                 │
│  Direct Peering 模型：                                          │
│                                                                 │
│  Cluster A ◄═══════════════════════════════► Cluster B          │
│           WireGuard P2P 直连                                     │
│           （低延迟、高带宽、加密）                                │
│                                                                 │
│  应用场景：                                                     │
│  ├─ 同区域多集群直接互联                                        │
│  ├─ VPC Peering 不可用时                                        │
│  ├─ 跨云服务商直连                                              │
│  └─ 需要加密但不使用云厂商 VPN 服务                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 WireGuard Direct Peering 配置

```
跨集群 WireGuard 配置：

┌─────────────────────────────────────────────────────────────────┐
│                    WireGuard Peering 配置                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Cluster A 配置：                                               │
│                                                                 │
│  # /etc/wireguard/wg0.conf                                     │
│  [Interface]                                                   │
│  Address = 10.100.0.1/24                                       │
│  PrivateKey = <cluster-a-private-key>                         │
│  ListenPort = 51820                                           │
│                                                                 │
│  # Peer to Cluster B                                           │
│  [Peer]                                                        │
│  PublicKey = <cluster-b-public-key>                            │
│  Endpoint = <cluster-b-public-ip>:51820                       │
│  AllowedIPs = 10.200.0.0/24                                   │
│  PersistentKeepalive = 25                                      │
│                                                                 │
│  Cluster B 配置：                                              │
│                                                                 │
│  # /etc/wireguard/wg0.conf                                     │
│  [Interface]                                                   │
│  Address = 10.200.0.1/24                                       │
│  PrivateKey = <cluster-b-private-key>                         │
│  ListenPort = 51820                                           │
│                                                                 │
│  # Peer to Cluster A                                           │
│  [Peer]                                                        │
│  PublicKey = <cluster-a-public-key>                            │
│  Endpoint = <cluster-a-public-ip>:51820                       │
│  AllowedIPs = 10.100.0.0/24                                   │
│  PersistentKeepalive = 25                                      │
│                                                                 │
│  Kubernetes 集成：                                             │
│  ├─ 使用 DaemonSet 在每个节点部署 WireGuard                     │
│  ├─ 配置路由使 Pod CIDR 通过 wg0 转发                           │
│  └─ 使用 kubeadm/kube-router 网络插件                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
