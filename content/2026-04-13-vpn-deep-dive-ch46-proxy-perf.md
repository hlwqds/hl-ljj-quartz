## 1. 概述：翻墙协议性能的特殊性

翻墙协议性能不仅取决于加密/协议开销，还受到以下因素影响：

- **GFW 干扰**：协议需要伪装和混淆来规避检测
- **传输层选择**：TCP/UDP/WebSocket/QUIC 各有优劣
- **中转与直连**：中转节点增加跳数
- **TLS 伪装开销**：Trojan/V2Ray TLS 层引入额外开销

```
翻墙协议 vs 传统 VPN：

┌─────────────────────────────────────────────────────────────────┐
│                     翻墙协议性能特点                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  与传统 VPN 的差异：                                            │
│  ├─ 需要 TLS 伪装来模拟正常 HTTPS 流量                         │
│  ├─ 协议特征需要足够「像」合法流量                              │
│  ├─ 混淆插件进一步增加开销                                      │
│  └─ 直连不稳定时需要中转节点                                    │
│                                                                 │
│  性能衡量维度：                                                │
│  ├─ 吞吐量（带宽利用率）                                        │
│  ├─ 延迟（RTT 增加）                                           │
│  ├─ 抗干扰性（GFW 丢包率）                                      │
│  ├─ 资源占用（CPU/内存）                                        │
│  └─ 稳定性（长时间连接保持）                                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 传输层性能分析

### 3.1 TCP vs UDP

```
TCP vs UDP 对翻墙协议的影响：

┌─────────────────────────────────────────────────────────────────┐
│                     传输层对比                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  UDP 优势：                                                    │
│  ├─ 无 TCP 拥塞控制，单包直发                                   │
│  ├─ 更难被 GFW 识别（模拟正常 QUIC）                           │
│  ├─ mKCP 可以在应用层实现重传控制                               │
│  └─ 延迟更低（省去握手）                                        │
│                                                                 │
│  UDP 劣势：                                                    │
│  ├─ 某些网络环境封锁 UDP 514 端口                              │
│  ├─ ISP 限速 UDP 流量                                          │
│  └─ 无 TLS 握手，伪装性差                                       │
│                                                                 │
│  TCP 优势：                                                    │
│  ├─ 全面可路由，网络兼容性好                                   │
│  ├─ TLS 伪装天然融入                                          │
│  └─ BBR 拥塞控制优化性能                                       │
│                                                                 │
│  TCP 劣势：                                                    │
│  ├─ 队头阻塞（head-of-line blocking）                          │
│  ├─ 握手延迟（TLS 1.3 1-RTT 改善）                             │
│  └─ GFW 可检测 TCP 特征                                         │
│                                                                 │
│  实际选择：                                                    │
│  ├─ 直连优先 UDP + mKCP                                        │
│  ├─ 中转或不稳定网络：TCP + TLS                                │
│  └─ 高风险环境：WebSocket + TLS                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 8. 总结

翻墙协议性能受多重因素影响：

- **协议开销**：Reality ≈ Shadowsocks < V2Ray < Trojan < Clash
- **传输层**：UDP+mKCP > TCP > WebSocket（延迟角度）
- **伪装强度**：TLS+WebSocket > TLS > mKCP（安全性角度）
- **真实利用率**：60-80%（考虑 GFW 干扰和节点质量）
- **优化关键**：选择匹配网络环境的传输层、合理配置加密算法

下一章我们将探讨 **VPN 安全加固**，从证书管理、密钥轮换、漏洞防护等角度全面强化 VPN 安全性。
