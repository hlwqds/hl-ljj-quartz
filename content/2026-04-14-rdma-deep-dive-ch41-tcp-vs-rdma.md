> [!abstract] 核心要点
> TCP 与 RDMA 代表两种截然不同的网络技术路线：TCP 强调通用性与兼容性，RDMA 追求极致性能。本章从协议栈、延迟、带宽、CPU 开销、成本等多个维度深度对比两种技术，并提供场景化的选型决策框架，帮助工程师在具体业务中做出正确选择。

## 1. 协议架构对比

### 1.1 TCP/IP 协议栈 vs RDMA 协议栈

```
TCP/IP 协议栈 (传统内核网络)：

  应用层      HTTP / gRPC / Redis / 数据库
                 ↓
  ────────────────────────────────────────────
                 ↓
  传输层        TCP (可靠连接、拥塞控制、流量控制)
                 ↓
  ────────────────────────────────────────────
                 ↓
  网络层        IP (路由、TTL、分片)
                 ↓
  ────────────────────────────────────────────
                 ↓
  数据链路层    Ethernet (MAC、VLAN)
                 ↓
  ────────────────────────────────────────────
                 ↓
  物理层        PHY (SerDes、PCIe)

  内核参与：
  - 每个数据包经过内核协议栈 (sk_buff)
  - 多次内存拷贝 (用户态 ↔ 内核态)
  - 上下文切换 (系统调用)
  - CPU 参与协议处理


RDMA 协议栈 (RoCEv2 为例)：

  应用层      libibverbs / RDMA CM API
                 ↓
  ────────────────────────────────────────────
                 ↓
  用户空间     直接访问 HCA (绕过内核!)
                 ↓
  ────────────────────────────────────────────
                 ↓
  传输层        IB Transport (RC/UC/UD)
                 ↓
  ────────────────────────────────────────────
                 ↓
  网络层        IP (仅路由用)
                 ↓
  ────────────────────────────────────────────
                 ↓
  数据链路层    Ethernet + IB Transport Header
                 ↓
  ────────────────────────────────────────────
                 ↓
  物理层        PHY (SerDes、PCIe)

  内核参与：
  - 仅在连接建立时参与 (CM)
  - 数据传输完全绕过内核
  - HCA 硬件完成协议处理
```

### 1.2 数据传输路径对比

```
TCP 数据传输路径 (多次拷贝 + 内核参与)：

  用户应用          用户空间
       │                  │
       │  write()/send()  │  ← 系统调用 (上下文切换)
       │                  ▼
  ┌─────────────────────────────────────────┐
  │              内核协议栈                    │
  │  ┌─────────────────────────────────────┐ │
  │  │  1. 分配 sk_buff                    │ │
  │  │  2. 从用户态拷贝数据                │ │
  │  │  3. TCP 头部添加                    │ │
  │  │  4. IP 头部添加                     │ │
  │  │  5. 发送到 NIC 驱动                 │ │
  │  └─────────────────────────────────────┘ │
  └─────────────────────────────────────────┘
       │                  ↑
       │                  │  sk_buff
       ▼                  │
  ┌─────────┐       内核空间
  │   NIC   │
  └─────────┘
       │
       │ PCIe DMA
       ▼
  ┌─────────────────────────────────────────┐
  │         网络 (TCP/IP 包)                 │
  └─────────────────────────────────────────┘

  关键开销：
  - 2+ 次内存拷贝 (用户 → sk_buff → NIC)
  - 上下文切换 (用户态 ↔ 内核态)
  - CPU 协议处理 (TCP checksum、拥塞算法)


RDMA 数据传输路径 (零拷贝 + 零 CPU)：

  用户应用          用户空间
       │
       │  ibv_post_send()  ← 直接提交到 HCA
       ▼
  ┌─────────────────────────────────────────┐
  │              HCA (SmartNIC)             │
  │  ┌─────────────────────────────────────┐│
  │  │  RDMA 引擎 (硬件实现)               ││
  │  │  - DMA 直接访问用户内存             ││
  │  │  - RDMA 头部封装                   ││
  │  │  - 校验和计算 (硬件)               ││
  │  └─────────────────────────────────────┘│
  └─────────────────────────────────────────┘
       │
       │ PCIe DMA
       ▼
  ┌─────────────────────────────────────────┐
  │         网络 (RDMA 帧)                   │
  └─────────────────────────────────────────┘

  关键优势：
  - 零内存拷贝 (DMA 直接访问)
  - 零上下文切换 (用户态提交)
  - 零 CPU 参与 (HCA 硬件处理)
```

## 2. 性能深度对比

### 2.1 延迟对比

```
延迟构成分析：

  TCP 延迟构成：
  ┌─────────────────────────────────────────────────────────────────┐
  │  发送端                                                        │
  │  - 应用准备数据:        1-5 us                                  │
  │  - 系统调用开销:        0.5-2 us                                │
  │  - 用户→内核拷贝:       1-3 us                                  │
  │  - TCP 协议处理:        2-5 us                                  │
  │  - NIC 传输:           <1 us                                   │
  ├─────────────────────────────────────────────────────────────────┤
  │  接收端                                                        │
  │  - NIC 中断/DMA:       1-2 us                                  │
  │  - 内核协议栈:          3-10 us                                 │
  │  - 内核→用户拷贝:       1-3 us                                  │
  │  - 上下文切换:          0.5-2 us                                │
  │  - 应用处理:            1-5 us                                  │
  ├─────────────────────────────────────────────────────────────────┤
  │  网络传输:              1 us/hop                               │
  └─────────────────────────────────────────────────────────────────┘
  TCP 典型单跳延迟: 20-50 us

  RDMA 延迟构成：
  ┌─────────────────────────────────────────────────────────────────┐
  │  发送端                                                        │
  │  - 应用准备数据:        1-5 us                                  │
  │  - ibv_post_send():    <1 us (用户态)                          │
  │  - HCA DMA + 封装:     <1 us                                   │
  ├─────────────────────────────────────────────────────────────────┤
  │  接收端                                                        │
  │  - HCA DMA:            <1 us                                   │
  │  - 应用 polling:       1-5 us                                  │
  ├─────────────────────────────────────────────────────────────────┤
  │  网络传输:              1 us/hop                               │
  └─────────────────────────────────────────────────────────────────┘
  RDMA 典型单跳延迟: 1-3 us

延迟对比数据 (同一硬件环境)：

  场景                TCP        RDMA      提升倍数
  ─────────────────────────────────────────────────
  同一交换机内 (1 hop)  25 us     1.5 us      17x
  跨交换机 (3 hops)     40 us     3.0 us      13x
  跨数据中心 (40km)     300 us    280 us       1.1x
```

## 4. 适用场景分析

### 4.1 TCP 适用场景

```
TCP 最佳应用场景：

  ┌─────────────────────────────────────────────────────────────────┐
  │  1. 通用 Web 服务 / API 网关                                     │
  │     - 延迟不敏感 (P99 < 100ms 即可)                            │
  │     - 突发流量，需要 TCP 拥塞控制                                │
  │     - 跨公网/Internet                                           │
  │                                                                  │
  │  2. 传统企业应用                                                 │
  │     - 数据库 (MySQL/PostgreSQL) 主从复制                       │
  │     - 消息队列 (Kafka/RabbitMQ)                                │
  │     - 现有架构迁移，避免大改                                     │
  │                                                                  │
  │  3. 开发/测试环境                                                │
  │     - 成本敏感                                                   │
  │     - 性能要求不高                                               │
  │                                                                  │
  │  4. 跨地域通信                                                   │
  │     - 长距离链路，RTT 本身已很高                                  │
  │     - RDMA 优势不明显                                           │
  │     - 需要 TCP 的拥塞控制应对丢包                                │
  └─────────────────────────────────────────────────────────────────┘
```

### 4.2 RDMA 适用场景

### 5.2 统一交换网络配置

```bash
# 双模交换机配置示例 (Mellanox Spectrum)

# 1. 创建 RDMA VLAN
vlan 100
  name RDMA_NETWORK

# 2. 配置 PFC (Priority 3 for RDMA)
priority-flow-control mode on
priority-flow-control priority 3 enable

# 3. 配置 DCBX
dcbx mode ieee
dcbx enable

# 4. 配置 ECN (for RoCE)
congestion-control roce ecn enable
congestion-control roce ecn min-threshold 20
congestion-control roce ecn max-threshold 80

# 5. 配置带宽分配 (ETS)
traffic-bandwidth egress-hierarchy ets 40 strict priority 3
traffic-bandwidth egress-hierarchy ets 60 fair bandwidth 0-2,4-7

# 6. 验证配置
show priority-flow-control
show dcbx status
show congestion-control roce
```

### 6.1 从 TCP 迁移到 RDMA

```
迁移策略：

  Phase 1: 并行运行

  ┌─────────────────────────────────────────┐
  │  - 性能基准对比                          │

  └─────────────────────────────────────────┘
```

## 7. 小结

- **延迟**：RDMA 1-3 us vs TCP 20-50 us（同一跳内），提升 10-20x
- **带宽利用率**：RDMA 95%+ vs TCP 75-80%，CPU 开销 RDMA <2% vs TCP 30%+
- **成本**：RDMA 硬件成本高 3-5x，但 CPU 节省可抵消
- **复杂度**：TCP 简单成熟，RDMA 需要专业知识和无损网络配置
- **选型**：AI/HPC/存储选 RDMA；通用服务/跨地域选 TCP
- **趋势**：混合部署是主流，RDMA 承担关键负载，TCP 承担通用流量
