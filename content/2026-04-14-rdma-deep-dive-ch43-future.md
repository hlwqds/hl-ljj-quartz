## 1. CXL 与 RDMA 融合

### 1.1 CXL 技术概述

```
CXL (Compute Express Link) 技术：

  CXL 是一种面向异构计算的快速互联技术：

  ┌─────────────────────────────────────────────────────────────────┐
  │                     CXL 协议栈                                   │
  │                                                                  │
  │   应用层                                                          │
  │      ↓                                                           │
  │   ┌───────────────────────────────────────────────────────────┐ │
  │   │  CXL.mem (内存扩展) | CXL.cache (缓存一致性) | CXL.io    │ │
  │   └───────────────────────────────────────────────────────────┘ │
  │      ↓                                                           │
  │   PCIe Gen5/6 物理层                                             │
  └─────────────────────────────────────────────────────────────────┘

  CXL vs RDMA：

  ┌─────────────────────────────────────────────────────────────────┐
  │           CXL                        RDMA                      │
  │  ────────────────────────────────────────────────────────────── │
  │  距离:    短距离 (同一服务器/机架)      长距离 (跨服务器/数据中心) │
  │  延迟:    <100 ns (本地内存级别)        1-5 us (网络级别)         │
  │  带宽:    1-2 TB/s (PCIe Gen5)          400-800 Gb/s             │
  │  寻址:    统一内存空间                  远程内存地址 (RKey)       │
  │  缓存:    支持一致 性缓存               无缓存一致性              │
  │  场景:    内存扩展、异构计算           跨节点通信、分布式存储    │
  └─────────────────────────────────────────────────────────────────┘
```

  │    │                 │          │  │ Exp.  │ │     │ │ Exp.  │  │
  │    │   ┌─────────┐   │          │  └───┬───┘ │     │ └───┬───┘  │
  │    │   │   DRAM   │   │          │      │     │     │      │
  │    │   │ (本地)   │   │          │      └──────┼─────┘      │
  │    │   └─────────┘   │          │             │ RDMA        │
  │    │                 │          │             │             │
  │    │   ┌─────────┐   │          │      ┌──────┴──────┐      │
  │    │   │ CXL Mem │   │          │      │             │      │

  - CXL 扩展本地内存，解决容量瓶颈

  - 统一编程模型，抽象差异

### 2.2 RDMA 与可编程交换机融合

```c
// RDMA + 可编程交换机融合示例
// 使用 P4 实现 RDMA 网内聚合

// P4 数据平面代码 (伪代码)
program RDMA_Aggregation {
    // 定义 RDMA 报文字段
    header rdma_header {
        bit<4>    version;
        bit<4>    opcode;      // RDMA_OP_*
        bit<24>   reserved;
        bit<8>    qp_num;      // Queue Pair Number
        bit<48>   remote_addr; // Remote Memory Address
        bit<32>   rkey;        // Remote Key
    }

    // 自定义网内计算元数据
    metadata in_network_meta {
        bit<16> aggregation_tag;
        bit<8>  partial_result[];
        bit<1>  is_last;
    }

    // RDMA Write with Immediate 处理
    action process_rdma_write() {
        // 提取聚合标签
        extract_agg_tag(rdma_header.qp_num);

        // 网内聚合逻辑
        if (is_partial_data()) {
            // 累加部分结果
            in_network_meta.partial_result += payload;
        }

        if (is_last) {
            // 最后一条，发送到目的地
            forward_to_cpu_or_memory();
        }
    }

    // 流水线入口
    apply {
        // 解析 RDMA 头
        parse_rdma_header();

        // 根据 opcode 处理
        switch (rdma_header.opcode) {
            case RDMA_OP_WRITE_IMM:
                process_rdma_write();
                break;
            case RDMA_OP_SEND:
                // 透传，不做计算
                forward();
                break;
        }
    }
}
```

## 4. 新一代传输协议

### 4.1 CNDP (Connected Network Data Plane)

```
C NDP 概述：

  CNDP (Connected Network Data Plane) 是 Linux 基金会的新项目，
  旨在为高性能应用提供统一的数据平面 API：

  ┌─────────────────────────────────────────────────────────────────┐
  │                     CNDP 架构                                   │
  │                                                                  │
  │   应用层                                                          │
  │      ↓                                                           │
  │   ┌───────────────────────────────────────────────────────────┐ │
  │   │                    CNDP API                                │ │
  │   │   - 统一的网络 API (替代 POSIX socket)                    │ │
  │   │   - 支持 RDMA/DPDK/TCP/UDP 统一抽象                       │ │
  │   │   - 异步 I/O + 零拷贝                                      │ │
  │   └───────────────────────────────────────────────────────────┘ │
  │                              ↓                                  │
  │   ┌───────────────────────────────────────────────────────────┐ │
  │   │                    传输层实现                              │ │
  │   │  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐       │ │
  │   │  │RDMA/IB │  │DPDK     │  │TCP/UDP │  │Memory   │       │ │
  │   │  │        │  │(libpcap)│  │(kernel)│  │Map      │       │ │
  │   │  └─────────┘  └─────────┘  └─────────┘  └─────────┘       │ │
  │   └───────────────────────────────────────────────────────────┘ │
  │                              ↓                                  │
  │   ┌───────────────────────────────────────────────────────────┐ │
  │   │                    硬件抽象层                              │ │
  │   │  ┌─────────┐  ┌─────────┐  ┌─────────┐                   │ │
  │   │  │ RDMA NIC│  │ ETH NIC │  │Memory   │                   │ │
  │   │  │(mlx5)   │  │(i40e)   │  │(CXL)    │                   │ │
  │   │  └─────────┘  └─────────┘  └─────────┘                   │ │
  │   └───────────────────────────────────────────────────────────┘ │
  └─────────────────────────────────────────────────────────────────┘

  CNDP vs RDMA：
  - CNDP 是 API 抽象层，可以封装 RDMA
  - 应用通过 CNDP 统一访问 RDMA/TCP/DPDK
  - 提供更好的可移植性
```

## 7. 小结

- **CXL + RDMA**：CXL 解决本地内存扩展，RDMA 解决跨节点访问，两者互补构成统一内存访问架构
- **可编程网络**：网内计算从 SHARP 演进到 P4 可编程，RDMA 网内聚合成为可能
- **SmartNIC**：从固定加速到可编程再到集成 NPU，网卡正在成为多功能计算平台
- **边缘 RDMA**：轻量化 RDMA Lite 协议适应边缘场景，低功耗设计是关键
- **CNDP/ODP**：统一 API 抽象层简化 RDMA 编程，提升应用可移植性
- **新兴场景**：隐私计算、量子通信、存算一体与 RDMA 的融合探索
- **速率演进**：400Gb/s 已成熟，800Gb/s 和 1.6Tb/s 正在规划中
