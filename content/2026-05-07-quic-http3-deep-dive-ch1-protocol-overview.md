```

## 2. QUIC 背景与动机

### 2.1 HTTP/1.1 到 HTTP/2 的问题

```
HTTP 并发问题：

┌──────────────────────────────────────────────────────────────────────┐
│                        HTTP/1.1 连接限制                            │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   浏览器 ──► Server                                                │
│                                                                      │
│   问题：每个域名 6 个连接上限                                       │
│   解决：域名分片 (shard)                                            │
│                                                                      │
│   www.example.com                                                   │
│   ├── assets1.example.com                                         │
│   ├── assets2.example.com                                         │
│   └── ...                                                          │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        HTTP/2 多路复用                               │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │            TCP Connection (Single)                          │   │
│   ├─────────────────────────────────────────────────────────────┤   │
│   │  Stream 1: HTML                                             │   │
│   │  Stream 2: CSS                                              │   │
│   │  Stream 3: JS                                               │   │
│   │  Stream 4: Image 1                                          │   │
│   │  Stream 5: Image 2                                          │   │
│   │  Stream 6: Image 3                                          │   │
│   └─────────────────────────────────────────────────────────────┘   │
│                                                                      │
│   问题：TCP HOL (Head-of-Line) 阻塞                                 │
│   · 丢包 → 所有 Stream 等待重传                                      │
│   │                                                             │
│   │  Stream 1  ████████████████░░░░░░░░                         │
│   │  Stream 2  ████████░░░░░░░░░░░░░░░                         │
│   │  Stream 3  ████████████████████████                         │
│   │                                                             │
│   │            └── packet loss ──┘                              │
│   │                                                             │
│   │  结果：所有 Stream 被阻塞等待                                │
│   │                                                             │
└──────────────────────────────────────────────────────────────────────┘

### 2.2 QUIC 解决思路

```
QUIC vs TCP+TLS：

┌──────────────────────────────────────────────────────────────────────┐
│                        TCP+TLS 握手延迟                              │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   TCP 3-way handshake:                                              │
│   Client ─────────────────────────────────────────────────► Server   │
│         ◄──────────────────────────────────────────────────         │
│                   1 RTT                                             │
│                                                                      │
│   TLS 1.3 handshake:                                               │
│   Client ─────────────────────────────────────────────────► Server   │
│         ◄──────────────────────────────────────────────────         │
│                   1 RTT                                             │
│                                                                      │
│   Total: 2 RTT (TCP) + 1 RTT (TLS) = 3 RTT                         │
│                                                                      │
│   + HTTP 请求/响应                                                   │
│   = 4 RTT (新连接)                                                   │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        QUIC 握手延迟                                 │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   Combined QUIC handshake (内嵌 TLS):                              │
│   Client ─────────────────────────────────────────────────► Server   │
│         ◄──────────────────────────────────────────────────         │
│                   1 RTT                                              │
│                                                                      │
│   + HTTP 请求/响应                                                   │
│   = 2 RTT (新连接)                                                   │
│                                                                      │
│   或 1-RTT (简化模式)                                                │
│                                                                      │
│   + 0-RTT (恢复会话)                                                │
│   = 1 RTT (0-RTT 数据)                                              │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 3. QUIC 核心概念

### 3.1 协议栈

```
QUIC 协议栈：

┌──────────────────────────────────────────────────────────────────────┐
│                        应用层 (HTTP/3)                              │
├──────────────────────────────────────────────────────────────────────┤
│                        QUIC 传输层                                  │
│   ┌──────────────────────────────────────────────────────────────┐  │
│   │  可靠性、拥塞控制、流控制、流量分帧                           │  │
│   │  Connection ID、Stream ID、Frame Type                        │  │
│   └──────────────────────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────────────────────────┤
│                        QUIC Crypto 层                               │
│   ┌──────────────────────────────────────────────────────────────┐  │
│   │  TLS 1.3 握手、密钥导出、证书验证                            │  │
│   │  0-RTT、1-RTT握手                                           │  │
│   └──────────────────────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────────────────────────┤
│                        UDP (Lite)                                   │
├──────────────────────────────────────────────────────────────────────┤
│                        IP                                           │
└──────────────────────────────────────────────────────────────────────┘

对比 TCP+TLS 栈：

┌──────────────────────────────────────────────────────────────────────┐
│                        应用层 (HTTP)                                │
├──────────────────────────────────────────────────────────────────────┤
│                        TLS                                          │
├──────────────────────────────────────────────────────────────────────┤
│                        TCP                                           │
│   ┌──────────────────────────────────────────────────────────────┐  │
│   │  可靠性、拥塞控制、流量控制、流分帧 (HTTP/2)                 │  │
│   └──────────────────────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────────────────────────┤
│                        IP                                           │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.2 连接与连接 ID

```
QUIC 连接：

┌──────────────────────────────────────────────────────────────────────┐
│                        QUIC 连接                                     │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   Client                              Server                        │
│   ───────                            ───────                       │
│   Connection ID: 0xA1B2C3D4          Connection ID: 0x11223344       │
│   (由 server 选择)                   (由 server 选择)             │
│                                                                      │
│   客户端使用 Server's CID 发送包                                    │
│   服务端使用 Client's CID 发送包                                     │
│                                                                      │
│   包的 source CID = 发送者的 CID                                    │
│   包的 dest CID = 接收者的 CID                                      │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

为什么需要 Connection ID？

┌──────────────────────────────────────────────────────────────────────┐
│                        连接迁移                                     │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   Client (192.168.1.100:54321) ───► Server (1.2.3.4:443)            │
│                                                                      │
│   WiFi ──► 切换 ──► 4G                                              │
│   IP 变化: 192.168.1.100 ──► 10.0.0.50                            │
│   Port 变化: 54321 ──► 65432                                      │
│                                                                      │
│   但 Connection ID 不变！                                           │
│   可以继续通信，无需重新建立连接                                     │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.3 Stream 多路复用

```
QUIC Stream：

┌──────────────────────────────────────────────────────────────────────┐
│                        QUIC 多路复用                                │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │            QUIC Connection                                   │   │
│   ├─────────────────────────────────────────────────────────────┤   │
│   │  Stream 0: HTTP Headers                                     │   │
│   │  Stream 1: CSS                                             │   │
│   │  Stream 2: JS                                              │   │
│   │  Stream 3: Image 1                                         │   │
│   │  Stream 4: Image 2                                         │   │
│   │  Stream 5: Image 3                                         │   │
│   └─────────────────────────────────────────────────────────────┘   │
│                                                                      │
│   独立可靠传输：                                                    │
│   · Stream 1 丢包 → 只重传 Stream 1                                 │
│   · Stream 2-5 不受影响                                            │
│   · 无 HOL 阻塞！                                                   │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

Stream vs HTTP/2 Stream：

┌──────────────────────────────────────────────────────────────────────┐
│                        Stream 对比                                   │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   HTTP/2 (over TCP):                                               │
│   · 丢包 → 所有流阻塞                                              │
│   · 拥塞窗口 共享                                                   │
│   · TCP 层面重传                                                    │
│                                                                      │
│   QUIC:                                                            │
│   · 丢包 → 只影响对应流                                            │
│   · 每个流独立拥塞控制                                              │
│   · QUIC 层面重传                                                  │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 4. QUIC Wire Format

### 4.1 包结构

```
QUIC 包格式：

┌──────────────────────────────────────────────────────────────────────┐
│                        QUIC Packet                                  │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │  Header                                                      │   │
│   │  ┌─────────────────────────────────────────────────────────┐│   │
│   │  │  Flags (8 bits)                                        ││   │
│   │  │  + Connection ID (0-160 bits, 可变)                    ││   │
│   │  │  + Version / Packet Number (可变)                      ││   │
│   │  └─────────────────────────────────────────────────────────┘│   │
│   └─────────────────────────────────────────────────────────────┘   │
│                                                                      │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │  Payload (加密)                                             │   │
│   │  ┌─────────────────────────────────────────────────────────┐│   │
│   │  │  Frames (STREAM, ACK, PADDING, etc.)                  ││   │
│   │  └─────────────────────────────────────────────────────────┘│   │
│   └─────────────────────────────────────────────────────────────┘   │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.2 Header 类型

```
Long Header Packet（首次握手）：

┌──────────────────────────────────────────────────────────────────────┐
│                        Long Header                                  │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ┌────────┬────────┬────────┬────────┬────────┬────────────────┐  │
│   │ 1 bit  │ 2 bits │ 2 bits │ 1 bit  │ Variable│  Variable      │  │
│   ├────────┼────────┼────────┼────────┼────────┼────────────────┤  │
│   │ 0      │ T1 T0  │ K P    │ S      │ Dest    │  Src           │  │
│   │        │        │        │        │ Conn ID │  Conn ID       │  │
│   │        │        │        │        │ (0-160) │  (0-160)       │  │
│   └────────┴────────┴────────┴────────┴────────┴────────────────┘  │
│                                                                      │
│   0: Long header (固定)                                            │
│   T1-T0: 包类型                                                     │
│     00: Initial                                                    │
│     01: 0-RTT                                                     │
│     10: Handshake                                                 │
│     11: Retry                                                     │
│   K: 包含詹森签名数据（Key Phase）                                  │
│   P: 包含 PADDING（在 Initial 包中）                                │
│   S: 包含令牌（Token）                                             │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

Short Header Packet（连接建立后）：

┌──────────────────────────────────────────────────────────────────────┐
│                        Short Header                                 │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ┌────────┬──────────────────┬────────────────────────────────┐   │
│   │ 1 bit  │ 5 bits           │  Variable                     │   │
│   ├────────┼──────────────────┼────────────────────────────────┤   │
│   │ 1      │ Connection ID   │  Packet Number                │   │
│   │        │ (0-160 bits)     │  (1-4 bytes)                   │   │
│   │        │                  │  + Encrypted Payload          │   │
│   └────────┴──────────────────┴────────────────────────────────┘   │
│                                                                      │
│   1: Short header (固定)                                           │
│   后跟 Connection ID 和包号                                         │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.3 包类型

```
包类型详解：

┌──────────────────────────────────────────────────────────────────────┐
│                        Initial Packet                              │
├──────────────────────────────────────────────────────────────────────┤
│   用途：握手开始，建立连接                                          │
│   包含：CRYPTO frame (Client Hello)                                │
│   加密：Initial 密钥（从 0-RTT 种子导出）                           │
│   大小：至少 1200 bytes（用于抗放大攻击）                           │
│   Token: 可选的 Retry Token                                        │
│                                                                      │
│   Frames: CRYPTO, ACK, PING, PADDING                               │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        0-RTT Packet                                │
├──────────────────────────────────────────────────────────────────────┤
│   用途：恢复会话，提前发送应用数据                                  │
│   包含：CRYPTO frame (early data)                                 │
│   加密：0-RTT 密钥                                                 │
│   限制：不能包含敏感请求（POST 等）                                 │
│   可被服务器拒绝（0-RTT rejected）                                  │
│                                                                      │
│   Frames: CRYPTO, STREAM, PING                                     │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        Handshake Packet                             │
├──────────────────────────────────────────────────────────────────────┤
│   用途：完成密钥交换，确认连接                                      │
│   包含：CRYPTO frame (Server Hello, etc.)                         │
│   加密：Handshake 密钥                                             │
│   必须：服务端必须收到并确认                                        │
│                                                                      │
│   Frames: CRYPTO, ACK, PING, STREAM                               │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        Short Header Packet                          │
├──────────────────────────────────────────────────────────────────────┤
│   用途：连接建立后，传输应用数据                                    │
│   包含：STREAM frames, ACK frames                                 │
│   加密：1-RTT 密钥                                                 │
│   优化：更短的 Header，减小开销                                     │
│                                                                      │
│   Frames: STREAM, ACK, PING, PADDING, CONNECTION_CLOSE             │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 5. Frame 类型

### 5.1 Frame 结构

```
Frame 格式：

┌──────────────────────────────────────────────────────────────────────┐
│                        QUIC Frame                                   │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ┌─────────────────────────────────────────────────────────────┐   │
│   │  Type (variable length)                                     │   │
│   │  + Payload (type-specific)                                  │   │
│   └─────────────────────────────────────────────────────────────┘   │
│                                                                      │
│   Frame = Type (1-2 bytes) + Payload                               │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 5.2 常用 Frame

```
常见 Frame 类型：

┌──────────────────────────────────────────────────────────────────────┐
│                        STREAM Frame                                 │
├──────────────────────────────────────────────────────────────────────┤
│   用途：传输应用数据                                                │
│   流向：双向                                                        │
│                                                                      │
│   ┌────────────────────────────────────────────────────────────┐    │
│   │  Type: 0x08-0x0f (stream_id 2bits + off/data/fin flags)  │    │
│   │  Stream ID (varint)                                        │    │
│   │  Offset (varint)                                          │    │
│   │  Length (varint)                                          │    │
│   │  Data (length bytes)                                      │    │
│   └────────────────────────────────────────────────────────────┘    │
│                                                                      │
│   标志位：                                                          │
│   · OFF: Offset 字段存在                                          │
│   · LEN: Length 字段存在                                          │
│   · FIN: 这是流的最后一个片段                                      │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        CRYPTO Frame                                 │
├──────────────────────────────────────────────────────────────────────┤
│   用途：传输 TLS 握手数据                                          │
│   位置：可用于 Initial, Handshake, 1-RTT 包                        │
│                                                                      │
│   ┌────────────────────────────────────────────────────────────┐    │
│   │  Type: 0x06                                                │    │
│   │  Offset (varint) - 数据在 crypto 流中的偏移                │    │
│   │  Length (varint)                                           │    │
│   │  Crypto Data (length bytes)                                │    │
│   └────────────────────────────────────────────────────────────┘    │
│                                                                      │
│   与 STREAM 的区别：                                                │
│   · 用于 TLS 握手，不经过应用层                                     │
│   · 有独立的 crypto 流偏移                                         │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        ACK Frame                                   │
├──────────────────────────────────────────────────────────────────────┤
│   用途：确认收到的包                                                │
│   变体：ACK (0x02-0x03), ACK_MUST (0x05)                           │
│                                                                      │
│   ┌────────────────────────────────────────────────────────────┐    │
│   │  Type: 0x02-0x03                                          │    │
│   │  Largest Acknowledged (varint)                            │    │
│   │  ACK Delay (varint)                                       │    │
│   │  ACK Range Count (varint)                                 │    │
│   │  First ACK Range (varint)                                 │    │
│   │  ACK Ranges [...]                                         │    │
│   │  ECNS (optional)                                          │    │
│   └────────────────────────────────────────────────────────────┘    │
│                                                                      │
│   ACK 延迟时间编码：                                                │
│   delay = ACK Delay * 2^ack_bleed_exponent                         │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        PADDING Frame                                │
├──────────────────────────────────────────────────────────────────────┤
│   用途：增加包大小，防御放大攻击                                    │
│                                                                      │
│   Type: 0x00                                                        │
│   Payload: 全零 bytes                                              │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        CONNECTION_CLOSE Frame                       │
├──────────────────────────────────────────────────────────────────────┤
│   用途：关闭连接                                                    │
│   变体：APPLICATION_CLOSE (0x1d), QUIC_CLOSE (0x1c)                │
│                                                                      │
│   ┌────────────────────────────────────────────────────────────┐    │
│   │  Type: 0x1c/0x1d                                          │    │
│   │  Error Code (varint)                                       │    │
│   │  Frame Type (varint) - 触发关闭的帧类型                    │    │
│   │  Reason Phrase Length (varint)                            │    │
│   │  Reason Phrase (UTF-8)                                    │    │
│   └────────────────────────────────────────────────────────────┘    │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        PING Frame                                   │
├──────────────────────────────────────────────────────────────────────┤
│   用途：保活，探测连接存活                                          │
│                                                                      │
│   Type: 0x01                                                        │
│   Payload: (empty)                                                 │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        HANDSHAKE_DONE Frame                        │
├──────────────────────────────────────────────────────────────────────┤
│   用途：服务端确认握手完成                                          │
│                                                                      │
│   Type: 0x1e                                                        │
│   Payload: (empty)                                                 │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 6. 连接建立流程

### 6.1 完整握手

```
QUIC 连接建立：

┌──────────────────────────────────────────────────────────────────────┐
│                        QUIC 握手时序                                 │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   Client                              Server                        │
│   ──────                              ──────                        │
│   Initial[CRYPTO(CH)] ──────────────────────────────────────►       │
│   (Client Hello)                                               │
│   0-RTT[STREAM(data)] ─────────────────────────────────────►       │
│   (early data, if 0-RTT supported)                                │
│                                                                      │
│         ◄────────────────────────────────────────── Initial[       │
│                                                   CRYPTO(SH),       │
│                                                   CRYPTO(EE),       │
│                                                   CRYPTO(CERT),     │
│                                                   CRYPTO(CDT),      │
│                                                   CRYPTO(CH)]       │
│         ◄────────────────────────────────────────── Handshake[       │
│                                                   CRYPTO(SFIN)]     │
│                                                                      │
│   Initial[ACK] ───────────────────────────────────────────►         │
│   Handshake[ACK] ──────────────────────────────────────────►         │
│                                                                      │
│   Short Header Packet[STREAM(data)] ────────────────────────►       │
│   (1-RTT data, encrypted with 1-RTT keys)                          │
│                                                                      │
│         ◄──────────────────────────────────── Short Header Packet[  │
│                                                   STREAM(data)]     │
│                                                                      │
│   RTT: 1 (with 0-RTT rejected: 2, without 0-RTT: 2)                │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

密钥派生顺序：

  Initial 密钥：
  · 从 TLS Client Hello 派生
  · 初始密钥使用不同的 AEAD (AES-128-GCM)
  · 认证加密

  Handshake 密钥：
  · 从 Client Hello 和 Server Hello 派生
  · 用于保护 Handshake 包

  0-RTT 密钥：
  · 从之前会话的 resumption secret 派生
  · 用于 0-RTT 数据

  1-RTT 密钥：
  · 从 Handshake 派生
  · 用于 Short Header 包
```

### 6.2 连接状态机

```
QUIC 连接状态机：

┌──────────────────────────────────────────────────────────────────────┐
│                        连接状态                                     │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   1. 尝试 (Attempt)                                                │
│      │                                                             │
│      ├──► 发送 Client Hello                                        │
│      │                                                             │
│      ▼                                                             │
│   2. 进行中 (In Progress)                                          │
│      │                                                             │
│      ├──► 收到 Server Hello → 派生密钥                           │
│      │                                                             │
│      ▼                                                             │
│   3. 握手完成 (Handshake Complete)                                │
│      │                                                             │
│      ├──► 收到 HANDSHAKE_DONE → 应用数据可发送                    │
│      │                                                             │
│      ▼                                                             │
│   4. 已确认 (Confirmed)                                             │
│      │                                                             │
│      └──► 0-RTT 确认或握手完成                                     │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

状态转换：

  attempting → in-progress: 发送 Initial 包
  in-progress → handshake-complete: 收到 Handshake 包
  handshake-complete → confirmed: 握手确认
  any → draining: 收到 CONNECTION_CLOSE
  draining → closed: 超时或清理
```

## 9. 小结

```
QUIC Ch1 总结：

核心设计理念：
  · 基于 UDP 实现可靠传输
  · 内置 TLS 1.3 握手
  · 多路复用无 HOL 阻塞
  · 连接迁移支持
  · 灵活的拥塞控制

与 TCP+TLS 对比：
  · 握手延迟：1-2 RTT vs 2-3 RTT
  · 0-RTT：QUIC 原生支持
  · HOL 阻塞：QUIC 无，TCP 有
  · 连接迁移：QUIC 支持，TCP 不支持

Wire Format：
  · Long Header: 握手阶段（Initial, 0-RTT, Handshake）
  · Short Header: 连接建立后
  · Frame: STREAM, CRYPTO, ACK, PING, PADDING, etc.

连接建立：
  · Initial 包启动握手
  · 密钥派生：Initial → Handshake → 1-RTT
  · 0-RTT 用于恢复会话提前发送数据

  - 详细握手流程
  - TLS 1.3 与 QUIC 集成
  - 密钥导出
  - 1-RTT vs 0-RTT
```
