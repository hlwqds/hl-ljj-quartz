## 2. HTTP/3 概述

### 2.1 HTTP 演化

```
HTTP 演化历程：

┌──────────────────────────────────────────────────────────────────────┐
│                        HTTP 历史                                     │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   HTTP/0.9 (1991)                                                   │
│   · 简单请求/响应                                                   │
│   · 仅 GET 方法                                                    │
│   · 无 header                                                      │
│                                                                      │
│   HTTP/1.0 (1996)                                                   │
│   · 添加了 POST/HEAD 方法                                          │
│   · Header 支持                                                    │
│   · 每个请求新建 TCP 连接                                           │
│                                                                      │
│   HTTP/1.1 (1999)                                                   │
│   · 持久连接                                                       │
│   · 管道化 (pipelining) — 很少实现                                 │
│   · 默认单连接                                                      │
│                                                                      │
│   HTTP/2 (2015)                                                     │
│   · 多路复用 (Stream)                                              │
│   · Header 压缩 (HPACK)                                            │
│   · Server Push                                                    │
│   · 流控制                                                         │
│   · 基于 TCP + TLS                                                 │
│                                                                      │
│   HTTP/3 (2022, RFC 9114)                                           │
│   · 基于 QUIC                                                     │
│   · 0-RTT                                                         │
│   · 改进的多路复用                                                 │
│   · 连接迁移                                                       │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 2.2 HTTP/3 设计目标

```
HTTP/3 设计目标：

┌──────────────────────────────────────────────────────────────────────┐
│                        HTTP/3 目标                                   │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   1. 消除 HTTP/2 的 HOL 阻塞                                       │
│      · HTTP/2 over TCP: 单个流丢包影响所有流                       │
│      · HTTP/3 over QUIC: 丢包只影响对应流                         │
│                                                                      │
│   2. 减少连接建立延迟                                              │
│      · 0-RTT 数据传输                                              │
│      · 1-RTT 完整握手                                              │
│                                                                      │
│   3. 改善丢包环境下的性能                                          │
│      · 多路复用 + 流级重传                                         │
│      · 更快的拥塞响应                                              │
│                                                                      │
│   4. 保持 HTTP 语义兼容                                            │
│      · 请求/响应 模型不变                                         │
│      · Header/Body 传输方式调整                                    │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 4. QPACK 头部压缩

### 4.1 HPACK vs QPACK

```
HPACK vs QPACK：

┌──────────────────────────────────────────────────────────────────────┐
│                        HPACK (HTTP/2)                               │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   问题：                                                            │
│   · 静态表: 61 个常用 header                                        │
│   · 动态表: 协商的 header 值                                        │
│   · 依赖 TCP 顺序传递                                               │
│   · 丢包会阻塞所有 header 解码                                      │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                        QPACK (HTTP/3)                               │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   改进：                                                            │
│   · 引入 Reference Set 机制                                        │
│   · 取消对 TCP 顺序的依赖                                           │
│   · 使用 QUIC STREAM 而非 TCP stream                               │
│   · 两个单向流传输 dynamic table modifications                       │
│   · 更大的静态表 (SRTP)                                            │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.2 QPACK 结构

```
QPACK 结构：

┌──────────────────────────────────────────────────────────────────────┐
│                        QPACK 组件                                   │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   1. 静态表 (Static Table)                                          │
│      · 127 个条目 (RFC 9204)                                       │
│      · :method: GET, POST, etc.                                    │
│      · :scheme: http, https                                        │
│      · :status: 200, 404, etc.                                    │
│                                                                      │
│   2. 动态表 (Dynamic Table)                                         │
│      · 协商添加 header                                             │
│      · FIFO 淘汰                                                   │
│      · 大小限制: 4096 entries                                     │
│                                                                      │
│   3. Reference Set                                                  │
│      · 当前使用的 header 引用集                                     │
│      · 用于增量编码                                                │
│                                                                      │
│   4. 编码器/解码器 Stream                                           │
│      · 单向流                                                       │
│      · 同步 dynamic table 状态                                     │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

QPACK 编码流：

  Encoder Stream:
  ┌────────────────────────────────────────────────────────────┐
  │  Dynamic Table insertions/modifications                     │
  │  (使用 '|' instruction)                                   │
  └────────────────────────────────────────────────────────────┘

  Decoder Stream:
  ┌────────────────────────────────────────────────────────────┐
  │  Dynamic Table acknowledgments                             │
  │  Stream cancellations                                      │
  └────────────────────────────────────────────────────────────┘
```

### 4.3 QPACK 指令

```
QPACK 指令：

┌──────────────────────────────────────────────────────────────────────┐
│                        Encoder Instructions                         │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ┌────────────────────────────────────────────────────────────┐     │
│   │  Set Dynamic Table Size                                 │     │
│   │  0b00111SSS... (6+2 bits)                              │     │
│   │  设置动态表大小                                           │     │
│   └────────────────────────────────────────────────────────────┘     │
│                                                                      │
│   ┌────────────────────────────────────────────────────────────┐     │
│   │  Insert with Name Reference                              │     │
│   │  0b01NNNDDD (7 bits) + value                           │     │
│   │  插入: 静态表引用 + 动态值                               │     │
│   └────────────────────────────────────────────────────────────┘     │
│                                                                      │
│   ┌────────────────────────────────────────────────────────────┐     │
│   │  Insert with Both References                             │     │
│   │  0b001NNNMMM (7 bits) + name + value                    │     │
│   │  插入: name 和 value 都引用                             │     │
│   └────────────────────────────────────────────────────────────┘     │
│                                                                      │
│   ┌────────────────────────────────────────────────────────────┐     │
│   │  Duplicate                                               │     │
│   │  0b00011111 + index                                     │     │
│   │  复制已有的 dynamic table entry                         │     │
│   └────────────────────────────────────────────────────────────┘     │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

QPACK 索引：

┌──────────────────────────────────────────────────────────────────────┐
│                        Header 索引                                   │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   0x00 - 0x1F:                                                    │
│   · Indexed Header Field (静态表引用)                              │
│   · 只引用静态表                                                   │
│                                                                      │
│   0x20 - 0x3F:                                                    │
│   · Indexed Header Field (动态表引用)                              │
│   · 引用动态表                                                    │
│                                                                      │
│   0x40 - 0x5F:                                                    │
│   · Literal Header Field with Name Reference                       │
│   · Name: 静态/动态表引用, Value: 字面值                          │
│                                                                      │
│   0x60 - 0x7F:                                                    │
│   · Literal Header Field with Name Reference                       │
│   · Name: 静态表引用, Value: 字面值                                │
│                                                                      │
│   0x80 - 0xBF:                                                    │
│   · Literal Header Field with Post-Base Name Reference            │
│   · Name: Post-Base 索引                                          │
│                                                                      │
│   0xC0 - 0xFF:                                                    │
│   · 其他 Literal 变体                                             │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 5.4 SETTINGS Frame

```
SETTINGS Frame：

┌──────────────────────────────────────────────────────────────────────┐
│                        SETTINGS Frame                               │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   用途：协商连接选项                                               │
│   发送方：双方在连接建立初期发送                                   │
│   发送次数：只能发送一次（发送后再次发送是错误）                    │
│                                                                      │
│   格式：                                                           │
│   ┌────────────────────────────────────────────────────────────┐     │
│   │  Type: 0x03                                                │     │
│   │  Length: varint                                            │     │
│   │  Settings: [] {                                           │     │
│   │    { identifier, value }                                   │     │
│   │  }                                                         │     │
│   └────────────────────────────────────────────────────────────┘     │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

SETTINGS 参数：

┌──────────────────────────────────────────────────────────────────────┐
│                        Settings 标识符                               │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   0x00: SETTINGS_HEADER_TABLE_SIZE                                │
│   · 编码器允许的最大 dynamic table size                            │
│   · 默认: 0 (0x20)                                               │
│   · 范围: 0 - 0xFFFFFF                                         │
│                                                                      │
│   0x01: SETTINGS_QPACK_BLOCKED_STREAMS                            │
│   · 编码器在等待 ACK 前可以阻塞的流数                             │
│   · 默认: 100                                                     │
│                                                                      │
│   0x02: SETTINGS_MAX_FIELD_SECTION_SIZE                           │
│   · 允许的最大 header section 大小                                │
│   · 默认: 2147483647 (2^31 - 1)                                  │
│                                                                      │
│   0x06: SETTINGS_QPACK_MAX_TABLE_CAPACITY                          │
│   · decoder 允许的 max dynamic table capacity                      │
│   · 必须 <= SETTINGS_HEADER_TABLE_SIZE                             │
│   · 默认: 0                                                       │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 6. 请求/响应流程

### 6.1 请求格式

```
HTTP/3 请求：

┌──────────────────────────────────────────────────────────────────────┐
│                        请求结构                                     │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   HEADERS Frame (Stream N):                                        │
│   ┌────────────────────────────────────────────────────────────┐     │
│   │  :method: GET                                             │     │
│   │  :scheme: https                                           │     │
│   │  :authority: example.com                                  │     │

│   │  user-agent: curl/7.88.1                                 │     │
│   └────────────────────────────────────────────────────────────┘     │
│                                                                      │
│   可选: DATA Frame(s):                                             │
│   ┌────────────────────────────────────────────────────────────┐     │

│   └────────────────────────────────────────────────────────────┘     │
│                                                                      │

Pseudo-headers (请求)：

  :method        必需     GET, POST, etc.
  :scheme        必需     http, https

  :path          必需     /foo?bar=baz

### 6.3 请求流程示例

```
HTTP/3 请求/响应流程：

┌──────────────────────────────────────────────────────────────────────┐
│                        完整流程                                     │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │

### 7.2 HTTP/3 优先级机制

```
HTTP/3 优先级机制：

┌──────────────────────────────────────────────────────────────────────┐
│                        HTTP/3 优先级                                │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   HTTP/3 使用 PRIORITY_UPDATE Frame (RFC 9218):                   │
│   · 带内发送优先级信息                                             │
│   · 客户端发送 (stream_id, urgency, etc.)                         │
│   · 不阻塞其他流                                                   │
│                                                                      │
│   PRIORITY_UPDATE Frame:                                          │
│   ┌────────────────────────────────────────────────────────────┐     │
│   │  Type: 0x80000007-0x80000008                            │     │
│   │  Stream ID / Push ID                                     │     │
│   │  Priority Field Value (variable)                         │     │
│   └────────────────────────────────────────────────────────────┘     │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

Priority Field Value:

  ┌────────────────────────────────────────────────────────────┐
  │  Bit 0: URGENT (高优先级)                                  │
  │  Bit 1-2: URGENCY (0-7)                                   │
  │  Bit 3: IDLE_INCLUDE (是否包含 idle 流)                   │
  │  Bits 4-7: Reserved                                        │
  └────────────────────────────────────────────────────────────┘

  Urgency levels:
  · 0-2: 低优先级 (background)
  · 3-5: 中优先级 (normal)
  · 6-7: 高优先级 (immediate)
```

## 9. 与 HTTP/2 对比

### 9.1 头部压缩对比

```
HPACK vs QPACK：

┌──────────────────────────────────────────────────────────────────────┐
│                        头部压缩对比                                  │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   HPACK (HTTP/2):                                                 │
│   · 静态表: 61 entries                                            │
│   · 动态表: 4096 bytes                                            │
│   · Reference Set                                                 │
│   · 依赖 TCP 顺序                                                  │
│   · 丢包阻塞所有 header                                           │
│                                                                      │
│   QPACK (HTTP/3):                                                 │
│   · 静态表: 127 entries                                           │

│   · 不依赖 QUIC 顺序                                              │
│   · 丢包不阻塞 header 解码                                        │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 10. 小结

```
HTTP/3 Ch4 总结：

HTTP/3 与 QUIC:
  · HTTP/3 使用 QUIC Stream 传输
  · Stream 0: 控制流
  · Stream 1,3,5,...: 客户端请求
  · Stream 2,4,6,...: 服务器推送

QPACK 头部压缩:
  · 127 个静态表条目
  · 动态表同步
  · 两个单向流
  · 不依赖 QUIC 包顺序

HTTP 帧:
  · DATA: 请求/响应 body
  · HEADERS: QPACK 编码的 headers
  · SETTINGS: 连接协商
  · PUSH_PROMISE: 服务器推送
  · GOAWAY: 关闭连接

优先级:
  · PRIORITY_UPDATE frame
  · Urgency (0-7)
  · IDLE_INCLUDE

服务器推送:
  · PUSH_PROMISE → Push ID
  · MAX_PUSH_ID 限制
  · CANCEL_PUSH 取消

与 HTTP/2:
  · 消除 TCP HOL 阻塞
  · 0-RTT 支持
  · 连接迁移
  · 更低的握手延迟

  - 0-RTT 详解
  - 连接迁移机制
  - 路径验证
  - 迁移场景
```
