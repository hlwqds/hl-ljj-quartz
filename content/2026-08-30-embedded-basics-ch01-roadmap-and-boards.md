## 1.1 受众自画像：从源码级软件到"从比特到引脚"

先把自己的位置标定清楚，学习路线才不会买错单。这个系列为下面这张自画像而写：

**已经有的（软件侧，源码级）：**

- 调度器：FreeRTOS 的任务生命周期、就绪链表、上下文切换已经逐行走过（见 [[2026-08-26-freertos-deep-dive-series-index|FreeRTOS 深度解析系列]]，包括 Xtensa port 的切换汇编）；
- 协议栈：lwIP 从 pbuf、内存管理到 TCP 状态机、网卡驱动适配层都读过（见 [[2026-08-26-lwip-deep-dive-series-index|lwIP 深度解析系列]]）；
- 系统底座：Linux 调度、内核跟踪、网络栈这类"软件向下"的功课也做过。

**缺的（硬件侧，一次都没下来过）：**

- 地址 `0x0` 到底是什么，为什么往某个地址写一个 32 位字，某个引脚的电平就变了；
- 时钟树：168MHz 的主频怎么从一颗 8MHz 晶振一步步倍频分频出来，波特率 115200 又是从哪条分频支路里除出来的；
- 一根线上的物理层：UART 的起始位在示波器/逻辑分析仪上长什么样，I2C 的 ACK 在第几个时钟沿被拉低；
- 调试的物理通道：SWD/JTAG 这几根线到底传了什么，openocd 在中间扮演的角色相当于什么。

一句话概括：**软件已经到了源码级，硬件还停留在"会烧录"**。中间断层的那一段——从比特到引脚——就是这个系列要补的手艺。

### 1. 用你已经会的东西来学

这份自画像最大的优势不是"零基础"，而是**每一件硬件事物都有一个你已经精通的软件对应物**。类比是这个系列的第一教学法：

| 你已精通的（软件）               | 待补的（硬件）                          | 共同本质                     |
| -------------------------------- | --------------------------------------- | ---------------------------- |
| tcpdump 抓包看协议交互           | 逻辑分析仪抓 UART/I2C 波形              | 在物理介质上旁观协议真实执行 |
| perf/火焰图找热点                | 万用表/示波器量电平与时序               | 测量先行，不猜               |
| 可编程中断分发器（软中断/irq）   | NVIC/ECLIC                              | 优先级、屏蔽、挂起位的状态机 |
| RFC + man page                   | 架构手册 + 参考手册（RM）+ datasheet    | 分层规范文档，逐层精读       |
| 页表/内存布局                    | 内存映射（Code/SRAM/外设区域）          | 地址空间的静态规划           |
| 链接脚本控制段布局（用户态见过） | 链接脚本控制 Flash/RAM 布局（裸机必备） | 告诉加载器东西放哪           |

右侧每一项学起来都不是从零开始，而是"把左侧的直觉换一套物理载体"。

### 2. 三层同时下探，而不是三层顺序爬

补硬件有三种常见路径：纯理论（教科书）、纯实操（跟着点灯教程抄）、纯仿真（QEMU 里过家家）。这个系列选择三层并行：

- **寄存器级**：每个外设都落到"哪个地址、哪个位域、为什么这么设计"（对照 RM0090 精读）；
- **协议级**：UART/I2C/SPI 当作链路层协议来学——成帧、容差、时序预算，和你读过的任何协议一样对待；
- **仪器级**：每个关键实验都配"这段代码在逻辑分析仪上应该长什么样"的预期波形，测量是验收标准而不是装饰。

把"从比特到引脚"展开成四层知识地图，全系列 12 章都能在图上找到位置：

| 层         | 回答的问题                           | 主要章节             |
| ---------- | ------------------------------------ | -------------------- |
| ISA 层     | 这颗核认识什么指令、什么编程模型     | 第三、九章           |
| 核内机制层 | 异常/中断怎么进出、栈怎么切换        | 第三、七、十二章     |
| 外设层     | 寄存器怎么组织、时钟怎么喂到外设     | 第五~八章            |
| 板级物理层 | 线怎么接、电平什么规格、信号长什么样 | 第二、六、十、十一章 |

软件背景的读者对前两层并不陌生——只是过去隔着 port 层汇编看它们；真正没下来过的是后两层。这个系列自底向上把四层各打一遍，最后在第十二章把四层重新穿在 FreeRTOS port 上收口。

### 3. 三条最常见的弯路（与这个系列的对应解法）

自画像里"软件很强、硬件没下来过"的读者，几乎都会以固定姿势走弯路。提前点名：

1. **HAL 依赖症**：跟着教程用现成库函数点灯，一路"函数调用成功"却从没见过一个寄存器地址——相当于只会调 glibc 封装而从没读过系统调用。解法：本系列主线**寄存器级裸机**，库只在理解寄存器之后作为生产力工具回顾；
2. **跳级到 Linux 开发板**：树莓派/香橙派上点个 GPIO 就以为"硬件入门了"——那是用户态驱动开发，MCU 世界的时钟树、中断裸机制、链接布局全被操作系统挡住了。解法：从"没有操作系统"的裸机开始向下打，打穿之后再回头看被抽象掉的东西；
3. **只做不量**：接线对了就翻篇，从不开逻辑分析仪看波形——代码"能跑"但不知道**为什么**能跑，容差用完了也不知道。解法：把测量写进验收标准，每个实验先写预期波形再动手。

## 1.2 为什么新学习线锚定 RISC-V + ARM 双架构

既然已经深度投资过 ESP32/Xtensa，为什么不顺势继续，反而换轨道？这一节把这个决策的账摊开算。

### 1. Xtensa 的小众性，量化地看

Xtensa 是 Cadence（2013 年收购 Tensilica）的可配置指令集架构：授权方买到的是一套**按自己需求定制后的核**——可以加自定义指令、改寄存器堆、调流水线。这套模式在音频/DSP 专用域有客户，但它的代价是：

- **ISA 碎片化**：每家授权方拿到的 Xtensa 配置都不同，工具链必须按配置打补丁——乐鑫维护着自己的 gcc/LLVM 分支来支撑 LX6/LX7，换一家就要再来一遍；
- **没有第二家通用 MCU 玩家**：在"跑 RTOS 的通用微控制器"这个品类里，采用 Xtensa 核的量产厂商只有乐鑫一家。ARM 有十几家、RISC-V 有几十家，Xtensa 的"同门师兄"数量是 0；
- **乐鑫自己也在迁移**：2020 年之后发布的新产品线——ESP32-C3/C6、ESP32-H2、ESP32-P4——内核全部是 RISC-V；Xtensa 只保留在经典 ESP32（LX6）与 S2/S3（LX7）存量线上。

把这三条放在一起：继续深耕 Xtensa，等于把架构层的学习投资绑在一个"单一厂商、且该厂商新片已不再采用"的私有 ISA 上。

三个 ISA 的生态位放一张表里对比，小众性更直观：

| 维度            | ARM（Cortex-M）          | RISC-V（RV32）                   | Xtensa（LX6/LX7）            |
| --------------- | ------------------------ | -------------------------------- | ---------------------------- |
| ISA 归属        | ARM 公司授权             | 开放标准（RISC-V International） | Cadence 授权，按配置定制     |
| 通用 MCU 供应商 | 十几家（ST/GD/NXP/...）  | 几十家（GD/WCH/乐鑫 C 线/...）   | 1 家（乐鑫）                 |
| 指令集一致性    | 每代架构统一             | 标准字母子集（I/M/A/C/F）描述    | 每份授权一个私有配置         |
| 裸机工具链      | `arm-none-eabi-gcc` 通用 | gcc/LLVM 主线原生支持            | 需要厂商维护的定制分支       |
| 架构手册获取    | ARM 官网注册下载         | 规范全文公开                     | 随授权交付                   |
| 换厂迁移成本    | 低（M 核编程模型稳定）   | 低（同子集即兼容）               | 高（配置不同即不通用）       |
| 在本系列的角色  | 教学主线                 | 对照主线                         | 已学存量，转 WiFi 协处理器位 |

### 2. 但结论不是"抛弃已会的"

小众不等于没价值——你已经读完的 Xtensa 材料里，**可迁移的部分远大于绑定的部分**。把知识分层看：

| 知识层     | 内容                                                   | 迁移性                                       |
| ---------- | ------------------------------------------------------ | -------------------------------------------- |
| 完全可迁移 | RTOS 抽象（任务/队列/信号量）、IP 协议栈、构建体系思维 | 与架构无关，FreeRTOS/lwIP 两个系列的全部积累 |
| 概念可迁移 | port 层契约：上下文切换要保存什么、临界区靠什么实现    | 每个 ISA 都要重答一遍，但你已经知道问题清单  |
| 绑定架构   | 切换汇编、中断控制器编程模型、异常入口机制             | Xtensa 版你已经读过一份                      |

关键洞察：port 层那些"绑定架构"的知识，你已经有了完整的一份（Xtensa）。**读过一份 port 的人，是学第二、第三份 port 最快的人**——因为他知道哪里是骨架、哪里是变体。这恰好是双架构学习法的起点（1.3 节）。

而 ESP 平台本身的知识也不浪费：**ESP 转投"WiFi 协处理器"位**。在本系列的综合项目章（第 12 章）里，联网需求会以"主控 + WiFi 协处理器"的架构讨论出现——ESP01-S/ESP32 作为挂在主控 UART/SPI 上的网络协处理器选项参与选型对比。这正是 ESP 在真实产品里的经典生态位，也是你已有 lwIP/ESP-IDF 知识（见 [[2026-08-26-lwip-deep-dive-ch18-esp32-wifi-lwip-integration|lwIP 系列：ESP32 WiFi 集成]]）最有产出效率的用法。按系列铁律，ESP 不进入教学主线——主线代码永远跑在 STM32+GD32 上。

### 3. 为什么是 ARM + RISC-V 这一对

- **ARM（Cortex-M）**：存量最大、资料最全、文档体系最规整——ARMv7-M 架构手册管"核怎么想"，厂商参考手册（RM0090）管"外设怎么长"，两层文档分工清晰，是学习"规范怎么读"的最佳教材；
- **RISC-V（RV32）**：开放 ISA，工具链在 gcc/LLVM 主线，国内产品线密集（GD32VF/CH32V/ESP32-C 系列），且特权级规范薄到可以通读——读完 ARMv7-M 的中断章节再读 RISC-V 的对应章节，会同时加深两边的理解。

一个代表过去十五年的工业主流，一个代表开放指令集的现在进行时。**双架构不是双倍工作量，而是同一门课的两个参照系**——这是下一节的方法论。

## 1.3 双架构学习法：GD32VF103 是 STM32F103 的寄存器级双胞胎

### 1. 为什么这对组合的学习效率最高

GD32VF103 是兆易创新把 GD32F103（STM32F103 兼容线）的 Cortex-M3 内核替换为芯来（Nuclei）Bumblebee 核（RV32IMAC，108MHz）的产物——**外设部分几乎原样保留**。这意味着：

- **外设布局同源**：GPIO、USART、SPI、I2C、定时器的寄存器组织与地址布局沿用 F1 世代（对照 ST RM0008 与 GD32VF103 用户手册，外设章节结构一一对应，仅命名有系统性差异，如 GPIO 控制寄存器在 GD32 侧叫 `CTL0/CTL1`、ST 侧叫 `CRL/CRH`）；
- **手册同源**：GD32VF103 用户手册的章节组织基本镜像 RM0008，你在 F407 上学会的"查手册定位寄存器"技能直接复用；
- **引脚级兼容**：Longan Nano 等板卡的引出脚与 F103 最小系统同类，面包板接线方法通用。

于是"同任务双板重做"成为可能：**同一个任务（点灯、UART 收发、定时中断）先在 STM32 上写一遍，再在 GD32VF103 上写一遍**。两份代码做 diff——C 代码主体大同小异，真正的差异集中在启动文件、中断入口、链接布局这些"架构接缝"处。**diff 本身就是架构知识的显形**：你亲眼看到"向量表换成了 mtvec、NVIC 换成了 ECLIC"在代码里长什么样。

一个必须交代清楚的细节：**主线是 F407（Cortex-M4F），对照双胞胎是 F103 级的 GD32VF103**——两块板隔了一代。这不是疏漏：F4 的外设是 F1 的超集演进（多数外设寄存器布局沿用 F1 世代，新增 FPU 与更复杂的时钟树），在 F407 上学的外设知识大半可平移到 GD32VF103；**平移得动的部分是外设知识，平移不动的部分（核架构差异）恰好是双架构对照要学的本体**。F407 独有的增量（FPU、更密的时钟树）本身就是学习内容，而不是障碍。

### 2. 三处对照点预告

整个系列的对照学习集中在三处"架构接缝"上，每处先给一句话预告，正文在对应章节展开：

1. **向量表 vs `mtvec`**：Cortex-M 用一张可重定位的异常向量表（`VTOR` 指向）作为中断分发中心，RISC-V 则用 `mtvec` CSR 直接记录陷阱入口（支持直接/向量两种模式）——同一个问题的两种回答，[[2026-08-30-embedded-basics-ch09-riscv-gd32-contrast|第九章]] 展开；
2. **NVIC vs ECLIC**：NVIC 是 ARMv7-M 架构内建的中断控制器（优先级分组、尾链这些行为写死在架构手册里），ECLIC 则是芯来在 RISC-V 基础特权架构之上外挂补齐的等价物——"架构内建 vs 厂商补齐"本身就是两种架构哲学，[[2026-08-30-embedded-basics-ch07-interrupts-nvic|第七章]] 与第九章前后呼应；
3. **PendSV vs machine timer**：FreeRTOS 的 Cortex-M port 用 PendSV 这个"可悬挂、永居最低优先级"的异常完成上下文切换，RISC-V port 的 tick 与切换则落在 machine timer 上——你在 Xtensa port 里读过的那套切换仪式（见 [[2026-08-26-freertos-deep-dive-ch17-xtensa-port-internals|FreeRTOS 系列：Xtensa 端口深挖]]），将在 [[2026-08-30-embedded-basics-ch12-freertos-port-contrast|第十二章]]换两套架构再演两遍。

### 3. 两块主控的正式对照表

| 维度         | STM32F407VET6（主线）        | GD32VF103（对照板）                   |
| ------------ | ---------------------------- | ------------------------------------- |
| 核架构       | ARM Cortex-M4F（ARMv7-M）    | 芯来 Bumblebee（RISC-V RV32IMAC）     |
| 主频         | 168MHz                       | 108MHz                                |
| FPU          | 有（单精度）                 | 无（软浮点，对照点之一）              |
| 中断控制器   | NVIC（架构内建）             | ECLIC（Nuclei 扩展）                  |
| 异常入口     | 向量表（`VTOR` 可重定位）    | `mtvec`（直接/向量模式）              |
| 外设手册     | RM0090                       | GD32VF103 用户手册（结构对应 RM0008） |
| 调试接口     | SWD/JTAG（ADIv5）            | JTAG（RISC-V debug module）           |
| 在系列中角色 | 教学主线：所有外设先在此精读 | 对照镜像：同任务重做，diff 出架构知识 |

### 4. 同任务双板重做的工作流

"双板重做"不是把教程做两遍，而是一个固定的四步工作流，从第五章开始反复执行：

1. **F407 先行**：在主线上寄存器级实现任务，吃透"写了哪些地址、为什么这么写"；
2. **GD32 重做**：不抄自己的旧代码，凭对外设的理解在 GD32VF103 上重新实现同一个任务；
3. **diff 两份工程**：C 主体、外设寄存器、启动代码、链接脚本逐块对比；
4. **归档对照笔记**：把 diff 中"架构性"的差异沉淀进自己的对照表——这就是三处对照点不断充实的过程。

diff 里什么变、什么不变，可以预先画出来：

| 工程组成     | 双板重做时的命运              | 背后的原因                                  |
| ------------ | ----------------------------- | ------------------------------------------- |
| 外设读写主体 | 大体相同（地址/命名微调）     | GD32VF103 外设布局沿用 F1 世代，手册同源    |
| 时钟配置     | 相同的思路，不同的倍频/分频值 | 各自时钟树参数不同，RCC≈RCU 概念对应        |
| 启动汇编     | 全部重写                      | 向量表与 mtvec、初始化栈的指令集都不同      |
| 中断入口编写 | 全部重写                      | NVIC 编程模型 vs ECLIC 编程模型             |
| 链接脚本     | 主体相同，地址与段名微调      | 各自 Flash/RAM 基址与架构约定的入口符号不同 |
| 烧录与调试   | 各走各的探                    | SWD/ADIv5 与 JTAG/DTM 两套协议（见 1.4 节） |

上层越靠近外设越稳定，越靠近核越分化——**这张表本身就是"外设知识与架构知识"的分界线**，也是双架构学习法效率的来源：分化部分高度集中在少数几处接缝上，学习火力不需要撒满全图。

两个采购细节值得说明：

- **为什么 RISC-V 侧不能省掉 RV Debugger 用 ST-Link 凑合**：ST-Link 的调试协议栈是 ARM 的 ADIv5（SWD/JTAG 上说 DAP 方言），RISC-V 的调试模块走标准 JTAG 之上的 DTM/DMI 协议，两者不互通——所以"探"必须是两只，各管一架构；
- **为什么 Longan Nano 可以盲烧**：GD32VF103 出厂固化了 USB DFU 引导程序，没有调试器也能经 Type-C 用 dfu-util 烧录。RV Debugger 缺货/在路上时，学习不必停摆。

### 3. 避坑注记

这三条是这个价位段的经典坑，下单前值得三十秒：

> [!warning] 避坑 1：BMP280 冒充 BME280
> 低价"BME280 模块"大量实为 BMP280——外观几乎一致，但 BMP280 **没有湿度传感器**。鉴别方法在读到第十章时是基本功：读 chip id 寄存器（`0xD0`），`0x58` 是 BMP280，`0x60` 才是 BME280。三针蓝色小板基本可直接判定为 BMP280。

> [!warning] 避坑 2：Blue Pill 翻新片与假片
> "Blue Pill"（STM32F103C8T6 最小系统板）是翻新片/假片重灾区：CS32/CKS 等兼容片冒充 ST、磨字翻新片混装。本系列主线用 F407 核心板天然避开此坑；若后续想补 F103，选 WeAct 等开源核心板而非散装 Blue Pill。

> [!warning] 避坑 3：金属壳 ST-Link 发热
> 金属壳 ST-Link V2 仿制品长时间通电发热明显（内部电源方案压差大、静态电流偏高），外壳烫手的案例常见。建议：选塑料壳版本，且只在烧录/调试会话时插电。RISC-V 侧的 RV Debugger Plus 兼任 USB 串口时可减少 ST-Link 的在位时间。

### 4. 两个刻意的"没有"

**为什么没有示波器？** 本系列的信号几乎全是数字域的（UART/I2C/SPI 电平、时钟、中断线），24MHz 逻辑分析仪足够覆盖；入门示波器（百元级带宽）能看的它都能看，它不能看的（模拟波形细节）百元示波器也看不好。升级触发条件明确：需要看**电源纹波、晶振起振、模拟传感器原始信号**时，再上百 MHz 级示波器——那已在本系列结业之后。

**为什么没有任何"开发板套装"（Arduino/micro:bit/ESP32 开发板）？** 套装的卖点是把底层封好让你快速出活——与本章受众的诉求正好相反：我们要的就是**没有被封装挡住的那一层**。至于 ESP32，按系列铁律它不出现在教学主线，只在综合项目章作为 WiFi 协处理器选型选项出现（1.2 节）；届时需要的只是一颗 ~10 元的 ESP01-S 模组，在扩展表里。

## 1.5 无板先行：理论、协议与 QEMU 先行，接线章占位回填

板卡在路上的一到两周，是这个系列设计上**不允许空转**的时间。方法声明如下：

**本系列按两类章节组织（板未到位也能开工）：**

- **先行章**：理论、协议、工具链、QEMU 仿真——不依赖实体板，全部立即写作与学习；
- **真机占位章**：核心价值是接线/电气实操——先写理论骨架、接线图、预期现象与推断依据（datasheet 哪一节），标 `真机待验证`，板到后回填实测。

**为什么这样设计——等板期的沉没成本最小化：**

1. **QEMU 是够用的裸机底座**：`qemu-system-arm` 的 `mps2-an385` 机型（Cortex-M3）带 UART、SysTick、定时器模型，裸机课程的主体实验（启动流程、异常入栈、SysTick 节拍）都能真实跑出输出，不是纸面推演；
2. **协议与仪器知识零硬件依赖**：UART 成帧、I2C 时序、逻辑分析仪判读法，用样例波形与 PulseView 就能学——正如学 TCP 不需要先有生产事故，读 pcap 就够；
3. **真机实验的价值密度在"验证与修正"**：有 QEMU 与理论打底后，板到手的每一小时都花在"接线、量测、对照预期"上，而不是从零开始找感觉。

**边界也要诚实**：QEMU 不仿真 F407 专有外设（GPIO 端口级、EXTI 等）——这些章节采用"编译验证+反汇编摘录+真机占位"的降级路径；RISC-V 侧本机暂无裸机工具链——第九章以架构理论与对照分析为主，汇编示例给源码并标注工具链安装路径。所有"真机现象"在成文时必须标注推断依据，杜绝编造。

对照 1.1 节的软件经验：这等价于你早就熟知的"先读源码与文档、上机只为验证假设"的工作流，只是介质从代码换成了电路。

## 1.7 小结

- **受众与缺口**：软件已源码级（调度器、协议栈、port 汇编都读过），缺"从比特到引脚"；本系列用类比教学法把每个硬件概念锚在你已有的软件直觉上，寄存器/协议/仪器三层同时下探；
- **架构决策**：Xtensa 是单厂商采用的私有授权 ISA（且乐鑫新片已转 RISC-V），但已会的不抛弃——可迁移层全保留，绑定层（port）恰好是学新架构的加速器，ESP 知识转投 WiFi 协处理器位；
- **双架构学习法**：GD32VF103≈STM32F103 的寄存器级双胞胎（外设布局对应、手册同源），同任务双板重做，diff 即架构知识；三处对照点（向量表 vs mtvec、NVIC vs ECLIC、PendSV vs machine timer）是全系列的架构主线；
- **装备**：三件套（板/探/仪）启动包约 287 元一次买齐，扩展件按章节触发再买；三条避坑注记（BMP280 冒充、Blue Pill 翻新片、金属壳 ST-Link 发热）下单前过一眼；
- **无板先行**：先行章立即学（理论/协议/QEMU），真机占位章等板回填——等板期的沉没成本被压到最低；
- **工作流**：每个任务四步走——F407 寄存器级先行、GD32 凭理解重做、diff 两份工程、归档对照笔记；分化集中在启动汇编、中断入口、链接脚本几处接缝上；
- **路径**：工具驯化与裸机解剖（QEMU）→ 外设 craft（真机）→ 总线与双架构对照 → 综合会师（FreeRTOS port 对照+WiFi 协处理器架构）。

快递单号已经可以下了。下一章在板到之前就能开工：[[2026-08-30-embedded-basics-ch02-tools-multimeter-la|第二章：工具驯化]]——万用表的判读法、逻辑分析仪与 PulseView 的上手、以及不看硬件也能练的 UART 波形判读自检法。仪器的手感，是这个系列所有"测量先行"习惯的起点。
