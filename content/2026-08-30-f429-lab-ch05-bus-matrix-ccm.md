## 目标（先说结论）

- 前四章的每个寄存器地址都不是随口给的——它们都在一张「谁挂哪条总线」的地图上。
  本章把这张图画出来：**Cortex-M4 三条私有出口（I/D/S-bus）→ BusMatrix → 各总线外设**。
- 全图最重要的一个岔路：**192KB SRAM（Static RAM，静态随机存储器——通电即保持数据、无需定时刷新的快速内存）挂在矩阵上，谁都能访问（CPU、DMA、以太网、USB、LCD）；
  64KB CCM 只挂在 CPU 的 D-bus 上，除 CPU 外无人可见**——这就是「近端内存」的全部含义。

> 📖 **术语卡：CCM（Core Coupled Memory，核心耦合内存）**
> **是什么**：F429 里一块 64KB 的 SRAM，物理布线只接在 Cortex-M4 内核的 D-bus 上，不进总线矩阵——地址 0x10000000，仅 CPU 一个客户。
> **为什么存在**：给 CPU 一块「零等待、永不被仲裁拖累」的专属内存——放调度器私有数据、热点查找表这类只有 CPU 碰的东西，延迟恒定最优。
> **类比**：你家保险箱（只有你有钥匙、永远不用排队）vs 小区公共储物间（谁都能放，高峰要排队）。
> ⚠️ 类比边界：保险箱只是「更私密」；CCM 的排他性是物理拓扑级的——DMA 控制器访问它会直接总线错误，不是慢、是根本到不了（ch13 实测预告）。

- 落到工程实物：对着 `~/stm32/f429-freertos/STM32F429IG.ld` 链接脚本逐段解读
  FLASH/SRAM/CCM 三个 MEMORY 区，并埋下 ch13 的雷：把 DMA 缓冲放进 CCM 会怎样。

## 系统侧类比：NUMA 与专用 lanes

| F429 侧                                                                  | 系统侧对应                                              |
| ------------------------------------------------------------------------ | ------------------------------------------------------- |
| CCM 64KB：D-bus 直挂、CPU 专属                                           | NUMA 节点的本地内存：低延迟、非本节点不可见             |
| 192KB SRAM：挂矩阵、多主共享                                             | DDR：所有设备共抢一根内存总线                           |
| BusMatrix 多主多从 + 轮转仲裁                                            | PCIe/QPI fabric 与其仲裁：并发冲突时主设备互相 stall    |
| DMA 与 CPU 抢 SRAM 端口                                                  | 网卡 DMA 与应用抢内存带宽：吞吐上不去先看总线不打架没有 |
| FMC → 外挂 SDRAM（同步动态 RAM：容量大但要定时刷新、需控制器侍候；若有） | 经 PCIe 挂的远端设备内存：更远、更慢、共享              |
| AHB→APB 桥                                                               | PCIe-to-I2C 桥芯片：快域到慢域的协议翻译                |

> 表右列的 NUMA、PCIe/QPI fabric、`perf`/`numastat` 都是你的主场，只作路标不展开。

「NUMA 本地内存」类比的精确版本：CCM 不是「快一点的内存」，而是**拓扑上只连着 CPU 的内存**——
延迟恒定、零等待、永不被仲裁拖累；代价是 DMA 控制器在它的地址上只能撞墙。而 SRAM 像 DDR：
谁都能放数据，但高峰期要排队。
（⚠️ 类比边界：NUMA 里「远端内存」是慢、但可达；CCM 对 DMA 是**根本不可达**——不是延迟问题，是墙上没门的问题。）

## 总线全景图（本章资产一）

> 📖 **术语卡：总线矩阵（BusMatrix）与主/从设备、轮转仲裁**
> **是什么**：芯片内部的「立交桥」——多条 AHB 主口与多条从口交叉互联。**主设备**（master）能自己发起读写（CPU、DMA、以太网 MAC…），**从设备**（slave）只能应答（SRAM、GPIO、定时器…）；多个主同时抢同一个从时，矩阵用**轮转仲裁（round-robin，轮流分配，类似公平队列）**裁决谁先走。
> **为什么存在**：若全芯片共享一条总线，任一外设传输时其他人都得干等；矩阵让「不冲突的路径」真正并发（CPU 读 SRAM3 的同时 DMA 写 SRAM1）。
> **类比**：机场航站楼的指廊布局——不同登机口（从设备）与不同航司（主设备）各走各的廊桥，只有同一登机口才排队。
> ⚠️ 类比边界：航站楼有全局调度中心；矩阵的仲裁是硬件固定策略（round-robin），不看电影散场动态改优先级。

> 📖 **术语卡：DMA（Direct Memory Access，直接内存访问控制器）**
> **是什么**：一个独立的小「搬运工」外设：CPU 给它写好「从哪搬、搬到哪、搬多少」，它就自己在外设与内存之间倒数据，搬完（或搬一半）发个中断通知；全程不占 CPU。
> **为什么存在**：CPU 一字节一字节搬数据是最大的浪费；把 memcpy、收包、发包这类重复劳动下沉给硬件，CPU 只管配置与消费。
> **类比**：机场摆渡车——你（CPU）告诉司机地址就能去干别的，货到了车自己跑——你的主场（网卡 DMA 你天天调）。
> **⚠️ 本章要点**：DMA 是矩阵上的一类**主设备**，能到哪取决于它的端口接在矩阵哪一侧——CCM 不在矩阵上，所以 DMA 到不了 CCM，这就是 ch13 要引爆的雷。

> 📖 **术语卡：I-bus / D-bus / S-bus（Cortex-M4 的三条私有出口）**
> **是什么**：ARMv7-M（ARM 为 M3/M4 定的架构规范）规定内核有三条直出总线：I-bus 指令总线（取指）、D-bus 数据总线（数据访问+内核私有外设）、S-bus 系统总线（通往矩阵、覆盖 SRAM 与全部外设）。三条按**地址段**自动分工——同一地址的取指走 I、取数走 D。
> **为什么存在**：取指与取数天生是两股流量，分开口才能并行；核心私有外设（SysTick 节拍定时器、NVIC 中断控制器、SCB 内核控制块）挂在 D-bus 的私有段，不进矩阵、永不被外设流量拖累。
> **类比**：小区三出口——人行门（I）、住户货运门（D）、社会车辆主入口（S）；各走各的，货运门后还藏着物业机房（核心私有外设）。
> ⚠️ 类比边界：三个门各管固定地址段是硬件焊死的，软件无法把访问「换口」；布线还决定地址段的实际可达性（CCM 地址在 I/D 区间内，但物理只接 D-bus）。

核心三条出口的地址分工（ARMv7-M 架构规定，放之 M3/M4 皆准）：

| 出口  | 地址范围                                      | 用途                                                                                               |
| ----- | --------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| I-bus | 0x00000000–0x1FFFFFFF                         | 取指（Flash 别名区、CCM 里的代码）                                                                 |
| D-bus | 0x00000000–0x1FFFFFFF + 0xE0000000–0xE00FFFFF | 数据访问；**SysTick/NVIC/SCB 等核心私有外设也在这**（ch01 的 0xE000E010 为什么「不经矩阵」的答案） |
| S-bus | 0x20000000–0xDFFFFFFF、0xE0100000 起          | 到矩阵的系统出口：SRAM、全部外设、FMC                                                              |

（表中「Flash 别名区」：同一块物理 Flash 在地址空间多个段有映像——真身在 0x08000000，而
0x00000000 起的窗口由 BOOT 配置映射到 Flash/系统 ROM/SRAM 之一；复位后 CPU 固定从 0x00000000
取初始栈顶与首条指令，别名窗口就是让「从哪儿启动」可切换的机制。）

前四章寄存器地址在这张图上的落位自查：SysTick(0xE000E010) 与 NVIC(0xE000E100) 在 D-bus 的
核心私有区（不经矩阵，所以 `mdw`（OpenOCD 读内存命令，memory display word，按 32 位字读物理地址）活体读永不与 DMA 抢带宽）；RCC(0x40023800)、GPIOA(0x40020000)
在 AHB1；USART1(0x40011000)、EXTI(0x40013C00)、ADC1(0x40012000) 在 APB2；TIM4(0x40000800)
在 APB1——每章那些「速查表」从此有了共同的索引。

**图中名词快释**（缩写一次清完，按图从上到下）：

- **SysTick/NVIC/SCB**：内核自带的节拍定时器 / 中断控制器 / 系统控制块（ch01 已出场）；
- **DMA1/DMA2**：两颗通用搬运控制器，DMA2 有内存、外设两个主口（图上分两行）；
- **以太网 DMA / USB OTG-HS（On-The-Go High Speed，USB 主从双角色高速口）/ LTDC（LCD-TFT 显示控制器）/ DMA2D（2D 图形加速搬运器）**：F429 新增的重型主设备；
- **OTG-FS（Full Speed 全速口）/ DCMI（数字摄像头接口）/ CRYP、HASH（加密/散列硬件加速器）/ RNG（随机数发生器）**：AHB2 上的外设；
- **USART/SPI/I2C/CAN**：四类常见串行接口（串口/短距同步/两线板级/车用总线）；**PWR**（电源控制）、**SYSCFG/EXTI**（系统配置/外部中断控制器）。

两个结构性知识点补完：

- **Flash 的 ICode/DCode 双从端口**：取指与数据分口进 Flash（配合预取（prefetch——趁总线空闲提前取下一条指令）与 ART 缓存（Adaptive Real-Time memory accelerator，自适应实时存储加速器——Flash 速度追不上 180MHz 内核时的硬件补偿，靠宽读取+缓存摊平等待周期）），
  I 与 D 并行不抢线——矩阵存在的意义就是这种「按口分流」。
- **APB 桥是慢域尾巴**：AHB→APB 桥做协议与时钟域翻译（APB1=45MHz、APB2=90MHz），
  定时器时钟在桥后再 ×2（ch03 的翻倍规则源头就在这级）。

## 链接脚本逐段解读（本章资产二）

> 📖 **术语卡：链接脚本（Linker Script，.ld 文件）与 MEMORY/SECTIONS**
> **是什么**：写给链接器（linker——把 .o 目标文件拼成最终 elf/可执行文件的程序）的地图文件：`MEMORY{}` 声明这块芯片有哪几块内存（起址+大小+属性），`SECTIONS{}` 规定程序的每一段（代码/数据/栈）各放进哪一块。
> **为什么存在**：C 代码里从不写地址，但每个变量、每条指令最终必须有确定地址；地址的「户口政策」只能集中一处声明——就是链接脚本。
> **类比**：机房上架规划表——机柜（MEMORY）有编号与容量，服务器（SECTIONS 各段）按规划插进具体机柜。
> ⚠️ 类比边界：规划错了顶多返工；链接脚本写错（比如把 DMA 缓冲分进 CCM）是运行期才炸的静默雷——本章乃至 ch13 的主题。

工程的 `STM32F429IG.ld`（真身，非示意）。先看 MEMORY 三行——这就是上图三块存储的官方户口：

```text
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 2048K   ← 2MB 程序存储器（I/D-bus 经矩阵访问）
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 192K    ← 矩阵上的公共 SRAM（DMA 可达）
    CCM   (rwx) : ORIGIN = 0x10000000, LENGTH = 64K     ← CPU 专属近端内存（DMA 不可达）
}
```

**MEMORY 三行的字母表**：括号里的 `rx`=只读+可执行（Flash 的天性），`rwx`=可读+可写+可执行；
`ORIGIN`=起始地址，`LENGTH`=容量。三行就是三块内存的「户口登记」，链接器分配地址只在此范围内。

| MEMORY 区 | 地址范围              | 大小   | 挂哪       | 谁能访问                 |
| --------- | --------------------- | ------ | ---------- | ------------------------ |
| FLASH     | 0x08000000–0x081FFFFF | 2 MB   | 矩阵从口×2 | CPU 取指/数据、DMA（读） |
| RAM       | 0x20000000–0x2002FFFF | 192 KB | 矩阵       | **所有主设备**           |
| CCM       | 0x10000000–0x1000FFFF | 64 KB  | D-bus 直挂 | **仅 CPU**               |

注意 F429 的 192KB「RAM」在物理上是三块：SRAM1(112K)+SRAM2(16K)+SRAM3(64K) 在同一地址段
连续排布，链接器视角就是一整块；但**物理端口在矩阵里是分开的从口**——DMA 打 SRAM1 的同时
CPU 读 SRAM3 可以真并发，这是后期 DMA 实验里「缓冲放哪一块」的调优空间。

再看 SECTIONS 怎么把程序铺进这些区：

```text
.isr_vector  > FLASH          向量表钉在 Flash 头部；KEEP 防止链接器 GC 掉——
                              它没有被代码「引用」，却是复位后第一跳（序章 3.4 的现场）
.text/.rodata > FLASH         代码与常量
.data        > RAM AT> FLASH  双地址：VMA 在 RAM（运行时在 SRAM）、LMA 在 Flash（断电保存）；
                              启动文件用 _sidata/_sdata/_edata 把它从 Flash 搬运到 SRAM——
                              「重启即重演」的搬运，每次上电都跑一遍
.bss (NOLOAD)> RAM            未初始化数据：不占 Flash 体积，启动时清零
.heap        > RAM (+0x400)   newlib 小堆；FreeRTOS 的 heap_4 64KB 是静态数组，落在 .bss
CCM          （声明未使用）    一行都没往里放——留给 ch13/ch19 当实验田
```

**SECTIONS 走读**（把每行翻译成人话）：

| 段                      | 是什么、为什么这么放                                                                                                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `.isr_vector > FLASH`   | 向量表（中断/异常处理函数的入口地址表，复位后第一跳的落点）；`KEEP(...)` 阻止链接器 GC（garbage collection，未引用段回收——同编译器死代码消除，你的主场）把它删掉——它没有被任何代码「引用」，但删了就开不了机 |
| `.text` / `.rodata`     | 机器码 / 只读常量（字符串、`const` 表）——都不可变，天然归 Flash                                                                                                                                              |
| `.data > RAM AT> FLASH` | 已初始化的全局/静态变量：初值必须断电保存（存 Flash=加载地址 LMA），运行时又要可写（放 RAM=运行地址 VMA）——双地址机制，见下方术语卡                                                                          |
| `.bss (NOLOAD)`         | 未初始化（或显式置 0）的全局/静态变量：不占 Flash 体积，`NOLOAD` 告诉工具链「别往镜像里塞」，启动代码统一清零——C 全局变量初值 0 就是这里白送的                                                               |
| `.heap > RAM (+0x400)`  | newlib（嵌入式 C 库——printf/malloc 的精简实现）的小堆；FreeRTOS 的 heap_4（FreeRTOS 自带堆方案之一：静态数组上实现 malloc/free）不在这——它的 64KB 数组本身是个全局变量，落在 .bss                            |
| `CCM`                   | 声明了但一行没放——整块留给后章当实验田                                                                                                                                                                       |

> 📖 **术语卡：VMA 与 LMA（Virtual / Load Memory Address，加载地址与运行地址）**
> **是什么**：段的两个地址——LMA 是「烧进 Flash 时住在哪」（初值的仓库），VMA 是「程序跑起来时住在哪」（CPU 实际访问的地址）。`.data` 的 LMA 在 Flash、VMA 在 RAM，两者之差就是启动代码要搬的距离。
> **为什么存在**：RAM 断电即失忆，变量的初值必须有不失忆的存放处；于是「仓库」与「工位」分离，开机搬运一次。
> **类比**：搬家纸箱——LMA=储藏室的箱子（贴好原样），VMA=新家的书架；入住第一件事是把箱子按原样摆上架（启动搬运），之后生活全在书架（RAM）上。
> ⚠️ 类比边界：箱子搬完就空了；.data 的 Flash 副本搬运后仍在，每次重启「重演」一遍搬运。

配套符号的地址算术（对照上文推导可直接口算）：

- `_estack = ORIGIN(RAM)+LENGTH(RAM) = 0x20030000`——主栈顶放 192K SRAM 的最高处，
  向下生长（栈，stack：函数调用与局部变量所在的内存区，后进先出；「向下生长」=每压入一层，地址变小。
  `_estack` 就是复位时主栈指针 MSP 的初始值）。**为什么栈不进 CCM？** 栈要被 ISR、被调试器、被未来的 DMA 目标共享，
  放进「仅 CPU 可见」的房间等于给所有非 CPU 访问者上锁；FreeRTOS 的任务栈同理（都在 SRAM）。
- `.data` 的 LMA 与 VMA 之差就是「搬运距离」——`arm-none-eabi-objdump -h` 能同时列出两列地址，
  这是核对启动搬运逻辑是否正确的实证手段（序章「验证改动进产物」的姊妹招）。

**命令拆解：** `arm-none-eabi-objdump -h build/f429-freertos.elf`

| 部分                      | 作用                                                                                                                  |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `arm-none-eabi-objdump`   | GNU 二进制检视工具的 ARM 裸机版（`arm-none-eabi-` 前缀=「无操作系统的 ARM」交叉工具链——在 x86 主机上生成 ARM 机器码） |
| `-h`                      | display **h**eaders：把可执行文件里每个段的 VMA、LMA、大小、对齐列成一张表                                            |
| `build/f429-freertos.elf` | 待检视的产物（elf=Executable and Linkable Format，带符号表的最终可执行文件，烧录与调试都以它为源）                    |

**你会看到**：`.data` 一行有两个地址（VMA 0x2000xxxx、LMA 0x08xxxxxx），差值即搬运距离；`.bss` 只有 VMA。
**失败了先查**：elf 是否刚重新构建（旧 elf 看旧布局）、别找错段（`.bss` 是 NOLOAD 没有 LMA，属正常）。

**CCM 的正确用法预告**：放「只有 CPU 碰」的数据——调度器私有结构、热点查找表、关键 ISR 的
工作区。收益：零等待、不受 DMA 带宽挤兑；雷区：一旦哪天有人把这块缓冲交给 DMA——ch13 实测翻车。

## 与 FreeRTOS / ESP32 对照

- **FreeRTOS 堆的选址**：本工程 heap_4 的 64KB 静态数组在 .bss（SRAM）。为什么不放 CCM？
  未来 lwIP 的 pbuf 要交给以太网 DMA 发送（阶段 5），DMA 不可达的内存对网络栈是毒药——
  「堆选址」其实是「谁要访问堆」的拓扑决策，与 NUMA first-touch/`numactl --membind`
  的考量同构（first-touch、membind 都是你的主场）：**先问消费者在哪，再定生产者放哪**。
- **ESP32 地址空间**：Xtensa（ESP32 的 CPU 架构名）的 IRAM/DRAM（指令 RAM/数据 RAM）物理同体但**地址区间分身**（cache 直读与穿透访问
  是两个地址段），F429 则是物理分块+拓扑决定可达性——两种「内存多面性」的设计答案，
  对照阅读[[2026-08-26-freertos-deep-dive-ch17-xtensa-port-internals|FreeRTOS（十七）：Xtensa 端口内部]]
  与[[2026-08-26-freertos-deep-dive-ch2-esp32-xtensa-architecture|FreeRTOS（二）：ESP32 架构]]。
- **Linux 侧**：CCM 的「CPU 专属」在服务器上的对应物是 per-CPU 本地内存与 per-CPU 变量（你的主场）；
  SRAM 上的带宽争抢则像 DDR 带宽争抢——`perf` 里 memory bandwidth 热点、`numastat` 的
  远端命中率，衡量的是同一件事：**数据离消费者有多近**。
- 栈与堆的布局细节在[[2026-08-26-freertos-deep-dive-ch21-stack-and-memory-layout|FreeRTOS（廿一）：栈与内存布局]]
  有 ID F429 双侧展开，本章提供的是它的物理底座。
