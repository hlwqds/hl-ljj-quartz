> 📖 **术语卡：SPI（Serial Peripheral Interface，串行外设接口）**
> **是什么**：四线制同步串行总线——时钟线 SCK 由主机独发，数据线 MOSI/MISO 双向各一根，另加片选
> CS 点名从机。
> **为什么存在**：比 UART 快（时钟专线送达、速率上限高）、比 I2C 简单（无地址无仲裁），Flash、屏幕、
> SD 卡的经典挂法。
> **类比**：主站把节拍器（SCK）直接牵到对方桌上的专线对讲：喊口令、点名、双方同时说话。
> ⚠️ 类比边界：SPI 总线层零协议功能——无地址、无重传、无流控，全靠驱动自觉。

## 目标（先说结论）

- SPI 四根线（SCK 时钟线、MOSI 主出从入、MISO 主入从出、CS 片选——四根线的名字就是各自职能）
  - 四种 CPOL/CPHA 模式（时钟极性/相位的组合旋钮，下节展开），一页 ASCII 时序讲透——本质是
    **同步全双工串行链路**（同步=时钟专线送达；全双工=同一时刻收发两个方向都在走数据）：时钟随数据
    走，不存在 UART 那种「各自凭约定速率」。
- F429 侧寄存器级驱动：CR1 的 BR（Baud Rate，时钟分频比）/CPOL/CPHA/MSTR（主模式选择位，置 1
  当主机）/SPE（SPI Enable，外设总开关），SR 的 TXE/RXNE（含义同 ch06 的 UART 版：可发了/
  收到了）、BSY（Busy，移位器仍在逐位挪动），全双工的「**写即读**」节奏——往 DR 写一字节的同时，
  对面也在往你的 DR 里塞一字节，不读就欠账（OVR=Overrun，SPI 版接收溢出：接收缓冲没腾空，
  新来的挤掉旧的）。
- 板载 W25Q64 走完 NOR Flash 标准流程：读 JEDEC ID（JEDEC=固态技术协会，行业标准组织；这条命令
  让芯片自报家门三字节：厂商/类型/容量）→ 扇区擦除 → 页编程（页=256 字节的一次写入单位）→ 读回
  比对；擦写之间靠 0x05 轮询状态寄存器 WIP 位（Write In Progress，设备内部写操作进行中标志）——
  **磁盘忙位**的微缩版。

## 系统侧类比：同步串行总线协议

（右列全是你的主场——本表只锚定左右两边的对应关系，不展开。）

| SPI 侧                       | 系统侧对应                                           |
| ---------------------------- | ---------------------------------------------------- |
| CS 拉低=事务开始，拉高=结束  | 帧定界符/TCP 连接：选中的从机独占总线，事务边界明确  |
| CPOL/CPHA 模式协商           | 协议参数协商：两端不一致=位错位=「看似有数据的乱码」 |
| W25Q64 状态寄存器 WIP 轮询   | 磁盘/NVMe 忙位轮询：写完不等于落盘，要等设备说好了   |
| 擦后才能写（1→0 易、0→1 难） | SSD/FTL 的块擦写语义：写只能翻 0，翻回 1 得整块重置  |

与 ch06 的 UART 对照：UART **异步**（两端各自 115200，差 2% 就 FE）；SPI **同步**（时钟专线
送达——从机跟不上还能把线拉住，那是 I2C 的戏码，ch08 见）。

## 原理下钻

### 四线、四模式

```text
STM32 F429（主）→ W25Q64（从，板载）
SCK  ─────────────────────────▶ SCK    位时钟：主发，每拍 1 bit
MOSI ─────────────────────────▶ MOSI   主出从入
MISO ◀───────────────────────── MISO   主入从出
CS   ─────────────────────────▶ CS     片选：拉低=独占总线的「连接」建立
```

> 📖 **术语卡：片选 CS（Chip Select，从机选择）**
> **是什么**：主机的一根普通输出线，接到某个从机的使能脚：拉低=点名说话，拉高=轮不到你发言。
> **为什么存在**：SCK/MOSI 是广播的，总线上所有从机都听得见；靠 CS 点名，从机才知道时钟与数据
> 是发给自己的，也才知道一个事务从哪到哪。
> **类比**：交换机端口的定向转发——只有被点中的端口收帧；拉高≈挂断。
> ⚠️ 类比边界：CS 没有 MAC 那种全球唯一地址，一根线只点一个从机；多从机=多根 CS 线（或菊花链接法）。

四模式以模式 0 画图（其余三种是它的旋钮变体，见表）：

```text
模式 0（CPOL=0, CPHA=0）——本章与 W25Q64 的共同语言
SCK  __________┌───┐____┌───┐____┌───┐____┌───┐________
              ↑1       ↑2       ↑3       ↑4     ← 上升沿=双方采样
MOSI ==b7=========b6=========b5====…              ← 下降沿后切换、上升沿前保持
       （CPHA=0 纪律：MSB 在首个上升沿之前就须在线上——CS 拉低即预置）
```

（图里 MSB=Most Significant Bit，最高有效位：SPI 惯例每字节先发高位 b7，b0 压轴。）
模式 1 = 采样挪到第 2 个沿（数据改在第 1 沿切换）；模式 2/3 = 把整图上下翻转（SCK 空闲变高）。
CPOL=时钟空闲电平（Clock Polarity：没事干时 SCK 停在低还是高），CPHA=第 1 还是第 2 个沿采样
（Clock Phase：采样对齐前沿还是后沿）——两个旋钮各拧一半就是四种模式：

| 模式 | CPOL | CPHA | 采样沿（相对空闲低的图） | W25Q64 支持？ |
| ---- | ---- | ---- | ------------------------ | ------------- |
| 0    | 0    | 0    | 第 1 个沿（上升）        | ✓ 本章采用    |
| 1    | 0    | 1    | 第 2 个沿（下降）        | ✗             |
| 2    | 1    | 0    | 第 1 个沿（下降）        | ✗             |
| 3    | 1    | 1    | 第 2 个沿（上升）        | ✓             |

模式不配对的症状是「收到看似合法的错误数据」——与两端 MTU/编码不一致同款静默劣化；四模式的波形差异 ch09 拍给你看。

### F429 SPI 寄存器：写即读的节奏

> 📖 **术语卡：全双工与「写即读」（移位交换）**
> **是什么**：SPI 的收发由同一个移位寄存器（一字节并行装进、逐位移出，同时把对方移进来的逐位接住）
> 完成——时钟每拍一动，MOSI 出 1 bit、MISO 进 1 bit，8 拍后双方各换到对方一字节。
> **为什么存在**：四线设计天然成对走线，带宽零浪费；「发」与「收」在 SPI 里不是两个动作而是同一个。
> **类比**：全双工以太网——同一时刻两边都能说话；但 SPI 是字节对字节的强同步交换，你不发时钟对方不还手。
> ⚠️ 类比边界：想只读不写？也得往 DR 塞个占位字节（惯例 0xFF）制造时钟——SPI 没有单向操作。

SPI1 基址 `0x40013000`（内存映射寄存器块基址；APB2 总线=90MHz——总线与时钟概念见 ch06；候选
SPI5 在 `0x40015000`，同为 APB2）：

| 偏移    | 寄存器 | 本章用到的位                                              |
| ------- | ------ | --------------------------------------------------------- |
| `+0x00` | CR1    | BR[5:3]、CPOL(1)、CPHA(0)、MSTR(2)、SPE(6)、SSM(9)/SSI(8) |
| `+0x04` | CR2    | 全 0：不用中断/DMA（ch10 预留）                           |
| `+0x08` | SR     | RXNE(0)、TXE(1)、BSY(4)                                   |
| `+0x0C` | DR     | 8 位访问；写=发送，读=接收                                |

三条纪律：

1. **先等 TXE 再写**；**写完必等 RXNE 必读**——每写一字节，移位寄存器同步收回一字节，
   不读走，下下个字节就 OVR。命令阶段读回的 0xFF 垃圾也要读。
2. **事务结束等 BSY=0 再拉高 CS**——最后一位还在移位器里挪时拉 CS，从机看到截断事务。
3. **CS 用 GPIO 软件控**（NSS=从机选择信号的功能名，即 CS 的学名；SSM=Software Slave Management
   软件从选模式，置 1 后片选不再由硬件管；SSI=软件里模拟的片选电平，主模式下与 SSM 配对置 1 表示
   「内部 NSS 恒为高」——三件套合起来禁用硬件自动片选输出）——F4 硬件 NSS 时序多坑，手控最稳。

时钟分频：BR 编码 000–111 对应 ÷2/4/8/16/32/64/128/256；÷16=5.625MHz 为首跑档。W25Q64 普通读
标称上限 50MHz（**待核对批次手册**）→ ÷2=45MHz 理论可达，先跑通再提速。

### 挂载三候选（本章头号待核对）

| 候选 | 控制器 @总线     | 引脚候选（全待核对）      | 依据与疑点                                                                                           |
| ---- | ---------------- | ------------------------- | ---------------------------------------------------------------------------------------------------- |
| A    | SPI1 @APB2=90MHz | PA5/PA6/PA7 AF5、CS 待定  | 教程常见；但 PA5 与 J78 触摸按键（板卡事实库）冲突存疑                                               |
| B    | SPI5 @APB2=90MHz | PF7/PF8/PF9 AF5           | F429 新增控制器，PA 口被占时的常见去处                                                               |
| C    | QUADSPI @AHB3    | 专用六线（含双/四线数据） | 「Boot 8M Flash」丝印暗示可能为 QSPI 启动预留；若属实则本驱动整体改道 QUADSPI 寄存器（另一章的功课） |

核对方法：原理图「Boot 8M Flash」区+万用表通断档（蜂鸣档：表笔点两处、电气直通即响，用来追
「丝印上这根线到底连到芯片哪个脚」）。**代码以宏占位，实测后只改宏块**（ch02 KEY 宏同款纪律）。

顺带释词：表里的「AF5」=Alternate Function 5（复用功能 5 号）。STM32 的一个物理引脚内部是个
多路开关，可接到 USART、SPI、定时器等不同外设，接哪个由 AF 编号决定——「PA5 的 AF5 是
SPI1_SCK」这类对应关系要查数据手册的 AF 映射表；编错号=引脚配成了别的外设，线看着接对也不通。

### W25Q64 命令集

> 📖 **术语卡：NOR Flash（或非型闪存，W25Q64 所属物种）**
> **是什么**：掉电不丢的非易失存储；支持随机按字节读，但写只能把 1 改成 0，擦才能归回 1，且擦除
> 以扇区（4KB）为单位整块进行。W25Q64=Winbond 出品、64Mbit=8MB 的 SPI 接口 NOR Flash。
> **为什么存在**：读延迟低、可原地执行代码（XIP），启动介质的经典选择；代价是写前必须擦、擦写有寿命。
> **类比**：SSD 的 FTL 你很熟——这里没有 FTL，「先擦后写」的裸语义直接暴露给驱动作者（你）。
> ⚠️ 类比边界：NOR 没有 out-of-place 写、没有硬件磨损均衡；页内想改一个 bit 也得整扇区重来。

CS 拉低后第一个字节永远是指令码，24 位地址高字节在前（大端序——高字节在前的字节序，同网络
字节序，你的主场）：

| 命令         | 码   | CS 拉低后的字节流             | 用途                       |
| ------------ | ---- | ----------------------------- | -------------------------- |
| 读 JEDEC ID  | 0x9F | cmd + 3 字节回读              | 「你是谁」：厂商/类型/容量 |
| 写使能       | 0x06 | 仅 cmd                        | 擦/写前必须，WEL 置位      |
| 读状态寄存器 | 0x05 | cmd + N 字节回读（可连续）    | bit0=WIP：写操作进行中     |
| 扇区擦除     | 0x20 | cmd + addr[23:0]              | 4KB 全变 FF，典型几十 ms   |
| 页编程       | 0x02 | cmd + addr[23:0] + ≤256 字节  | 只能 1→0；跨页会回卷覆盖   |
| 读数据       | 0x03 | cmd + addr[23:0] + N 字节回读 | 顺序读，任意长度           |

> 📖 **术语卡：WIP 与 WEL（状态寄存器里的两位门神）**
> **是什么**：WIP=Write In Progress（bit0，只读）：设备内部擦/写仍在进行，为 1 时接受新擦写命令会
> 被拒；WEL=Write Enable Latch（bit1）：每次擦/写前必须用 0x06 命令置起的一次性「拔栓」，操作
> 完成后自动落回。
> **为什么存在**：Flash 擦写以 ms 计，慢到必须有忙位供主机轮询；WEL 防误写——上电默认写锁死。
> **类比**：WIP=磁盘/NVMe 的 busy 位轮询（你的主场）；WEL≈数据库的 WAL 开关，动了才能写。
> ⚠️ 类比边界：没有「写完通知你」的中断机制，只能轮询（0x05 可连续读）；别把 WIP 当错误位——它
> 是正常忙碌，不是事故。

擦写读回的全流程（也是本章实验的脚本）：读 ID(0x9F) → [0x06+0x20+addr] 擦扇区 → 轮询 WIP(0x05)
→ [0x06] 写使能 → [0x02+addr+data] 页编程 → 轮询 WIP → [0x03+addr] 读回 → memcmp。

## 实验：读 ID、擦、写、读回

```c
/* ---------- W25Q64 挂载宏：候选 A（SPI1）成文，实测后只改这一块 ---------- */

#define FLASH_SPI        SPI1                /* 待核对：SPI1 / SPI5（QUADSPI 则另起炉灶） */
#define FLASH_CLK_EN()   do { RCC->APB2ENR |= RCC_APB2ENR_SPI1EN; } while (0)
#define FLASH_PORT       GPIOA               /* 候选 A 三根信号线同口；全部待核对（三候选表） */
#define FLASH_SCK_PIN    5u
#define FLASH_MISO_PIN   6u
#define FLASH_MOSI_PIN   7u
#define FLASH_CS_PIN     4u
#define FLASH_AF_NUM     5u                  /* SPI1 的 AF5；换 SPI5 仍多为 AF5，核对 AF 表 */

#define CS_LOW()  (FLASH_PORT->BSRR = (1u << FLASH_CS_PIN))        /* 选中：事务开始 */
#define CS_HIGH() (FLASH_PORT->BSRR = (1u << (FLASH_CS_PIN + 16))) /* 释放：事务结束 */

static void gpio_af_out(GPIO_TypeDef *port, uint32_t pin, uint32_t af)
{
    port->MODER = (port->MODER & ~(3u << (pin * 2u))) | (2u << (pin * 2u));      /* AF 模式 */
    port->AFR[pin >> 3] = (port->AFR[pin >> 3] & ~(0xFu << ((pin & 7u) * 4u)))
                        | (af << ((pin & 7u) * 4u));                              /* 挑 AF 号 */
    port->OSPEEDR |= (3u << (pin * 2u));                                          /* 高速档 */
}

static void spi_flash_init(void)
{
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;   /* 换候选时连时钟一起改 */
    gpio_af_out(FLASH_PORT, FLASH_SCK_PIN,  FLASH_AF_NUM);
    gpio_af_out(FLASH_PORT, FLASH_MISO_PIN, FLASH_AF_NUM);
    gpio_af_out(FLASH_PORT, FLASH_MOSI_PIN, FLASH_AF_NUM);
    FLASH_PORT->MODER = (FLASH_PORT->MODER & ~(3u << (FLASH_CS_PIN * 2u)))
                      | (1u << (FLASH_CS_PIN * 2u));           /* CS=推挽输出 */
    CS_HIGH();   /* 上电即失选！复位期 CS 悬空在低 = 幽灵事务 */
    FLASH_CLK_EN();
    FLASH_SPI->CR1 = (3u << 3)          /* BR=011：90MHz/16=5.625MHz 首跑档 */
                   | SPI_CR1_MSTR      /* 主模式 */
                   | SPI_CR1_SSM | SPI_CR1_SSI  /* 软件从选：NSS 电气坑绕行 */
                   | SPI_CR1_SPE;      /* CPOL=0/CPHA=0 模式 0；SPE 最后落位 */
}

static uint8_t spi_xfer(uint8_t tx)     /* 全双工一字节：写即读的节奏本体 */
{
    while (!(FLASH_SPI->SR & SPI_SR_TXE)) { }   /* 1. 等发送缓冲空 */
    FLASH_SPI->DR = tx;                         /* 2. 写出=同时启动接收 */
    while (!(FLASH_SPI->SR & SPI_SR_RXNE)) { }  /* 3. 等收满 */
    return (uint8_t)FLASH_SPI->DR;              /* 4. 必读：不读就 OVR 欠账 */
}

static void spi_wait_idle(void)          /* 事务收尾：BSY=0 才准拉高 CS */
{
    while (FLASH_SPI->SR & SPI_SR_BSY) { }
}

static uint8_t flash_sr1(void)           /* 0x05：读状态寄存器 1 */
{
    uint8_t sr;
    CS_LOW();
    spi_xfer(0x05);
    sr = spi_xfer(0xFF);                 /* 命令阶段 MOSI 发什么从机不理，惯例 0xFF */
    spi_wait_idle();
    CS_HIGH();
    return sr;
}

static uint32_t flash_wait_wip(void)     /* 轮询 WIP 直到设备闲，返回轮询次数（时长刻度） */
{
    uint32_t n = 0;
    while (flash_sr1() & 0x01u) n++;     /* 每轮=一次 2 字节 SPI 事务 ≈ 数 µs */
    return n;
}

static void flash_cmd_then_addr_data(uint8_t cmd, uint32_t addr24,
                                     const uint8_t *wr, uint8_t *rd, uint32_t len)
{
    CS_LOW();
    spi_xfer(cmd);
    spi_xfer((addr24 >> 16) & 0xFFu);    /* 24 位地址：高字节在前（大端序上总线） */
    spi_xfer((addr24 >> 8) & 0xFFu);
    spi_xfer(addr24 & 0xFFu);
    for (uint32_t i = 0; i < len; i++) {
        uint8_t r = spi_xfer(wr ? wr[i] : 0xFFu);  /* 全双工：同一循环里既写又读 */
        if (rd) rd[i] = r;
    }
    spi_wait_idle();
    CS_HIGH();
}

static void flash_read_jedec(uint8_t id[3])
{
    CS_LOW();
    spi_xfer(0x9F);
    id[0] = spi_xfer(0xFF); id[1] = spi_xfer(0xFF); id[2] = spi_xfer(0xFF);
    spi_wait_idle();
    CS_HIGH();
}
```

**代码走读：`spi_flash_init` 的 CR1 拼装与几个易忽略点**

| 位/操作                         | 值       | 为什么                                                                                |
| ------------------------------- | -------- | ------------------------------------------------------------------------------------- |
| `FLASH_CLK_EN()`（RCC_APB2ENR） | SPI1EN   | STM32 外设默认断电：先开总线时钟，寄存器才「活着」（RCC=复位与时钟控制块）            |
| `BR=3u<<3`                      | 011      | 分频码 011=÷16：90MHz/16=5.625MHz，首跑求稳，跑通再提速                               |
| `MSTR`                          | 1        | 当主机：SCK 由我发——从机模式是 ch08 的戏份                                            |
| `SSM\|SSI`                      | 11       | 软件从选+自选电平，绕开硬件 NSS 电气坑（三条纪律 3）                                  |
| `SPE`                           | 最后     | 配置完才使能——寄存器改半截就使能是未定义行为                                          |
| `CS_HIGH()` 在时钟使能之前      | —        | 上电先失选：复位期 CS 悬空在低=从机误吞幽灵事务                                       |
| `CS_LOW/CS_HIGH` 用 BSRR        | —        | 位设置/复位寄存器：单条写原子置位或清零某个引脚，免读-改-写竞态                       |
| `OSPEEDR` 置 11                 | 高速档   | 5.625MHz 的边沿对引脚输出驱动强度有要求，留余量                                       |
| `MODER` 置 01（CS 脚）          | 推挽输出 | 推挽=输出级一推一拉、高低电平都能主动驱动（ch08 的 I2C 用它的反面「开漏」，届时对照） |

主流程（打印用 ch06 工程里新增的 `uart_puthex8`，两 nibble 转 ASCII 的小助手）：

```c
int main(void)
{
    clock_init();
    uart_init();
    spi_flash_init();

    uint8_t id[3];
    flash_read_jedec(id);
    uart_puts("[FLASH] JEDEC ID = ");
    uart_puthex8(id[0]); uart_puts(" "); uart_puthex8(id[1]);
    uart_puts(" "); uart_puthex8(id[2]); uart_puts("\r\n");

    /* 擦扇区 0 → 写使能+页编程 → 读回比对（写使能 0x06 是脉冲：每次擦/写前都要重发） */
    flash_cmd_then_addr_data(0x06, 0, 0, 0, 0);                 /* WREN */
    flash_cmd_then_addr_data(0x20, 0, 0, 0, 0);                 /* 扇区擦除 @0 */
    uart_puts("[FLASH] erase WIP polls = "); uart_putdec(flash_wait_wip());
    uart_puts("\r\n");

    static const uint8_t msg[] = "F429-SPI-OK";
    uint8_t echo[sizeof(msg)];
    flash_cmd_then_addr_data(0x06, 0, 0, 0, 0);                 /* WREN（擦完已自灭） */
    flash_cmd_then_addr_data(0x02, 0, msg, 0, sizeof(msg));     /* 页编程 @0 */
    uart_puts("[FLASH] program WIP polls = "); uart_putdec(flash_wait_wip());
    uart_puts("\r\n");

    flash_cmd_then_addr_data(0x03, 0, 0, echo, sizeof(msg));    /* 读回 */
    uart_puts("[FLASH] readback = \""); uart_puts((const char *)echo); uart_puts("\"\r\n");
    uart_puts(memcmp(msg, echo, sizeof(msg)) ? "[FLASH] FAIL\r\n" : "[FLASH] PASS\r\n");
    for (;;) { }
}
```

**代码走读：主流程的四组 CS 事务**

| 步  | 事务（CS 拉低→字节流→拉高）            | 目的                                               |
| --- | -------------------------------------- | -------------------------------------------------- |
| 1   | `0x9F` + 读 3 字节                     | 验明正身；ID 全 FF=接线/挂载有错，先排障再往下走   |
| 2   | `0x06`（WREN）→ `0x20+addr` → 轮询 WIP | 写使能是「脉冲」：擦完自动灭，下次写前必须重发     |
| 3   | `0x06` → `0x02+addr+msg` → 轮询 WIP    | 页编程：一次 ≤256B、只能 1→0，跨页会回卷覆盖       |
| 4   | `0x03+addr` + 读 sizeof(msg) 字节      | 读回后 `memcmp` 对账（内存逐字节比较，全同返回 0） |

| 0       | 0xEF | 厂商 ID：Winbond                                    |

| ---------- | ----------- | ---------- | --------------------------------------------------- |
| 0x40023844 | RCC_APB2ENR | 0x00005010 | USART1EN(4)+SPI1EN(12)+SYSCFGEN(14)（沿用 ch02 值） |
| 0x40013000 | SPI1_CR1    | 0x0000035C | SPE(6)+SSM(9)+SSI(8)+MSTR(2)+BR=011(/16)            |

**命令拆解：** `mdw 0x40013000`（核对上表用的活体观察）

| 部分         | 作用                                                     |
| ------------ | -------------------------------------------------------- |
| `mdw`        | OpenOCD 的 memory-dump-word：按 32 位字读内存/外设寄存器 |
| `0x40013000` | SPI1 寄存器块基址——读出的第一个字就是 CR1                |

**你会看到**：`0x0000035C`（上表推导值；候选 B 则对 `0x40015000` 重读）。
**失败了先查**：OpenOCD 与目标板的 SWD 连接是否活着；地址敲错常见症状是读出全 0 或全 F。

## 与 FreeRTOS / ESP32 对照

- **ESP32**：片内 Flash 就是同族 W25Q；`spi_bus_initialize()`+`spi_device_transmit()` 是本章
  `spi_flash_init`+`spi_xfer` 的驱动层打包——排队、CS 时序、双工事务全被封装。
- **FreeRTOS**：`flash_wait_wip` 的死轮询在 RTOS 里是毒药（任务空转），标准姿势是
  `vTaskDelay(1)` 间隔轮询或设备中断+任务通知；多任务共享 SPI 总线要互斥，正是
  [[2026-08-26-freertos-deep-dive-ch11-semaphore-mutex-priority-inheritance|FreeRTOS（十一）：信号量与优先级继承]]
  的用武之地——裸机靠「别在 ISR 里调驱动」的君子协定，RTOS 靠锁的数学。
- **Linux**：spidev 字符设备+设备树（Device Tree：描述硬件拓扑交给内核的数据结构——你的主场）
  描述片选，是「宏占位」的制度化——芯片挂哪、CS 哪根从代码搬进 DT。
