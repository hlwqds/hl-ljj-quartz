> 📖 **术语卡：I2C（Inter-Integrated Circuit，两线制同步总线）**
> **是什么**：只用两根线（SDA 数据、SCL 时钟）的多设备总线：主机发时钟与起始信号，用 7 位地址
> 点名从机，被点名者应答（ACK）后按读/写方向搬数据。
> **为什么存在**：引脚是稀缺资源——两根线挂 N 个传感器/EEPROM，比 SPI 每个从机一根片选省得多；
> 代价是速率低、协议规矩多。
> **类比**：一条共享总线上的点名式轮询网络：地址≈短 MAC，ACK≈链路层确认，时钟拉伸≈零窗口流控。
> ⚠️ 类比边界：没有重传、没有 CRC（仅 1 bit ACK）；错了就是错了，正确性靠上层自查。

## 目标（先说结论）

- 第一次双板实验：树莓派 4B 当 **I2C 主机**（发起时钟与事务的一方），F429 写成 **I2C 从机**
  （被点名、被动应答的一方）——做通标准只有一条：RPi 上 `i2cdetect -y 1` 扫到 `2a`，且
  STM32 收到字节回显串口（双板联动的 hello world）。
- I2C 物理层一页讲透：**开漏 + 上拉**（open-drain+pull-up：输出级只管把线拉低、高电平交给电阻
  回弹，为什么这样设计下节拆）为什么是必须而非建议（线与=任何节点拉低则全线为低、多主仲裁=
  多主机同时开口时的电气裁决、时钟拉伸=从机踩刹车的全部物理基础都在这个电气选择里）。
- F429 侧 I2C1 **从机模式**寄存器级实现：OAR1（Own Address Register 1，自身地址寄存器——
  「我叫什么名字」写在这里）自配 7 位地址 0x2A、地址匹配 ADDR 中断（主机点中我们时触发的
  事件）、收/发缓冲与事件状态机。从机模式是「被扫描者」的视角——平时都是我们扫别人，这次当一次设备。

## 原理下钻

### 开漏 + 上拉：一页电气契约

> 📖 **术语卡：开漏 + 上拉（I2C 的电气契约）**
> **是什么**：开漏（open-drain）=输出级只有一个下拉管，能输出 0、不能输出 1；「1」靠外接上拉
> 电阻把线拽回高电平。
> **为什么存在**：多设备共享一根线时，谁都不许「推高」——否则一个推高、一个拉低=电源对地短路。
> 开漏让所有节点只能拉低，高电平成为「没人说话」的公共默认态。
> **类比**：共享介质的冲突检测地基：谁都能发 0、冲突可被看见——线与是把「多路共写一根线」安全化
> 的电气手段。
> **⚠️ 类比边界：** 代价是速率受限——高电平靠 RC 回弹（τ=RC），线越长电容越大越慢；这是 I2C 快
> 不起来的根本原因。

```text
        3V3
         │
       [Rp 上拉]            高电平没人「驱动」，靠电阻回弹（RC 斜坡，决定速率上限）
         │
   ──────┼────────────── SDA（或 SCL）——两板共享的一根线
     │         │
   [NMOS]   [NMOS]          任意节点输出 0 = 下拉管导通 → 全线为低
   F429       RPi           「线与」：一低全低；多主同发 0，电气上分不出谁——
     │         │             仲裁失败方检测到线低而自己发高，自动退出（冲突退避的硬件版）
   GND       GND            （必须共地！RPi 实验室 ch01 的红线规约）
```

三条推论：

1. **没有上拉就没有 I2C**：所有节点都只会拉低，「高」全靠电阻把线拽回去。回弹时间
   τ=RC（RPi 板载 1.8kΩ × 总线电容约 100pF → τ≈180ns），100kHz 的高电平窗口 5µs 绰绰有余。
2. **推挽输出是违章建筑**：推挽=高低电平都主动驱动（ch07 的 CS 脚用的就是它）；一边推高、
   一边拉低=电源对地短路。所以 F429 侧 GPIO 必须配开漏（OTYPER=输出类型寄存器，逐脚选推挽/
   开漏），这条错了轻则通信烂、重则伤引脚。

   > 📖 **术语卡：时钟拉伸（clock stretching）**
   > **是什么**：从机把 SCL 拉低不放，主机的时钟高电平就回不来，只能干等从机腾出手——协议层零
   > 开销的硬件流控。
   > **为什么存在**：从机（常是慢速 MCU）处理不过来时需要合法手段让总线停表；I2C 把刹车踏板直接
   > 焊在时钟线上。
   > **类比**：TCP 零窗口（你的主场）：接收方说「等一下」，发送方就必须等；差别是这里不用回包，
   > 拉线即生效。
   > ⚠️ 类比边界：个别主设备（某些 USB 转换器）不支持拉伸会直接报错；本实验 RPi 的控制器支持。

3. **时钟拉伸是白送的**：从机把 SCL 拉低，主机的高电平永远回不来，只能等——流控不需要
   协议字段，电气上天然成立。F429 的 I2C 在 ADDR 置位后会自动拉伸 SCL 直到软件清标志，
   「从机 ISR 慢，主机就等着」是硬件保证的。

### 事务帧格式

```text
S（起始）= SCL 高时 SDA 下跳；P（停止）= SCL 高时 SDA 上跳
      ┌S┐                                ┌P┐
──────┘  └──[7位地址][R/W]──[ACK]──[数据]──┘  └──────
0x2A+W 例： 0101010 0       ACK(STM32)  0x5A   ACK(STM32)     ← i2cset 的完整生命周期
0x2A+R 例： 0101010 1       ACK(STM32)  0xA5   NACK(RPi=读够了)← i2cget 的完整生命周期
```

> 📖 **术语卡：7 位地址与 ACK/NACK**
> **是什么**：地址是总线上点名从机的 7 位编号（0x00 保留作广播 GENCALL，其余可用）；每传完一个
> 字节（含地址字节），第 9 个时钟位是接收方的应答位：拉低=ACK（收到），保持高=NACK（不要了/
> 读够了）。
> **为什么存在**：两线共享介质必须有点名机制；ACK 让发送方知道对面在不在、收没收到。
> **类比**：地址≈本地总线的短 MAC；ACK≈链路层确认；0x00≈广播地址——你的主场一排全对上。
> ⚠️ 类比边界：7 位只有约 112 个可用地址，不少已被模块出厂焊死（0x20~0x27 是撞车重灾区）；
> 同地址两设备=总线打架。

地址左对齐进字节高 7 位、最低位是方向（0=写 1=读）——所以 OAR1 里存的是 `地址<<1`
（左移一位腾出方向位；这也是「7 位地址 0x2A」在线上字节里看到 0x54 的原因）。

### STM32 I2C1 从机模式的寄存器

基址 `0x40005400`（APB1=45MHz）。F4 的 I2C 是老式（非 F0/L4 的 TIMINGR 新版）：

| 偏移    | 寄存器 | 从机模式用法                                                    |
| ------- | ------ | --------------------------------------------------------------- |
| `+0x00` | CR1    | PE(0) 总使能、ACK(10) 地址匹配后自动应答、SWRST(15) 复位        |
| `+0x04` | CR2    | FREQ[5:0]=45（APB1 MHz）；ITERREN(8)、ITEVTEN(9)、ITBUFEN(10)   |
| `+0x08` | OAR1   | 自家地址：`(1<<14) \| (addr<<1)`——bit14 手册规定恒 1            |
| `+0x10` | DR     | 收/发数据                                                       |
| `+0x14` | SR1    | ADDR(1) 地址匹配、RxNE(6)、TxE(7)、STOPF(4)、AF(10)、BERR(8) 等 |
| `+0x18` | SR2    | TRA(2) 传输方向、MSL(0) 主/从模式                               |

三个老 I2C 的「怪癖」，每条都和前面章节的习惯相反，值得点名：

1. **ADDR 的清除是「读 SR1 再读 SR2」**——不是写清。ISR 里必须老老实实两连读。
2. **错误位 AF（Ack Failure，没等到应答）/BERR（Bus Error，总线错误）/ARLO（Arbitration Lost，
   仲裁丢失）/OVR（Overrun，溢出）是写 0 清除**——与 EXTI PR 的 w1c（write-1-to-clear，写 1
   清除；EXTI=外部中断外设，PR=其挂起寄存器，嵌入式最常见的清标志惯例）正好相反。
3. **CCR/TRISE 时序寄存器在从机模式可简化**：SCL 节拍跟主机走，CCR/TRISE 是主机侧算式
   （Standard 模式 CCR=FREQ/2）；从机只要求非零合法值，按惯例填 45/46 即可（RM0090
   原文口径**待核对**）。F0/L4/H7 的新版 I2C 把这坨时序换成了 TIMINGR 一寄存器，那才是
   要算表的主——本板赶上了老式的福利。

中断通道：`I2C1_EV_IRQn=31`（事件）、`I2C1_ER_IRQn=32`（错误），ISER0 bit31 + ISER1 bit0。

## 实验：让树莓派扫到自己

### 接线表

| RPi 侧（40-pin）      | 信号 | F429 侧（黑排针，丝印待核对） | 备注                                                               |
| --------------------- | ---- | ----------------------------- | ------------------------------------------------------------------ |
| 物理 3（GPIO2, SDA1） | SDA  | PB7（I2C1_SDA，AF4）          | RPi 此脚板载 1.8k 上拉                                             |
| 物理 5（GPIO3, SCL1） | SCL  | PB6（I2C1_SCL，AF4）          | 同上；PB6 若被占（ch03 备选方案曾提名 TIM4_CH1）则引脚映射整体重核 |
| 物理 6                | GND  | 任意 GND                      | **第一根线先共地**（RPi ch01 规约）                                |
| —                     | 电平 | —                             | 两板均 3.3V 逻辑可直连；BCM2711 非 5V 容忍                         |

释词三枚：SDA=Serial Data 数据线、SCL=Serial Clock 时钟线（I2C 全部家当就这两根+地线）；
BCM2711=树莓派 4B 的主 SoC 型号；「非 5V 容忍」=该脚接 5V 逻辑电平会损坏（所以两板都跑
3.3V 才能直连，杜邦线=面包板常用的单根跳线）。

上拉策略：RPi 的 1.8k 板载上拉（GPIO2/3 硬件焊接，不可禁用）在「两设备+短杜邦线」场景
通常够用，F429 侧**不再外加**；若线长/挂多设备，再加 4.7k 外部上拉（并联后等效阻值减小，
上升沿更快，但也更费驱动电流——上拉不是越大越好）。

### STM32 从机固件

器件语义定成「一字节回显存储器」：主机写一个字节=记住；主机读=返回最近写入值（初值 0xA5）。
这样 `i2cset` 后 `i2cget`（i2c-tools 工具族的一写一读命令，参数级拆解见下文「树莓派侧命令」）
能闭环验证。打印沿用 ch06 纪律：**ISR 只入队，串口打印留给主循环**
（事件环就是 ch06 SPSC 环的再就业）。

```c
#define SLAVE_ADDR 0x2Au   /* 自选地址；先跑一遍 i2cdetect 全表确认 0x2A 空位 */

static volatile uint8_t g_i2c_last = 0xA5u;          /* 「寄存器」本体：写进去的、读出来的 */
static volatile uint32_t g_i2c_wr, g_i2c_rd, g_i2c_af, g_i2c_err;

#define EVT_RING 8u                                    /* ISR→main 的事件环（ch06 同款 SPSC） */
#define EVT_READ  0xFFu    /* 事件编码：主机读事务（数据=g_i2c_last，打印时取） */
#define EVT_WADDR 0xFEu    /*           地址命中（写方向；无数据相随=扫描在敲门） */
static volatile uint8_t g_evt[EVT_RING];               /* 其余值=主机写入的字节（写 0xFF/0xFE
                                                          会与事件码撞名——教学板可接受） */
static volatile uint32_t g_evt_head, g_evt_tail;

static void i2c1_slave_init(void)
{
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOBEN;              /* PB6/PB7 待核对 */
    /* AF + 开漏 + 上拉：开漏是 I2C 电气契约（推挽=违章，见正文） */
    GPIOB->MODER = (GPIOB->MODER & ~((3u << (6 * 2)) | (3u << (7 * 2))))
                 | (2u << (6 * 2)) | (2u << (7 * 2)); /* AF 模式 */
    GPIOB->OTYPER |= (1u << 6) | (1u << 7);           /* 开漏输出 */
    GPIOB->PUPDR = (GPIOB->PUPDR & ~((3u << (6 * 2)) | (3u << (7 * 2))))
                 | (1u << (6 * 2)) | (1u << (7 * 2)); /* 内部上拉兜底（主力是 RPi 的 1.8k） */
    GPIOB->AFR[0] = (GPIOB->AFR[0] & ~((0xFu << (6 * 4)) | (0xFu << (7 * 4))))
                  | (4u << (6 * 4)) | (4u << (7 * 4));/* AF4 = I2C1 */

    RCC->APB1ENR |= RCC_APB1ENR_I2C1EN;
    I2C1->CR1 = I2C_CR1_SWRST;                        /* 先复位一遍，从已知状态起跑 */
    I2C1->CR1 = 0;

    I2C1->CR2 = 45u | I2C_CR2_ITERREN | I2C_CR2_ITEVTEN | I2C_CR2_ITBUFEN;
    I2C1->OAR1 = (1u << 14) | (SLAVE_ADDR << 1);      /* bit14 恒 1；地址占 [7:1] */
    I2C1->CCR = 45u;                                  /* 从机安全值（见正文怪癖 3） */
    I2C1->TRISE = 46u;                                /* FREQ+1 惯例值 */
    I2C1->CR1 = I2C_CR1_ACK | I2C_CR1_PE;             /* ACK=1：地址匹配后硬件自动应答 */

    NVIC->ISER[0] = (1u << 31);                       /* I2C1_EV_IRQn=31 */
    NVIC->ISER[1] = (1u << 0);                        /* I2C1_ER_IRQn=32 */
}

void I2C1_EV_IRQHandler(void)                          /* 事件状态机：每个标志一条支路 */
{
    uint32_t sr1 = I2C1->SR1;
    if (sr1 & I2C_SR1_ADDR) {                          /* 地址匹配（本章只有 0x2A 会来） */
        uint32_t sr2 = I2C1->SR2;                      /* 读 SR1 后读 SR2=清 ADDR（怪癖 1） */
        if (sr2 & I2C_SR2_TRA) {                       /* TRA=1：主机在读我们 */
            g_i2c_rd++;
            g_evt[g_evt_head & (EVT_RING - 1u)] = EVT_READ; g_evt_head++;
        } else {                                       /* 写方向：无数据相随=扫描在敲门 */
            g_evt[g_evt_head & (EVT_RING - 1u)] = EVT_WADDR; g_evt_head++;
        }
    } else if (sr1 & I2C_SR1_RXNE) {                   /* 主机写：收到一字节 */
        uint8_t b = I2C1->DR;
        g_i2c_last = b;                                /* 「寄存器」更新 */
        g_i2c_wr++;
        g_evt[g_evt_head & (EVT_RING - 1u)] = b; g_evt_head++;   /* 只入队，ISR 不打印 */
    } else if (sr1 & I2C_SR1_TXE) {                    /* 主机读：DR 空了，续货 */
        I2C1->DR = g_i2c_last;                         /* 事务数已在 ADDR/TRA 分支记过 */
    } else if (sr1 & I2C_SR1_STOPF) {                  /* 主机发了 STOP：事务结束 */
        (void)I2C1->SR1;
        I2C1->CR1 |= I2C_CR1_PE;                       /* 读 SR1 后写 CR1=清 STOPF */
    }
    /* BTF：RxNE/TxE 及时处理后不会到达；若到，读/写一次 DR 即释放（SCL 拉伸随之解除） */
}

void I2C1_ER_IRQHandler(void)
{
    uint32_t sr1 = I2C1->SR1;
    if (sr1 & I2C_SR1_AF) g_i2c_af++;                  /* 主机 NACK：读事务的正常收尾，单记账 */
    else g_i2c_err++;                                  /* BERR/ARLO/OVR 才是真异常 */
    I2C1->SR1 &= (uint32_t)~(I2C_SR1_AF | I2C_SR1_BERR | I2C_SR1_ARLO | I2C_SR1_OVR);
    /* 怪癖 2：写 0 清除——&= 恰好把要清的位写 0、其余写 1（无副作用），与 EXTI 的 w1c 反着记 */
}
```

**代码走读：`I2C1_EV_IRQHandler` 的事件状态机（一条标志一支路）**

| 支路       | 触发条件                 | 动作与含义                                                        |
| ---------- | ------------------------ | ----------------------------------------------------------------- |
| ADDR+TRA=1 | 主机点名 0x2A 且方向=读  | 记 rd 计数、投 EVT_READ；两连读 SR1/SR2 清 ADDR，SCL 拉伸随之解除 |
| ADDR+TRA=0 | 主机点名且方向=写        | 只投 EVT_WADDR——若没有后续数据事件，就是 i2cdetect 在敲门         |
| RXNE       | 主机写的字节进了 DR      | 读走存入 `g_i2c_last`（「寄存器」本体）、投数据事件               |
| TXE        | 主机还在读、发送缓冲空了 | 续填 `g_i2c_last` 给主机搬走                                      |
| STOPF      | 主机发了停止条件         | 读 SR1 再写 CR1 清标志——事务收线                                  |

（TRA=SR2 里的传输方向位：1=主机在读我们，0=主机要写我们。）

主循环消费事件环并打印三种事件：`EVT_WADDR` → `[I2C] ADDR(W) hit`（若没有后续数据事件，
就是 i2cdetect 的扫描在敲门）；`EVT_READ` → `[I2C] master read -> 0xXX`（取 `g_i2c_last`）；
其他 → `[I2C] RX 0xXX`（主机写入）。统计行每秒报 wr/rd/af/err 四个计数，其中
**af 应与 rd（即 i2cget 次数）一致**——每次读都以主机 NACK 收尾，这是「AF 不是错误」的实测判据。

### 树莓派侧命令（全流程）

```bash
# 0) 前提：RPi ch01 基线完成（Bookworm、共地规约成文）
# 1) 开 I2C1 并装工具
sudo raspi-config nonint do_i2c 0          # 或 raspi-config 交互：Interface Options → I2C
sudo apt install -y i2c-tools
ls /dev/i2c-1                               # 在位即开

# 2) 扫描（做通标准第一条）
i2cdetect -y 1                              # 注：会对每个地址发事务，生产总线慎用

# 3) 读写（做通标准第二条：回显闭环）
i2cget -y 1 0x2a                            # 读一字节：初值预期 0xa5
i2cset -y 1 0x2a 0x5a                       # 写一字节
i2cget -y 1 0x2a                            # 再读：预期 0x5a
```

**命令拆解：** `sudo raspi-config nonint do_i2c 0`

| 部分           | 作用                                                  |
| -------------- | ----------------------------------------------------- |
| `sudo`         | 以 root 权限执行（改系统配置需要）                    |
| `raspi-config` | 树莓派官方配置工具                                    |
| `nonint`       | 非交互模式：参数直接生效、不进菜单（脚本/自动化友好） |
| `do_i2c`       | 要执行的动作：切换 I2C 接口开关                       |
| `0`            | 0=启用、1=禁用                                        |

**命令拆解：** `sudo apt install -y i2c-tools` 与 `ls /dev/i2c-1`

| 部分            | 作用                                                                 |
| --------------- | -------------------------------------------------------------------- |
| `apt install`   | Debian 系包管理器装软件                                              |
| `-y`            | 所有确认问答自动答「是」                                             |
| `i2c-tools`     | i2cdetect/i2cget/i2cset 三件套所在的包                               |
| `ls /dev/i2c-1` | 看设备文件在不在：在=I2C 已启用（Linux 把 I2C 控制器暴露为字符设备） |

**命令拆解：** `i2cdetect -y 1`（做通标准第一条）

| 部分        | 作用                                             |
| ----------- | ------------------------------------------------ |
| `i2cdetect` | 扫描 I2C 总线，看哪些地址有设备应答              |
| `-y`        | 跳过「确认要扫吗」的交互提问                     |
| `1`         | 扫 1 号 I2C 控制器（RPi 引出的那组物理引脚 3/5） |

**你会看到**：一张 16×8 地址表，0x2A 处显示 `2a`（我们的 STM32 从机）。
**失败了先查**：I2C 是否 raspi-config 启用、SDA/SCL 接反、没共地。

**命令拆解：** `i2cget -y 1 0x2a` / `i2cset -y 1 0x2a 0x5a`

| 部分            | 作用                                           |
| --------------- | ---------------------------------------------- |
| `i2cget/i2cset` | 从指定从机读一字节 / 往指定从机写一字节        |
| `-y`            | 同上，跳过交互确认                             |
| `1`             | 1 号 I2C 控制器                                |
| `0x2a`          | 目标从机的 7 位地址（即固件里的 `SLAVE_ADDR`） |
| `0x5a`          | 要写入的字节值（i2cget 没有这个参数）          |

**你会看到**：i2cget 打印一行十六进制（首读 `0xa5`=初值）；i2cset 成功时静默。
**失败了先查**：地址敲错（是 0x2a 不是 0x54——后者是含方向位的字节形态）；接线表第 1 行共地。

## 与 Linux / ESP32 对照

- **同一协议的两种身份**：RPi 侧的 i2c-tools 走的是内核 i2c-dev + 设备树的官僚体系
  （用户态 ioctl——操控设备驱动的系统调用，你的主场 → 内核驱动 → 控制器寄存器），F429 侧是
  直配寄存器的裸机从机——
  一根双绞线上对讲的两端，隔着整套操作系统与零操作系统。树莓派实验室系列后面的
  request_irq/设备树章（规划中）会把 RPi 那一侧也拆开对照。
- **ESP32**：`i2c_slave_*` API 一族把 OAR1/ADDR/RxNE 这些寄存器包成回调与队列；
  「从机地址=设备身份」在 ESP-IDF 的 i2c 设备树形参数里同样一行定生死。
- **FreeRTOS**：事件环 + 主循环打印就是「中断顶半、任务底半」的裸机预演；上了 RTOS，
  `xQueueSendFromISR` 替掉手搓环（[[2026-08-26-freertos-deep-dive-ch14-stream-message-buffers|FreeRTOS（十四）]]），
  但「ISR 里不做慢事」的纪律一字不改。
