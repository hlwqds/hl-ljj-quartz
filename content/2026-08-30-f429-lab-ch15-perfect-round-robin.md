## 目标（先说结论）

- [[2026-08-26-freertos-deep-dive-ch8-priority-timeslice-rr|FreeRTOS（八）：优先级与时间片]]讲过：
  Vanilla（原版：freeRTOS.org 官方内核，未经芯片厂商魔改）的同优先级轮转是**完美 Round-Robin**，IDF
  FreeRTOS（乐鑫 ESP-IDF 开发框架里的魔改版）在双核 SMP（Symmetric Multi-Processing，对称多处理：
  多核共享内存、共同调度同一批任务）下退化为 **Best-Effort**（尽力而为：只承诺「试着」轮转，不保证严格
  交替）。本章在
  真机上把前者的「完美」拍成时间戳序列——严格 ABABAB，一拍不乱。
- 为什么必须这块板：**单核、无 SMP、无系统任务搅局**。`FreeRTOSConfig.h` 没定义
  `configNUMBER_OF_CORES`（配置宏：告诉内核有几个 CPU 核），内核取默认值 1（`include/FreeRTOS.h:89-90`）
  ——pxCurrentTCB（内核里「现在谁在占 CPU」的指针；TCB＝Task Control Block，任务控制块——每个任务的
  档案袋，记着栈顶、优先级、状态）是单数、临界区（一段不许任何人打断的代码段）是
  关中断、没有 spinlock（自旋锁：拿不到锁就原地空转重试，多核互斥才用得上）；板上也没有 wifi/esp_timer 这类乐鑫系统任务来抢戏。同样的实验搬上 ESP32，
  同优先级任务的切换被另一个核和系统任务弄脏，ABAB 里会混进 (core N) 跳变与随机插队。
- 机制深挖到源码两行：`xTaskIncrementTick()`（内核的每拍管账员：每个 tick 清点该唤醒谁、要不要切换）
  的时间片分支（时间片＝同优先级「到点让位」的强制轮换规则；tasks.c:4967-4975）+ 就绪链表的
  pxIndex 轮转（include/list.h:286）。并且要辨析一个容易混的事实——**delay 版 ABAB 的直接驱动力是
  「同一 tick 到期点的唤醒排队」，时间片分支真正出场是在忙循环对照组**。
- 时间戳工具：g_ms 的 RTOS 身份（`xTaskGetTickCount()`）给毫秒，DWT CYCCNT 给微秒——180MHz 下
  1µs = 180 个周期，分辨率 5.6ns。

> 📖 **术语卡：Round-Robin（时间片轮转）**
> **是什么**：多个同优先级任务按固定顺序轮流占用 CPU，每拍 tick 到点强制换人，谁也不多占。
> **为什么存在**：同级任务在「谁先跑」上没有自然答案，轮转给出人人机会等量的公平分法。
> **类比**：食堂打饭排一条队——打完一份的人自动去队尾重新排，队伍转起来人人有份。
> ⚠️ 类比边界：食堂队比的是等待时长，Round-Robin 保证的是「机会等量」（每拍轮到一次），不是实际运行时长——中途阻塞让出的任务会把没用完的份额让给别人。

## 为什么 ESP32 上做不干净这个实验

把主实验（两个同优先级任务、同周期 delay、带序号打印）原样搬去 ESP32，三种污染立刻进场：

| 污染源         | 机制                                                                       | 出处                                                                                    |
| -------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 双核 SMP       | 两个任务可以同时各占一核，「交替」根本不成立；不绑核的任务落在当时有空的核 | [[2026-08-26-freertos-deep-dive-ch22-smp-refactor-overview\|FreeRTOS（廿二）]]          |
| 系统任务       | wifi（CORE0 常驻）、esp_timer（优先级 22）随时插队，同优先级就绪队列被搅乱 | [[2026-08-26-freertos-deep-dive-ch1-from-bare-metal-to-rtos\|FreeRTOS（一）]]1.5 节实测 |
| Best-Effort RR | 时间片检查按核独立进行，切换语义从「轮到谁」变成「这核这拍让不让」         | [[2026-08-26-freertos-deep-dive-ch8-priority-timeslice-rr\|FreeRTOS（八）]]             |

本板上这三样全部不存在：`configUSE_TIME_SLICING=1`（FreeRTOSConfig.h:11；配置宏：打开时间片轮转）、
`configUSE_PREEMPTION=1`（配置宏：打开抢占——高优先级任务就绪时立刻打断低优先级）、
就绪队列里只有你创建的任务和 Idle（优先级 0 的兜底任务：没有别人可跑时由它占着 CPU）。**单核是 Round-Robin 的无菌手术室**。

## 机制：两行源码撑起一个调度语义

### 1. tick 里的时间片分支：同优先级就绪数 > 1 就申请切换

```c
/* tasks.c:4967-4975（xTaskIncrementTick，单核分支）——每 1ms 被SysTick喊一次 */
#if ( ( configUSE_PREEMPTION == 1 ) && ( configUSE_TIME_SLICING == 1 ) )
{
    #if ( configNUMBER_OF_CORES == 1 )
    {
        if( listCURRENT_LIST_LENGTH( &( pxReadyTasksLists[ pxCurrentTCB->uxPriority ] ) ) > 1U )
        {
            xSwitchRequired = pdTRUE;    /* ← 就这一行：时间片到期，让位 */
        }
    }
    #endif
}
#endif
```

当前任务的优先级队列里若还有别人排队，本拍 tick 就把 `xSwitchRequired` 置位，中断退出走 PendSV
做上下文切换——这就是「每 tick 轮转」的全部实现。

> 📖 **术语卡：PendSV 与上下文切换（Context Switch）**
> **是什么**：PendSV 是 Cortex-M 处理器专门留给操作系统用的「可挂起中断」（Pendable Service Call：先登记、稍后统一处理）；上下文切换＝把当前任务的寄存器现场存进它的栈、再把下一任务的现场装回 CPU。
> **为什么存在**：切换现场必须等所有中断都处理完再做，否则现场会被新中断撕坏；PendSV 可以配成最低优先级，天然保证「最后执行、一次切干净」。
> **类比**：剧场换场——所有演员（其他中断）先谢幕退场，最后统一搬布景（换上下文）。
> ⚠️ 类比边界：换场只搬布景；上下文切换搬的是任务的全部寄存器现场（R4-R11、栈指针等），必须一字不差全量保存。

### 2. 选人：就绪链表的 pxIndex 走步（尾插头取的轮转）

```c
/* tasks.c:197-212（taskSELECT_HIGHEST_PRIORITY_TASK，通用路径） */
while( listLIST_IS_EMPTY( &( pxReadyTasksLists[ uxTopPriority ] ) ) != pdFALSE )
    uxTopPriority--;
/* 源码注释原文（tasks.c:208-210）：
 * "listGET_OWNER_OF_NEXT_ENTRY indexes through the list, so the tasks of
 *  equal priority get an equal share ..." */
listGET_OWNER_OF_NEXT_ENTRY( pxCurrentTCB, &( pxReadyTasksLists[ uxTopPriority ] ) );
```

`listGET_OWNER_OF_NEXT_ENTRY`（include/list.h:286）把链表的 `pxIndex` 向前走一格并取该格的 TCB；
任务被唤醒/变为就绪时经 `vListInsertEnd`（list.c:105）插到 pxIndex **前一格**——即轮转队列的**队尾**。
排队的人从尾进、按 index 轮流出，同优先级人人等量：教科书 Round-Robin 的数据结构实现，总共十来行。

> 📖 **术语卡：就绪链表（pxReadyTasksLists）与 pxIndex 轮转**
> **是什么**：FreeRTOS 给每个优先级配一条双向链表，链上挂着「这个优先级里正在等 CPU 的任务」；pxIndex 是链表游标，记住上一次取到谁，下次取它后面那个。
> **为什么存在**：同级轮转要「轮流出列」而不是「每次都取第一个」——游标每走一步取一个，天然公平。
> **类比**：传菜转盘——指针每转一格夹下一道菜，新上的菜从指针前一格（队尾）放上去。
> ⚠️ 类比边界：转盘只管「取的顺序」；任务被唤醒插进队尾后，若优先级不够高，照样一步都轮不到（对照组①第二版就是现场）。

### 3. 辨析：delay 版的 ABAB 到底是谁驱动的

这是本章最容易想当然的地方，必须掰开：A/B 同优先级、都 `vTaskDelay(200ms)` 时——

- 两人在**同一个 tick 到期点**被唤醒（delay 链表＝延时队列：挂着所有睡觉任务、按「该醒来的时刻」排序；
  同时刻按入表顺序：先创建的 A 在前）；
  唤醒后逐个从 delay 链表摘下、`vListInsertEnd` 进就绪队列（tasks.c 的 delay 解锁循环）；
- Idle 正在跑、优先级 0 < 2 → 抢占切换；A 打印、随即 `vTaskDelay` **阻塞让出** → 切到 B；B 打印、阻塞；
- 下一个 200ms 边界重复。全程没有一次「时间片到期把正在跑的人请下来」——ABAB 的秩序来自
  **唤醒排队 + 阻塞让出**，时间片分支（1 小节）在这条路径上只是把「两人同时就绪」翻译成切换请求。

> 📖 **术语卡：阻塞让出 vs 抢占 vs 时间片**
> **是什么**：阻塞让出＝任务自己调用 `vTaskDelay` 之类的 API 主动睡下、交出 CPU；抢占＝更高优先级任务变成就绪时，内核立刻打断当前任务把它请下去；时间片＝同优先级任务到点强制轮换。
> **为什么存在**：CPU 一个时刻只能跑一个任务，让出 CPU 的路只有这三条——分清「谁让的、为什么让」才能看懂调度日志。
> **类比**：会议室里：自己说「我先走了」＝阻塞让出；被老板一句「让一下」请起来＝抢占；按规则轮流发言、到点换人＝时间片。
> ⚠️ 类比边界：被抢占的任务仍是「就绪」态（站在门口随时能回来继续），阻塞的任务是「等待」态（要睡到闹钟响）——会议室里并没有这么精确的门口队列。

时间片分支真正的主场是本章的忙循环对照组：任务**不阻塞**、一直就绪，每拍 tick 都满足
「同优先级就绪数 > 1」→ 每 1ms 强制轮转一次。两个实验、两种机制、同一对任务——这是本章的对照法骨架。

## 时间戳：g_ms 的 RTOS 身份 + DWT CYCCNT

ch01 裸机里的毫秒地基是 `SysTick_Handler`（SysTick＝Cortex-M 内核自带的 24 位倒计数定时器，专给
操作系统当心跳用；这个函数是它的中断服务程序）维护的 `g_ms`（每次中断加一的毫秒变量）。本固件里这个
向量已被三行映射
（FreeRTOSConfig.h:64-66）交给 `xPortSysTickHandler`（FreeRTOS 移植层接管 SysTick 的入口：先清中断
标志，再调内核的每拍管账函数）——同一颗 SysTick、同一个 `LOAD=0x2BF1F`
（ch01 的对账结论），毫秒账本从裸机变量变成内核的 `xTickCount`（内核的拍子计数变量）：tick 1000Hz
（每秒 1000 拍，即 1ms 一拍——本章一切节奏都由它定），
**`xTaskGetTickCount()`（读 xTickCount 的官方 API）就是 RTOS 版的 g_ms**。毫秒之外再要微秒，上 DWT：

| 寄存器   | 地址       | 用法                                  |
| -------- | ---------- | ------------------------------------- |
| DEMCR    | 0xE000EDFC | bit24 TRCEN=1：DWT 全局使能（总开关） |
| DWT_CTRL | 0xE0001000 | bit0 CYCCNTENA=1：开启周期计数器      |
| CYCCNT   | 0xE0001004 | 32 位自由跑的 CPU 周期计数，写 0 清零 |

> 📖 **术语卡：DWT 与 CYCCNT（周期计数器）**
> **是什么**：DWT（Data Watchpoint and Trace，数据观察点与跟踪单元）是 Cortex-M 处理器内核里的调试部件；CYCCNT 是其中的 32 位计数器，每过一个 CPU 时钟周期就加 1。
> **为什么存在**：毫秒级的 SysTick 打点太粗，测调度间隔需要微秒级；CYCCNT 是硬件自带的「周期级秒表」，读一次只要几纳秒，几乎不打扰被测对象。
> **类比**：SysTick 是每毫秒报一次时的挂钟，CYCCNT 是随按随读的秒表。
> ⚠️ 类比边界：秒表可以停表读数；CYCCNT 自由跑不停，只能读两次取差值，且 32 位在 180MHz 下约 23.86 秒回绕（数满归零重数）一次。

```c
#define DEMCR      (*(volatile uint32_t *)0xE000EDFC)
#define DWT_CTRL   (*(volatile uint32_t *)0xE0001000)
#define DWT_CYCCNT (*(volatile uint32_t *)0xE0001004)

static void dwt_init(void)
{
    DEMCR |= (1u << 24);    /* TRCEN：先开总闸（CM4 直接写，无 M7 的 LAR 解锁步骤） */
    DWT_CYCCNT = 0u;
    DWT_CTRL |= (1u << 0);  /* CYCCNTENA */
}
```

换算与边界：180MHz → 1µs = 180 周期，打印时除以 180 即得整数微秒；32 位回绕周期
2^32/180MHz ≈ 23.86s——观测窗口压在 20s 内（200ms 一对，100 对封顶）就不用处理回绕。
回绕（wraparound）＝计数器数满 2^32 后归零从头再数；只要每次差值都在一个回绕周期内算完，就不需要特殊处理。

## 实验：主实验 + 两个对照组

主实验代码（加进 `main.c`，创建放 `vTaskStartScheduler()` 之前，`dwt_init()` 放 `uart_init()` 之后）：

```c
static void rr_task(void *arg)
{
    const char *name = (const char *)arg;
    uint32_t n = 0, t0;
    for (;;) {
        uart_puts(name); uart_putdec(n++);
        uart_puts(" cy="); uart_putdec(DWT_CYCCNT);  /* 周期级时间戳，主机侧 /180 得 µs */
        uart_puts("\r\n");
        vTaskDelay(pdMS_TO_TICKS(200));
    }
}

/* main() 里：同优先级 2、栈 256 字（ch14 的教训）、A 先创建 */
xTaskCreate(rr_task, "A", 256, "A", 2, NULL);
xTaskCreate(rr_task, "B", 256, "B", 2, NULL);
```

**代码走读：** `xTaskCreate(rr_task, "A", 256, "A", 2, NULL)` 的六个参数

| 参数位   | 本实验取值 | 意思                                                                                 |
| -------- | ---------- | ------------------------------------------------------------------------------------ |
| 任务函数 | `rr_task`  | 任务从哪个函数开始跑；签名固定为 `void f(void *arg)`，永不 return                    |
| 名字     | `"A"`      | 调试/统计时显示用，不参与调度                                                        |
| 栈深     | `256`      | 单位是**字**（word＝4 字节），不是字节！256 字＝1024 字节（ch14 教训：给小了会溢出） |
| 传参     | `"A"`      | 塞进任务的 `arg`，任务用它区分自己该打印 A 还是 B                                    |
| 优先级   | `2`        | 数字越大越优先；A、B 同为 2，才轮得到本章的轮转                                      |
| 句柄回传 | `NULL`     | 用来事后操作该任务（删除/改优先级）的句柄出口，本实验用不上                          |

任务循环三件套：`uart_puts`/`uart_putdec` 是 ch01 写好的串口小工具（打字符串/打十进制数）；
`uart_putdec(DWT_CYCCNT)` 打印周期计数（主机侧除以 180 换算微秒）；
`vTaskDelay(pdMS_TO_TICKS(200))` 把任务挂进延时队列睡 200ms（`pdMS_TO_TICKS` 把毫秒换算成 tick 数，
1000Hz 下 200ms＝200 tick）——这一步就是「阻塞让出」，睡醒回到循环顶部继续打印。

**对照组①（判别器：忙旋暴露「时间片 vs 阻塞让出」）**：给 A 的打印后加一段忙旋再 delay——

```c
/* rr_task 里 vTaskDelay 之前插入（仅 A 生效，B 不动）： */
t0 = DWT_CYCCNT;
while (DWT_CYCCNT - t0 < 9u * 1000000u) { }  /* 忙旋 50ms = 9,000,000 周期，绝不阻塞 */
```

忙旋（busy-wait）＝空转循环纯烧时间、**全程不让出 CPU**——对照组①的灵魂就在「绝不阻塞」四个字：
A 忙旋的每一毫秒里都保持就绪，时间片分支的触发条件（同优先级就绪数 > 1）全程成立。

同优先级版预期：B 在 A 忙旋开始后的**第一个 tick（≤1ms）**就被时间片送进来打印——时间片分支的现场
抓获。然后把 B 的优先级改成 1（`FreeRTOSConfig.h:16` 的 `configMAX_PRIORITIES=5`（优先级档位上限：
合法优先级 0–4）内随意调）再烧：
A 忙旋的 50ms 里 B 一个字都打不出来（低优先级就绪也轮不到），B 的打印整体退到 A 阻塞之后——
**阻塞让出**的现场。同样的 ABAB 外观，B 的出线时刻差 50ms，这就是两种调度语义的可观测差异。

**对照组②（纯忙循环：每 tick 轮转的裸形态）**：去掉 `vTaskDelay`，两任务无限打印。此时两人永远就绪，
每拍 tick 都触发轮转——预期连续的 ABABAB，串口每行约 12 字符成为节流阀（见下节算术），每任务一行
周期 ≈ 1–2ms。另一个教学点藏在暗处：Idle（优先级 0 的兜底任务：没有别人可跑时由它占着 CPU，通常顺手执行节能
指令）从此饿死（starvation：永远分不到 CPU），而 **Vanilla 内核没有任何看门狗会报警**
——[[2026-08-26-freertos-deep-dive-ch24-debugging-tracing-pitfalls|FreeRTOS（廿四）]]24.6 节的对照：这场景
在 IDF 上 5 秒内必收 `IDLE0 (CPU 0)` 的 TWDT 告警（TWDT＝Task Watchdog Timer 任务看门狗：盯着「太久没跑到」的任务，并点名占着 CPU 的元凶），在本板上是无声的。

## 预期输出（待实测核销）

串口节流算术（预期间隔的来历）：115200bps（每秒传 115200 个 bit）8N1（8 数据位、无校验位、
1 停止位——三者拼起来每字符 10 bit）= 每字符 10bit ≈ 86.8µs；一行 `"A42 cy=36000123"`
≈ 13 字符 ≈ **1.13ms**；一对 200ms = 36,000,000 周期整。

主实验（数字为推导值，窗口取前 3 对）：

```text
A0 cy=18000123        ← 调度器启动后第一对，t0 未知，看差值
B0 cy=18001194        ← Δ(A0→B0) ≈ 1.13ms：B 紧随 A 阻塞让出，间隔=一行串口时间
A1 cy=36000123        ← Δ(B0→A1) ≈ 198.87ms：凑满一个 200ms 周期
B1 cy=36001194
A2 cy=54000123
B2 cy=54001194        ← 严格 ABAB，对周期 36,000,000 周期 ±1 tick
```

微秒间隔表（推导；判别只看**首拍**——忙旋让 A 的周期变成 251ms ≠ B 的 200ms，第二对起配对结构自然漂移，
那不是调度乱，是两个人的周期本来就不互质了）：

| 观测点          | 同优先级（时间片在场）           | B=优先级 1（阻塞让出在场）      |
| --------------- | -------------------------------- | ------------------------------- |
| A 首行 → B 首行 | ≈ 1.1ms（一行串口时间，≤1 tick） | ≈ 51ms（等 A 忙旋结束并阻塞）   |
| B 出线由谁决定  | tick 分支：同优先级就绪数 > 1    | 优先级：A 阻塞前 B 就绪也轮不到 |
| 首拍后          | B 周期 200ms，A 忙旋拍 251ms     | 同左，且 B 每拍还要等 A 让出    |

对照组②（连续忙轮转）：AB 交替、每任务行周期 ≈ 1–2ms（1ms 时间片与 1.13ms 串口行的相位差导致
偶尔一拍打两行或零行——具体相位待实测，这正是「时间片粒度 vs 输出粒度」的现场）。

| 维度         | 本板（Vanilla 单核）         | ESP32（IDF SMP）                  | Linux                                                                                |
| ------------ | ---------------------------- | --------------------------------- | ------------------------------------------------------------------------------------ |
| 同优先级语义 | 完美 RR（pxIndex 轮转）      | Best-Effort RR（按核独立检查）    | SCHED_RR 时间片；CFS 按权重（CFS＝完全公平调度器，Linux 默认——你的主场，一句话即可） |

**命令拆解：** `openocd` 会话里执行 `mdw 0xE000EDFC`（另两个地址同理）

| 部分         | 作用                                                                   |
| ------------ | ---------------------------------------------------------------------- |
| `mdw`        | memory dump word：按 32 位字读一个地址——openocd 里「读寄存器」的基本功 |

| `0xE0001000` | DWT_CTRL 地址；读回值的 bit0 应为 1，证明 CYCCNTENA 开了               |
| `0xE0001004` | CYCCNT 本体；**连读两次**，两次数值不同＝计数器真的在跑                |
