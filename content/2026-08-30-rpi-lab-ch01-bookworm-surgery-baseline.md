## 1. 为什么必须升级：给标本换固定液

这台树莓派 2020 年刷完 Buster 就没再动过。把它当 Linux 反向解剖课的标本，Buster 有三个硬伤
（Buster/Bookworm 分别是 Debian 10/12 的发行代号，Debian 历来用《玩具总动员》角色命名）：

| 维度      | Buster（现状，2020）             | Bookworm（目标）                             |
| --------- | -------------------------------- | -------------------------------------------- |
| 发行版    | Debian 10，LTS 支持 2024-06 已止 | Debian 12，apt 源活跃                        |
| 内核      | 4.19（上游 LTS 亦已止）          | 6.6（rpi-6.6.y 分支）                        |
| GPIO 生态 | sysfs 旧接口时代的库             | libgpiod / pinctrl / 设备树 overlay 现行体系 |

> 📖 **术语卡：sysfs GPIO（旧接口）**
> **是什么**：Linux 早年提供的「把每个 GPIO 当成文件」的接口——往 `/sys/class/gpio/gpio17/value` 写 `1` 点灯、写 `0` 熄灯。
> **为什么存在**：让用户态程序不写内核代码也能碰 GPIO，在 2000 年代算先进。
> **为什么被弃用**：没有所有权管理（谁都能写同一根线）、无法可靠处理输入事件，内核 4.8 起官方建议改用 libgpiod。
> ⚠️ 类比边界：网上的老教程满屏 `echo 17 > /sys/class/gpio/export`，本系列会解剖它但不推荐照抄——那是标本，不是处方。

> 📖 **术语卡：libgpiod（现行 GPIO 库）**
> **是什么**：Linux 官方新一代 GPIO 用户态库（`gpiod` = GPIO device），配套 `gpioset`/`gpiomon` 等命令行工具，是 ch03 的主角。
> **为什么存在**：补 sysfs 的两个洞——「先申请（request）独占一根线、用完释放」的所有权模型，以及可靠的边沿事件监听。
> **类比**：数据库连接池——先拿连接（申请）、用完归还（释放），而不是全世界裸抓同一个句柄。

> 📖 **术语卡：设备树（Device Tree, DT）与 overlay**
> **是什么**：描述「这块板上有什么硬件、各接在哪个总线地址、引脚复用成什么功能」的数据文件（编译后是 `.dtb`），启动时内核按它来认硬件。overlay 是不动原文件、在启动配置里追加启用的「补丁包」。
> **为什么存在**：同一个内核镜像要能跑上百种板子——硬件差异全部外置成数据，而不是写死进内核代码。
> **类比**：装修清单 + 变更单——房子（内核）不动，清单（DT）描述家具布局，变更单（overlay）临时加改。
> ⚠️ 类比边界：DT 在内核启动早期就被解析，之后的热插拔另有机制（后续章节）。

表中还有个 `pinctrl`（pin control）：内核管理引脚复用（一根物理脚当 GPIO 还是当 I2C/UART 用）的子系统；树莓派另提供了一个同名 `pinctrl` 命令行小工具，可随手查/改每根脚的当前状态，ch02 会用到。

教学上的理由更直接：本系列要解剖的是**现代内核的官僚体系**——threaded IRQ（中断处理线程化：硬中断只做急活、慢活丢给内核线程做，ch05 详释）、
gpiod 请求制（先申请后使用的所有权模型，见上文术语卡）、
6.6 的设备树生态。拿 4.19 做标本，解剖出来的器官是 2020 年的。

运维类比：这就是把一台跑了六年的生产机从 CentOS 7 迁到新 LTS——**新机部署 + 切换 + 旧机回滚**，
而不是原地 `do-release-upgrade` 跨三个大版本（那条路的依赖冲突排期不可控）。树莓派的「新机」
恰好是物理的：一张新 SD 卡。

## 2. 术前：SD 卡全卡备份（旧卡 = 回滚方案）

### 2.1 认卡纪律

dd 的第一定律：`of=` 写错盘，笔记本磁盘直接报废。动手前先认卡：

```bash
lsblk -o NAME,SIZE,MODEL,TRAN
# 认准读卡器的设备名（如 /dev/sdc：32GB、USB TRAN），以下以 /dev/sdc 为例
```

`/dev/sdc` 是**设备文件**（`/dev` 下的特殊文件，读写它就等于直接读写硬件本身），整卡一个设备文件，卡上的分区是 `sdc1`、`sdc2`——dd 操作的是前者。

**命令拆解：** `lsblk -o NAME,SIZE,MODEL,TRAN`

| 部分                      | 作用                                                               |
| ------------------------- | ------------------------------------------------------------------ |
| `lsblk`                   | list block devices：列出系统里所有块设备（盘/卡/分区）的树状清单   |
| `-o NAME,SIZE,MODEL,TRAN` | 只显示四列：设备名、容量、型号、传输总线（USB 读卡器会显示 `usb`） |
| （输出中的）`/dev/sdc`    | 目标：`TRAN=usb` 且容量等于卡容量的那条                            |

**你会看到**：笔记本自带磁盘（`nvme0n1` 或 `sda`）之外，多出一个 USB 总线、容量等于卡容量的设备。
**失败了先查**：读卡器没被识别（换个口/换个读卡器）、把带 `TRAN=sata/nvme` 的系统盘误认成卡——认错盘就是下一节 dd 的灾难现场。

### 2.2 dd 全卡镜像 + sha256 双记账

「全卡」而不是挂载拷文件：镜像要含分区表与启动分区，才能逐字节回滚
（分区表：卡开头记录「分了几个区、各在什么位置」的目录信息；启动分区：树莓派引导固件所在的第一个分区。挂载后拷文件只复制「文件内容」，分区表这类「磁盘格式本身」会丢掉）。

```bash
# 路线 A（磁盘空间够）：直写镜像文件，conv=fsync 确保落盘
sudo dd if=/dev/sdc of=~/rpi4b-buster-20260830.img bs=4M status=progress conv=fsync

# 路线 B（空间紧）：管道压缩（SD 卡大量空白区，压缩比很可观）
sudo dd if=/dev/sdc bs=4M status=progress | gzip -1 > ~/rpi4b-buster-20260830.img.gz

# 双记账：H_card 证明「镜像 = 卡」，H_file 证明「归档没烂」
sudo dd if=/dev/sdc bs=4M | sha256sum          # H_card（原始流哈希）
sha256sum ~/rpi4b-buster-20260830.img.gz       # H_file（归档文件哈希）
```

**命令拆解：** `sudo dd if=/dev/sdc of=~/rpi4b-buster-20260830.img bs=4M status=progress conv=fsync`（路线 A）

| 部分              | 作用                                                                     |
| ----------------- | ------------------------------------------------------------------------ |
| `dd`              | 裸拷贝：从设备/文件逐字节搬到另一个设备/文件，不理解分区语义（你的主场） |
| `if=/dev/sdc`     | input file = 整张卡（分区表 + 全部分区，一个字节不落）                   |
| `of=~/...img`     | output file = 家目录下的镜像文件                                         |
| `bs=4M`           | block size：每次搬 4MB 大块（默认 512 字节慢一个数量级）                 |
| `status=progress` | 搬运中实时显示已拷字节数（默认只在结束时报总数）                         |
| `conv=fsync`      | 收尾前把数据真正物理写进磁盘再退出（否则可能只停在内存页缓存里）         |

**你会看到**：进度数字一路涨到卡的整容量（32GB 卡约 32GB），家目录出现一个等大的 img 文件。
**失败了先查**：`if`/`of` 写反（把系统盘当源、甚至往系统盘写 = 笔记本数据报废）；卡被桌面环境自动挂载（先 `umount` 再 dd）。

**命令拆解：** `sudo dd if=/dev/sdc bs=4M status=progress | gzip -1 > ~/...img.gz`（路线 B）

| 部分            | 作用                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------- |
| `\| gzip -1`    | 管道把 dd 的原始输出直接喂给 gzip；`-1` = 最快档压缩（SD 卡大量空白区是全零，照样压得很小） |
| `> ~/...img.gz` | 把压缩流重定向进归档文件（不必先落 32GB 再压，不占双倍空间）                                |

**命令拆解：** 双记账两条

| 命令                                     | 作用                                                              |
| ---------------------------------------- | ----------------------------------------------------------------- |
| `sudo dd if=/dev/sdc bs=4M \| sha256sum` | 从卡裸读全部字节流、不落盘直接算哈希 = H_card（「这张卡」的指纹） |
| `sha256sum ~/...img.gz`                  | 对归档文件算哈希 = H_file（「这份备份」的指纹）                   |

（sha256：把任意长数据算成 256 位指纹的单向哈希函数，输入变一位则指纹面目全非——你的主场。日后回写时可再算一次流哈希与 H_card 对账，证明「回写 = 原卡」。）

回滚有两条路，优先级从高到低：

1. **物理换卡**（首选）：旧卡拔下来原样收进防静电袋，Bookworm 刷在**另一张卡**上。回滚 = 换回旧卡，零操作风险。
2. **镜像回写**（第二道保险）：`gunzip -c rpi4b-buster-20260830.img.gz | sudo dd of=/dev/sdc bs=4M status=progress conv=fsync`，回写后用 H_card 对账。

## 3. 全新刷 Bookworm：Imager 的镜像定制

用 Raspberry Pi Imager（树莓派官方图形界烧录工具：选系统 → 选目标卡 → 写入，三步走）刷**另一张卡**，选型与预配置如下：

| 项       | 选择                                       | 理由                                                                                    |
| -------- | ------------------------------------------ | --------------------------------------------------------------------------------------- |
| 系统     | Raspberry Pi OS **Lite (64-bit)** Bookworm | 服务器标本：无 GUI，省下桌面占用的内存与排障噪音                                        |
| 写入目标 | 新 SD 卡                                   | 旧卡是回滚资产，不动                                                                    |
| 主机名   | raspberrypi                                | 沿用 mDNS 名 raspberrypi.local（mDNS：局域网组播名字解析，`.local` 后缀即它——你的主场） |

Imager 的「OS 定制」（新版是烧录前的向导按钮，旧版快捷键 Ctrl+Shift+X——入口形态以装好的
Imager 版本为准）是 headless 的关键：

> 📖 **术语卡：headless（无头运行）**
> **是什么**：设备不接显示器（「头」）和键盘，从第一次开机就全靠网络远程管理。
> **为什么存在**：Lite 版系统本就没有桌面，接屏幕只是临时手段；预配置让系统**第一次启动**就带着 SSH、账号和密钥，「开箱即远程」。
> **类比**：机房里的服务器从来不上 KVM——你的主场。

- **用户名/密码必须显式设置**。Bookworm 系镜像已**没有默认 pi/raspberry 账户**（2022-04 起的
  安全整改）——这是与 Buster 时代刷机流程最大的差异，不设置就只能接屏幕走首启向导。
- 服务页：启用 SSH，认证方式选「公钥」，把笔记本的 **ed25519 公钥**注入——第一次连接即免密
  （ed25519：现代椭圆曲线签名算法，密钥短、验签快——你的主场）。
- WiFi：跳过。本实验室走网线直连笔记本（NetworkManager shared，笔记本是 10.42.0.1，树莓派
  从 10.42.0.0/24 DHCP 取址），不引入无线变量
  （NM shared：笔记本把网口变成小路由器——DHCP 发地址 + NAT 转发——你的主场）。
- locale/时区按笔记本本机设（locale：语言、编码、时区等地域设置的一揽子打包）。

写入完成后：新卡上板、网线插笔记本、上电。首次引导扩容根分区需要一两分钟
（扩容根分区：镜像里的根分区在第一次开机时自动扩到整卡容量，开机慢这一两分钟属正常）。

## 4. 恢复既定访问：SSH 8082 + 公钥

### 4.1 known_hosts 清账

重刷系统 = 主机密钥全部新生成，旧记录会触发 `REMOTE HOST IDENTIFICATION HAS CHANGED`
（主机密钥：SSH 服务端的身份指纹密钥对，重刷后全部换新；known_hosts：客户端记「见过的主机指纹」的清单，指纹对不上就拉响上面的警报——你的主场）。
本机历史上也因主机密钥损坏走过重生成流程，恢复动作相同：

```bash
# 注意非标端口下 -R 的写法："[host]:port" 带方括号，否则匹配不到
ssh-keygen -R "[raspberrypi.local]:8082"
ssh-keygen -R "[10.42.0.152]:8082"   # 以实际 DHCP 地址为准
```

**命令拆解：** `ssh-keygen -R "[raspberrypi.local]:8082"`

| 部分            | 作用                                                          |
| --------------- | ------------------------------------------------------------- |
| `ssh-keygen -R` | remove：从 known_hosts 里删掉指定主机的旧指纹记录             |
| `"[host]:port"` | 非标端口的记法——必须带引号和方括号；写成 `host:port` 匹配不到 |
| 两条各删一次    | 按 mDNS 名一条、按 DHCP 地址一条——同一台机两条记录都要清      |

**你会看到**：输出 `Host [raspberrypi.local]:8082 found: line N ... Original contents retained as ...`。
**失败了先查**：还是报警 → 大概率残留的是另一条名字（IP/hostname）的记录，逐个清。

### 4.2 改端口 8082：drop-in 与两个新式坑

drop-in（「只写改动项」的小配置文件，放进 `sshd_config.d/` 目录、被主配置 Include 进来叠在默认值之上——你的主场）。先经默认 22 口连上（`ssh pi@raspberrypi.local`），再改端口：

```bash
# /etc/ssh/sshd_config.d/10-port8082.conf
sudo tee /etc/ssh/sshd_config.d/10-port8082.conf <<< "Port 8082"
sudo systemctl restart ssh
ss -tlnp | grep 8082    # 新端口在听，再继续
```

**命令拆解：** 写 drop-in → 重启 → 验证三连

| 命令                                | 作用                                                                                                                                       |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `sudo tee 文件路径 <<< "Port 8082"` | `<<<` 把字符串喂给 tee 的标准输入；tee 既写入文件又回显（绕开 `sudo echo ... >` 的重定向不经 sudo 坑）；文件名前缀 `10-` 排定 Include 顺序 |
| `sudo systemctl restart ssh`        | 重启 ssh 服务，让新配置生效                                                                                                                |
| `ss -tlnp \| grep 8082`             | socket statistics：列出 TCP（`-t`）监听（`-l`）端口，数字形式（`-n`）、带进程（`-p`），grep 确认 8082 在听                                 |

**你会看到**：`LISTEN 0 ... *:8082 ... users:(("sshd",...))` 一行。
**失败了先查**：没有输出——sshd 没起或端口没生效，`systemctl status ssh` 看报错。

两个坑要写进 runbook：

1. **sshd 配置「先到先得」**：同一关键字以**第一次出现**为准，而 sshd_config 开头就
   `Include sshd_config.d/*.conf`——drop-in 会压过主文件里的同名配置。放 drop-in 是稳妥路线。
2. **套接字激活（待核对）**：部分新版发行版的 ssh 改由 `ssh.socket` 激活（套接字激活：systemd
   先占住端口监听，有连接进来才拉起服务进程——此时监听端口归 systemd 管，改 sshd_config 的
   Port 无效，要改 socket 单元或禁用 socket 改回 service——你的主场），先查：
   `systemctl is-enabled ssh.socket ssh`。RPi OS Bookworm 是否启用待实测。

**纪律：验证通过前不退出当前会话。** 端口改错的经典结局是把唯一的门锁上。

### 4.3 防火墙两侧对账

- 树莓派侧：RPi OS 默认不带活跃防火墙规则；若日后装了 ufw/nftables（用户态防火墙前端/内核包过滤框架——你的主场），放行 8082 入站。
- 笔记本侧：NM 的 shared 连接自动做 10.42.0.0/24 的 NAT（网络地址转换——你的主场）；Fedora 的 firewalld（Fedora 默认的防火墙服务，zone 分组管理规则——你的主场）对 shared zone
  默认放行本网段。SSH 连不上先 `ping 10.42.0.x` 分层定位（链路 → 地址 → 端口）。

### 4.4 authorized_keys 权限链

Imager 注入的公钥落在 `~/.ssh/authorized_keys`。公钥登录**静默失效**（回退问密码）十有八九是
权限链问题——sshd 的 StrictModes 会拒绝「太开放」的家（StrictModes：sshd 的安全自检开关，发现家目录/密钥文件权限过宽即拒用密钥，且不提示原因——你的主场）：

```bash
chmod 755 /home/pi          # 家目录不能组可写
chmod 700 /home/pi/.ssh
chmod 600 /home/pi/.ssh/authorized_keys
chown -R pi:pi /home/pi/.ssh
```

**命令拆解：** 权限链三连 + 属主归位

| 命令                               | 作用                                                       |
| ---------------------------------- | ---------------------------------------------------------- |
| `chmod 755 /home/pi`               | 家目录：本人全权、他人只读可进——「组可写」正是被拒的雷     |
| `chmod 700 ~/.ssh`                 | .ssh 目录仅本人可进                                        |
| `chmod 600 ~/.ssh/authorized_keys` | 公钥文件仅本人可读写                                       |
| `chown -R pi:pi ~/.ssh`            | 递归把属主/属组改回 pi（属主不是本人同样触发 StrictModes） |

最终验证（免密 + NOPASSWD sudo 一次过；NOPASSWD：sudoers 里允许该用户 sudo 免输密码——你的主场）：

```bash
ssh -p 8082 pi@raspberrypi.local 'uname -r && sudo -n true && echo NOPASSWD-OK'
```

**命令拆解：** `ssh -p 8082 pi@raspberrypi.local 'uname -r && sudo -n true && echo NOPASSWD-OK'`

| 部分               | 作用                                                                                                                 |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `-p 8082`          | 指定目标端口（默认 22）                                                                                              |
| `'...'` 内的命令串 | 远程依次执行：内核版本；`sudo -n`（non-interactive，不弹密码，NOPASSWD 没配则直接失败）空跑 `true`；都成功则打印标记 |
| 全程无密码提示     | 公钥免密 + sudo 免密**同时**达标的外在证据                                                                           |

**你会看到**：一行 `6.6.x-v8...` 加一行 `NOPASSWD-OK`，中间不问任何密码。

## 5. NTP 校时：无 RTC 的历史坑

NTP（Network Time Protocol，网络时间协议：向时间源对钟——你的主场）。

树莓派没有 RTC，断电即失忆——时钟回到固件时代，TLS 证书校验（证书有效期依赖「现在几点」——你的主场）、git、make 时间戳全部崩坏。
这是本实验室已踩过并记录在案的坑，规约是**上电第一件事校时**。裸机无所谓绝对时间
（SysTick：Cortex-M 内核自带的 24 位递减计数器，裸机延时/走时全靠它，从 0 数起即可），Linux 用户态生态强依赖墙钟——这是同一个问题在两个世界的不同价格。

> 📖 **术语卡：RTC（Real-Time Clock，实时时钟）**
> **是什么**：主板上独立的走时芯片 + 纽扣电池，整机断电后仍继续数秒；开机时操作系统从它那里读出「现在几点」。
> **为什么树莓派没有**：成本与定位——4B 主板没焊 RTC 芯片（官方假设设备联网，用网络校时补位；高配版 CM4 可外接）。
> **后果**：每次断电，时钟归零回到固件时代，所有依赖绝对时间的软件集体失灵——所以要靠 NTP 每次上电重新对表。

树莓派侧（systemd-timesyncd 指向笔记本；timesyncd：systemd 自带的轻量 NTP 客户端，chrony：Fedora 侧常用的全功能 NTP 实现——你的主场）：

```bash
# /etc/systemd/timesyncd.conf
[Time]
NTP=10.42.0.1

sudo systemctl restart systemd-timesyncd
timedatectl set-ntp true
```

笔记本侧（Fedora chrony 放行该网段）：`allow 10.42.0.0/24` 加进 chrony 配置后
`sudo systemctl restart chronyd`。

应急通道（NTP 抖动时手工注入笔记本时间）：

```bash
ssh -p 8082 pi@raspberrypi.local "sudo date -s @$(( $(date +%s) + 1 ))"
```

**命令拆解：** `ssh -p 8082 pi@raspberrypi.local "sudo date -s @$(( $(date +%s) + 1 ))"`

| 部分                 | 作用                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| `$(date +%s)`        | 外层是**双引号**，所以它先在**笔记本本地**展开：当前时间的 Unix 秒数 |
| `$(( ... + 1 ))`     | 算术展开：加一秒，粗略补偿 ssh 往返耗时                              |
| `sudo date -s @秒数` | 远程执行：把树莓派系统时间设为该秒数（`@` 前缀 = 按 Unix 秒数设时）  |

**你会看到**：无输出的命令返回后，树莓派 `date` 显示与笔记本同刻。

## 6. 实验室基线规约（一次固化，全系列引用）

| 规约       | 内容                                                                        |
| ---------- | --------------------------------------------------------------------------- |
| 共地       | **任何跨板信号线连接前，先把两板 GND 相连**；不共地的「信号」是天线不是数据 |
| 电平红线   | BCM2711 GPIO **非 5V 容忍**，3.3V 逻辑；任何 5V 信号不得接入                |
| 直连白名单 | RPi / F429 / ESP32 三块板均 3.3V 逻辑，信号线可直连                         |
| 测量纪律   | 万用表/仪器表笔先共地，再碰信号点                                           |
| 装备       | 杜邦线 + LED + 330Ω 电阻小包（~¥10）；万用表建议（~¥50）                    |

> 📖 **术语卡：BCM2711**
> **是什么**：树莓派 4B 板上的主控 SoC（System on Chip：把 CPU、GPU、内存控制器、GPIO 控制器等封进一颗芯片），博通（Broadcom）出品。
> **为什么重要**：本系列解剖的所有 GPIO 寄存器（GPFSEL/GPSET/GPCLR…，ch02 登场）都是这颗芯片的数据手册定义的；名字里的 BCM 就是 Broadcom 的缩写——GPIO「BCM 编号」即按它的引脚序号。
> **类比**：相当于 F429 板上那颗 STM32F429 主芯片——只是这颗上面跑的是完整 Linux。

> 📖 **术语卡：共地（Common Ground）**
> **是什么**：两块板交换信号前，先把双方的 GND（ground，0V 参考点）用一根线直接连通。
> **为什么存在**：电压没有绝对值，只有「相对谁」的差。A 板的 3.3V 是相对 A 板 GND 说的；不共地，B 板拿自己的 GND 当尺子去量 A 板的信号，读数毫无意义。
> **类比**：楼层对话——「我在三楼」必须先约定从哪个地面起算；两栋楼不共享地面，「三楼」无从对起。
> ⚠️ 类比边界：不共地轻则读数乱跳，重则电流改走信号线找回路、烧端口——这已经不是「数据错了」，是「事故」。

> 📖 **术语卡：逻辑电平（Logic Level）与「非 5V 容忍」**
> **是什么**：数字信号用电压区间表示 1 和 0。3.3V 逻辑里，高（1）≈ 3.3V、低（0）≈ 0V，中间存在无定义的模糊带。「非 5V 容忍（not 5V-tolerant）」= 引脚能承受的电压上限就是 3.3V 档，喂 5V 会损坏芯片。
> **为什么是红线**：BCM2711 的 GPIO 是 3.3V 逻辑且非 5V 容忍——5V 一经接入，轻则该引脚永久失灵，重则整颗 SoC 报废，板上没有任何电路替你「把 5V 翻译下来」。
> **类比**：电器铭牌电压——220V 设备插 380V 不是「凑合能用」，是烧。

> 📖 **术语卡：BCM 编号 vs 物理引脚号**
> **是什么**：BCM 编号按主控芯片 GPIO 控制器的引脚序号算（BCM2711 共 58 根，GPIO0~GPIO57，40-pin 头只引出其中一部分）；物理引脚号按 40-pin 排针从 1 数到 40 的机械位置算。两套互不相干：GPIO17 在物理第 11 脚，GPIO2 反而在物理第 3 脚。
> **为什么是坑**：老教程、命令行工具、各种库混用两套编号（还有第三套 WiringPi 编号），同一根线能冒出三个名字。
> **保命法**：接线前对照 pinout.xyz 板图核一遍；本系列统一用 BCM 编号，物理号只在插线时用。

装备行的两个词：杜邦线（两端带插针/插孔的彩色连接线，面包板与排针之间随手插拔）；LED（发光二极管，长脚为正极）串联的 330Ω 是**限流电阻**（把电流压到 LED 安全值，防止 GPIO 引脚过流损坏）。

LED 标准接线（ch02 起所有点灯实验复用）：**GPIO17**（BCM 编号 17 = 40-pin 头物理引脚 11，物理
引脚号以 pinout.xyz 板图核对——BCM 编号与物理编号是两套体系，混用是新手第一个坑）→ 330Ω →
LED 正极 → LED 负极 → GND（物理引脚 9）。

## 与 F429/裸机对照

| 维度     | F429 裸机                                                                  | RPi Linux                                    |
| -------- | -------------------------------------------------------------------------- | -------------------------------------------- |
| 系统载体 | 片内 flash，换系统 = openocd 烧录                                          | SD 卡外置，换系统 = 换卡/重刷镜像            |
| 回滚     | 旧固件 .bin 留在笔记本，重烧即回                                           | 旧卡物理保留（秒级回滚），另有 dd 镜像双保险 |
| 救砖     | BOOT0 + ROM ISP（[[2026-08-30-stm32f429-brick-rescue-debug-story\|序章]]） | 换卡即救，启动介质与实验介质分离             |
| 绝对时间 | 裸机不需要，tick 从 0 数                                                   | 用户态强依赖，无 RTC 必须网络校时            |

对照表生词速查：openocd（开源片上调试代理，经调试器走 SWD 烧写片内 flash）；BOOT0（STM32 的启动模式选择引脚，拉高后不从 flash 启动、改走芯片 ROM 内置的串口烧录程序，即 ROM ISP——救砖通道，详见序章）；掉电一致性（写入进行到一半断电，文件系统是否损坏的问题——你的主场）。

启动介质外置是树莓派的「容错红利」：F429 首烧即砖要用 BOOT0 跳线救（序章实录），树莓派把
固件和 SD 卡插槽分离，最坏情况就是换卡。代价是 SD 卡的寿命与掉电一致性——服务器标本的
_known issue_，不重要。
