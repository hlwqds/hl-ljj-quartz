## 8.1 为什么 BLE 调试也要懂射频：空口证据链的天花板

第一章的分层取证里，L2 空口抓包几乎无所不能——但它有一个结构性天花板：**嗅探器只能看见「到达了嗅探器」的包**。设备发了一帧、对面没收到、链路超时——这中间发生了什么（发射功率不足？灵敏度边缘？被干扰淹没？），空口抓包无法作证，因为它展示的是「从我的位置看，包发出来了」，不是「从对端看，包到没到」。第七章的掉线取证反复遇到这一步：错误码 0x08、无告别帧、重传密集——**链路层只能告诉你「没了」，射频层才告诉你「为什么没」**。

```text
证据链的天花板在哪里
 L3 主机栈（btmon）：「链路超时了」        ← 常规排查的终点
 L2 空口（嗅探器）：「包发过、对面没 ACK」 ← 更细，仍停在现象
 L4 射频（本章）：  「为什么对面收不到」    ← 功率/灵敏度/频偏/干扰/天线
```

三层证据能回答与不能回答的，一张表钉死（排查时按列自查，别拿 L2 的结论硬答 L4 的问题）：

| 层        | 能回答                           | 不能回答                         | 工具                       |
| --------- | -------------------------------- | -------------------------------- | -------------------------- |
| L3 主机栈 | 断连错误码、参数生效值、发起侧   | 包为什么丢、信号为什么差         | btmon/btsnoop/设备栈日志   |
| L2 空口   | 告别帧有无、重传密度、事件完整性 | 未到嗅探器的包；对端实际接收质量 | nRF Sniffer + Wireshark    |
| L4 射频   | 功率/频偏/灵敏度/占用是否达标    | 协议层行为（回 L2/L3）           | 仪器（8.3）或降级法（8.6） |

什么时候该下钻到本章：0x08 成簇 + 位置/时段相关性（第七章已判）、认证预测试 fail（第十一章）、吞吐/距离不达标且主机栈无异常。在此之前，**改板子永远放最后**的纪律不变——绝大多数「信号差」的投诉最终归因在软件参数与结构设计，不是射频芯片坏了。

与 WiFi 系列的关系：分层思想、仪器方法、指标体系全部同源（[[wifi-hw-debug-ch07-phy-measurements|WiFi 调试（七）]] 讲过的频谱仪/综测仪手法本章直接引用不重教）；区别在 BLE 的指标限值与调参口径完全是一张新表。dBm/链路预算的数学基础见 [[ch03-decibel-family|射频入门（三）]]，灵敏度与噪声的机理见 [[ch05-rx-chain-sensitivity|射频入门（五）]]。

## 8.2 物理层速览：GFSK 与四种 PHY

### 8.2.1 调制与信道（Core Spec 口径）

BLE 用 **GFSK**（高斯频移键控）：带宽-符号积 BT=0.5，调制指数 0.45~0.55（声明「稳定调制指数」能力的收窄到 0.495~0.505）；1 Msym/s 档最小频偏 ≥185 kHz，2 Msym/s 档 ≥370 kHz；符号定时精度 ±50 ppm。40 个 2 MHz 射频信道铺满 2402~2480 MHz，其中 3 个广播信道（2402/2426/2480 MHz，避开 WiFi 主信道中心）+ 37 个数据信道——广播信道的取舍逻辑在 [[ble-debug-ch04-advertising-packets|第四章]] 讲过。

### 8.2.2 四种 PHY：速率与灵敏度的交换表

| PHY           | 数据速率 | 灵敏度下限（Core Spec 要求） | 典型芯片实测量级（datasheet 口径） | 用途                       |
| ------------- | -------- | ---------------------------- | ---------------------------------- | -------------------------- |
| LE 1M（必选） | 1 Mb/s   | ≤ -70 dBm                    | -90 ~ -97 dBm 一带                 | 兼容底座，全设备必支持     |
| LE 2M         | 2 Mb/s   | ≤ -70 dBm                    | 比 1M 差 2~4 dB 量级               | 吞吐/省电（缩短 radio on） |
| LE Coded S=2  | 500 kb/s | ≤ -75 dBm                    | 1M 基础上再抬若干 dB               | 距离换速率的折中           |
| LE Coded S=8  | 125 kb/s | ≤ -82 dBm                    | 最远档，比 1M 抬 6~10 dB 量级      | 长距/电池供电深覆盖        |

读表三句话。其一，**规格下限与芯片实测量级差着 20 dB 以上**：Core Spec 只要求 -70 dBm 及格线，主流 SoC 实测普遍到 -90~-100 dBm（具体值查所用芯片 datasheet，不虚构）——所以「规格说 -70，为什么 -80 就断」这类问题要看芯片手册，不看规格书。其二，Coded PHY 的速率代价是 1/2（S=2）与 1/8（S=8）：编码换灵敏度，**距离换速率**，反向使用就是第九章吞吐优化的约束项。其三，2M/Coded 都是连接期协商的（LL 层 PHY 更新过程），广播始终 1M——所以「广播收得到、连接后断」也可能有 PHY 选择的份。

厂商宣传的「4 倍距离」要用链路预算口径翻译：Coded S=8 相对 1M 的灵敏度改善是 12 dB 量级（规格下限差与芯片实测差都印证这个量级），按自由空间 6 dB/倍距换算约 4 倍距离——**理想空间里的数字**；室内每堵墙吃 8~15 dB（8.4 的表），宣传值要按自家环境打折。

### 8.2.3 PHY 的调试视角：连着的链路到底跑在哪个 PHY 上

排查吞吐与距离问题时，第一件事是确认**当前连接实际生效的 PHY**——它不等于芯片能力，等于两端协商结果：

| 取证位置     | 能看到什么                                                               |
| ------------ | ------------------------------------------------------------------------ |
| 空口抓包     | LL_PHY_REQ / LL_PHY_UPDATE_IND 过程与协商结果（nRF Sniffer + Wireshark） |
| btmon（HCI） | LE PHY Update Complete 事件；主动查询用 LE Read PHY 命令                 |
| 手机端       | nRF Connect 连接详情里的 PHY 字段（App 展示口径）                        |
| 设备端       | 协议栈 API/日志（如 NimBLE 的连接 PHY 状态，实现口径）                   |

三个常见坑。其一，**协商失败静默回落**：一端不支持/未使能 2M 时链路默默留在 1M，无报错——「换了支持 2M 的新板子怎么没变快」先查协商结果再谈吞吐。其二，**DTSI/SDK 配置与运行时请求是两回事**：编译进了 2M 支持不等于连接里用了 2M，要发起 PHY 更新过程。其三，**Coded PHY 的对端支持极不普及**：手机侧普遍不支持 Coded，长距设计要落在一对专用设备之间（如设备↔网关），别把「规格支持」当「可用」。

## 8.3 射频指标四件套：对账清单

四件套的仪器测量方法（频谱仪设置、综测仪流程、OTA 测试）与 WiFi 章完全同源，见 [[wifi-hw-debug-ch07-phy-measurements|WiFi 调试（七）]]；本节给 BLE 自己的**限值口径**与**现场判读**，一一对应。

### 1）发射功率

| 项            | 口径                                                                                                                             |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 规格范围      | 最大发射功率必须落在 0.01 mW（-20 dBm）~ 100 mW（+20 dBm）之间（Core Spec 口径），且不得超当地法规                               |
| 功率等级      | Class 1（>10~20 dBm）/ 1.5（>4~10）/ 2（>0~4）/ 3（-20~0 dBm）（Core Spec Table 口径）                                           |
| 典型 SoC 档位 | -20 ~ +8 dBm 可编程分档为主流（量级综述口径，具体查 datasheet）                                                                  |
| 现场判读      | 广播包 TxPower 字段只是声明值；真值要 OTA/传导测。手机不做功率控制的老连接，近场过强反而让对方接收机饱和——**越近越断**的一种解释 |

Core 5.2 起有 LE Power Control Request：两端可互相请求调整发射功率，链路恶化时先抬功率、空闲时降回去——排查「忽远忽近」类问题前先确认双方是否启用了该特性（能力位在 LL 层特性交换里可见）。功率上不去的硬件侧排查路径：PA 供电、匹配网络、天线净空——[[ch12-power-supply|射频入门（十二）]] 与 [[ch13-pcb-layout|射频入门（十三）]] 的既有内容，不重复。

### 2）频偏与漂移（Frequency Accuracy / Drift）

| 限值             | 数值（Core Spec 口径）           | 现场病灶指向                                                    |
| ---------------- | -------------------------------- | --------------------------------------------------------------- |
| 包内中心频偏上限 | ≤ ±150 kHz（初始频偏与漂移合计） | 晶体频差过大/校准缺失——[[ch11-crystal-clock\|射频入门（十一）]] |
| 包内漂移         | < 50 kHz                         | 频率综合器/锁相环问题；长包（DLE 251）更易暴露                  |
| 漂移速率         | < 400 Hz/µs                      | 同上                                                            |
| 符号定时         | ±50 ppm                          | 晶体精度等级不够（常与频偏问题同源）                            |

频偏超限的表现极具迷惑性：近距离一切正常（信噪比余量掩盖解调损失），远场或干扰环境里误码率抬升、重传变多、断连率升高。判别路径：先排除干扰（7.4.2），再怀疑频偏——低成本验证是「温循测试」：温度变化时晶体频差漂移，问题随温度复现/消失是强指向。晶体选型与布局的完整展开在 [[ch11-crystal-clock|射频入门（十一）：晶振与时钟]]。

### 3）灵敏度（Sensitivity）

规格下限 8.2.2 的表已给；现场更关心**实测判据**与「最低可用 RSSI」：

| 判据           | 口径                                                                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 实验室判据     | 信号源以 -70 dBm（未编码 PHY）注入，BER ≤ 0.1% 必须满足（Core Spec 口径）；Direct Test Mode 可让被测件进测试态收发测试包——预测试用法在第十一章 |
| 芯片实测口径   | 以 datasheet 典型值为准（主流 -90~-100 dBm 量级）                                                                                              |
| 现场代理判据   | 链路最低可用 RSSI ≈ 芯片灵敏度 + 6~10 dB 工程余量（经验口径）；余量内别谈「信号差」                                                            |
| 灵敏度劣化信号 | 同一位置 RSSI 不变但重传/断连率上升 → 灵敏度在劣化（干扰、频偏、供电噪声都在嫌疑列表）                                                         |

「灵敏度劣化」三条通路的现场鉴别（同一症状，三种病根）：

| 通路         | 机理                                   | 鉴别指纹                                                                 |
| ------------ | -------------------------------------- | ------------------------------------------------------------------------ |
| 同频干扰抬噪 | 干扰把噪底抬高，等效灵敏度变差         | 时段相关性 + 频谱占用（8.5 对照）                                        |
| 频偏侵蚀解调 | 载波偏差吃掉解调余量                   | 温度相关性；近距离正常远场劣化                                           |
| 供电噪声串扰 | 电源纹波调制射频（常见于 DCDC 配置差） | 与负载/外设动作相关；纹波实测（[[ch12-power-supply\|射频入门（十二）]]） |

### 4）邻道与杂散（Spurious Emissions）

Core Spec 对带内频谱模板的规定（1M 档口径）：偏离载波 2 MHz 的 1 MHz 邻道功率 ≤ -20 dBm，≥3 MHz ≤ -30 dBm（允许三个 1 MHz 窄带例外 ≤ -20 dBm）。它的意义在**认证**而不是日常连通性：邻道/杂散超标通常能连能用，但过不了认证预测试——测试项地图与常见 fail 在 [[ble-debug-ch11-qualification-pretest|第十一章：认证与预测试]] 展开，法规背景在 [[ch17-certification-regulations|射频入门（十七）]]，预测试方法与 WiFi 章同源（[[wifi-hw-debug-ch11-precompliance|WiFi 调试（十一）]]）。现场只需记住一条关联：**「能用但认证 fail」的射频问题十有八九落在这件套上**，日常排障不必盯它。

### 5）四件套速查总表

| 指标      | 规格口径（Core Spec）                     | 芯片/器件口径             | 劣化症状                    | 仪器依赖 |
| --------- | ----------------------------------------- | ------------------------- | --------------------------- | -------- |
| 发射功率  | -20 ~ +20 dBm 硬范围；分级别管理          | datasheet 档位与精度      | 远场断、近场饱和（过强）    | 中       |
| 频偏/漂移 | 包内 ±150 kHz / 漂移 50 kHz / 400 Hz·µs⁻¹ | 晶体精度 ±10~±50 ppm 一带 | 远场误码升、温变敏感        | 高       |
| 灵敏度    | 未编码 ≤ -70 dBm 及格线                   | datasheet 典型 -90~-100   | RSSI 不差却重传升；距离缩水 | 高       |
| 邻道/杂散 | 带内模板 -20/-30 dBm 分频偏段             | 匹配/滤波器性能           | 连通性正常，认证 fail       | 高       |

仪器依赖「中/高」的含义：手机 + 开发板能做相对测量（8.6 降级法），但「指标合不合规」的定量结论只能来自仪器——这是第十一章预测试的地盘。

## 8.4 链路预算实务：把「信号差」变成一张账

### 8.4.1 一条公式 + 一张表

```text
接收 RSSI = TX 功率 + TX 天线增益 − 路径损耗 − 穿透/遮挡损耗 + RX 天线增益
链路预算 = TX 功率 − RX 灵敏度                          （双向取差值小的一侧）
工程余量 = 链路预算 − 实际路径损耗 − 穿透遮挡           （建议 ≥ 10~15 dB，经验口径）
```

自由空间路径损耗在 2.4 GHz 的好记值：1 m ≈ 40 dB，距离每翻倍 +6 dB（10 m ≈ 60 dB，100 m ≈ 80 dB）。室内远比自由空间恶劣，穿透损耗经验表（**经验口径**，随材料与入射角浮动大）：

| 障碍         | 损耗量级（经验口径） | 备注                         |
| ------------ | -------------------- | ---------------------------- |
| 木门/石膏板  | 3~8 dB               | 普通住宅的主力衰减           |
| 砖墙         | 8~15 dB              | 承重与非承重差异明显         |
| 混凝土承重墙 | 15~25 dB             | 一堵就吃掉大半预算           |
| 人体         | 10~20 dB             | 第七章「口袋断」主角         |
| 金属柜/电梯  | >25 dB（近乎屏蔽）   | 别做覆盖预算，做自动重连策略 |

### 8.4.2 一笔示意账（教学计算示意）

```text
传感器（TX +4 dBm，板载天线按 0 dBi 计）↔ 手机（灵敏度按 -95 dBm 量级，datasheet 口径）
链路预算 = 4 − (−95) = 99 dB
自由空间 10 m 路径损耗 60 dB → 理论余量 39 dB
叠加：一堵砖墙 12 dB + 人体转角遮挡 15 dB → 余量只剩 12 dB，仍可用
再叠一口金属配电箱（25 dB）→ 余量 -13 dB → 断连（第七章 0x08 无告别帧形态）
```

用法不是算准，而是**判断改动方向**：余量还厚时别动硬件，先查软件；余量为负时，抬 TX 档位、挪位置、换天线方向、减遮挡，按「每改一个变量重测一次」的纪律逐项验证（与 [[wifi-hw-debug-ch07-phy-measurements|WiFi 调试（七）]] 的对照纪律相同）。天线类型与选型的展开在 [[ch06-antenna-basics|射频入门（六）：天线基础]]。

### 8.4.3 三个常见误判

| 误判场景               | 真相多半是                                            | 验证动作                                |
| ---------------------- | ----------------------------------------------------- | --------------------------------------- |
| 「RSSI -50 还断连」    | 干扰/频偏/共存——RSSI 只描述信号强度，不描述信噪比质量 | 时段复测 + 抓包重传统计（第七章 7.4.2） |
| 「加满功率就不断了」   | 症状被掩盖：干扰下满功率互怼，邻居更差、电池更亏      | 功率档位对照实验 + 邻道占用观察         |
| 「某个方向永远连不上」 | 天线方向图凹陷：板载天线的方向性不是球型              | 旋转产品定向复测 RSSI（8.6 梯度法变体） |

## 8.5 2.4G 共存：AFH 是 BLE 的自救，不是 WiFi 的让路

### 8.5.1 BLE 信道与 WiFi 信道的重叠地图

WiFi 三个 2.4G 主信道各占约 20 MHz（±11 MHz 量级），与 BLE 37 个数据信道的重叠关系（**近似示意**，按中心频率对齐估算）：

| WiFi 信道  | 大致重叠的 BLE 数据信道（近似示意） | 缓冲带          |
| ---------- | ----------------------------------- | --------------- |
| 1（2412）  | 0–9                                 | 信道 10 附近    |
| 6（2437）  | 11–22                               | 信道 23/24 附近 |
| 11（2462） | 25–35                               | 信道 36 附近    |

三个 WiFi 信道之间的空隙里，BLE 的信道 9/10、23/24 是相对干净的缓冲带。WiFi 侧怎么看待蓝牙占用、怎么用扫描统计确认拥挤，互链 [[wifi-hw-debug-ch06-throughput-debugging|WiFi 调试（六）]]；两种 2.4G 设备互相干扰的完整机理在 [[ch14-interference-coexistence|射频入门（十四）]]。

### 8.5.2 AFH：信道地图的机制与取证

AFH（自适应跳频）的机制一句话：**连接的两端共同维护一张「哪些数据信道可用」的位图（channel map，5 字节，37 位）**，跳频只在 map 内的信道上进行。谁改地图：central 基于自身的信道质量评估（丢包/CRC 统计，实现口径）发起更新，通过 LL_CONTROL 层的 **LL_CHANNEL_MAP_IND** 下发，携带新地图与 instant（生效时刻的连接事件计数器）——到点双方同时切换，中途无感知。Core Spec 要求 map 至少保留 2 个可用信道（Core 口径）；较新版本 Core Spec 还允许 peripheral 上报信道状态辅助 central 分类（版本口径，随实现支持度）。

取证视角（接第七章的干扰家族）：空口抓包里 LL_CHANNEL_MAP_IND 可见——**地图什么时候改、把哪些信道标黑了，就是设备自己「感觉到的干扰地图」**。反复更新 + 新地图持续拉黑某段信道 = 该段被持续占用（常与 WiFi 信道对表 8.5.1 交叉验证）；从不更新却一直断连 = 干扰不集中、或问题根本不在信道占用（回第七章 7.4.1 链路预算）。

### 8.5.3 同芯共存与 PTA 一句话

双芯方案（BLE 芯片 + WiFi 芯片各管一摊）靠共存接口协调空口时间，最常见的是 **PTA（Packet Traffic Arbitration）**——REQUEST/GRANT/PRIORITY 类握手线，让两颗芯片在发帧前互相申请许可（概念一句话，实现随厂商各异，细节查芯片共存应用手册）。单芯方案（WiFi+BLE 同芯）则由片内仲裁器分时，配置入口随 SDK 而异——BOX-3 的配置实践见 [[ch16-wifi-events|BOX-3（十六）]]。排障要点只有一条：**双芯共存异常的症状是「开 WiFi 后 BLE 掉线率上升」，验证方法是关掉一侧对照**。

### 8.5.4 现场共存排障三步

把 8.5.1~8.5.3 收成一条可执行路径（与第七章 7.4.2 干扰家族衔接）：

```text
「开 WiFi 就断/变差」
 ① 对照：关 WiFi 复测 → 症状消失 = 共存问题坐实；症状不变 = 回 7.4.1/7.4.2
 ② 定位：抓包看 LL_CHANNEL_MAP_IND —— 地图持续拉黑哪段信道？
    对照 8.5.1 的重叠表：拉黑段与 WiFi 主信道吻合 → AFH 在正确工作，问题在「可避让
    信道太少」（环境太挤/共存仲裁失败），不是「AFH 没用」
 ③ 处置：双芯 → 查 PTA 接线与仲裁配置；单芯 → 查 SDK 共存配置项；
    环境侧 → WiFi 固定到离 BLE 业务远的主信道（1/6/11 三选一错开）
```

一条红线：AFH 只在 37 个数据信道里避让，**三个广播信道（2402/2426/2480）不可避让**——广播被干扰挤压的病（扫不到/连得慢），AFH 无能为力，只能动环境或广播参数（回第四章）。

## 8.6 没有仪器的降级估计：定距 RSSI 梯度法

没有频谱仪/综测仪时，用手机 App 的 RSSI 读数做相对测量，能回答大半「链路预算够不够」的问题。RSSI 的绝对精度有限（芯片间可差数 dB，**datasheet 口径，跨机型不可比**），所以纪律是：**同一台手机、同一位置姿态、只比相对变化**。

```text
定距 RSSI 梯度法（30 分钟出结论）
 ① 定点：0.5 / 1 / 2 / 5 / 10 m 五个点，各记录 10~20 个广播包 RSSI 取均值
    （nRF Connect 列表逐条记录，或 btmon 的广播报告事件里也带 RSSI）
 ② 对账：理想自由空间每翻倍距离 +6 dB；室内允许更陡，但相邻点突变 >10 dB
    → 该方向有遮挡/反射强区，换方向重测定位问题面
 ③ 判读：末端点 RSSI − 芯片灵敏度 ≥ 10~15 dB 余量 → 预算合格（经验口径）
    余量 < 5 dB → 第七章的 0x08 断连只是时间问题
 ④ 双向验证：对端也发（手机↔设备都做主），两侧不对称 > 6 dB
    → 差的一侧 TX 或天线有病（板级问题指向第八章 8.3 发射功率件套）
```

双设备互测是梯度法的板间版：两块开发板固件分别当「定标发射源」与「RSSI 记录仪」，固定距离互换角色——不对称性直接暴露发射侧问题。这套方法的局限也要交代：不能测频偏/杂散（必须仪器），RSSI 在多径环境里跳动大（取均值、多点取样），**它回答「预算够不够」，不回答「指标合不合规」**——后者仍是第十一章的预测试。

梯度数据的判读矩阵（斜率形态 → 结论 → 动作）：

| 梯度形态（示意）               | 结论                   | 动作                               |
| ------------------------------ | ---------------------- | ---------------------------------- |
| 每翻倍 +6 dB 上下，末端余量足  | 预算健康               | 别动射频，回软件层排查             |
| 每翻倍 +6 dB 但末端余量 < 5 dB | 距离确实到边           | 抬 TX 档位 / 改结构 / 引 Coded PHY |
| 相邻点突变 >10 dB              | 定向遮挡/反射强区      | 换方位重测定位问题面；查结构遮挡   |
| 全程斜率远陡于 +6 dB/倍距      | 天线效率差或方向图凹陷 | 双设备互测定侧；查匹配与净空       |
| 两方向不对称 > 6 dB            | 单侧发射/天线问题      | 差的一侧按 8.3 发射功率件套排查    |
| 同一点读数方差 > 5 dB 且不收敛 | 多径主导（近场反射强） | 加密取样点；以时间均值代替空间单点 |

> [!summary] 收束
> 本章的用法是**对账**，不是炫技：空口证据链到了天花板（0x08 无告别帧、位置/时段相关、重传密集），就按四件套逐项对限值——功率、频偏、灵敏度、杂散；没有仪器就先用定距梯度法回答「预算够不够」。记住两条分界：灵敏度下限看芯片 datasheet 不看规格书 -70 dBm；AFH 治「可避让的占用」，治不了「全频段烂」和「预算为负」。链路预算合格之后还慢，就是下一章的账本——吞吐与延迟。
