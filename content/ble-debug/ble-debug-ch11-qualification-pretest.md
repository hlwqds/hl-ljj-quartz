## 本章证据口径

> [!note] 先立规矩
> 本章涉及两套体系：**Bluetooth SIG Qualification**（协议合规，规则以 SIG 官网的 Qualification Program 文档为准）与**国别射频法规**（FCC/CE/SRRC 等，限值与测试方法以法规原文为准）。凡涉及限值数字、费用金额、流程细节，本章一律**不写具体值**，标注「以现行文件/官方渠道为准」；流程性描述为便于建立概念的口径，送测前务必以当期官方文档复核。

## 11.1 现场引入：不熟流程的代价账

先算账，再讲技术。某团队第一次做 BLE 产品，把「蓝牙认证」当成一件小事：以为过了 FCC 就万事大吉，量产准备发货时渠道方要 **QDID**（Qualification Design ID，SIG 认证声明编号），才发现产品从未做过 SIG listing；补做时又发现协议栈版本太老、测试要求已更新，前后耽误数周，错过渠道铺货窗口。这不是虚构情节，而是蓝牙团队新人期的**常见故障模式综述**（教学复盘案例；时间与金额为量级示意，以实际行情为准）：

| 代价项               | 量级（示意）    | 说明                                                                         |
| -------------------- | --------------- | ---------------------------------------------------------------------------- |
| 补做 Qualification   | 周级起步        | 流程走通本身不难，难在临时补材料、补测试                                     |
| 协议栈版本不满足要求 | 数周            | 老版本协议栈可能不满足当期测试要求，升级涉及回归                             |
| 射频法规 fail 复测   | 千元到万元级/次 | 与 WiFi 章同款账，见 [[wifi-hw-debug-ch11-precompliance\|WiFi 调试（十一）]] |
| 错过上市窗口         | 按季计          | 与 [[wifi-hw-debug-ch11-precompliance\|WiFi 调试（十一）]] 的代价账同构      |

两条线**必须分开记**，这是本章的第一结论：

| 线       | 是什么                       | 谁管          | 没做的后果                                            |
| -------- | ---------------------------- | ------------- | ----------------------------------------------------- |
| 协议合规 | 证明产品按标准实现了蓝牙协议 | Bluetooth SIG | 不能宣称「Bluetooth」品牌与商标；渠道/客户验厂要 QDID |
| 射频法规 | 证明发射满足该国无线频谱法规 | 各国监管机构  | 合法上市的前置条件，海关与市场监管可直接卡            |

两条线互不替代：SIG listing 不能代替 FCC/CE，过了 FCC 也不能省掉 SIG——**一个 BLE 产品要出海，两条线都要走**。

## 11.2 认证体系速览：SIG 一条线、法规一条线

### 11.2.1 Bluetooth SIG Qualification 的骨架

SIG Qualification 的现代流程以**声明制（Declaration）**为主：会员在 SIG 的门户上创建 listing、声明产品符合测试要求、签署声明文件后获得 QDID 与 listing 状态。概念骨架如下（细节以 SIG 官方文档为准，**待核对以当期流程为准**）：

| 概念           | 一句话解释                                                           |
| -------------- | -------------------------------------------------------------------- |
| Membership     | 做 Qualification 先成为 SIG 会员（分档，费用与权益不同，以官网为准） |
| Declaration    | 在门户上声明产品完成所需测试并合规，是流程的核心动作                 |
| QDID / Listing | 声明完成后获得编号与公开条目，客户/渠道可查                          |
| 测试证据       | 射频/协议测试按分层要求执行，部分层级可声明豁免（见下）              |
| 品牌使用       | 合规后才可在产品与包装上使用 Bluetooth 商标与标志                    |

### 11.2.2 分层复用：用已认证芯片+协议栈时，你到底要测多少

对大多数应用团队，这是本章最有实用价值的一节。Qualification 的测试要求是**分层**的：芯片厂商已经为控制器射频行为、协议栈供应商已经为主机协议行为各自做过 Qualification——你的整机 listing 可以**复用**这些已认证组件（引用其 QDID），自己补做的只剩「集成层」：产品特有的 Host 实现/配置/profile 声明与必要的互操作性测试。选型期的动作清单：

| 动作                                          | 目的                                                          |
| --------------------------------------------- | ------------------------------------------------------------- |
| 确认芯片/模组厂商提供其 QDID 与可复用范围     | 复用的前提是上游真的做过、且你的用法在复用边界内              |
| 确认协议栈（ROM 栈/协议栈供应商）的认证状态   | 同上；换协议栈版本可能触发重新评估                            |
| 核对你宣称的 profile/服务在 listing 里的声明  | 宣称什么 profile 就要有什么依据（含采纳的与自定义的声明方式） |
| 与 SIG 门户流程对齐（谁建 listing、谁签声明） | 明确责任人与时间点，避免 11.1 的「发货前才发现没做」          |

一句话版本：**照抄已认证的芯片+协议栈、不自己实现协议底层，SIG 这条线主要是流程活与集成声明；自己移植/魔改协议栈，测试工作量就回来了。**这层「照抄参考实现就能省大钱」的逻辑与 [[wifi-hw-debug-ch11-precompliance\|WiFi 调试（十一）]] 的模组认证复用完全同构。

### 11.2.3 与射频法规的关系：两条线各测各的

法规线的概念框架——FCC/CE/SRRC 是什么、限值逻辑、模组认证为什么值钱——[[ch17-certification-regulations|射频入门（十七）]]已建立，实操方法 [[wifi-hw-debug-ch11-precompliance|WiFi 调试（十一）]]已展开，本章**不重复**，只给 BLE 视角的差异表：

| 差异点        | WiFi 产品                   | BLE 产品                                                       |
| ------------- | --------------------------- | -------------------------------------------------------------- |
| 频段          | 2.4G/5G 多信道、大带宽      | 2.4 GHz ISM 内 40 个 1 MHz 信道（数据信道口径，Core Spec）     |
| 典型标准      | Part 15.247 / EN 300 328 等 | 同族标准适用（具体适用条款以法规原文为准，**待核对**）         |
| 发射功率      | 可到较高功率、EIRP 账复杂   | 典型 BLE 产品功率低（Class 口径见 Core Spec），EIRP 账简单得多 |
| DFS           | 5 GHz 专属痛点              | 无此问题（只待在 2.4G）                                        |
| 与 SIG 的关系 | 无                          | 两条线并行，样品可部分共用测试模式固件（11.3）                 |

记忆锚点：**SIG 管「协议像不像蓝牙」，法规管「电波吵不吵别人」**。SIG 测试里有射频项、法规测试里也有射频项，但判据、方法、报告体系完全不同，互不抵扣。

### 11.2.4 新人最常问的四个问题（FAQ）

| 问题                                              | 简答                                                                                                                                   |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 「我们用的大厂芯片/模组，SIG 认证是不是就免了？」 | 不免：上游认证可**复用**，但整机 listing（声明）仍要你自己做——声明动作不可外包给芯片厂商                                               |
| 「只在中国大陆卖，要做 FCC/CE 吗？」              | 法规线按销售市场走（大陆是 SRRC 等）；SIG 线看品牌与渠道要求，与销售国无必然绑定                                                       |
| 「过了一国法规，报告能复用到另一国吗？」          | 体系间互不抵扣（判据与方法不同）；部分市场接受指定互认的测试数据，以各国现行规则为准（待核对）                                         |
| 「固件 OTA 升级后要重新认证吗？」                 | 法规线：不改变发射特性的功能升级一般不需重测（以法规与机构口径为准）；SIG 线：协议行为变更需评估声明更新（**待核对**，以当期流程为准） |

这四个问题背后的同一条原则：**认证状态是「产品 + 配置 + 宣称」三者的属性**——任何一项变了，都要回头问一句「我的认证还在覆盖范围内吗」。

## 11.3 RF 测试项地图：TX 测什么、RX 测什么

正式射频测试的思路与第八章的物理层概念直接对接：**发射看「像不像干净的 GFSK」，接收看「多弱还收得到」**。下表为测试维度的地图（限值与方法以对应标准原文与 SIG 测试要求为准）：

| 类别 | 测试维度                      | 测的是什么                                               | 与本系列哪章对应                                                 |
| ---- | ----------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------- |
| TX   | 输出功率                      | 各信道发射功率在限值/宣称范围内                          | 第八章链路预算                                                   |
| TX   | 调制质量（调制指数/矢量误差） | GFSK 的调制特征是否符合 Core Spec 容差                   | 第八章 GFSK 概念                                                 |
| TX   | 载波频率容限与频偏            | 中心频率偏差、调制频偏在容差内（晶振问题的直接暴露点）   | 第八章频偏；[[ch11-crystal-clock\|射频入门（十一）]]             |
| TX   | 带内杂散/邻道功率             | 邻信道泄漏与带内杂散是否超限                             | 第八章邻道与杂散                                                 |
| TX   | 带外杂散（传导/辐射）         | 谐波与寄生分量，法规口径                                 | [[wifi-hw-debug-ch11-precompliance\|WiFi 调试（十一）]] TOP 清单 |
| RX   | 灵敏度                        | 规定误码率下的最小接收电平（Core Spec 有参考灵敏度口径） | 第八章灵敏度                                                     |
| RX   | 抗干扰性能                    | 同频/邻频/互调干扰下的接收保持能力                       | 第八章共存概念                                                   |

两类测试的工程不对称性值得记一笔：**TX 项传导口径就能测（一根同轴线进频谱仪），RX 项必须有信号源**（要造出「已知质量的弱信号」才能测灵敏度）。所以预测试阶段 TX 项的可自测性远好于 RX 项——预算有限时，仪器优先投给 RX（灵敏度）与杂散宽扫两件事，功率与频偏用最基础的频谱仪配置就能起步。

### 11.3.1 测试包与 Direct Test Mode：让设备「进考场的姿势」

射频测试的前提是让被测设备**可控地发射/接收标准测试序列**。蓝牙为此定义了两种入口（概念口径，细节以 Core Spec 测试章节为准）：

| 入口                  | 是什么                                                                            | 谁用                                                               |
| --------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Direct Test Mode      | 通过 HCI 专用命令让控制器进入射频测试态：指定信道、包类型、发测试包或进入收包统计 | 实验室与产线测试的标准入口；nRF/ESP 等厂商的 RF 测试工具基于此概念 |
| RF test 模式/工程固件 | 厂商自定义的连续发射/连续接收工程模式                                             | 预测试、产线校准；入口方式以各芯片厂商文档为准                     |

调试与送测含义：**测试模式固件是送测必备品**（11.6），而且预测试阶段（11.5）就靠它把传导测起来。工程上建议把「进入测试模式」做成固件的标准入口（串口命令/特殊广播/按键组合），并与机构确认他们认可的触发方式。

Direct Test Mode 的能力边界也要心里有数（概念口径）：它能指定**信道、包类型/载荷、发射功率档**并进入**收包统计**，覆盖 TX 定量测试与 RX 灵敏度统计的绝大部分场景；但「整机真实天线态下的辐射性能」它测不了——那是天线与结构的事，回到 [[wifi-hw-debug-ch08-antenna-structure|WiFi 调试（八）]] 的结构排查方法。预测试阶段的分工由此清晰：**测试包管控制器，结构审查管天线，两件事别混着归因**。

## 11.4 常见 fail TOP 与对策

BLE 射频项的 fail 排序是行业经验的量级叙述（教学复盘综述口径，非统计报告），TOP 三名与对策如下。设计侧排查方法论与 [[wifi-hw-debug-ch08-antenna-structure|WiFi 调试（八）]] 的结构排查方法同源，引用不重抄。

### TOP 1：杂散超标

| 环节       | 内容                                                                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 失败机理   | 时钟谐波（晶振基频整数倍）与 DCDC 开关噪声耦合进天线/线缆辐射出去——机理与对策与 WiFi 章完全同款                                          |
| BLE 加重项 | BLE 产品往往更小更密：天线离时钟/电源区更近、净空更难保；纽扣电池+升压电路的组合常见                                                     |
| 低成本对策 | 布局审查（时钟线不贴馈线）、屏蔽罩接地、出壳线缆滤波、晶振包地——逐项见 [[wifi-hw-debug-ch11-precompliance\|WiFi 调试（十一）]] TOP 1/2/5 |
| 验证手段   | 传导宽扫看谐波族（等间隔谱线，间隔=时钟基频）；不需要暗室                                                                                |

### TOP 2：频偏/调制质量超差

| 环节       | 内容                                                                                                                                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 失败机理   | 晶振容差不足、负载电容不匹配、温漂——中心频偏吃掉容差；供电纹波劣化调制质量                                                                                                                                           |
| 典型嫌疑   | 为省 BOM 用了宽容差晶振；负载电容按经验值而非按晶振规格配；低温/高温环境下漂移出界（产品没有温度维度测试）                                                                                                           |
| 低成本对策 | ① 核对晶振规格与负载电容匹配（[[ch11-crystal-clock\|射频入门（十一）]]）；② 预测试用测试包实测频偏而不是等实验室；③ 供电纹波检查（第九章电源完整性同款，见 [[wifi-hw-debug-ch09-power-integrity\|WiFi 调试（九）]]） |
| 验证手段   | Direct Test Mode 发测试包 + 频谱仪测中心频偏与调制频偏                                                                                                                                                               |

### TOP 3：灵敏度余量不足

| 环节       | 内容                                                                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 失败机理   | 接收灵敏度贴着 Core Spec 参考口径甚至更差——天线失配、匹配网络偏差、噪声底被板内噪声抬高等                                                               |
| 典型嫌疑   | 天线净空被结构侵入/失谐（天线结构排查方法见 [[wifi-hw-debug-ch08-antenna-structure\|WiFi 调试（八）]]）；板上 DCDC/时钟噪声抬高噪声底；装配应力改变匹配 |
| 低成本对策 | ① 传导口径先测「控制器本身」的灵敏度（绕开天线），把「芯片差」与「天线差」分离；② 净空与结构审查；③ 干扰源排查                                          |
| 验证手段   | 灵敏度测试需要信号源+误码统计（Direct Test Mode 的收包统计入口），没有仪器时降级为「距离/误码对照法」粗判                                               |

### TOP 3 的连锁反应：天线失谐的「一对多」症状

灵敏度不足的根因里，**天线失谐**值得单独一页，因为它很少只坏一项——失谐是「一对多」的病灶：

| 失谐后果             | 在测试项目上的表现                    | 在用户侧的表现            |
| -------------------- | ------------------------------------- | ------------------------- |
| 辐射效率下降         | 传导正常但整机辐射场强弱              | 距离变短、RSSI 整体偏低   |
| 阻抗失配引入带外能量 | 邻道/杂散读数劣化（与 TOP1 症状重叠） | 特定姿势/装配态下更明显   |
| 谐振点漂移出频段     | 灵敏度在信道间不均匀                  | 某些信道/某侧朝向明显更差 |

排查动作沿用 [[wifi-hw-debug-ch08-antenna-structure|WiFi 调试（八）]] 的结构方法：净空审查、装配态 vs 裸板态对照、按压复测。BLE 产品的小体积让天线离结构件更近，**外壳材质（金属喷漆、电镀logo）与电池位置**是最常见的两只黑手——设计评审时对着净空图逐项问。

### 汇总速查表

| Fail 项目     | 失败机理一句话            | 第一动作（免费）               | 第二动作（花小钱）  |
| ------------- | ------------------------- | ------------------------------ | ------------------- |
| 杂散超标      | 时钟/DCDC 噪声耦合上天线  | 布局审查 + 屏蔽接地 + 线缆滤波 | 频谱仪传导宽扫      |
| 频偏/调制超差 | 晶振与负载电容不匹配      | 核对晶振规格 + 测温漂维度      | 测试包实测频偏      |
| 灵敏度不足    | 天线失配或板内噪声抬底    | 净空审查 + 传导/辐射分离定位   | 信号源+误码统计实测 |
| 功率超限      | EIRP 账算错（少见于 BLE） | 重算功率预算表                 | 逐信道传导复测      |

## 11.5 低成本预测试路线

路线与 [[wifi-hw-debug-ch11-precompliance|WiFi 调试（十一）]] 的第 11.5 节同构，此处只给 BLE 视角的执行差异，方法细节引用不重复：

| 预测试动作        | BLE 特有要点                                                                                    | 复用的 WiFi 章方法           |
| ----------------- | ----------------------------------------------------------------------------------------------- | ---------------------------- |
| 传导功率/杂散宽扫 | 用 Direct Test Mode 逐信道发测试包；BLE 只有 2.4G 一个频段，扫描范围小、项目少                  | 传导法概念（WiFi 章 11.5A）  |
| 频偏/调制质量     | 测试包 + 频谱仪测频偏；没有矢量分析能力时至少测中心频偏（晶振健康的最便宜指标）                 | 频率容限项                   |
| 灵敏度            | 信号源发标准包 + Direct Test Mode 收包统计；无仪器时用「固定距离误码对照法」在好/坏机间横向比较 | 物理层判据口径（第七章方法） |
| 设计侧自查（¥0）  | 净空、屏蔽罩接地、接口滤波、EIRP 预算——清单与 WiFi 章完全共用                                   | WiFi 章 11.5B 全表           |

降级路线同样适用：实验室**预扫服务**（买方向性数据）、借/合租仪器。BLE 的好消息是：一个频段、低功率、小带宽，**预测试能覆盖的比例比 WiFi 更高**——把「低级 fail」在自己工位上排掉的可行性更强。

预测试的执行顺序建议照抄 WiFi 章的阶梯思想，按「免费→便宜→贵」排：

```text
设计定稿 ──► 设计侧自查（¥0：净空/屏蔽/滤波/EIRP 预算，WiFi 章清单共用）
              ▼
        Direct Test Mode 传导自测（频谱仪级：功率/频偏/杂散宽扫）
              ▼
        灵敏度专项（信号源+收包统计；无仪器则好/坏机对照法粗判）
              ▼
        实验室预扫（可选，买方向性数据）
              ▼
        正式送测（SIG listing 与法规测试并行推进，11.6）
```

诚实划界（沿用 WiFi 章的做法，避免「自查过了为什么还挂」的错觉）：

| 预测试能排掉                               | 排不掉（必须实验室/正式流程）                  |
| ------------------------------------------ | ---------------------------------------------- |
| 功率、频偏、调制质量的量级问题（传导口径） | 辐射杂散的**准确判定**（暗室不可复制）         |
| 杂散谐波族的「存在性」（时钟/DCDC 谱线）   | 辐射限值余量（环境本底淹没小信号）             |
| 灵敏度的芯片级定位（传导/信号源口径）      | 正式报告、QDID listing 与证书本身              |
| 净空/屏蔽/滤波类设计侧低级错误             | 各国法规的判定细节与互认问题（以机构口径为准） |

## 11.6 送测准备清单

两条线各有一份清单。SIG 线以官方门户流程为准（材料要求随流程版本变动，**以当期官方文档为准**）；法规线的完整准备表在 [[wifi-hw-debug-ch11-precompliance|WiFi 调试（十一）]] 11.6 已给全，这里只列 BLE 侧的增量项：

| 准备项           | 要点                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------- |
| 测试模式固件     | Direct Test Mode 或厂商 RF test 模式入口可用且稳定；与机构确认触发方式被认可                 |
| 上游 QDID 材料包 | 芯片/模组与协议栈的 QDID、可复用声明范围、供应商出具的支持文件（SIG 线复用的证据基础）       |
| 宣称清单         | 产品要宣称的 profile/服务列表——SIG listing 与手册宣传口径一致（11.1 教训：文档与行为要一致） |
| 样机状态         | 法规线通常需多台不同状态样机（含最大发射态、连发模式），以机构要求为准                       |
| 温度维度样件     | 频偏类问题常在温漂维度暴露；预测试阶段就应覆盖高低温（多数消费级实验室支持温箱项）           |
| 排期与预算       | 两条线的周期独立排：SIG listing 是流程周、法规测试是排队+测试周；fail 预案参考 WiFi 章代价账 |
| 协议栈版本记录   | 送测样机的固件/协议栈版本冻结并记录——测过的版本就是 listing 声明的版本，临场换版本等于重测   |

一条经验规则与 WiFi 章同款：**机构测的是你「说明书里承诺的产品」**。宣称了没实现的 profile 是 SIG 线的风险；实现了没宣称的模式，法规线一般不测但 SIG 声明要如实——别用「文档装傻」赌任何一边。

## 11.7 收尾：认证预测试 checklist

| #   | 检查项                                                       | 状态口径                      | 对应小节  |
| --- | ------------------------------------------------------------ | ----------------------------- | --------- |
| 1   | 两条线分开立项：SIG Qualification 与目标国射频法规各有责任人 | 立项文档可见                  | 11.1/11.2 |
| 2   | 芯片/模组 QDID 与可复用范围已确认并拿到支持文件              | 供应商文件在案                | 11.2.2    |
| 3   | 协议栈版本与认证状态确认（升级栈是否触发重评已评估）         | 与供应商书面确认              | 11.2.2    |
| 4   | 宣称的 profile/服务清单与产品行为一致                        | 手册 ↔ listing ↔ 固件三方一致 | 11.2/11.6 |
| 5   | Direct Test Mode / RF test 模式固件就绪且入口稳定            | 工程上可重复触发              | 11.3.1    |
| 6   | 晶振规格、负载电容、温漂维度核对完成                         | 与晶振规格书逐项对照          | 11.4      |
| 7   | 净空/屏蔽/接口滤波/EIRP 预算等设计侧自查表全绿               | 沿用 WiFi 章自查清单          | 11.5      |
| 8   | 传导预测试完成：功率/杂散/频偏逐信道过                       | 有数据记录；无仪器则预扫替代  | 11.5      |
| 9   | 灵敏度余量核对（传导口径，芯片与天线分离定位）               | 有对照数据或仪器实测          | 11.4      |
| 10  | 温度维度预测试覆盖（至少高低温两点频偏/功率）                | 有温箱数据或预扫              | 11.4/11.6 |
| 11  | 样机数量与状态满足两条线各自要求                             | 以机构/流程要求为准           | 11.6      |
| 12  | SIG listing 流程的责任人、时间点已排入项目计划               | 发货前留足流程周期            | 11.1/11.6 |

第 1~4 项是选型与立项期动作，第 5~10 项是设计/预测试期动作，第 11~12 项是送测动作。**十二项全绿再送测**——SIG 这条线尤其如此：它不贵、不难，但**漏了就卡发货**。
