# 蓝牙调试实战系列：从广播包到认证报告

> [!tip] 系列说明
> 本系列是 [[wifi-hw-debug|WiFi 硬件调试实战]] 的姊妹篇：方法论同源（症状分类 × 分层取证 × 证据链），调试对象换成蓝牙。主攻 **BLE**（低功耗蓝牙，今天一切嵌入式/物联网场景的主角）；经典蓝牙 BR/EDR 只在第三章用一页划清边界，不展开。
>
> 写法延续仓库传统：**现象驱动**。每章从具体故障现场出发，按「现象 → 分层定位 → 取证手段 → 根因 → 对策」推进；`bluetoothctl`/`btmon`/`nrfutil`/Wireshark 等软件侧命令可直接复制，需要专用嗅探器或仪器的实验标注实测口径，不虚构读数。装备零成本优先：一部手机（nRF Connect/LightBlue）+ Linux 笔记本 + 一块 nRF52 级开发板，就能走完前半程。

## 方法论：BLE 症状五分类 × 分层取证

蓝牙故障先按用户可感知现象分五类，每类对应一条主排查路径：

| 症状分类      | 典型表现                         | 首选取证手段                      | 对应章节   |
| ------------- | -------------------------------- | --------------------------------- | ---------- |
| **扫不到**    | App 列表里没有设备 / 时有时无    | 广播抓包 + 多手机对照             | 第四章     |
| **连不上**    | 点连接转圈失败 / 偶发成功        | 分阶段取证（广播→连接→加密→GATT） | 第五章     |
| **掉线/不稳** | 用着断、口袋里断、特定距离断     | 断连事件 + 空口时间线             | 第七章     |
| **慢/延迟大** | 数据刷新慢、响应迟钝             | conn interval 账 + 吞吐实测       | 第九章     |
| **功耗/认证** | 续航与规格差一个量级；过不了认证 | 电流曲线 + RF 预测试              | 十、十一章 |

取证顺序沿用分层框架，但每一层的"管子"换成蓝牙的：

```text
L1 观测层 —— 手机 App 看到的：广播名/RSSI/服务列表/断连频次
L2 空口层 —— 嗅探器看到的：广播包/连接建立/数据包/断连原因
L3 主机栈层 —— btmon/hcidump/NimBLE 日志：HCI 命令与事件流
L4 控制器射频层 —— 物理层健康吗：功率/灵敏度/频偏/晶体/共存
```

原则不变：**取证成本从低到高，改板子永远放最后**。蓝牙还有一条特有纪律：手机端（操作系统）既是你的测试仪又是最大的变量——每一份证据都要标注「用什么手机、什么系统版本测的」。

## 目标读者与承诺

- 读过（或在跟）[[wifi-hw-debug|WiFi 硬件调试实战]] 或 [[wifi-rf-hw|射频硬件入门]]，具备 dBm/RSSI/灵敏度等基础概念
- 有一台 Linux 笔记本（BlueZ 环境）和一块 BLE 开发板（nRF52/ESP32 系均可）
- **承诺**：读完能独立抓广播与连接包定位配对失败、用 btmon 读 HCI 流排查主机栈问题、做conn interval/广播参数的功耗账、判断「这锅归 App、协议栈还是射频」
- **不承诺**：不教音频 BR/EDR（A2DP/HFP）与经典蓝牙协议栈、不教芯片射频设计、不替代 Bluetooth SIG 正式 Qualification——预测试的终点是「送测前排掉低级 fail」

## 环境与装备约定

| 项       | 约定                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------- |
| 测试手机 | 至少两台不同品牌的 Android（nRF Connect）+ 一台 iPhone（LightBlue/nRF Connect）；每份证据标注机型与系统版本 |
| 主机     | Linux 笔记本 + BlueZ（`bluetoothctl`/`btmon`）；macOS 的 CoreBluetooth 与 Windows 栈只提差异不展开          |
| 开发板   | 一块 BLE SoC 板（nRF52/ESP32 系）；能跑主机栈的 USB dongle（如 nRF52 dongle）可选                           |
| 嗅探     | nRF Sniffer for BLE + Wireshark（几十元级板子即可充当）；专业分析仪（Ellisys/Frontline）只讲边界            |
| 仪器     | 频谱仪/功耗仪按「看什么/什么时候需要」介绍，不假设拥有，替代方案随章给出                                    |
| 证据口径 | 命令与输出以工具官方文档为准；数值引 Bluetooth Core Spec/芯片 datasheet 注明口径，查不到标「待核对」        |

## 学习节奏建议

- **顺序推进 Part I**：协议栈地图（第三章）是后面所有章节的名词表，务必先读。
- **案例章（五、七、九）按需跳读**：手头卡哪类症状直接翻，工具盲区回第一、二章补课。
- **第八章与 WiFi 系列第八章互补**：两套 2.4G 设备的共存问题建议对照读。
- **每章一个可复制的取证动作**：软件侧给完整命令，硬件侧给步骤与观察点并标注实测口径。
