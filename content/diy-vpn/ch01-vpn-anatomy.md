# 手写 VPN（一）：VPN 解剖——虚拟、专用、网络三个词各值多少钱

VPN 这三个字母被用得太滥：企业远程办公是 VPN，跨境访问是 VPN，连浏览器插件都自称 VPN。这一章把它拆回本义：**V（虚拟）+ P（专用）+ N（网络）是三个正交的能力**——封装（隧道）、加密、虚拟网卡与路由。每个能力都能单独实现、单独理解，本系列就是一次把它们逐个手写出来再拼回去。读完它，任何一个自称 VPN 的东西你都能一句话说出它实现了哪几个字母。

姊妹篇 [[vpn-deep-dive|VPN 与隧道技术系列]]负责"拆别人的轮子"（WireGuard/IPsec/SS 协议逐字节分析）；本系列造自己的轮子，两条线在第九章（与 WireGuard 对照）汇合。

---

## 1.1 三个字母，三种能力

### 1. P（专用）= 加密 + 完整性 + 认证

"专用"的本义是：这条链路上的数据**只有通信双方能读懂、且无法被篡改**。工程上拆成三件事：

- **机密性**（加密）：第三方抓包只见乱码；
- **完整性**（MAC/AEAD）：改一个比特，接收方拒收；
- **认证**（密钥交换 + 身份验证）：确认"能解密的对方"就是"我想连的对方"，而不是中间人。

这三件事分别在本系列 ch04、ch05、ch06 手写。要注意它们**缺一即破**：只加密不校验完整性，攻击者可以翻转密文比特篡改明文（CBC 位翻转一类攻击的温床）；加密 + 完整性但不认证密钥交换，中间人笑着把两边的钥匙都换成自己的（ch06 的中间人实验当场演示）。

### 2. N（网络）= 封装 + 转发

隧道的本质是**把一种包塞进另一种包**：内层是你要保护的 IP 包，外层是能在公网上路由的载体（UDP/TCP/ICMP 甚至 DNS）。收到后剥掉外层、还原内层、转发到目的地。代理式 VPN（SOCKS/Shadowsocks）在应用层做这件事，包级 VPN（IPsec/WireGuard）在 IP 层做——层次不同，本质相同。

### 3. V（虚拟）= 虚拟网卡 + 路由

这是最容易被忽略、却让 VPN 成为"网络"的那一块：一块**虚拟网卡（TUN/TAP）** + **路由表项**。应用程序照常 `connect(10.7.0.1)`，操作系统查路由表把包丢给 TUN 设备，你的用户态程序从 TUN 里读出裸 IP 包、塞进加密隧道发走。对应用完全透明——**VPN 之所以是 VPN 而不是代理，就差在这块网卡上**（ch03/ch07/ch08 三章造它）。

```text
         应用层代理式（SS/SOCKS）              包级 VPN（WireGuard/我们的 mini-VPN）
应用      浏览器配置代理 ──────────▶           应用照常发包，无感知
          （每个应用要单独配）                  │ 路由表：10.7.0.0/24 → tun0
封装      用户态协议帧                          ▼
          │                              TUN 虚拟网卡（V 的本体）
          │                                   │ 内核递过来的是裸 IP 包
          ▼                                   ▼
外层载体  TCP/UDP                       加密封装（P+N）→ UDP → 公网
```

## 1.2 四种隧道形态：成本与能力的阶梯

按"离内核多近"排一个阶梯，本系列的实现路径正好沿它下行：

| 形态                   | 代表                   | 透明度 | 实现成本 | 本系列    |
| ---------------------- | ---------------------- | ------ | -------- | --------- |
| 应用层代理             | SOCKS/Shadowsocks      | 低     | 最低     | ch02 骨架 |
| 用户态包封装（无 TUN） | 早期 UDP 隧道          | 中     | 低       | ch02→ch06 |
| 用户态 + TUN 虚拟网卡  | OpenVPN(UDP)/boringtun | 高     | 中       | ch07      |
| 内核态实现             | WireGuard/IPsec        | 高     | 高       | ch09 对照 |

阶梯的每一级往下，**性能更好、更透明**，但**离内核更近、调试更难**。WireGuard 进内核不是炫技：TUN 方案每秒要在用户态和内核之间搬运几十万个包上下文切换，内核态把这些全部省掉（ch09 的性能账）。

## 1.4 先把"敌人"想清楚：威胁模型

动手前必须回答"防谁"。本系列按同一威胁模型设计，它也是现实 VPN 的标准假设：

1. **攻击者能看**：中间链路（ISP/咖啡店 WiFi/骨干网）完整看到你的每一个外层包（IP、端口、长度、时序）；
2. **攻击者能改**：丢包、重放、篡改、重排都在其能力范围内；
3. **攻击者不能**：拿到你的设备与私钥、破解密码学原语本身。

注意第 1 条的推论：加密隐藏的是**内容**，不是**通信事实**——流量分析（长度/时序指纹）是另一门攻防（[[vpn-deep-dive|姊妹篇]]的流量识别章节展开）。"防住 1+2，不幻想防住流量分析"，这就是本系列手写每个零件时的验收标准。

## 1.5 小结

- VPN = 三个正交能力：P（加密/完整性/认证）、N（封装转发）、V（虚拟网卡+路由）——可分别实现、分别理解，最终拼装。
- 四级阶梯：应用层代理 → 用户态隧道 → 用户态 + TUN → 内核态；越往下越透明越快，也越难写。本系列走到第三级，第四级用 WireGuard 对照。
- 威胁模型三句话：攻击者能看、能改，拿不到密钥、破不了密码学；加密护内容，不护通信事实。
- 与姊妹篇分工：那边拆 WireGuard/IPsec 的协议字节，这边从零造一遍同构物，第九章汇合对照。
