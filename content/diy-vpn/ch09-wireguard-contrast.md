# 手写 VPN（九）：对照 WireGuard——我们的轮子差在哪

mini-VPN 能跑了，现在把它和工业标准的 WireGuard 摆上对撞台。先看两者**惊人的相似**（9.1：传输帧几乎同构），再逐项清点**四项差距**（9.2–9.5）：前向保密、身份隐藏、DoS 防护、内核态性能——每项都说清"WireGuard 多做了什么、我们的轮子少在哪、代价是什么"。密码学细节的完整拆解在 [[vpn-deep-dive|姊妹篇]]第十九、二十章（协议详解 + 密码学全家桶），本章专注"手写者视角"的对照。

---

## 9.1 先看相似：传输帧几乎同构

WireGuard 的数据传输报文剥到骨头：

```text
WireGuard 传输帧（外层 UDP 内）：          我们的 mini-VPN 帧：
┌──────────┬─────────┬───────┬─────────┐  ┌────────┬──────────────┬────────┐
│ type=4   │ receiver│ counter│ 密文     │  │ ctr(8) │ 密文(IP包)    │ tag32  │
│ (1B)+保留 │ 索引(4B)│ (8B)   │ +Poly1305│  │        │              │        │
└──────────┴─────────┴───────┴─────────┘  └────────┴──────────────┴────────┘
  receiver：会话索引，收方据此查会话        （我们单 peer，索引省略）
  counter：64 位计数器 → 防重放窗口          同款
  加密：ChaCha20-Poly1305（AEAD）           ChaCha20 + HMAC（组合式）
  内层载荷：IPv4/IPv6 包                     同款（TUN 读出的标本）
```

**计数器 + AEAD + 裸 IP 包**——第七章的帧格式设计在这里得到最强背书：与工业协议同构。差异全在"看不见的地方"，以下四项。

## 9.2 差距一：前向保密——Noise 握手的两次 DH

mini-VPN 用静态对称密钥（ch07 欠下的债）。WireGuard 每次握手跑 Noise IK 模式：**两次 DH**（临时×临时 + 临时×静态）派生会话密钥，每 2 分钟轮换。后果对照：

| 场景                        | mini-VPN            | WireGuard                   |
| --------------------------- | ------------------- | --------------------------- |
| 服务器密钥文件泄露          | 历史流量全部可解 ❌ | 只能冒充身份，历史仍安全 ✅ |
| 攻击者今天开始录流          | 录到的永远解不开 ✅ | 同 ✅                       |
| 被动录流 + 明天偷到静态私钥 | 全解 ❌             | 解不开（会话密钥已焚）✅    |

ch06 的哲学在真协议里的完整落地：**静态密钥只认证身份，不加密内容**。

## 9.3 差距二：身份隐藏——被动抓包看不出谁连谁

WireGuard 握手帧里没有明文身份：发起方公钥用临时密钥加密后再 MAC（"IK"的 I），被动观察者只能看到"某个 UDP 流量"，**连不上"谁在跟谁握手**。mini-VPN 的 UDP 五元组 + 固定密钥指纹则可被轻松归档："这个 IP 每天早上 9 点连那个 IP"。这正是深度包检测（DPI）设备识别 VPN 流量的起点之一（[[vpn-deep-dive|姊妹篇]]的流量识别章节展开）——**身份隐藏不仅是隐私，也是存活能力**。

## 9.4 差距三：DoS 防护——cookie 的门票机制

无状态的握手端点会被"握手洪水"打死（每次握手都要做 DH，CPU 贵）。WireGuard 的解法：负载高时进入 **cookie 模式**——响应一个便宜的 MAC 挑战（用对端已知公钥 + 自己的秘密派生），对端拿回执换取真握手资格。**先验票、后干活**，把昂贵的 DH 挡在门票后面。mini-VPN 对握手洪水毫无防御（反正它连握手都没有）。

## 9.5 差距四：内核态——性能账

用户态 TUN 方案的每包成本：`内核→TUN→用户态 read→加密封装→sendto` 加上反向，**每包 4 次上下文切换 + 2 次数据拷贝**。WireGuard 在内核里完成全部：无切换、零拷贝路径、每核 SIMD 加密（ChaCha20 的 AVX2 实现）。量级差距：单核用户态方案典型在 1–3 Gbit/s 档，内核态 WireGuard 在同硬件可跑满 10 Gbit+ 网卡（具体数字见姊妹篇性能章）——**四千行内核代码买回一个数量级的吞吐**。手写用户态的价值不在赢性能，而在每一步都可 printf——这正是本系列走过的路。

## 9.6 两个手写时容易忽略的精巧件

- **Roaming（端点漂移）**：WireGuard 不记"对端地址"，而是**谁用合法会话密钥发包，就更新谁的位置**——手机从 WiFi 切 4G，隧道无感续传。我们的 mini-VPN 固定 peer 地址，换网即断。这个设计的深意：**身份（密钥）锚定连接，地址只是建议**——[[p2p-deep-dive|P2P 系列]]的 ICE 哲学在 VPN 里的回声。
- **定时器状态机**：握手重试、密钥轮换、keepalive、会话过期，全部由一个精简定时器矩阵驱动（被动响应优先，最小化发包）。我们只有 10 秒 keepalive 一个定时器——生产协议里"什么时候该说话"与"说什么"同样重要。

## 9.7 小结

- 传输帧层面 mini-VPN 与 WireGuard 同构（计数器+认证加密+裸 IP 包）——手写路线的正确性背书。
- 四项差距：Noise 两次 DH 买前向保密；加密身份买隐藏（也是抗检测存活）；cookie 门票把 DoS 挡在 DH 之前；内核态省掉每包 4 次切换，买一个数量级吞吐。
- Roaming = 身份锚定连接、地址只是建议；定时器矩阵是被低估的生产复杂度。
- WireGuard 的哲学：更少的代码（~4K 行 vs OpenVPN/OpenSSL 生态的几十万行）= 更小的攻击面 = 更容易审计——**简洁是安全属性**，这与手写教学殊途同归。
