# 手写 VPN（十）：生产化——多 peer、密钥管理与故障树

mini-VPN 是两台机器的玩具；生产系统是多 peer、要管钥、要排错、要扛流量的 organism。这一章把"从玩具到生产"的距离拆成四份：peer 管理（10.1）、密钥纪律（10.2）、可观测性与故障树（10.3–10.4），最后看 Tailscale 在这之上加盖的一层，三线（手写 VPN、协议分析、P2P）在此汇合，全系列收束。

---

## 10.1 peer 管理三级跳

- **一级（mini-VPN 现状）**：单 peer、配置文件手写。换 peer 改配置重启。
- **二级（WireGuard 的模型）**：每个 peer 一对密钥 + 一段 AllowedIPs（它有权自称哪些地址）；内核里一张 peer 表，**包来自谁的密钥、目的地址落在谁的 AllowedIPs，即完成转发判定**——加密与路由策略在一张表上合体。这就是 wg-quick 配置文件的语义：
  ```ini
  [Peer]                        # 我们没有的、也是值得自己加的第一个生产件
  PublicKey = xxx…              # 身份（ch06：公钥即身份）
  AllowedIPs = 10.7.0.2/32, 192.168.8.0/24   # 路由（ch08：split tunnel 的每 peer 版）
  Endpoint = 1.2.3.4:51820      # 地址只是建议（ch09 roaming）
  ```
- **三级（Tailscale 的模型）**：WireGuard 之上加**控制平面**——协调服务器持有所有设备的公钥与 ACL，设备间打洞直连（[[p2p-deep-dive|P2P 系列]]ch04 的 ICE 全套），穿透失败走 DERP 中继兜底（[[2025-12-02-easytier-learn-rust1|EasyTier 笔记]]与 [[2026-03-12-wireguard-protocol-deep-dive|WireGuard 协议解析]]是两个开源实例）。**数据面去中心化（P2P），控制面中心化（账号/ACL）**——P2P 系列 ch05 的混合架构哲学在 VPN 世界的终态。

## 10.2 密钥纪律：生成分发轮换

生产化的密钥三问：

1. **生成**：`/dev/urandom` 起手（mini-vpn 的 key 文件就是这么来的），公钥钥对看曲线（WireGuard 用 Curve25519，ch06 手写的 DH 是它的整数环先祖）；
2. **分发**：密钥文件永远不走过它自己保护的信道（先有鸡问题）——离线拷贝/配置管理/控制平面，三选一；ch06 的中间人教训在这里落地为纪律；
3. **轮换**：会话密钥短命（WireGuard 2 分钟自动轮），长期身份钥按事件换（人员离职/疑似泄露），**换钥不换身份**（公钥指纹变了才是新设备）。

## 10.3 可观测性：自造工具箱

排错前先要有眼睛，三层各配一副：

```bash
# 外层（隧道活不活）：公网口上只见密文
tcpdump -ni eth0 udp port 51820           # 有来有回 = 外层通；只有出 = 回包没路（NAT/防火墙）
# 中层（会话状态）：自造的 wg show 等价物——mini-vpn 加一个 stats 模式打印
#   最近 ctr、窗口左沿、收发字节、最近 keepalive —— 就是一个可用的 wg show
# 内层（业务通不通）：
ping 10.7.0.2                             # ICMP 双向验内层
curl -v --interface tun0 http://目标       # 应用层验收
```

## 10.4 故障树：四科分诊

| 症状                          | 首查                   | 常见病因                                  |
| ----------------------------- | ---------------------- | ----------------------------------------- |
| ping 不通、tcpdump 外层也无包 | 服务端进程/端口/防火墙 | NAT 映射过期（keepalive 没跑）、云安全组  |
| 外层有包、内层 ping 不通      | MAC 校验日志           | 两端密钥不一致（手改配置惹的祸）          |
| 小包通、大包/网页卡           | MTU/MSS（ch08 §8.4）   | 1420 没设、PMTU 黑洞、ICMP 被吞           |
| 时通时断、几分钟必断          | 会话/定时器            | keepalive 间隔大于 NAT 寿命、密钥轮换失败 |

**分诊的顺序本身就是教学**：先外后内（隧道载体 → 加密会话 → 内层业务），每一层用上层的"有眼睛"工具验证——这张表就是前九章知识点的反向索引。

## 10.5 全系列总结：手写者带走的东西

十个零件、五份实验，现在可以拆开揉碎地列出手写 VPN 教会我们的事：

1. **VPN 是三个正交能力的乘积**（V×P×N），每个都能单独实现、单独测试、单独理解——复杂系统拆成正交零件是第一工程能力；
2. **帧格式是协议的宪法**：从明文帧第一天就给计数器留位，后来防重放零改动接入——好的格式设计是预付款；
3. **密码学的工程风险不在算法在纪律**：nonce 不重复、EtM 顺序、常量时间比较、DH 必须认证——四条军规每条都是某次真实事故的碑文；
4. **TUN + 路由表是透明性的全部机关**：应用无感知 = 虚拟网卡 + 那只骗包的手；
5. **系统与程序的分工**：minivpn.c 管隧道两端，路由/NAT/MTU 是系统侧配置——wg-quick 的本质是命令清单的脚本化；
6. **对照真协议是最高效的复习**：传输帧同构给你信心，四项差距（前向保密/身份隐藏/DoS/内核态）给你方向——知道自己缺什么，比知道 WireGuard 有什么更值钱。
