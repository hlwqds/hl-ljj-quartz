## 1. 先看一眼我们今天要讲清楚的实测

系列前 22 章里，所有烧录、调试、`mdw` 读寄存器走的都是 JTAG——因为工程里的
`openocd.cfg` 写了 `transport select jtag`。2026-08-30 我们把配置改成一个字的差别
（`jtag` → `swd`），**同一条排线、板子一动不动**，结果：

```text
【实测】切换 SWD 后 openocd 的输出：
Info : CMSIS-DAP: Interface Initialised (SWD)      ← DAP 换了工作模式
Info : SWD DPIDR 0x2ba01477                        ← SWD 门牌号（JTAG 时是 0x4ba00477）
Info : [stm32f4x.cpu] Cortex-M4 r0p1 processor detected
0xe000ed00: 410fc241                               ← CPUID，M4 r0p1
0x40023800: 03035883                               ← 活体读：固件正跑在 180MHz（PLL 已锁）
0x200000e4: 00000634                               ← 活体读：FreeRTOS tick=1584，调度器活着
```

两种协议下芯片识别、烧录、读写内存**全部等价**——为什么两根线能干五根线的活？这就是本章要讲透的事。

## 2. 原理：从两根线到任意内存

### 2.1 SWD 的两根线各干什么

> 📖 **术语卡：SWD（Serial Wire Debug，串行线调试）**
> **是什么**：ARM 为 Cortex-M 设计的两线调试接口——**SWDIO**（数据，双向）+ **SWCLK**
> （时钟，由仿真器驱动）。两根线承载全部调试流量：识别芯片、停机、单步、读写任意
> 内存与寄存器、烧 Flash。
> **为什么存在**：前辈 JTAG 要 5 根线（TCK/TMS/TDI/TDO/TRST），小封装芯片引脚金贵；
> SWD 砍到 2 根还更快。
> **类比**：芯片的 SSH + 带外管理口（IPMI）——系统死透了也能连进去查现场；
> 又像 `gdb attach` + `/proc/kcore` 合体，但硬件原生、连操作系统都不需要。
> ⚠️ 类比边界：SSH 要协议栈活着；SWD 是物理引脚直连芯片内的调试单元，不依赖任何固件。

工作方式一句话：**半双工主从问答**。仿真器（主机）在 SWCLK 上打时钟，在 SWDIO 上
按位喊话（"读地址 0xE000ED00"），然后松开总线听芯片逐位回答。像对讲机——一边说完
另一边才能说，但每秒能问几百万次（我们配的 2MHz 时钟速率）。

> 📖 **术语卡：SWCLK / SWDIO**
> **是什么**：时钟线（主机→芯片，节拍器）与数据线（双向，命令和回答都在这）。
> **为什么存在**：没有独立时钟的异步线（如 UART）要双方约好波特率；同步线由主机
> 打拍子，芯片跟着走，快慢随主机。
> **类比**：I2C 的 SCL/SDA 同款分工——SWCLK≈SCL，SWDIO≈SDA（连"地址+数据双向"
> 的神韵都像）；差别是 I2C 有开漏上拉多挂从机，SWD 是点对点推挽。
> ⚠️ 类比边界：I2C 从机可以"时钟拉伸"流控，SWD 没有这个机制。

### 2.2 三层架构：电话→总机→办公楼（故障恢复那晚的实战地图）

```text
笔记本 openocd
   │ USB
野火 DAP（协议翻译官：USB ↔ SWD 位流）
   │ SWDIO + SWCLK（+ NRST）
   ▼
┌────────────────── 芯片内部 ──────────────────┐
│ 第一层 DP（Debug Port）  ← "电话接通没"       │
│   └─ 身份寄存器 DPIDR = 0x2ba01477           │
│ 第二层 AP（Access Port） ← "总机转哪条线"     │
│   └─ MEM-AP：通往芯片总线的那扇门             │
│ 第三层 芯片总线（AHB/APB） ← "办公楼里所有房间"│
│   └─ CPU、RCC、USART、Flash、RAM 全在这       │
│      CPUID=410fc241 / 你的 mdw 读到的一切     │
└──────────────────────────────────────────────┘
```

这张图是时钟配置故障复盘「分层判尸」的地图：当时 **DPIDR 读得到**（第一层活着）、**CPUID 读
出 0**（第三层死）→ 结论"传输层没坏、芯片内部出事"。系统侧的你应该觉得眼熟：这和
"网口灯亮（链路层通）但服务不响应（应用层死）"是同构的诊断结构。

> 📖 **术语卡：MEM-AP**
> **是什么**：AP 家族里最常用的一个成员——把调试器的读写请求转成芯片总线事务的"门"。
> **为什么存在**：DP 只管线路协议，不知道芯片总线长啥样；MEM-AP 补上这层翻译。
> **类比**：总机到办公楼的最后一段网线——前面电话打得再通，这段不通照样进不了房间。
> ⚠️ 类比边界：网线是透明转发，MEM-AP 会维护自己的重试/忙状态（openocd 的
> "ap wait"超时报错就是它说的）。

### 2.3 SWJ-DP：为什么同一条线两种协议都能用

挑战者的芯片里，调试端口叫 **SWJ-DP**（SWD+JTAG 双模调试端口）——它在物理上引出了
**两扇前门**：

| 门      | 用的引脚                              | 门牌号（身份寄存器）          |
| ------- | ------------------------------------- | ----------------------------- |
| JTAG 门 | TCK/TMS/TDI/TDO（PA14/PA13/PA15/PB3） | IDCODE = `0x4ba00477`（实测） |
| SWD 门  | SWCLK/SWDIO（PA14/PA13，两根）        | DPIDR = `0x2ba01477`（实测）  |

注意两扇门**共用 PA13/PA14 两根物理引脚**——芯片上电后侦测仿真器的敲门方式自动
决定走哪扇（openocd 发标准的协议切换序列，无需人工干预）。这就是我们只改一行配置
就完成切换的原因。

> 📖 **术语卡：PA13 / PA14**
> **是什么**：STM32 的两个 GPIO 引脚，出厂默认复用为 SWDIO/SWCLK——复位后默认就是
> 调试口，不用任何初始化。
> **为什么存在**：调试必须"任何固件之前可用"——所以这两脚的调试功能是硬件默认值，
> 固件可以 later 抢走它们当普通 GPIO（作死行为，会把自己锁在外面）。
> **类比**：服务器的 BMC 网口——系统盘还没启动它就在线了。
> ⚠️ 类比边界：BMC 网口是独立硬件；PA13/14 是复用引脚，固件真能抢走（抢走后只剩
> 断电 + BOOT0 故障恢复通道，见序章）。

### 2.4 SWD vs JTAG 全面对照

|                                 | JTAG（1985）                 | SWD（2004）                      |
| ------------------------------- | ---------------------------- | -------------------------------- |
| 信号线                          | 5 根（TCK/TMS/TDI/TDO/TRST） | 2 根（SWCLK/SWDIO）              |
| 协议风格                        | 16 态状态机 + 移位寄存器     | 半双工问答（请求/应答/奇偶）     |
| 速度                            | 慢（状态机开销）             | 快（同样 2MHz 时钟有效吞吐更高） |
| 多器件链式串联                  | ✓（JTAG chain，一颗颗排）    | ✗（点对点）                      |
| 边界扫描（PCB 连通性测试）      | ✓（它的最初用途）            | ✗                                |
| SWO 跟踪输出（printf 低开销版） | ✗                            | ✓（可复用 TDO 脚做单向高速打印） |

我们日常该用哪个？**SWD**——省引脚、更快、支持 SWO。JTAG 留着两个场景：想玩
边界扫描验 PCB 连通性，或调试多器件链。本工程两个配置文件都在：
`openocd.cfg`（JTAG，历史默认）与 `openocd-swd.cfg`（SWD，新增，推荐）。

### 2.5 野火 DAP 是什么角色

> 📖 **术语卡：CMSIS-DAP**
> **是什么**：ARM 定的**仿真器标准协议**——规定 USB 端的命令格式（DAP_Transfer 等）
> 和 SWD/JTAG 端的位操作。野火 DAP（fireDAP）就是实现这个标准的开源固件产品
> （`lsusb` 显示 `NXP Semiconductors fireDAP CMSIS-DAP`，`/dev/ttyACM0`）。
> **为什么存在**：让 openocd/gdb 这类上位机软件"认得"所有兼容仿真器——买谁家的
> 探针都能用同一套工具。
> **类比**：USB 串口的 CDC 标准——CH340/CP2102/FTDI 各家芯片，Linux 都是同一个
> ttyUSB 抽象。CMSIS-DAP 之于调试器，如同 CDC 之于串口。
> ⚠️ 类比边界：串口有波特率要约，CMSIS-DAP 的时钟速率由 openocd 的
> `adapter speed` 决定。

所以链路是三级翻译：**openocd 的意图（"mdw 0xE000ED00"）→ CMSIS-DAP 的 USB 命令 →
DAP 固件在 SWDIO/SWCLK 上打出的位流 → 芯片 DP 收到并执行**。

## 3. 接线

### 3.1 主方式：防呆排线（你现在的状态）

野火 DAP 与挑战者调试座都用 **2×10 防呆盒座**（20 脚，缺口对缺口，方向物理唯一，
插不反）。排线把 20 个触点全部接好：1 根 VREF（电平参考）、9 根 GND、SWDIO（TMS
位）、SWCLK（TCK 位）、TDI/TDO/nTRST（JTAG 用）、nSRST、VCC、两个保留位（fireDAP
上被野火挪作 TXD/RXD 串口扩展，见 ch00b §6.4）。**什么都不用想，咔哒一声。**

### 3.2 备用方式：杜邦线手动接（4 根最小集）——✅ 2026-08-30 实测一次点亮

没有防呆线、或想理解每根线的作用时，从 DAP 的排针（或任何 CMSIS-DAP 探针）接。
实操口诀（实测验证）：**认丝印不认脚号**——DAP 侧 TMS 位=SWDIO、TCK 位=SWCLK，
板侧认 SWDIO/SWCLK/GND/NRST 丝印；断电接线→逐根复查→先板后 DAP 上电。当晚
手接五线（含 nRST）一次通过全套验证（DPIDR/CPUID/活体 RCC/tick 全绿），细节
流程已固化进 fire-f429-flash 技能：

| DAP 侧信号 | 挑战者调试座丝印 | 意义                                                   |
| ---------- | ---------------- | ------------------------------------------------------ |
| SWDIO      | SWDIO            | 数据（PA13）                                           |
| SWCLK      | SWCLK            | 时钟（PA14）                                           |
| GND        | GND              | **共地，必须接**                                       |
| nRESET     | NRST             | 复位线（故障恢复建议接；不接则 halt/断点后要手按复位） |
| VTref      | 3V3              | 电平参考（多数 DAP 必须接才能知道 IO 用 3.3V 电平）    |

```text
野火 DAP                          挑战者调试座（顶边靠右）
┌────────┐   SWDIO  ───────────▶ SWDIO  (PA13)
│  USB   │   SWCLK ────────────▶ SWCLK  (PA14)
│  ▲     │   GND   ────────────▶ GND        ← 共地！
└─笔记本─┘   nRESET ───────────▶ NRST
             VTref  ───────────▶ 3V3
```

三条铁律：**共地优先**（任何跨设备信号的前提）；VTref 别接 5V（BCM/STM32 都是
3.3V 世界）；NRST 平时可不接，但断点实验和故障恢复时强烈建议接（openocd 的
`reset halt` 靠它把芯片按在复位里等你）。

### 3.3 NRST：调试器的"急停按钮"

> 📖 **术语卡：NRST（复位线）**
> **是什么**：一根直接连到芯片复位电路的线，拉低=芯片复位。
> **为什么存在**：调试器需要"在固件跑飞之前接管"的能力——`connect_assert_srst`
> 就是连接时先按住复位、识别完成再松手，抢在跑飞固件把芯片带进深渊之前拿到控制权。
> **类比**：IPMI 的强制重启（power cycle）——系统烂到没响应时的最后手段。
> ⚠️ 类比边界：NRST 是电平信号（按住=保持复位），IPMI 重启是脉冲动作；也正因为它
> 是电平信号，**被杀的 openocd 会话可能把它留在按住态**——表现为之后所有寄存器读
> 出全 0（序章踩过的坑），新会话 `reset halt` 即救。

## 4. Linux 命令实战（Fedora）

### 4.1 环境准备（一次性）

**命令拆解：** `sudo dnf install openocd`

| 部分          | 作用                                                      |
| ------------- | --------------------------------------------------------- |
| `dnf install` | Fedora 的包管理器安装动作                                 |
| `openocd`     | 开源片上调试器，支持 CMSIS-DAP/SWD 全家（含我们全部玩法） |

**你会看到**：一串下载安装，`openocd --version` 能出版本号（本机 0.12.0）。
**失败了先查**：dnf 源是否可用；权限。

工程目录 `~/stm32/f429-freertos` 已备好两个配置文件（内容见第 4.2）。权限说明：
openocd 访问 DAP（`/dev/ttyACM0`）在本机无需 sudo；若你的发行版要求，可加 udev
规则把设备划给 dialout 组。

### 4.2 配置文件逐行读懂

`openocd-swd.cfg` 全文只有 5 行有效内容：

```text
source [find interface/cmsis-dap.cfg]   ← 用哪个仿真器（CMSIS-DAP 家族）
transport select swd                    ← 敲 SWD 那扇门（唯一的协议开关！）
source [find target/stm32f4x.cfg]       ← 被调芯片是 ST F4 系列（含复位/烧录脚本）
adapter speed 2000                      ← SWCLK 2MHz（不稳就降到 1000）
reset_config srst_only srst_nogate connect_assert_srst
                                        ↑ 复位策略：只用 NRST；连接时先按住复位
```

想回 JTAG？复制一份把 `swd` 改 `jtag`——正是我们做的两个文件。

### 4.3 体检：识别芯片（probe）

**命令拆解：** `cd ~/stm32/f429-freertos && openocd -f openocd-swd.cfg -c "init; targets; shutdown"`

| 部分                 | 作用                                                                  |
| -------------------- | --------------------------------------------------------------------- |
| `-f openocd-swd.cfg` | 加载上面的配置                                                        |
| `-c "…"`             | 启动后要执行的动作串（分号分隔）                                      |
| `init`               | 连接芯片：敲 SWD 门 → 读 DPIDR → 经 MEM-AP 识别 CPU                   |
| `targets`            | 打印识别结果                                                          |
| `shutdown`           | 干净退出（**养成习惯**：被 timeout 杀掉的会话可能把 NRST 留在按住态） |

```text
【实测】预期你会看到：
Info : CMSIS-DAP: Interface Initialised (SWD)
Info : SWD DPIDR 0x2ba01477          ← SWD 门牌号；JTAG 模式下这行是 IDCODE 0x4ba00477
Info : [stm32f4x.cpu] Cortex-M4 r0p1 processor detected
Info : [stm32f4x.cpu] target has 6 breakpoints, 4 watchpoints
```

**失败了先查**：DAP 的 USB 有没有枚举（`lsusb | grep -i dap`）→ 排线插没插 →
换个 USB 口（拓展坞供电不足是常见暗坑）。

### 4.4 活体读寄存器：mdw（不用停机！）

**命令拆解：** `openocd -f openocd-swd.cfg -c "init" -c "reset run" -c "sleep 1500" -c "mdw 0x40023800 1" -c "shutdown"`

| 部分             | 作用                                                               |
| ---------------- | ------------------------------------------------------------------ |
| `reset run`      | 复位并放行（固件开始跑）                                           |
| `sleep 1500`     | 等 1.5 秒让固件跑起来（单位毫秒）                                  |
| `mdw <addr> [n]` | memory display word：从地址读 n 个 32 位字——**零侵入**，CPU 继续跑 |

```text
【实测】我们读到的三个"生命体征"：
0xe000ed00: 410fc241      ← CPUID：M4 r0p1（调试单元活着）
0x40023800: 03035883      ← RCC->CR：bit25 PLLRDY=1（时钟树健康，180MHz 在跑）
0x200000e4: 00000634      ← FreeRTOS xTickCount=1584（调度器活着，还在数拍子）
```

这就是序章方法论的落点：**软件状态（tick 在走）+ 硬件状态（PLL 锁定）一次读数全部
掌握**。常用的三个体检地址：CPUID `0xE000ED00`、RCC `0x40023800`、SysTick
`0xE000E010`。

### 4.5 断点与单步：调试器的看家本领

**命令拆解：** `openocd -f openocd-swd.cfg -c "init" -c "reset halt" -c "bp 0x08001780 2 hw" -c "resume" -c "sleep 1000" -c "halt" -c "reg pc" -c "rbp all" -c "shutdown"`

| 部分             | 作用                                                          |
| ---------------- | ------------------------------------------------------------- |
| `reset halt`     | 复位并停在第一条指令（起跑线捏住）                            |
| `bp <addr> 2 hw` | 在地址下硬件断点（2=Thumb 指令长度；芯片有 6 个断点单元 FPB） |
| `resume`         | 放行，跑到断点自动停                                          |
| `halt`           | 兜底强停（若没命中断点）                                      |
| `reg pc`         | 读程序计数器——停在哪条指令上了                                |
| `rbp all`        | 清掉所有断点（好习惯）                                        |

这套「断点二分」是序章定位 PLLRDY 死循环的手术刀，ch17 单步看 PendSV 上下文切换也
是它的进阶（`step` 单步、`make gdb` 进交互式调试器，见 ch16/17 实操）。

### 4.6 日常工作流：四个 make 目标

**命令拆解：** `cd ~/stm32/f429-freertos && make probe / flash / gdb / serial`

| 目标          | 干什么                                                       |
| ------------- | ------------------------------------------------------------ |
| `make probe`  | 第 4.3 节的体检，一行搞定                                    |
| `make flash`  | 烧录+校验+复位（`program … verify reset exit`）              |
| `make gdb`    | 起交互式调试（`target remote :3333`，断点/单步/看变量）      |
| `make serial` | 串口监听（115200 8N1，参数已固化含 `-parenb`，见序章乱码坑） |

### 4.7 常见故障速查（全部是本机踩过的真坑）

| 症状                             | 根因                          | 解法                        |
| -------------------------------- | ----------------------------- | --------------------------- |
| `halt` 超时（偶发）              | 本板对 halt 响应偶发慢        | 重试；或用 `reset halt`     |
| 寄存器读出全 0（连复位值都不是） | 上个会话被杀，NRST 留在按住态 | 新会话 `reset halt` 即救    |
| 完全连不上 DAP                   | USB/拓展坞供电、排线          | `lsusb` 查枚举、换直插口    |
| 报 ap/DP 超时错                  | adapter speed 过高            | `adapter speed 1000` 降速   |
| 两个 openocd 抢 DAP              | 残留会话                      | `pkill openocd` 后重开      |
| 烧录 Verified OK 但芯片跑飞      | 固件自身问题（时钟配错等）    | 序章四层 Bug 实录就是这门课 |
