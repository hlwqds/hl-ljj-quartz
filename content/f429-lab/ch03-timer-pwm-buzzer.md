## 目标（先说结论）

- TIM 外设（Timer，定时器——芯片里专门负责「数拍子」的外设，本章主角 TIM4 就是其中一路）三件套寄存器的分工一句话：**PSC/ARR 决定频率，CCR 决定占空比**——
  `f = TIMCLK / ((PSC+1) × (ARR+1))`，`duty = CCR / (ARR+1)`。全章就是这两个公式的展开。
- 一个容易漏听的规则：**APB 分频不为 1 时，挂在该总线上的定时器时钟自动 ×2**——
  TIM4 名义上挂 45MHz 的 APB1（Advanced Peripheral Bus 1——挂慢速外设的内部总线，下文开卡），实际跑 90MHz。算错这一档，音调全体偏差一倍。
- 实验：驱动 PI11 蜂鸣器按音阶发声。因 PI11 的定时器复用情况待核对，默认实现走
  **「TIM4 更新中断里软件翻转引脚」**的软方波路线（不依赖任何 AF 映射，必响）；
  核对出可用通道后再切硬件 PWM。

## 系统侧类比：hrtimer + duty cycle

| STM32 TIM 侧                      | 系统侧对应                                                                       |
| --------------------------------- | -------------------------------------------------------------------------------- |
| 时基单元（PSC/ARR/CNT）           | hrtimer 的 event device：周期性到期事件                                          |
| 更新中断（UIE/UIF）               | 定时器回调：每个周期打断 CPU 一次                                                |
| 硬件 PWM（CCR 比较+引脚自动翻转） | **内核里没有的直接对应物**——最接近的是 offload：把重复劳动交给硬件，CPU 退出循环 |
| CCR 占空比                        | duty cycle 概念（power management/cgroup cpu.max 同名参数）                      |

> 表右列的 hrtimer、DT、cpu.max 都是你的主场，只作路标不展开；左列每个词下文首次出现处都开卡。

Linux 里 PWM 走的是独立子系统和 DT 节点（Device Tree，设备树——你的主场；`pwm-fans`、 backlight），因为内核深知「让 CPU 引脚级
忙等翻转」是反人类的——`analogWrite()`（Arduino 的「模拟输出」函数，底层就是本章这套 PWM 寄存器）的世界底下全是本章这套寄存器。

## 原理下钻

### 时基单元：一个 16 位计数器加两级分频

> 📖 **术语卡：时基单元（Time Base Unit）**
> **是什么**：定时器里负责「计时」的核心电路：一个计数器 CNT（Counter，16 位，每来一个计数时钟加 1）加 PSC/ARR 两个配置寄存器。
> **为什么存在**：让 CPU 自己数拍子会占着它什么都不干；把「数数」固化成硬件电路，CPU 只管配置和收结果。
> **类比**：厨房机械计时器——拧到几分钟就自己走，到点响铃，期间你继续炒菜。
> ⚠️ 类比边界：机械计时器只能倒计时一路；时基单元可正数/倒数、可级联、还能边数边与 CCR 比较输出波形。

```text
TIMCLK(90MHz) ──/PSC+1──▶ 计数时钟 ──数 ARR+1 拍──▶ 更新事件(UEV)──▶ 重装 CNT
                              │
                              CNT 与 CCR 每拍比较：CNT<CCR 输出高、≥CCR 输出低（PWM 模式 1）
```

- `PSC`（预分频，16 位）+1：把 TIMCLK 分到计数时钟；
- `ARR`（自动重装，16 位）+1：计数器从 0 数到 ARR 归零，产生一次「更新事件」（UEV，Update Event——「一轮数满」的硬件信号；开了 UIE 即借此申请中断，UIF 则是它在状态寄存器里的标志位）；
- `CCR`（捕获/比较）：PWM 模式 1（PWM Mode 1，比较输出的一种波形配置：CNT < CCR 输出有效电平、否则输出无效电平；模式 2 极性正好相反）下，CNT < CCR 输出有效电平——**CCR/(ARR+1) 就是占空比**。

> 📖 **术语卡：预分频器（PSC，Prescaler）**
> **是什么**：把输入时钟先除以 (PSC+1) 的分频器；16 位宽，最多先除以 65536。
> **为什么存在**：定时器计数太快（90MHz 一秒数 9000 万下），先分慢才数得过来、算得清。
> **类比**：手表的秒针——不是每个时钟振荡都走一格，而是每振荡 32768 次走一格。
> ⚠️ 类比边界：PSC 是可编程的，手表分频是焊死的。

> 📖 **术语卡：自动重装寄存器（ARR，Auto-Reload Register）**
> **是什么**：计数器的「数到这里就归零」阈值；CNT 从 0 数到 ARR 后回 0，并发更新事件。
> **为什么存在**：只分频还不够——PSC 定「数多快」，ARR 定「数多大算一轮」，两者相乘才能凑出任意想要的周期。
> **类比**：田径场一圈 400 米——跑到线就回起点重新跑，跑一圈=一个周期。
> ⚠️ 类比边界：跑道长度固定，ARR 随时可改（且有影子寄存器防撕裂，见代码走读节术语卡）。

> 📖 **术语卡：捕获/比较寄存器（CCR，Capture/Compare Register）**
> **是什么**：与 CNT 实时比大小的阈值寄存器。输出场景（比较）：CNT < CCR 引脚出有效电平，否则出无效——这就画出 PWM；输入场景（捕获）：记录引脚跳变时的计数值，本章不用。
> **为什么存在**：让「什么时候翻引脚」也由硬件自动完成，占空比只需写一个数。
> **类比**：切蛋糕的刻线——一圈 ARR+1 块，前 CCR 块给你（高电平），其余不给（低电平）。
> ⚠️ 类比边界：蛋糕块是离散的，比较发生在每个计数拍上，时间粒度=计数周期（本例 1µs）。

又是两个「+1」：和 ch01 的 LOAD+1 同一家族。周期公式：

```text
f = TIMCLK / ((PSC+1) × (ARR+1))        duty = CCR / (ARR+1)
```

> 📖 **术语卡：占空比（Duty Cycle）**
> **是什么**：一个周期内输出「有效电平」的时间占比，0–100%；PWM 模式 1 下 = CCR/(ARR+1)。
> **为什么存在**：同一频率下占空比是方波唯一的自由度——调光、调速、舵机角度全靠它。
> **类比**：红绿灯的绿灯时长占整个信号周期的比例——周期不变，绿灯越短，通车「功率」越小。
> ⚠️ 类比边界：红绿灯是宏观统计；PWM 调功率靠被控对象（LED/电机/蜂鸣器膜片）对高频斩波的惯性滤波，不是逐周期生效。

### APB 定时器时钟翻倍规则（算错的头号来源）

> 📖 **术语卡：AHB 与 APB（两级内部总线）**
> **是什么**：芯片内部的数据公路。AHB（Advanced High-performance Bus）快，挂 CPU、内存、DMA；APB（Advanced Peripheral Bus）慢而省电，挂 USART、定时器等外设。
> **为什么存在**：低速外设不需要也不配跑满 CPU 频率，分成两级总线让快慢设备各走各的车道，门数和功耗都省。
> **类比**：机房的核心交换机（AHB，背板带宽高）下挂接入交换机（APB，端口多但每口慢）——你的主场。
> ⚠️ 类比边界：交换机是包转发无主从语义；总线是主从式同步读写，且 APB1/APB2 最高频率受限（F429 为 45/90MHz）。

RM0090（ST 官方《STM32F4 参考手册》的编号，F4 系列寄存器的字典）的原意：APB 分频本来是给慢速外设降频的，但定时器不该陪着降——于是硬件规定：

| 情形         | 定时器时钟 |
| ------------ | ---------- |
| APB 分频 = 1 | = PCLK     |
| APB 分频 ≠ 1 | = PCLK × 2 |

（PCLK = Peripheral Clock，APB 总线时钟的简称；TIMCLK = 定时器实际工作时钟——两者被上表规则拴在一起。）

套进本工程（序章验证的时钟树）：

| 总线 | 分频 | PCLK   | 定时器时钟  | 挂哪些定时器（本章相关）      |
| ---- | ---- | ------ | ----------- | ----------------------------- |
| APB1 | /4   | 45 MHz | **90 MHz**  | TIM2–7、TIM12–14（TIM4 在此） |
| APB2 | /2   | 90 MHz | **180 MHz** | TIM1/8/9/10/11                |

所以下文所有算例的 TIMCLK 都按 **90MHz**（TIM4@APB1）取值。系统侧类比：网卡 PPS 时钟与
总线时钟的倍频关系——设备的「名义挂载频率」和「实际工作频率」可以差一档，查手册而不是想当然。
（⚠️ 类比边界：PPS 语境是「对齐绝对时刻」，这里只借「名义频率 ≠ 实际频率」这一点，别整套搬。）

### 算例表：4kHz/50% 的具体数与音阶表

先定 PSC=89：计数时钟 = 90MHz/90 = **1MHz**（1 tick = 1µs，心算友好），于是
`ARR = 1e6/f − 1`、`CCR = (ARR+1)/2`：

| 目标频率 | 用途      | PSC | ARR  | CCR（≈50%） | 实际频率（换算误差）           |
| -------- | --------- | --- | ---- | ----------- | ------------------------------ |
| 1 kHz    | 低音参考  | 89  | 999  | 500         | 1000.00 Hz（整除）             |
| 4 kHz    | 本章算例  | 89  | 249  | 125         | 4000.00 Hz（整除）             |
| 8 kHz    | 高音参考  | 89  | 124  | 62          | 8000.00 Hz（CCR 取整致 49.6%） |
| 523 Hz   | C5（do）  | 89  | 1911 | 956         | 523.29 Hz                      |
| 587 Hz   | D5（re）  | 89  | 1703 | 852         | 586.85 Hz                      |
| 659 Hz   | E5（mi）  | 89  | 1516 | 758         | 659.63 Hz                      |
| 698 Hz   | F5（fa）  | 89  | 1432 | 716         | 698.47 Hz                      |
| 784 Hz   | G5（sol） | 89  | 1275 | 638         | 783.70 Hz                      |
| 880 Hz   | A5（la）  | 89  | 1135 | 568         | 880.28 Hz                      |
| 1047 Hz  | C6（do'） | 89  | 954  | 477         | 1047.12 Hz                     |

（音名频率取十二平均律（把一个八度按 2 的 1/12 次方等比切成 12 份的定音法）常用值；「实际频率」列展示取整误差——1MHz 时基下偏差都在 0.05% 内，
远小于人耳对音高的分辨阈值。）

**占空比与音量的数学**：无源蜂鸣器吃的是方波的基波分量，其幅度 ∝ sin(π·duty)——
50% 时最大；把占空比压到 10%，基波只剩 sin(18°)≈0.31 倍，声音明显变小。
「音调=频率、（无源）音量≈占空比」的量化版。

## 实验：让 PI11 蜂鸣器唱歌

### 板上事实与待核对项

已知（官方底板文档）：蜂鸣器接 **PI11**（GPIO 端口 I 的第 11 脚；GPIO = General Purpose
Input/Output，通用输入输出——芯片上可由软件控制高低电平的引脚，STM32 按「端口字母+脚号」命名），
**置高即响**。这句「置高即响」信息量很大但没说全：

> 📖 **术语卡：有源蜂鸣器 vs 无源蜂鸣器**
> **是什么**：有源（「源」=内置振荡源）蜂鸣器内部自带振荡电路，通直流即发固定音；无源蜂鸣器只是一片发声片，必须外部喂方波才响。
> **为什么存在**：有源省事（一根 GPIO 直接报警）；无源可控（频率即音调，能放旋律）——本章「唱歌」只有无源才玩得转。
> **类比**：有源像商场防盗门自带警笛模块（触发就响固定音）；无源像喇叭（喂什么信号出什么声）。
> ⚠️ 类比边界：两者外观几乎一样（黑圆柱），区分靠听（加直流：长鸣=有源、只咔一声=无源）或看器件丝印。

| 待核对项                                  | 影响                                                                                                   |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 有源还是无源蜂鸣器                        | 有源（内置振荡源）：GPIO 置高就响固定音；**改频率无用，改占空比≈改音量**。无源：必须喂方波，频率即音调 |
| 驱动电路形态（直推/三极管，高/低有效）    | 「置高即响」至少说明是**高有效**；三极管还是直推影响电流裕量                                           |
| PI11 有无 TIM 复用通道（datasheet AF 表） | 决定能不能走硬件 PWM 直出                                                                              |

**小白词快释**（上表黑话一次清完）：

- **直推** = GPIO 引脚直接接蜂鸣器；**三极管** = 晶体管开关，用引脚的小电流放大驱动蜂鸣器需要的大电流；
- **高/低有效** = 引脚是高电平（还是低电平）时器件工作——「置高即响」已说明是高有效；
- **datasheet AF 表** = 数据手册里的「引脚复用功能」表：每个引脚能交给哪些片上外设（定时器、串口……）都列在里面，AF2 这类编号就是表中行号；
- **丝印** = 元器件表面印的型号小字。

**适配策略**：默认实现用「TIM4 更新中断里翻转 PI11」的软方波——频率完全由 ARR 控制，
不依赖 AF 映射，对有源/无源都能出可听效果（无源听到音调变化，有源听到断续/音量变化，
这个差异本身就是「有源/无源」的听诊器）。核对后若 PI11 有通道，再切硬件 PWM 版。

### 代码：软方波 + 音阶播放

```c
/* ---------- TIM4 软方波：更新中断里翻转 PI11（不依赖 AF 映射的稳妥路线） ---------- */

static volatile uint32_t g_note_ms; /* 当前音符剩余时长（g_ms 时基，ch01 地基） */

static void buzzer_init(void)
{
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOIEN;    /* PI 口时钟；GPIOI @0x40022000 */
    GPIOI->MODER = (GPIOI->MODER & ~(3u << (11 * 2))) | (1u << (11 * 2)); /* PI11=推挽输出 */
    GPIOI->BSRR = (1u << (11 + 16));        /* 先静音：BSRR 高半字=复位（置低） */

    RCC->APB1ENR |= RCC_APB1ENR_TIM4EN;     /* TIM4 时钟 @0x40000800（APB1，定时器时钟=45×2=90MHz） */
    TIM4->PSC = 89u;                        /* 90MHz/90 = 1MHz 计数时钟，此后 ARR=1e6/f−1 */
    TIM4->ARR = 249u;                       /* 默认 4kHz：f = 1e6/(249+1) */
    TIM4->DIER = TIM_DIER_UIE;              /* 更新中断使能 */
    NVIC->ISER[0] = (1u << 30);             /* TIM4_IRQn=30 → ISER0 bit30 */
    TIM4->CR1 = TIM_CR1_CEN;                /* 开跑。PSC 是影子寄存器，本拍生效靠下一次 UEV 装载 */
}

static void tone_set(uint32_t arr) { TIM4->ARR = arr; } /* 换音=换 ARR（1MHz 时基下 arr=1e6/f−1） */

void TIM4_IRQHandler(void)
{
    TIM4->SR = ~(uint32_t)TIM_SR_UIF;       /* 清更新标志（w1c，直接写，禁 |=） */
    GPIOI->ODR ^= (1u << 11);               /* 每次更新翻转一次 → 引脚方波频率 = 更新率/2 */
}
```

**代码走读（软方波版）**——每条寄存器操作逐条翻译：

| 语句                                   | 拆解                                                                                                                                                       |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RCC->AHB1ENR \|= RCC_AHB1ENR_GPIOIEN` | RCC（Reset and Clock Control，全芯片复位/时钟控制单元）的 AHB1 时钟使能寄存器；STM32 外设默认断电，**先开时钟**再访问它的寄存器，否则读回全 0              |
| `GPIOI->MODER = … (1u << (11 * 2))`    | MODER（Mode Register，模式寄存器）每个引脚占 2 位：00=输入、01=通用输出、10=AF 复用、11=模拟；此处 PI11 的 2 位写成 01=输出                                |
| `GPIOI->BSRR = (1u << (11 + 16))`      | BSRR（Bit Set/Reset Register）低半字（bit0–15）写 1 置高、高半字（bit16–31）写 1 置低；一次写入原子生效，不像「读-改-写 ODR」可能被中断插队撕裂            |
| `RCC->APB1ENR \|= RCC_APB1ENR_TIM4EN`  | APB1 总线的时钟使能寄存器，给 TIM4 上电（注意：TIM4 挂 APB1，但定时器时钟按 ×2 规则=90MHz）                                                                |
| `TIM4->DIER = TIM_DIER_UIE`            | DIER（DMA/Interrupt Enable Register）的 UIE 位=Update Interrupt Enable，允许「一轮数满」事件申请中断                                                       |
| `NVIC->ISER[0] = (1u << 30)`           | NVIC（Nested Vectored Interrupt Controller，Cortex-M 内核自带的中断调度器）的中断使能寄存器组，每位管一个中断号；TIM4 的中断号是 30，落在 ISER[0] 的 bit30 |
| `TIM4->CR1 = TIM_CR1_CEN`              | CR1（Control Register 1）的 CEN 位=Counter Enable，计数器开跑                                                                                              |
| `TIM4->SR = ~(uint32_t)TIM_SR_UIF;`    | SR（Status Register）的 UIF=Update Flag；w1c（write-1-to-clear，写 1 清零）机制——想清哪位就向哪位写 1，所以必须取反直写，用 `\|=` 会把别的标志误清掉       |
| `GPIOI->ODR ^= (1u << 11)`             | ODR（Output Data Register，输出数据寄存器）按位异或=翻转；BSRR 只能置/清不能翻转，所以翻转用 ODR                                                           |

> 📖 **术语卡：影子寄存器（Shadow Register）**
> **是什么**：真正驱动电路的寄存器（影子）前再垫一层用户写入的缓存（预装载寄存器）；写入只进缓存，等下一次「更新事件」才整体搬进影子生效。
> **为什么存在**：改 ARR 时计数器可能正数到一半，立即生效会让这一轮时长错乱；缓存+统一切换保证周期原子更新、波形无毛刺。
> **类比**：DNS 的缓存+TTL——你改的是权威记录，TTL 到期解析才真正切换——你的主场。
> ⚠️ 类比边界：DNS 是尽力而为的最终一致；影子寄存器是硬件保证的、精确到下一个更新事件的原子切换。

> 📖 **术语卡：推挽输出（Push-Pull）**
> **是什么**：GPIO 的一种输出结构：上下两只晶体管轮流导通——输出高时上管把电流「推」出去，输出低时下管把线「拉」回地，两个方向都有驱动能力。
> **为什么存在**：对比「开漏输出」（只有下管，只能拉低、高电平要靠外部上拉电阻），推挽能主动给出两种电平且边沿陡峭，驱动蜂鸣器这类负载正合适。
> **类比**：电梯门的双向电机——开、关两个方向都出力；开漏像只有关门弹簧，开门全靠行人自己推（=外部上拉）。
> ⚠️ 类比边界：开漏不是缺陷，它的真实价值是线与（多器件共享一根线）和电平转换。

注意软方波的**二分之一陷阱**：翻转产生方波，引脚周期 = 2×更新周期，所以 4kHz 引脚频率
要求更新中断跑 8kHz（ARR=124）。上表「ARR」列对应更新率，软方波路线播放时**每项 ARR 减半重算**
（如 C5 需更新率 1046Hz → ARR=955）。这正是「软方波虽稳，代价是中断频率×2 + CPU 常驻」——
硬件 PWM 的价值所在。

播放器（小星星：do do sol sol la la sol— fa fa mi mi re re do—）：

```c
static const struct {
    uint16_t arr;   /* 更新率对应的 ARR（软方波路线已含 ×2） */
    uint16_t ms;    /* 时值 */
} song[] = {
    {955, 350}, {955, 350}, {637, 350}, {637, 350}, {567, 350}, {567, 350}, {637, 700},
    {715, 350}, {715, 350}, {757, 350}, {757, 350}, {851, 350}, {851, 350}, {955, 700},
};

static void play_song(void)
{
    for (uint32_t i = 0; i < sizeof(song) / sizeof(song[0]); i++) {
        tone_set(song[i].arr);
        uint32_t until = g_ms + song[i].ms;
        while ((int32_t)(g_ms - until) < 0) { } /* 忙等音符时值（用 ch01 的 g_ms） */
    }
    TIM4->CR1 &= ~TIM_CR1_CEN;  /* 曲终停表=静音（ODR 停在随机电平，显式置低更稳） */
    GPIOI->BSRR = (1u << (11 + 16));
}
```

**代码走读（播放器）**：

- `sizeof(song) / sizeof(song[0])`：数组总字节数除以单个元素字节数=元素个数；C 数组不自带长度，这是数元素个数的标准写法。
- `while ((int32_t)(g_ms - until) < 0)`：两个无符号数相减再按**有符号**解释——即便 `g_ms`（毫秒计数）将来回绕（wrap around，从最大值跳回 0），差值符号仍然正确。这是嵌入式防「时间回绕」的惯用法，内核 `time_after` 宏同一招——你的主场。
- `TIM4->CR1 &= ~TIM_CR1_CEN;`：清 CEN 位停表，更新事件停发，再显式置低 PI11 收尾静音。

### 硬件 PWM 版（核对出通道后启用）

若 datasheet AF 表核对出 PI11 有 TIM 通道，删掉中断翻转，改成比较输出直出
（以 TIM4_CH1 为例，引脚 AF 编号按表回填）：

```c
TIM4->CCMR1 = (6u << 4) | TIM_CCMR1_OC1PE; /* OC1M=110: PWM 模式 1；CCR 预装载       */
TIM4->CCER  = TIM_CCER_CC1E;               /* 使能 CH1 输出，默认高有效              */
TIM4->CCR1  = 125;                         /* ARR=249 时占空比 50%——频率不经过 CPU   */
TIM4->CR1   = TIM_CR1_ARPE | TIM_CR1_CEN;  /* ARR 也走影子寄存器，改频率不毛刺        */
TIM4->EGR   = TIM_EGR_UG;                  /* 手动产生一次更新事件，立刻装载 PSC/ARR  */
/* 引脚侧还需 MODER=AF + AFR 选对 AF 编号——全部依赖「待核对」的 AF 表，故此处只留骨架 */
```

**代码走读（硬件 PWM 版骨架，先认字再说）**：

| 语句                                            | 拆解                                                                                                                                      |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `TIM4->CCMR1 = (6u << 4)   \| TIM_CCMR1_OC1PE;` | CCMR1（Capture/Compare Mode Register 1）的 OC1M（Output Compare 1 Mode，3 位）=110 表示「PWM 模式 1」；bit4 恰是 OC1M 的起始位，故 `6<<4` |
| `TIM_CCMR1_OC1PE`                               | OC1 Preload Enable——给 CCR 也配上影子寄存器，写入后到下个更新事件才切换，防占空比跳变撕裂波形                                             |
| `TIM_CCER_CC1E`                                 | CC Enable——把该通道的比较结果真正接到引脚上（默认高有效，即 CCR 有效段输出高电平）                                                        |
| `TIM_CR1_ARPE`                                  | ARR Preload Enable——ARR 同样走影子，运行中改频率不产生半截周期                                                                            |
| `TIM_EGR_UG`                                    | EGR（Event Generation Register）的 UG 位：软件手动制造一次更新事件，把刚写的 PSC/ARR/CCR 立刻从缓存装进影子，不必干等第一次数满           |

硬件版的关键收益：**更新中断没了，CPU 零参与**——和 ch10 把 memcpy 交给 DMA（Direct Memory Access，绕过 CPU 直接搬数据的搬运工外设）是同一哲学：
重复劳动下沉给硬件，CPU 只在「换音符」时写一次寄存器。

## 与 FreeRTOS / ESP32 对照

- **ESP32 LEDC**（LED Controller，ESP32 里专管 PWM 输出的外设）：`ledc_timer_config()`（频率+精度位）+ `ledc_channel_config()`（占空比）——
  正是 PSC/ARR 与 CCR 的驱动层包装；LEDC 的 duty resolution 位宽对应「ARR 开多大」，
  频率与分辨率共享同一颗计数器，此消彼长（本表 ARR 249≈8 位精度同理）。
- **FreeRTOS 下**：换音符的「到点做事」若用软件定时器（`xTimerStart`），分辨率受 tick 与
  定时器任务排队影响（本工程 tick——RTOS 心跳节拍，你的主场——=1kHz，jitter 可达毫秒级）——音乐节拍勉强、方波生成完全不可用。
  硬件定时器中断 + `*_FromISR` 通知才是正路，而最优解仍是硬件 PWM 让 CPU 彻底离场。
- **中断负载的算术**：软方波跑 8kHz 更新中断 = 每秒 8 万次 ISR（Interrupt Service Routine，中断服务例程——你的主场）进出（每次几十周期），
  约吃掉百分之几的 CPU——单看无害，但它是从「零成本」滑向「常驻成本」的第一级台阶，
  ch10 的 DMA 章会把这组账算到底。

| 部分         | 作用                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------- |
| `mdw`        | Memory Display Word——按 32 位「字」为单位读出并打印一片物理内存（兄弟命令：`mdb` 按字节、`mdh` 按 16 位半字） |
