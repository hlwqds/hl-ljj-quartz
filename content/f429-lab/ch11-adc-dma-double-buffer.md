## 目标（先说结论）

- ch04 是「要一次、读一次」的点读模式；本章把它升级为**无 CPU 的采样流**：连续转换 + DMA
  循环模式（连续转换=CONT 位：软件触发一次后硬件自动接着采；循环模式=CIRC 位：DMA 搬到
  缓冲尾自动回卷重装），ADC 结果被硬件逐点搬进环形缓冲——CPU 与采样过程**零耦合**。
- 主角是**半满（HT）/全满（TC）双中断**：缓冲前半被处理时，硬件正在写后半——两块内存无限
  乒乓，**零拷贝采样流**（处理函数直接在缓冲上原地读，没有第二次搬运）。
- 一笔设计账先记结论：**中断频率 = 采样率 ÷ 半区点数**。本章满速（≈45.7kS/s；kS/s=千样本每
  秒）、半区 32 点 →
  每 0.70ms 一次中断、HT 与 TC 合计 ≈2858 次/秒，CPU 税 ≈**0.16%**——ch04 轮询版同样的速率
  是 100% CPU（每点忙等 21.9µs）。
- 实验：旋钮波形在串口上画**ASCII 示波器**——ch04 的静态读数升级为连续流；判据之一是
  **HT 计数 : TC 计数 ≈ 1:1**（乒乓对称性的直接证据）。

> 📖 **术语卡：ADC（Analog-to-Digital Converter，模数转换器）**
> **是什么**：把引脚上的连续电压量化成整数的电路。两个核心参数：分辨率（每个点用几比特表示——F429 的 ADC 是 12 位，输出 0–4095，对应 0–VREF+）和采样率（每秒出几个点，单位 S/s 或 kS/s）。
> **为什么存在**：CPU 只会算数不会「读电压」；旋钮、传感器、麦克风全是模拟量，进数字世界必须先过这道门。
> **类比**：音频采集卡的采样精度/采样率双参数——12bit@45.7kHz 的一个具体实例。
> ⚠️ 类比边界：声卡采的是 0 附近的交流小信号；ADC 单端量程 0–VREF+（本板 3.3V），读数=电压×4095/3.3。

## 系统侧类比：descriptor ring 与 ALSA period

| ADC+DMA 侧            | 系统侧对应                                        |
| --------------------- | ------------------------------------------------- |
| DMA 循环模式（CIRC）  | 网卡 RX descriptor ring：到尾自动回卷             |
| HT/TC 双中断          | ring 的双指针：硬件写指针过半/到底各通知一次      |
| 半区乒乓              | ALSA period：音频每填满一个 period 醒一次应用     |
| NDTR 剩余计数         | ring 中 tail 到 head 的距离（消费进度探头）       |
| 处理函数原地读半区    | 零拷贝收包：直接在 DMA buffer 上解析，不再 memcpy |

| 硬件 OVR 标志         | NIC 的 rx_no_buffer：连 DMA 都没搬走的最后告警    |

（ch20/21）会把同一骨架放大到 100Mbps。

## 原理下钻

### 从 ch04 改三处：扫描、连续、DMA 请求

ch04 的 `adc_init()` 原样保留，增量只有三行位：

```c
ADC1->CR1 |= ADC_CR1_SCAN;               /* ① 扫描模式：按 SQR 表逐项推进（表长 1 下与
                                            单通道连续等价，DMA 场合的标准姿势） */
ADC1->CR2 |= ADC_CR2_DMA | ADC_CR2_DDS;  /* ② DMA 请求使能 + 持续请求：每次转换完成都
                                            发一个 DMA 请求，而不是只发一轮序列 */
ADC1->CR2 |= ADC_CR2_CONT;               /* ③ 连续转换：软件触发一次后自续，速率封顶 */
```

EOC 中断不开（EOC=End Of Conversion，转换完成标志）：DMA 模式下 EOC 由 DMA 读 DR 消化，人再
开就是 ch10 说过的「抢 DR 中断风暴」。
三 ADC 共用区的 `ADC->CCR`（ADC1/2/3 三个转换器共享的公共配置寄存器）保持独立模式默认
（DMA 位段=00——那是多 ADC 模式用的，独立模式
不碰，ch04 已定过 ADCPRE）。

### DMA2 Stream4 Ch0：循环模式的搬运单

> 📖 **术语卡：循环模式（CIRC，Circular Mode）**
> **是什么**：DMA stream 的一种工作模式（CR.CIRC=1）：NDTR 数到 0 时不停止、不报「传完」就停工，而是自动把 NDTR 重装回初始值、内存地址回卷到 M0AR 起点，无限循环地写这块缓冲——一块内存被当成环形缓冲（ring buffer）用。
> **为什么存在**：连续数据流（ADC 采样、串口接收）没有「搬完」一说；有了 CIRC，CPU 不必每次 TC 中断后重挂 stream（ch10 每帧都要的「EN=0→重装→EN=1」在这里整段消失）。
> **类比**：网卡 RX descriptor ring：写指针到尾自动回卷到头——硬件里长出来的 ring（你的主场）。
> ⚠️ 类比边界：DMA 的「ring」只有一块连续内存+回卷，没有描述符链；消费者判断进度靠读 NDTR 反推，而不是读 next-to-clean 指针。

ADC1 挂 APB2，路由表只给两条路：**Stream0 Ch0 或 Stream4 Ch0**（RM0090 Table 43，写作时已
自查）。ch10 已占 DMA2 的 S2/S7，本章选 **S4**（S0 留作备选）。搬运单与 ch10 的差异只有三处：
**CIRC=1（到尾自动回卷）、PSIZE/MSIZE=16 位（ADC 数据是半字）、HTIE 打开（半区通知）**：

```c
#define ADC_HALF 32u                        /* 半区 32 点 */
#define ADC_RING (2u * ADC_HALF)            /* 环深 64 点 */
static uint16_t g_adc_ring[ADC_RING];       /* 唯一的缓冲：两半区原地乒乓，零拷贝 */

static volatile uint32_t g_ht_cnt, g_tc_cnt, g_te_cnt, g_half; /* g_half: 1=前半就绪 2=后半 */

static void adc_dma_start(void)
{
    RCC->AHB1ENR |= RCC_AHB1ENR_DMA2EN;
    DMA2_Stream4->CR = 0;
    while (DMA2_Stream4->CR & DMA_SxCR_EN) { }
    DMA2->HIFCR = DMA_HIFCR_CTCIF4 | DMA_HIFCR_CHTIF4 | DMA_HIFCR_CTEIF4
                | DMA_HIFCR_CDMEIF4 | DMA_HIFCR_CFEIF4;
    DMA2_Stream4->PAR  = (uint32_t)&ADC1->DR;         /* 源：ADC 数据寄存器（固定） */
    DMA2_Stream4->M0AR = (uint32_t)g_adc_ring;
    DMA2_Stream4->NDTR = ADC_RING;                    /* 64 项，数到 0 自动重装 */
    DMA2_Stream4->CR = DMA_SxCR_CIRC                  /* 循环：ring 的硬件化身 */
                     | DMA_SxCR_MINC
                     | (1u << 11) | (1u << 13)        /* PSIZE/MSIZE=16bit */
                     | DMA_SxCR_HTIE | DMA_SxCR_TCIE | DMA_SxCR_TEIE;
    NVIC->IP[60] = 0x60;                              /* DMA2_Stream4=IRQ60（0x60 的含义见 ch12） */
    NVIC->ISER[1] = (1u << 28);
    DMA2_Stream4->CR |= DMA_SxCR_EN;

    adc_init();                                       /* ch04 原样 + 上面三行改动 */
    ADC1->CR2 |= ADC_CR2_SWSTART;                     /* 软件首发：之后 CONT 自续 */
}

void DMA2_Stream4_IRQHandler(void)
{
    uint32_t hisr = DMA2->HISR;
    if (hisr & DMA_HISR_HTIF4) {                      /* 写指针过半：前半区完整就绪 */
        DMA2->HIFCR = DMA_HIFCR_CHTIF4; g_ht_cnt++; g_half = 1;
    }
    if (hisr & DMA_HISR_TCIF4) {                      /* 写指针到底回卷：后半区完整就绪 */
        DMA2->HIFCR = DMA_HIFCR_CTCIF4; g_tc_cnt++; g_half = 2;
    }
    if (hisr & DMA_HISR_TEIF4) {                      /* 传输错误：ch13 会故意触发它 */
        DMA2->HIFCR = DMA_HIFCR_CTEIF4; g_te_cnt++;
    }
}
```

**命令拆解：** `DMA2_Stream4->CR = DMA_SxCR_CIRC | DMA_SxCR_MINC | (1u << 11) | (1u << 13) | DMA_SxCR_HTIE | DMA_SxCR_TCIE | DMA_SxCR_TEIE;`（ADC 流的控制字拼装）

| 部分            | 作用                                                                        |
| --------------- | --------------------------------------------------------------------------- |
| `DMA_SxCR_CIRC` | bit8：循环模式——NDTR 到 0 自动重装、地址回卷（ch10 的每次重挂被它整体替代） |
| `DMA_SxCR_MINC` | bit9：内存地址逐项递增（环里逐格写）                                        |
| `(1u << 11)`    | bit12:11=01：PSIZE=16 位——外设侧（ADC 的 DR）按半字取                       |
| `(1u << 13)`    | bit14:13=01：MSIZE=16 位——内存侧也半字（uint16_t 环的元素宽度）             |
| `DMA_SxCR_HTIE` | bit3：半传输中断使能——NDTR 数到一半（写指针过半）时通知                     |
| `DMA_SxCR_TCIE` | bit4：传输完成中断使能——数到 0（写指针到底回卷）时通知                      |
| `DMA_SxCR_TEIE` | bit2：传输错误中断使能（位号与 ch10 的 CR 位表一致）                        |
| 没写 CHSEL      | CHSEL=000 复位默认即 Channel 0——ADC1 的请求线正是 Ch0，这行才能「少一个宏」 |

**对照 ch10**：CR 长得几乎一样，差异恰好是本章三处改动——多了 CIRC、宽度从字节变半字、多了
HTIE。中断标志/写 1 清零（HIFCR 清 HISR）体系与 ch10 完全相同，只是 S4 在高半区（HISR/HIFCR）。

**命令拆解：** `NVIC->IP[60] = 0x60; NVIC->ISER[1] = (1u << 28);`（开 DMA2_Stream4 中断）

| 部分            | 作用                                                                    |
| --------------- | ----------------------------------------------------------------------- |
| `NVIC->IP[60]`  | 优先级数组按 IRQ 号下标；60=DMA2_Stream4 的向量号（比 ch10 的 S2 多 2） |
| `0x60`          | 优先级字节，M4 只用高 4 位 → 优先级 6（ch12 连本带利讲透）              |
| `NVIC->ISER[1]` | 使能寄存器第 1 组（管 IRQ32–63）                                        |
| `(1u << 28)`    | 组内位号：32×1+28=IRQ60                                                 |

**你会看到**：NDTR 在 0–63 间滚动、`ht`/`tc` 计数齐涨——写指针在环上不停转圈。
**失败了先查**：`mdw` 读 S4CR 确认 CIRC/HTIE/EN 都写进去了；ht 只涨 tc 不涨→查半字宽度（PSIZE/MSIZE）；全不涨→查 ADC1_CR2 的 DMA/DDS/CONT 与 SWSTART。

### HT/TC：为什么这就是「无缝双缓冲」

> 📖 **术语卡：半满/全满双中断（HT/TC）与乒乓（ping-pong）**
> **是什么**：HT（Half Transfer，半传输）=NDTR 数到初始值一半时置位的标志/中断；TC（Transfer Complete，全满）=数到 0（回卷）时置位的标志/中断。开启 HTIE+TCIE 后，一圈环产生两个通知点，把缓冲逻辑上劈成前后两半——**乒乓**：任一时刻 DMA 写这一半、CPU 读另一半，下次交换。
> **为什么存在**：只有一个 TC 的话，CPU 必须在「DMA 从头写到尾」的整段时间内不碰缓冲，否则要等一整圈才拿到数据（延迟一整环）；劈成两半后延迟减半，且读写区永不重叠——无缝双缓冲不用两块内存、不用硬件切指针。
> **类比**：ALSA/audio 的 period 中断：缓冲分 period，每填满一段唤醒一次应用；也是网卡 ring 双指针（next_to_use/next_to_clean）的过半/到底版（你的主场）。
> ⚠️ 类比边界：网卡双指针可以任意粒度消费；HT/TC 的通知点是死的（只有「过半/到底」两处），消费者必须在下个通知到来前处理完当前半区，否则就是逻辑覆盖。

```text
        ┌─────────── 环形缓冲 64 点（DMA 独占写，main 独占读半区）───────────┐
        │  前半区 [0..31]      │  后半区 [32..63]        │ （回卷→前半区）   │
        └──────────────────────┴─────────────────────────┴───────────────────┘
 t0  DMA 写前半 ──过半──► HT 中断：main 处理 [0..31]，DMA 同时写 [32..63]
 t1                ──到底──► TC 中断：main 处理 [32..63]，DMA 回卷写 [0..31]
 t2                ──再过半──► HT …（无限乒乓，永不停机、永不撕裂数据）

 无缝性论证：main 的处理窗口 = 半区填充时间（0.70ms@满速）。只要处理比这快，
 硬件永远在写「另一半」——生产者与消费者各碰各的半区，零拷贝、零等待。
```

这正是网卡 descriptor ring 的双指针心智模型：硬件指针（写）与应用指针（读）之间的距离就是
可消费量（你的主场：next_to_use 与 next_to_clean 同构）；HT/TC 只是「指针过半/到底」的两个通知点。
ch10 的 CR.DBM 双缓冲（DBM=Double Buffer Mode：硬件在 M0AR/M1AR 两个缓冲地址间自动切换，
就是 ch10 寄存器表里 M1AR 那行的伏笔）解决的是同构问题——**硬件乒乓换缓冲指针，半区乒乓原地
切半**，后者省一半内存、且与循环模式天然兼容。

### 设计算例：采样率 → 缓冲深度 → 中断频率

软件触发 + CONT 的满速由 ch04 的时序公式钉死：`f_s = ADCCLK/(480+12) = 22.5MHz/492 ≈ 45.73kS/s`
（480 个 ADCCLK 周期用于采样-保持、12 个周期用于转换出数，合计 492 个周期产出一个点）。
设计自由度全在「半区点数 N」——**中断间隔 T = N/f_s，每次中断处理 N 个点**：

| 场景                 | f_s        | 环深 | 半区 N | 中断间隔 T=N/f_s | 通知频率（HT+TC） |
| -------------------- | ---------- | ---- | ------ | ---------------- | ----------------- |
| 精确低速流（进阶节） | 1 kS/s     | 32   | 16     | 16 ms            | 125/s             |
| 语音级               | 8 kS/s     | 64   | 32     | 4 ms             | 500/s             |
| 本章满速             | 45.73 kS/s | 64   | 32     | 0.70 ms          | ≈2858/s           |

选型的两难一目了然：N 大→中断稀、省 CPU，但延迟与内存涨；N 小→实时性好、但中断税涨。
本章满速档的账：2858 次/s × ≈百十个周期 ≈ 0.31M 周期/s ≈ **180MHz 的 0.16%**——对照 ch04
轮询版每点忙等 21.9µs（45.73kS/s 下恰好 100% CPU），这就是「无 CPU 的采样流」的含义。

### 两种 overrun：硬件 OVR 与逻辑覆盖

ch04 埋的 OVR 伏笔在这里收尾（OVR=Overrun 溢出：ADC 的 DR 里上一个结果还没被读走、新结果
又到了时置位的硬件标志）。DMA 模式下 DR 总被 DMA 及时读走，**硬件 OVR 几乎不会置位**
（只有 DMA 停机/配置错才会）；真实的风险是**逻辑覆盖**：消费者太慢，新半区把没处理完的半区
冲掉——症状不是标志位，而是波形上出现「新旧拼接的断层」。这正是 ch06 环形缓冲丢新/丢旧
问题的流式版本：本章用 `g_half` 的覆盖语义（ISR 只写、main 慢了就被新值覆盖）+ 差值计数
把丢帧如实记账。

## 实验：串口 ASCII 示波器

```c
static void putc_raw(uint8_t c)          /* 控制面打印：轮询 TX。数据面走 DMA、控制面走
                                            轮询——按路径选机制，两不耽误 */
{
    while (!(USART1->SR & USART_SR_TXE)) { }
    USART1->DR = c;
}

static uint32_t g_shown;                 /* 已画的半区数（对照 g_ht_cnt+g_tc_cnt 即丢帧数） */

static void scope_draw(const uint16_t *half)   /* 16 点/屏 × 60 列：把 0–4095 拉直成横轴 */
{
    for (uint32_t i = 0; i < ADC_HALF / 2u; i++) {     /* 每屏取 16 点（半区抽一半） */
        uint32_t col = (uint32_t)half[i] * 60u / 4095u;
        putc_raw(i == 0 ? '>' : ' ');
        for (uint32_t c = 0; c <= 60u; c++)
            putc_raw(c == col ? '*' : (c == 30u ? ':' : ' '));   /* ':'=中位基准线 */
        putc_raw('\r'); putc_raw('\n');
    }
}

int main(void)
{
    clock_init(); uart_init(); adc_dma_start();
    uint32_t last = 0;
    for (;;) {
        uint32_t h = g_half;             /* SPSC 又现：ISR 唯一写 g_half，main 唯一读 */
        if (h) {
            g_half = 0;                  /* 先清再画：画期间到达的新半区不丢标志 */
            scope_draw(h == 1u ? &g_adc_ring[0] : &g_adc_ring[ADC_HALF]);
            g_shown++;
        }
        if (g_ms - last >= 1000u) {
            last += 1000u;
            uart_puts("[ADC] ht=");  uart_putdec(g_ht_cnt);
            uart_puts(" tc=");       uart_putdec(g_tc_cnt);
            uart_puts(" shown=");    uart_putdec(g_shown);
            uart_puts(" drop=");     uart_putdec(g_ht_cnt + g_tc_cnt - g_shown);
            uart_puts(" te=");       uart_putdec(g_te_cnt);
            uart_puts("\r\n");
        }
    }
}
```

**命令拆解：** `uint32_t col = (uint32_t)half[i] * 60u / 4095u;`（scope_draw 的核心一行：把采样值映射到列号）

| 部分            | 作用                                                                  |
| --------------- | --------------------------------------------------------------------- |
| `half[i]`       | 半区里第 i 个采样点，范围 0–4095（12 位 ADC 满量程）                  |
| `* 60u / 4095u` | 线性定标：0–4095 拉直到 0–60 列——整数运算先乘后除，防中间结果截断为 0 |
| `col`           | `*` 号要画在第几列；越高的电压越靠右                                  |

**配套小注**：`putc_raw` 里轮询的 TXE（Transmit data register Empty，发送寄存器空标志）——
控制面打印走轮询、数据面采样走 DMA，按路径选机制；`g_half` 的「ISR 唯一写、main 唯一读」
又是一次 SPSC（单生产者单消费者——你的主场），`先清再画` 保证画图期间到的新半区不丢标志。

量级预告（推导）：满速档每秒 2858 个半区就绪，串口画一屏（16 行×63 字节≈1KB）要 ≈89ms
→ 每秒至多画 11 屏——**drop 会非常大**（≈2847/s），这不是 bug，是「示波器刷新率追不上采样流」
的直观教材；把屏距调大或抽点即可缓解。判据是三件事：波形连续可辨、`ht:tc≈1:1`、`te=0`。

## 进阶：TIM2 TRGO 触发的精确采样率（配置路径）

> 📖 **术语卡：定时器与 TRGO（触发输出）**
> **是什么**：TIM（定时器）本质是「预分频器 PSC + 自动重装寄存器 ARR 驱动的硬件计数器」——输入时钟先经 PSC 分频，计到 ARR 值归零（更新事件 update event），周而复始；TRGO（Trigger Output，触发输出）是把定时器的某个事件（常用更新事件）引出到一根内部信号线上，给别的外设当触发脉冲。
> **为什么存在**：软件触发+CONT 的速率被 ADC 自身时序钉死，只能选「多快」不能选「多准」；定时器当节拍器后采样率=定时器频率，任意可设、且多个外设可共享同一节拍（多 ADC 同步、与 PWM 对齐采样）。
> **类比**：给采集子系统接一台统一的时钟源/PTP grandmaster——采样点的时间戳从此与节拍器同源（你的主场）。
> ⚠️ 类比边界：TRGO 是芯片内部一根信号线，没有协议栈、没有迟到概念；错过一次就是少一个点。

软件触发 + CONT 的速率钉死在 ADCCLK/(N+12)，想**任意定值**就得让定时器当节拍器——只列
路径不展开：TIM2（APB1，定时器时钟 90MHz——APB1 的 45MHz 经「定时器时钟 ×2」规则加倍）、
`PSC=90-1`（→1MHz）、`ARR=1000-1`（→1kHz）、
`CR2.MMS=010`（更新事件作 TRGO 输出）；ADC 侧清掉 CONT，改 `EXTSEL=0110`（TIM2_TRGO，
RM0090 Table 70 已自查）+ `EXTEN=01`（上升沿）。效果：每 1ms 精确一点，采样点与定时器同
源——多 ADC 同步采样、与 PWM 对齐采样的地基都在这一级。TIM 的 PSC/ARR 数学见
[[ch03-timer-pwm-buzzer|ch03]]。

**命令拆解：** 这条触发链的五个配置值（两级分频 + 三级选择）

| 配置          | 作用                                                                               |
| ------------- | ---------------------------------------------------------------------------------- |
| `PSC=90-1`    | 预分频器：90MHz÷90=1MHz，计数器每 1µs 走一格（写 N-1 是因为从 0 数到 N-1 恰 N 格） |
| `ARR=1000-1`  | 自动重装值：数到 1000 格触发更新事件——1MHz÷1000=1kHz 的节拍                        |
| `CR2.MMS=010` | 主模式选择：把「更新事件」放到 TRGO 线上输出（定时器还有别的可选信号）             |
| `EXTSEL=0110` | ADC 外部触发源选择：这 3 位指定「听 TIM2_TRGO 这根线」                             |
| `EXTEN=01`    | 外部触发使能与极性：上升沿有效——节拍脉冲来了才转换一次                             |

**你会看到**：f_s 钉死在 1kHz（与 ADCCLK 无关）；ht 频率=1k/32≈31/s——想多少就设多少。
**失败了先查**：ADC 侧 CONT 忘清会叠加自跑；MMS/EXTSEL 编码抄错则一次转换都不发生（线没接上）。

## 与 FreeRTOS / lwIP 对照

- **零拷贝的谱系**：处理函数直接读半区、不搬家——与
  [[ch6-zero-copy-tcp-write|lwIP（六）：零拷贝 TCP 写]]、
  [[ch4-pbuf-anatomy|pbuf 解剖]]是同一条思想线：数据放在 DMA 能
  直达的地方，指针传递代替内存复制。阶段 5 的以太网收包（ch20/21）会再走一遍这条路。
- **RTOS 形态**：`g_half` 标志 + 忙等轮询在 FreeRTOS 下的正身是任务通知/流缓冲——ISR 里
  `xTaskNotifyFromISR` 唤醒消费者任务（FreeRTOS 的「从中断发事件给任务」API——你的主场；
  [[ch13-task-notifications|FreeRTOS（十三）：任务通知]]），
  ISR 优先级必须 ≥5 的契约正是 ch12 的主题。
- **对照 ESP32**：IDF 的 `adc_continuous` 驱动（DMA + frame 回调）就是本章骨架的官方打包版，
  连「半区/帧」的通知粒度设计都同构——平台换了，descriptor ring 的心智模型不变。
