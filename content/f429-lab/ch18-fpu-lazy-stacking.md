## 目标（先说结论）

- CM4F（Cortex-M4F，F429 的 CPU 内核名，末位 F 表示这颗内核内置 FPU 浮点单元）的浮点上下文保存是一笔**欠账**：任务用过 FPU（CONTROL.FPCA=1）之后，每次异常进入硬件只在栈上
  **预留** 18 字空位（s0–s15+FPSCR+1 保留字）而**不立刻搬数**（FPCCR.LSPEN=1 时）；ISR（Interrupt
  Service Routine，中断服务程序——CPU 响应中断事件时跳去执行的那个函数）若全程不碰
  FPU，异常返回时空位直接作废——这笔账永远不用还。省的是每次异常约 17 个周期的搬运（ARM 手册口径数字，
  见待核对）。ISR 第一条 FPU 指令执行前，硬件才补搬——**惰性求值的硬件实现**。
- FreeRTOS 端口两头配合：启动时永远开 ASPEN+LSPEN（port.c:447-448 原注释 "Lazy save always."）；
  `xPortPendSVHandler`（PendSV 的服务函数；PendSV=可悬起服务调用异常，FreeRTOS 把所有上下文切换都塞给它，ch17 的主角）用 `tst r14, #0x10` 判断被打断的任务是否带 FPU 债（EXC_RETURN bit4），有债才
  额外压 s16–s31 的 16 字（port.c:516-518）。
- 两种任务的切换账单（本章主结论，推导待实测）：**整数任务上下文 = 17 字**（硬件 8 + 软件 9），
  **FPU 任务 = 51 字**（硬件 26 + 软件 25）——FPU 溢价 34 字 = 硬件预留区 18 字 + 软件 s16–s31 16 字。
  也就是说，一行 float 用不用，每次切换栈开销差 3 倍。
- 纠正一个以讹传讹：**FPSCR 没有内存地址**（只能 `MRS/MSR fpSCR` 特殊寄存器指令访问）；0xE000EF38
  住的是 FPCAR（惰性补搬的目标地址偏移寄存器，CMSIS core_cm4.h:1325 实证）。FPU 寄存器块基址
  0xE000EF30，FPCCR 在 +4 = **0xE000EF34**（port.c:88 同值）。
- 对照[[ch17-xtensa-port-internals|FreeRTOS（十七）]]17.5 节：Xtensa（ESP32 系列 CPU 的指令集架构名，与 Arm 是两个门派）的 FPU
  惰性切换靠**协处理器异常 + 软件属主数组**，CM4F 是**硬件状态机**——同一个「不用不付钱」哲学的两代实现。

> 📖 **术语卡：FPU（Floating Point Unit，浮点运算单元）**
> **是什么**：CPU 里专门执行浮点加减乘除的硬件电路；F429 的 CM4F 内置 32 个 32 位单精度浮点寄存器 s0–s31。
> **为什么存在**：整数运算部件算浮点要靠软件模拟，慢几十倍；有 FPU 后一条 `vmul.f32` 约一个周期出结果。
> **类比**：主板上板载的独立显卡——主 CPU 照常干活，图形/浮点这类重活交给专门部件。
> ⚠️ 类比边界：显卡可以拔掉换块主板，FPU 是内核里一体的电路，永远「在」；CPACR 门禁没开时它是「在但禁用」，一执行 FPU 指令就 fault。

> 📖 **术语卡：惰性保存（Lazy Stacking）**
> **是什么**：中断进来时硬件只在栈上「预留」FPU 寄存器的位置但不立刻搬数，等中断里真用到 FPU 再补搬。
> **为什么存在**：大多数中断不碰浮点——预留不搬就白省 17 个周期的搬运费。
> **类比**：酒店提前留房不打扫，客人真入住才打扫。
> ⚠️ 类比边界：酒店晚打扫没有正确性风险，硬件补搬必须原子完成。

> 📖 **术语卡：EXC_RETURN**
> **是什么**：异常进入时硬件塞进 LR 的「魔法返回地址」——不是真实地址，是一串编码；其中 bit4 记录被打断现场的栈帧是基本帧（1）还是带 FPU 状态的扩展帧（0）。
> **为什么存在**：异常返回把 LR 写回 PC 时，硬件凭这串编码决定弹 8 字还是 26 字、回到哪个模式、用哪个栈指针——没有它硬件不知道该怎么收尾。
> **类比**：快递取件码——取件（异常返回）时柜台凭码决定开哪个柜、给你几件货。
> ⚠️ 类比边界：取件码丢了可以补发，EXC_RETURN 丢了线程就回不去原现场；所以端口把它当上下文存进每个任务的软件帧里代管。

## 原理一：三个寄存器撑起一台欠账机

| 寄存器  | 地址/访问方式                 | 关键位                                                                                |
| ------- | ----------------------------- | ------------------------------------------------------------------------------------- |
| CONTROL | 0xE000ED14（MSR/MRS 访问）    | bit2 **FPCA**：任务执行过 FPU 指令则硬件置 1；bit1 SPSEL（ch17）                      |
| FPCCR   | 0xE000EF34（mdw 可裸读）      | bit31 **ASPEN**（自动预留）、bit30 **LSPEN**（惰性搬运）、bit0 LSPACT（欠账未清标志） |
| FPSCR   | 无内存地址（`mrs/msr fpscr`） | FPU 侧的 xPSR：舍入模式、比较标志、异常标志                                           |
| FPDSCR  | 0xE000EF3C                    | FPSCR 的复位默认值模板                                                                |
| FPCAR   | 0xE000EF38                    | 惰性补搬写入栈的位置偏移（本工程默认 0，用不到）                                      |

（FPU 块基址 FPU_BASE=SCS_BASE+0xF30=0xE000EF30、各成员偏移见 CMSIS core_cm4.h:1585 与 1324-1327。）

> 📖 **术语卡：s0–s31 与 FPSCR**
> **是什么**：CM4F 的 32 个 32 位单精度浮点寄存器（s0–s31，也就是 16 个 64 位双寄存器 d0–d15），外加一个 FPSCR（浮点状态/控制寄存器——记舍入模式、比较结果标志，相当于整数侧的 xPSR）。
> **为什么存在**：它们和 R0–R12 一样是「活状态」，任务切换不保存就会互相踩掉对方的中间结果；但保存 32+1 个字很贵，于是硬件只自动管低半区 s0–s15+FPSCR，高半区 s16–s31 按 ABI 由软件负责。
> **类比**：16 格公共储物柜（s0–s15，谁来了都可能抢用，物业=硬件统一代管）+ 16 格私人保险柜（s16–s31，各函数自己负责）。
> ⚠️ 类比边界：柜子不按人固定分配——哪个任务用哪几个寄存器完全随意，保存责任只按「寄存器区间」划分，不按使用者划分。

欠账流程按时间线走一遍——这是本章的心脏：

```text
T0 任务首次执行 FPU 指令（如 vmul.f32）
    → 硬件置 CONTROL.FPCA=1（从此这个任务「有债」）
T1 任务被异常打断（ASPEN=1 且 FPCA=1）
    → 硬件压基本 8 字帧（R0-R3/R12/LR/PC/xPSR）
    → 硬件再在帧上方【预留】18 字空位：s0-s15 + FPSCR + 1 保留字——不写值！
    → EXC_RETURN.bit4 = 0（扩展帧标记）；LSPEN=1 → FPCCR.LSPACT=1（账挂上了）
T2a ISR 全程不碰 FPU
    → 异常返回：预留区【原样作废】，一个字都没搬过——账自动赖掉，省 ~17 周期
T2b ISR 执行第一条 FPU 指令（含 PendSV 里的 vstmdbeq！）
    → 该指令执行前，硬件先把 s0-s15+FPSCR 补搬进预留区，LSPACT 清 0——还账
T3 异常返回（EXC_RETURN.bit4=0）
    → 硬件按 26 字弹栈：基本 8 字 + FPU 18 字，任务带着完整的 FPU 状态复活
```

系统侧类比双连：**写时复制**（fork 只挂页表不复制页，写的那一刻才复制——预留=挂账，补搬=复制触发）；
**惰性求值**（promise 不求值，force 时才计算——ISR 不碰 FPU 就是永不 force）。

> ⚠️ 类比边界（这两个都是你的主场，只提醒差异）：写时复制每挂一页都有页表/缺页管理费，lazy stacking 的「预留」只是把栈指针一次挪 18 字、没有逐笔簿记；promise 可以永远不被 force，硬件补搬却有一个硬期限——handler 里第一条 FPU 指令执行之前必须完成，过期就出错。

## 原理二：端口源码的三个配合点（实读 port.c）

**配合点 1：永远开惰性**。`xPortStartScheduler` 末尾：

```c
/* port.c:446-448 —— 原注释 "Lazy save always." */
vPortEnableVFP();                              /* 834-846：再写一次 CPACR 开 CP10/CP11（兜底） */
*( portFPCCR ) |= portASPEN_AND_LSPEN_BITS;   /* 0x3<<30：ASPEN|LSPEN 一起置位 */
```

CPACR（Coprocessor Access Control Register，协处理器访问门禁寄存器，0xE000ED88——CP10/CP11 两位分别是 FPU 的两扇门，全 1 才允许任意特权级访问）的首次使能早在 `SystemInit` 就做了（system_stm32f4xx.c:171，
`SCB->CPACR |= (3UL<<20)|(3UL<<22)`——CP10/CP11 全访问）；没有这一步，任何 FPU 指令都是
UsageFault（用法错误异常——CPU 认得这条指令、但当前状态不允许执行它，于是跳去 fault 向量而不是当场死机），端口自己也过不了 port.c:37-39 的 `#error This port can only be used when ... hardware
floating point support`。

**配合点 2：启动前把账抹平**。`prvPortStartFirstTask` 特意清 CONTROL：

```c
/* port.c:280-290，注释原文：
 * "This also clears the bit that indicates the FPU is in use in case the FPU
 *  was used before the scheduler was started - which would otherwise result in
 *  the unnecessary leaving of space in the SVC stack for lazy saving of FPU registers." */
" mov r0, #0            \n"   /* 289 */
" msr control, r0       \n"   /* 290：CONTROL=0 —— SPSEL 与 FPCA 一起清零 */
```

main 在调度器启动前若用过 FPU（比如 float 打印换算），FPCA=1 的残债会让第一个 SVC 的栈帧多出
18 字预留区——端口宁可抹掉重来。这个细节顺带证明：**FPCA 是「上下文」属性，不是「指令」属性**——
调度器不关心任务将来用不用 FPU，只看被打断那一刻 FPCA 是几。

**配合点 3：PendSV 的条件压栈**。ch17 走过的序列里，这三行是本章主角：

```c
/* port.c:516-520（保存侧）与 538-542（恢复侧，镜像） */
"   tst r14, #0x10          \n"  /* EXC_RETURN.bit4：0=扩展帧（有 FPU 债）1=基本帧 */
"   it eq                   \n"
"   vstmdbeq r0!, {s16-s31} \n"  /* bit4=0（EQ 成立）→ 压 FPU 高半区 16 字 */
"   stmdb r0!, {r4-r11, r14}\n" /* 两种任务都要的 9 字（R4-R11+EXC_RETURN） */
```

分工会设计的巧处就在这：**s0–s15+FPSCR 归硬件**（异常进入预留/补搬、返回弹栈，全程自动），
**s16–s31 归软件**（ABI——Arm 的函数调用约定，规定函数之间谁负责保存哪些寄存器——里的 callee-saved「被调用方保存」高半区：函数动用前必须先存原值、返回前必须还原，硬件根本不管，端口用条件指令补上）。而判断依据
EXC_RETURN 由硬件给出、由任务自带——`pxPortInitialiseStack` 给每个新任务摆的初值是
`portINITIAL_EXC_RETURN=0xfffffffd`（port.c:93、226，bit4=1）：**任务出生无债**，第一次被切换时
`tst` 不成立、16 字跳过；直到任务真的执行过 FPU 指令，硬件才会开始给它的异常打 bit4=0 的返回标记。
这一枚 EXC_RETURN 存进软件帧（`stmdb {..., r14}`）、恢复时取回（`ldmia {..., r14}`）——ch17 说过，
每个任务自己保管自己的返回帧类型。

账单汇总（推导，待实测）：

| 场景                     | 硬件帧        | 软件帧            | 合计      | PendSV 期间 PSP 移动 |
| ------------------------ | ------------- | ----------------- | --------- | -------------------- |
| 整数任务（FPCA=0）       | 8 字          | 9 字（R4-R11+LR） | **17 字** | −9 字                |
| FPU 任务（FPCA=1，欠账） | 26 字（8+18） | 25 字（16+9）     | **51 字** | −25 字               |

（ch14 曾粗算初始上下文「≈16 字=64 字节」——那是抹掉 EXC_RETURN 一字的整数路径口径，精确值 17 字；
pxPortInitialiseStack 摆的字数与其一一镜像。）

## 实验：让 vstmdbeq 执行起来

**改造 ①：加一个用 FPU 的任务**（其余不动；256 字栈装 51 字帧绰绰有余）：

```c
static volatile float g_sink;

static void fpu_task(void *arg)
{
    (void)arg;
    volatile float x = 1.0f;
    for (;;) {
        x = x * 1.0001f + 0.0001f;   /* volatile：逼编译器真出 vmul.f32/vadd.f32（-O0 下必出） */
        g_sink = x;
        vTaskDelay(pdMS_TO_TICKS(200));
    }
}
/* main() 里追加： */
xTaskCreate(fpu_task, "fpu", 256, NULL, 2, NULL);
```

代码走读（三行各有任务）：`volatile float x` 的 volatile（易变限定符——告诉编译器「这个变量随时可能被外部观察到，别把读写优化掉」）保证每次循环真的生成 `vmul.f32`/`vadd.f32` 两条 FPU 指令——它们一执行，硬件就把 FPCA 置 1（时间线 T0 时刻）；`g_sink` 把结果漏给观察者，防止整个计算被当作死代码砍掉；`vTaskDelay(pdMS_TO_TICKS(200))` 让 fpu 任务每 200ms 主动让出 CPU，制造「被 PendSV 打断」的机会——不打断就永远看不到切换账单。`xTaskCreate` 的 256 是**字**不是字节（FreeRTOS 栈单位 uxStackDepth 以字计，实际 1KB），装 51 字帧绰绰有余。

**改造 ②（观察 FPCCR 配置）**：openocd 裸读（任务跑起来之后任意时刻，序章方法 3——不用 halt）：

```bash
> mdw 0xE000EF34 1     # FPCCR：预期 0xC0000000（bit31 ASPEN + bit30 LSPEN）
> mdw 0xE000EF30 4     # FPU 块全览：+0 预留 / +4 FPCCR / +8 FPCAR / +C FPDSCR（默认值待实测）
```

**命令拆解：** `mdw 0xE000EF34 1`

| 部分         | 作用                                                                 |
| ------------ | -------------------------------------------------------------------- |
| `mdw`        | openocd 的 Memory Display Word 命令：从指定地址读 32 位字并打印      |
| `0xE000EF34` | FPCCR 的物理地址（FPU 寄存器块基址 0xE000EF30 + 偏移 4）             |
| `1`          | 读 1 个字；改成 4 就能连读 FPCCR/FPCAR/FPDSCR 一整排（见上一行命令） |

**你会看到**：`0xe000ef34: c0000000`（推导值，实跑核销）。
**失败了先查**：地址打错（EF30/EF34 差一个数字就是另一个寄存器）；调度器还没启动（port.c:448 那行没执行过，读到复位值）。

**主实验：两种 EXC_RETURN 的单步对照**。方法完全复用 ch17，断点下在 `tst` 那条
（当前构建 0x080016b8，加代码后以 `nm`/`objdump` 重查——**每次加代码地址必挪**，这是 ch17 钉过的纪律）：

```bash
> reset run; sleep 1500
> bp 0x080016b8 2 hw    # tst.w lr,#16 —— 压栈分叉点
> resume                # 多次命中，交替抓「整数任务被切」与「fpu 任务被切」两种现场
> reg lr                # 整数任务：0xfffffffd；fpu 任务：0xffffffed（bit4=0）
> reg psp
> mdw <psp> 26          # fpu 现场：+0x00..0x1C 基本 8 字，+0x20..0x5F 欠账区 s0-s15，
                        #            +0x60 FPSCR，+0x64 保留字
```

**命令拆解（主实验五连）**：

| 部分                       | 作用                                                                                                                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `reset run; sleep 1500`    | 复位芯片后立刻放跑、openocd 睡 1.5 秒——让任务全部跑起来再开始观察                                                                                                        |
| `bp 0x080016b8 2 hw`       | 在 `tst` 指令地址下断点：2=覆盖长度（Thumb 指令 2 字节），hw=用芯片硬件断点单元（不停 Flash、不用软件补丁）                                                              |
| `resume`                   | 全速继续跑，直到断点命中；每次命中就是一次「某任务被 PendSV 打断」的现场抓拍                                                                                             |
| `reg lr`                   | 读 LR 寄存器——此刻它装的就是 EXC_RETURN（0xfffffffd 或 0xffffffed）                                                                                                      |
| `reg psp` → `mdw <psp> 26` | 先读 PSP（Process Stack Pointer，进程栈指针——线程模式下任务私有栈的当前位置；与 handler 用的 MSP 主栈是两套），再把读到的数值代入 `<psp>` 连读 26 个字，把整帧栈倒出来看 |

**你会看到**：`lr` 在 0xfffffffd / 0xffffffed 两种值之间交替——每交替一次就是整数任务与 fpu 任务各被打断一次。
**失败了先查**：断点永不命中→地址挪了（加过代码必须重查符号地址，见下）；命中但 lr 两个值都不是→烧的是旧固件。

**命令拆解：** `arm-none-eabi-objdump -d f429-freertos.elf | grep -A 12 xPortPendSVHandler`

| 部分                               | 作用                                                                    |
| ---------------------------------- | ----------------------------------------------------------------------- |
| `arm-none-eabi-objdump -d`         | 反汇编工具：把 ELF（带符号的构建产物）里的机器码翻译回汇编指令          |
| `f429-freertos.elf`                | 构建输出文件（build/ 目录下）；`nm` 列符号表、`objdump -d` 看指令级细节 |
| `\| grep -A 12 xPortPendSVHandler` | 只显示该函数名起 12 行，在其中找 `tst.w lr, #16` 那条，抄下它的地址     |

**你会看到**：`080016b8 <tst.w lr, #16>` 这样的行——地址换成你当前构建的值再下断点。
**失败了先查**：grep 没命中（符号被裁/名字不同就用 `arm-none-eabi-nm | grep PendSV` 先定位函数名）。

单步越过 `vstmdbeq`（fpu 任务版）前后各读一次 FPCCR——**LSPACT 位（bit0）应由 1 变 0**：`vstmdbeq`
本身是 handler 里的第一条 FPU 指令，它执行前硬件完成补搬（欠账清零）。这正是 T2b 分支的现场。
欠账区内容的对照读法：在断点命中（tst 未过）时 `mdw <psp+0x20> 16`——此时 s0–s15 **还没搬进来**，
读到的应是上一次使用残留/未定义数据；`vstmdbeq` 过后再读，变成 fpu 任务断点处的真值。两帧快照
就是「预留」与「补搬」的物证。（LSPACT 触发规则按 ARMv7-M「handler 内首条 FPU 指令触发补搬」表述，
实测确认项见清单。）

**对照实验 ③（讲解层面，实操可选）：ISR 里的 float**。在任一 ISR（如给 EXTI 挂一个测试中断）里写
`volatile float y = 1.5f * 2.0f;`：异常进入 → 预留 18 字不搬 → `vmul.f32` 执行前硬件补搬 → 返回弹 26 字。
判别法：在 vmul 那条下断点，断点命中时（指令未执行）预留区已补搬完毕——断点停下的那一刻账已经还了。
教学价值：若把 LSPEN 清零（`mww 0xE000EF34 0x80000000`——只留 ASPEN），同一 ISR 的异常进入变成
**立即搬运**，多了那 ~17 个周期——惰性与非惰性的开关就在一位上。（改 FPCCR 属侵入操作，实跑时单独
一轮、跑完恢复，标待实测。）

**命令拆解：** `mww 0xE000EF34 0x80000000`

| 部分         | 作用                                                                                          |
| ------------ | --------------------------------------------------------------------------------------------- |
| `mww`        | openocd 的 Memory Write Word 命令：往物理地址写一个 32 位字                                   |
| `0xE000EF34` | FPCCR 的地址（同上）                                                                          |
| `0x80000000` | 写入值：只置 bit31（ASPEN 自动预留）、bit30（LSPEN 惰性搬运）清零——保留「自动」、关掉「惰性」 |

**你会看到**：ISR 异常进入从「预留不搬」变成「立刻全搬」——惰性与非惰性的差别就在这一位。
**失败了先查**：写完忘了恢复——跑完这一轮必须 `mww 0xE000EF34 0xC0000000` 还原，否则后续实验全被污染。

## 预期输出（待实测核销）

FPCCR 读数：

```text
> mdw 0xE000EF34 1
0xe000ef34: c0000000     ← ASPEN|LSPEN（port.c:448 写入后的预期值）
```

两种任务的栈布局对照图（PSP 均为 PendSV 压完 s16–s31 之前、`stmdb` 之前的值；字数推导见账单表）：

```text
        整数任务（lr=0xFFFFFFFD）        fpu 任务（lr=0xFFFFFFED）
高地址 ▲ 抢占前的 PSP                     抢占前的 PSP
        ┌────────────┐                   ┌────────────┐
        │   xPSR     │                   │ 保留字 1 字 │
        │   PC       │                   │   FPSCR    │
        │   LR       │ 硬件 8 字          │ s15 …… s0  │ 硬件欠账区 18 字
        │   R12      │                   │   xPSR     │ （LSPACT=1 期间为空）
        │   R3       │                   │   PC       │
        │   R2 R1 R0 │                   │   LR R12   │ 硬件基本 8 字
        ├────────────┤ ← PSP             │   R3 R2 R1 │
        │ EXC_RETURN │ 软件 9 字          │   R0       │
        │ R11 … R4   │                   ├────────────┤ ← PSP
        └────────────┘                   │ s31 …… s16 │ vstmdbeq 压 16 字
        ← stmdb 后 PSP                   │ EXC_RETURN │ 软件 9 字
             共 17 字                    │ R11 … R4   │
                                         └────────────┘
                                         ← stmdb 后 PSP，共 51 字
```

单步观察点汇总（全部待实测回填）：

```text
[整数任务被切] reg lr → 0xfffffffd；tst 后跳过 vstmdbeq；PSP 仅 −9 字（ch17 已推演）
[fpu 任务被切] reg lr → 0xffffffed；
               断点命中时 mdw <psp+0x20> 16 → 残留值（未补搬）+ FPCCR bit0=1
               vstmdbeq 之后同址 mdw      → s0-s15 真值 + FPCCR bit0=0
               stmdb 之后 reg psp         → 再 −25 字（16+9），共 51 字深度
```

## 与主系列对照：两种惰性 FPU 的两代实现

| 维度            | CM4F（本板）                                        | Xtensa（ESP32，FreeRTOS（十七）17.5）                               |
| --------------- | --------------------------------------------------- | ------------------------------------------------------------------- |
| 惰性触发        | 硬件状态机：FPCCR.LSPACT + 首条 FPU 指令补搬        | 协处理器异常（EXCCAUSE=CP_DISABLED）→ `_frxt_coproc_exc` 全软件处理 |
| 保存位置        | 任务栈上的硬件预留区（s0–s15）+ 软件压栈（s16–s31） | 任务栈顶锚定的 CPSA（72B，含属主位图），xchal_cp0_store/load        |
| 所有权管理      | 无需管理（每任务自带帧，EXC_RETURN 传承）           | `_xt_coproc_owner_sa[CP][core]` 属主数组 + 跨核 spinlock            |
| ISR 用 FPU      | 合法且透明（硬件补搬；代价 ~17 周期）               | 默认直接 panic（需 `CONFIG_FREERTOS_FPU_IN_ISR` 开锁）              |
| 不用 FPU 的成本 | 零（整数任务的切换账里没有 FPU 字段）               | 零（CPENABLE 清位，协处理器异常不发生）——殊途同归                   |
| 附带约束        | 无（任务可任意迁移）                                | 用 FPU 的未钉核任务被钩子自动钉核（FPU 每核一份）                   |
| 更大背景        | 软件压栈哲学：16 个通用寄存器全靠软件显式保存       | 硬件窗口哲学：call4/retw 零拷贝换寄存器组，spill 藏在异常陷阱里     |

两代架构给了同一个问题（浮点上下文很贵、大多数任务不用）同一个答案（不用不付钱），但实现代差巨大：
Xtensa 把惰性做成**异常+软件协议**（灵活、可定制、但要处理属主和钉核）；CM4F 把惰性做进**硬件状态机**
（零软件参与、但对 ISR 内使用的优化止于搬运时机）。把这张表和 ch17 的切换对照表并排读——「上下文切换
的地基焊进硬件还是留给软件」这条哲学分界线，在这两章里各出现了一次。
