# P2P 网络深度解析（五）：非结构化 P2P——Gnutella、泛洪与超级节点

连接问题（ch02–ch04）解决之后，P2P 面对真正的大题：**一百万个互不相识的节点，怎么找到持有某份数据的那一个？** 这一章先看最直觉的答案——把问题广播出去（Gnutella 的泛洪），算清它的带宽账单，看它如何被免费搭车拖垮，再看两条改良路线（随机游走、超级节点），最后证明一个结构性结论：**只要数据存放位置与网络拓扑无关，查找就注定是概率性的、低效的**——这个困境只有靠"结构化"来解，即后两章的 DHT。

---

## 5.1 Gnutella：把搜索变成广播

### 1. 五报文协议

Gnutella 0.4 协议只有五种消息，全部是对称设计——任何节点既是提问者也是应答者：

| 报文     | 方向       | 作用                                             |
| -------- | ---------- | ------------------------------------------------ |
| Ping     | 广播（发） | "有人在吗？"——探活并请求邻居自报家门             |
| Pong     | 单播（回） | 应答 Ping：报告自己的 IP:port 与共享文件数/大小  |
| Query    | 广播（发） | 搜索请求：匹配串 + 最小速度要求                  |
| QueryHit | 沿原路回   | 命中节点的地址与文件列表                         |
| Push     | 沿原路发   | 无法被连入的节点（NAT 后）请求对方主动连过来上传 |

每条消息带一个 23 字节描述符头，其中两个字段撑起了整个路由机制：

```text
Descriptor Header
┌────────────────┬──────────┬─────┬──────┬───────────────┐
│ Descriptor ID  │ Payload  │ TTL │ Hops │ Payload Length │
│ 16字节随机UUID │ 类型     │     │      │               │
└────────────────┴──────────┴─────┴──────┴───────────────┘
转发规则：每经过一个节点，TTL-1、Hops+1；TTL=0 → 丢弃
```

### 2. 泛洪的路由逻辑

节点收到 Query 后：本地匹配 → 命中则沿来路回 QueryHit；**无论命中与否**都向除来路外的所有邻居转发（TTL 未耗尽时）。去重靠 Descriptor ID——每个节点记住见过的 ID，重复的丢弃（无结构泛洪图里必然成环，没有去重就是指数爆炸 + 死循环）：

```text
         ┌───┐ TTL=7
         │ A │──发 Query──▶ 邻居们
         └─┬─┘
     ┌─────┼─────┐
   ┌─▼─┐ ┌─▼─┐ ┌─▼─┐      第 1 跳：3 个节点收到，各转发给除 A 外的邻居
   │ B │ │ C │ │ D │      第 2 跳：又 ~6 个节点……
   └─┬─┘ └───┘ └─┬─┘      ……
   ┌─▼─┐        ┌─▼─┐      QueryHit 沿反方向逐跳回到 A（每个中间节点记住了
   │ E │◀───────│ F │      "这个 DescriptorID 从哪个邻居来"）
   └───┘ 命中！  └───┘
```

TTL 默认 7，是为了把爆炸半径钉死在常数——但也意味着**第 8 层之外的节点永远搜不到**，Gnutella 网络大了以后"搜得到"本身变成彩票。

### 3. 带宽放大账单

设平均每个节点有 d=4 个邻居，一条 Query 被转发的次数约为 d×(d-1)^(TTL-1) 量级的上界（去重后实际低一些，但量级仍在数百到数千）。也就是说：**一百万节点的网络里，一次用户敲下回车的搜索，会变成几百上千次报文转发**，而其中 99% 落在与此无关的节点上。2000 年代的测量研究普遍记录了 Gnutella 查询流量占据带宽的大头——这正是 ISP 引入 DPI 与限速的直接动因，也催生了后面的协议加密猫鼠游戏（ch10）。

> [!note] Push 报文：NAT 困境的 2000 年代解法
> QueryHit 的应答者若在 NAT 后无法被直连，请求方就发一条 Push 请它**主动反向连出**（出站永远通畅，ch03 的教训）。这个设计在原理上就是"打洞"的退化版——没有 STUN 情报、没有时序编排，只是单纯利用"出站不受阻"。它同时是历史上的安全软肋：伪造 Push 报文可以把任意流量引向任意节点（DoS 放大），ch10 再回来清算。

## 5.2 免费搭车：测量数据打脸乌托邦

P2P 的可扩展性叙事假设"人人贡献"。2000 年 Adar 与 Huberman 对 Gnutella 的经典测量（采集数万个节点样本）给出三记重锤：

- **约 70% 的用户不共享任何文件**——纯消费者；
- **约 1% 的节点回答了约 50% 的查询**——贡献高度集中于极少数节点；
- 关闭贡献最高的少数节点，网络可用内容量骤降——**"对等"网络事实上运行在寡头长尾上**。

这是 free riding（免费搭车）问题的第一次大规模实证。它揭示了无激励设计的必然命运：理性用户没有理由上传（费电、费带宽、惹法律麻烦），系统滑向"少数圣徒供养多数搭客"的伪 P2P——拓扑上对等，经济学上两级分化。BitTorrent 的 tit-for-tat（ch08）就是对着这张体检报告开的药方。

## 5.3 改良路线一：随机游走与查询路由

学术界给泛洪开出的第一类药方是**降低转发冗余**：

- **随机游走（random walk）**：Query 不再广播给所有邻居，而是随机挑一个走下去（或同时放 k 个"walker"）。带宽从 d^TTL 降到 k×TTL，代价是延迟变长、覆盖率变成概率性——用时间换带宽的折中。
- **迭代加深（iterative deepening）**：先 TTL=2 问一圈，没结果再 TTL=4……模仿 TCP 慢启动的探测哲学，多数查询在小半径内就能命中。
- **查询路由（QRP）**：节点向邻居广播自己的**关键词布隆过滤器**（哪些词我可能有），邻居据此决定是否转发——LimeWire 时代的 Gnutella 靠它把无谓转发砍掉一个量级。布隆过滤器的误报与 ch10 的索引投毒在这里第一次交汇。

这些优化很优雅，但没有触及根本：**数据在哪与拓扑长什么样毫无关系**，再聪明的游走也是在赌概率。

## 5.4 改良路线二：超级节点——向现实低头

工业界的解法更粗暴：**承认节点不平等，让强者多劳**。KaZaA/FastTrack（以及后来的 Skype）把节点分成两层：

```text
     ┌────────┐ ┌────────┐ ┌────────┐      超级节点层：带宽大、在线久、公网可达
     │  SN-1  │─│  SN-2  │─│  SN-3  │      各自索引几百个子节点的共享清单，
     └─┬─┬─┬──┘ └────┬───┘ └───┬────┘      超级节点之间互通
       │ │ └──────┐  │         │
     ┌─▼▼───┐ ┌───▼──────┐ ┌──▼─────┐    普通节点层：连一个 SN，查询只发给 SN，
     │child │ │  child   │ │ child  │    文件传输仍 child↔child 直连
     └──────┘ └──────────┘ └────────┘
```

查询从"全网泛洪"变成"问自己的 SN → SN 查本地索引 → 未命中再问隔壁 SN"，一跳之内覆盖数百节点的目录。代价是重新引入了**结构性中心点**：SN 宕机带走整棵子树的搜索能力（KaZaA 的应对是 SN 动态选举与冗余连接），且 SN 的合法性可以被投毒者伪造（索引投毒的主战场，ch10）。

超级节点是"混合架构"的原型，其思想活到了今天：以太坊的 bootnode、BitTorrent 的 tracker、Tailscale 的协调服务器——**把全局目录这类便宜但需要一致性的东西中心化，把昂贵的数据搬运留给对等层**。这不是妥协，是工程成熟。

## 5.5 结构性困境：为什么非结构化注定低效

把本章的失败汇总，可以提炼成一个定理式的观察：

> **查找效率 = f(数据位置与拓扑的耦合度)。** 非结构化网络里这个耦合度为零——数据存在谁那，与谁连谁完全无关——所以任何查找算法都只能在"问遍所有人（泛洪）"与"问到就算运气（随机游走）"之间滑动，无法既便宜又确定。

要确定性地 O(log N) 找到数据，必须**人为制造耦合**：规定每个键的存放位置由哈希函数决定，拓扑按同样的哈希逻辑组织——这就是结构化 P2P / DHT（Distributed Hash Table）。它用"数据必须搬家到法定宿主"的纪律性，换取"任何人都能算出宿主在哪"的可导航性。

## 5.6 小结

- Gnutella 五报文（Ping/Pong/Query/QueryHit/Push）+ 描述符头的 TTL/Hops 机制，构成了零基础设施的全分布搜索；去重靠 Descriptor ID，回程靠逐跳记忆来路。
- 泛洪的账单：TTL=7、平均度 4 时单条查询触发成百上千次转发，99% 与目标无关；TTL 同时决定了搜索覆盖的天花板。
- Push 报文是 NAT 困境的 2000 年代解法（利用出站不受阻），也是 DoS 放大攻击的历史软肋。
- 免费搭车实证：约 70% 用户零共享、约 1% 节点回答约 50% 查询——无激励对等网络的必然归宿，BitTorrent 激励的直接动因。
- 改良路线两条：随机游走/迭代加深/QRP（治带宽冗余），超级节点（治拓扑无序）——后者开创"控制面中心化、数据面对等化"的混合范式，沿用至今。
- 根本困境：数据位置与拓扑零耦合 ⇒ 查找只能是概率性穷举；确定性查找要求人为耦合——哈希定宿主、拓扑随哈希走，这就是 DHT。
