# P2P 网络深度解析（七）：Kademlia——现实世界的 DHT 通用语

Chord 定义了 DHT 的骨架（哈希定宿主 + O(log N) 导航），但现实世界最终选择了另一个设计：**Kademlia**（Maymounkov 与 Mazières，2002）。BitTorrent 的 Mainline DHT、IPFS 的节点网络、以太坊的节点发现（discv4/discv5）、I2P、Tox——2002 年这篇论文成了它们共同的底座。这一章拆它凭什么：XOR 度量带来的数学红利（7.1）、k-bucket 的反直觉可靠性哲学（7.2）、四条 RPC 撑起的并发迭代查找（7.3–7.4），以及它对 Chord 三大短板的逐条清算（7.5）。

---

## 7.1 XOR 度量：把"环上的顺时针"换成对称空间

### 1. 距离的定义

Chord 的世界里方向是绝对的：键属于"顺时针第一个 ≥ 它的节点"，路由只能单向走。Kademlia 的世界里没有方向，只有距离：

```text
distance(a, b) = a XOR b        （按位异或，160 位 ID 空间）
```

XOR 是合格的度量：自反（d(a,a)=0）、对称（d(a,b)=d(b,a)）、且满足三角不等式（由 a^c = (a^b)^(b^c) ≤ d(a,b)+d(b,c) 推出）。键 K 的宿主不再是"顺时针第一个"，而是**全局 XOR 距离最近的 k 个节点**——用 k 个副本换单点宿主的容错。

### 2. 二进制前缀：桶的直觉

XOR 距离的二进制读法是理解 Kademlia 的钥匙：**距离的最高有效位告诉你"第一个不同的位在哪"**。比如 8 位空间里：

```text
self  = 0x35 = 0011 0101
key   = 0xA0 = 1010 0000
dist  = 0x95 = 1001 0101   ← 最高位是 bit7：目标在"第 7 位不同"的那一大类里
```

把 ID 空间按"与我的距离落在 [2^i, 2^(i+1))"分层，恰好是**按最长公共前缀的补集**分层：桶 0 里是只有最后一位不同的节点（隔壁），桶 7 里是最高位就不同的节点（半个 ID 空间那么远）。每往上一层，可选节点数理论上翻倍——**指数分层的地址簿**，与 Chord finger table 的指数间距思想同源，但组织方式从"指针列表"变成了"熟人桶"。

### 3. 对称性红利

d(a,b)=d(b,c) 不只是优雅。它意味着：**A 查 B 时学到的路由信息，B 对 A 也同样成立**——每次 RPC 的收发双方互相把对方塞进自己的桶，一次通信两边都变聪明。Chord 的 finger table 没有这个性质（顺时针指针不保证反向可用），学习是单向的、浪费的。

## 7.2 k-bucket：地址簿的可靠性哲学

### 1. 结构

每个节点维护 160 个桶（bucket i 存"与我的 XOR 距离在 [2^i, 2^(i+1)) 区间"的联系人），每桶容量 k（论文建议 20 量级的小常数，BitTorrent Mainline 实现取 8）：

```text
                ┌─ bucket 159: 距离 [2^159, 2^160)  ── 最高位不同的半个空间，最稀
    我的         ├─ bucket 158: 距离 [2^158, 2^159)
  地址簿  ────▶  ├─  ……
 160 桶         ├─ bucket 1:   距离 [2, 4)
                └─ bucket 0:   距离 [1, 2)          ── 只差最后一位的邻居，最密
```

### 2. 淘汰策略：老熟人最可靠

桶满了来了新联系人怎么办？直觉是"挤掉最老的"（LRU），Kademlia 反着来：**优先怀疑最新的，最老的联系人最可信**。流程是：新人在桶满时不直接插入，而是先去 ping 桶里**最老**的那个——它还活着就忽略新人，它死了才让位：

> [!note] 为什么"旧的更可靠"
> 节点在线时长是重尾分布：已经在线很久的节点，大概率还会继续在线很久（"未来在线时长与过去在线时长正相关"的经验规律）。新节点则多半是闪现型 churn 噪声。这条策略让桶里沉淀下来的都是"长寿节点"，整个路由表在网络风暴里自动保值。这也是对 ch05 免费搭车测量（1% 节点承担 50% 贡献）的工程回应：**识别并绑定那 1% 的长期节点**。

### 3. 桶内自由度：拓扑感知的挂钩

Chord 的 finger 指向"ID 上恰好那个位置的节点"，没有选择余地；Kademlia 只要求桶的**距离区间**正确，桶内选谁进 k 个名额是自由的——**实现可以用 RTT 排序，把延迟低的节点留在桶里**。XOR 度量的三角不等式保证：桶内换人不会破坏路由收敛性（距离分层不变）。Chord 的"无拓扑感知"短板，就这样被一个自由度解掉。

## 7.3 四条 RPC：协议的全部动词

Kademlia 协议小到可以在一张名片背面写完：

| RPC        | 请求    | 应答                                   | 用途                       |
| ---------- | ------- | -------------------------------------- | -------------------------- |
| PING       | —       | 存活应答                               | 探活（桶淘汰前的最后通牒） |
| STORE      | 键, 值  | —                                      | 把数据存到目标 k 近节点    |
| FIND_NODE  | 目标 ID | 发送者已知的最接近目标的 k 个节点      | 路由的主力                 |
| FIND_VALUE | 键      | k 个近节点；**若恰持有该键则直接回值** | 查数据                     |

加一条隐性规则：**每个 RPC 的应答者都把请求方记进自己的桶**（7.1 的对称红利落地）。BitTorrent 的 Mainline DHT 把这套动词改名换姓（get_peers/announce_peer，ch08 详述），IPFS 与以太坊各自加签名与加密，但"四个动词 + 应答即学习"的骨架原样保留。

## 7.4 迭代查找：α 路并发的收敛

### 1. 算法

与 Chord 的"逐跳转发"不同（请求包在网络里旅行，起点只收到最终应答），Kademlia 用**迭代**模式：发起者亲自控制每一轮——

1. 从自己的桶里选出与目标 XOR 距离最近的 α 个节点（α 典型取 3）；
2. **并行**向它们发 FIND_NODE；
3. 汇总应答里的新节点，并入候选集；
4. 从候选集挑出离目标最近的 α 个未查询节点，重复；
5. 候选集不再产生更近的节点时终止——当前的 k 近即答案；FIND_VALUE 则在任一节点回值时提前结束。

### 2. 手工算例（8 位空间）

self=0x35 查 key=0xA0，距离 0x95（7.1 算过，落桶 7）。桶 7 里有三个联系人 0xC2、0xF0、0x88，与目标的距离：

```text
0xC2 ^ 0xA0 = 0x62 = 98
0xF0 ^ 0xA0 = 0x50 = 80
0x88 ^ 0xA0 = 0x28 = 40   ← 最近的候选
```

第一轮并行问这三个（α=3）。0x88 应答"我知道的最接近 0xA0 的 k 个是 {0xB1, 0x9C, …}"，其中 0xB1 ^ 0xA0 = 0x11 = 17 < 40——候选集收紧。第二轮问 0xB1、0x9C、0xF0……**每一轮通常把最高一位不同的位再敲掉一位**（距离的最高有效位每轮至少向右移一位的期望），8 位空间两三轮收敛，160 位空间对应 **O(log N) 轮，一百万节点约 20 轮**——量级与 Chord 相同，但：

- **并行掩盖延迟**：每轮 α 路 RTT 重叠，比 Chord 的串行逐跳快得多；
- **发起者全程掌控**：不把请求交给可能撒谎的中转者，每一步的应答都可验证（重算 XOR 距离即知应答质量），ch10 的攻击面因此更小；
- **失败天然容错**：一路超时不阻塞其他路，churn 友好。

### 3. 维护开销的清算

Chord 要周期性 fix 160 个 finger 指针，Kademlia 的桶几乎自维护：查找顺路刷新沿途所有桶（应答即学习），只有**长期安静的桶**需要主动刷新——小时级周期、桶区间内随机挑个 ID 发起一次查找即可。第三个短板（稳定化开销）至此清零。

## 7.5 为什么是 Kademlia 赢了

| 维度     | Chord                   | Kademlia                        |
| -------- | ----------------------- | ------------------------------- |
| 路由状态 | 160 项 finger 指针      | 160 桶 × k 联系人（冗余即容错） |
| 状态维护 | 周期 fix 全部指针       | 查找顺路刷新 + 安静桶小时级刷新 |
| 路由学习 | 单向（finger 不可反向） | 对称（应答双方互相学习）        |
| 查找模式 | 串行逐跳转发            | α 路并行迭代，发起者可控可验证  |
| 拓扑感知 | 无（ID 近 ≠ 网络近）    | 桶内自由度挂 RTT 排序           |
| 宿主容错 | 后继链                  | 天然 k 副本                     |

再加上实现简单（没有环、没有 successor 链的织补）、论文给出正确的收敛证明、许可宽松——2005 年前后 BitTorrent 与各路开源项目陆续采用后，**Kademlia 成为事实标准**，后续 DHT 研究几乎全部以它为基线（增强它的 S/Kademlia 防女巫设计在 ch10 展开）。

> [!tip] 在三个系统里认出它
> **BitTorrent Mainline DHT**（ch08）：FIND_NODE→find_node、FIND_VALUE→get_peers、STORE→announce_peer，节点 ID 160 位、k=8，服务于"谁有这个种子"。**IPFS**：Kademlia 做 provider 记录的分发（谁存着这个 CID），配合 bitswap 拉数据。**以太坊 discv4/discv5**：节点发现层就是 Kademlia（discv5 加了 topic 广播与握手加密），区块链的组网本身就是 ch01 说的"P2P + 共识"。

## 7.6 小结

- XOR 度量给 DHT 带来三个红利：对称距离（路由学习双向免费）、按最长公共前缀补集分层的天然桶结构、三角不等式（桶内换人不破坏收敛）。
- k-bucket 是"指数分层的地址簿"：每桶 k 个长寿联系人，淘汰策略反直觉地保护最老的（在线时长远重尾分布），桶内自由度留给 RTT 排序做拓扑感知。
- 协议只有四个动词（PING/STORE/FIND_NODE/FIND_VALUE）+ 应答即学习；迭代查找 α 路并行、发起者全程掌控，每轮敲掉一位距离，O(log N) 轮收敛。
- 对 Chord 的三大短板逐条清算：桶冗余换容错、顺路刷新换维护成本、并行迭代换延迟与可验证性——外加实现足够简单。
- Kademlia 是 DHT 的通用语：BitTorrent 找 peer、IPFS 找 provider、以太坊找节点，动词不同、骨架同源。
