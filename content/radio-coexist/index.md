# 无线共存调试实战系列：WiFi × 蓝牙 × Thread 同板生存指南

> [!tip] 系列说明
> 本系列是无线调试三部曲的收官篇：[[wifi-hw-debug|WiFi 硬件调试实战]]、[[ble-debug|蓝牙调试实战]]、[[thread-debug|Thread 调试实战]] 各自解决了「一种射频怎么查」，本系列解决「**三种射频挤在一块板子上怎么查**」——智能家居中枢、带 Thread 的路由器、Matter 边缘网关、多协议 SoC（ESP32-C6/H2、nRF54 系）都是这个处境。
>
> 共存问题有一条铁律：**症状在 A 协议上，根因常在 B 协议的时序里**。所以本系列的骨架是「共存三层次」：频谱共存（空口互扰）、片上共存（收发器时间分配）、网络协作（谁给谁供网/入网）——每章先归层再取证。所有单协议概念回链前三个系列，**只讲共存特有的增量**，不重复教。

## 方法论：共存三层次 × 互拖矩阵

多射频故障先归层，层错了方向就全错：

| 层次         | 问题本质                   | 典型症状                         | 对应章节                      |
| ------------ | -------------------------- | -------------------------------- | ----------------------------- |
| **频谱共存** | 空口上互相占时/互相干扰    | 距离变近、重传升高、特定信道劣化 | 第二章                        |
| **片上共存** | 收发器时间被调度互抢       | 单协议工作正常、双协议同开就抖   | 三、四、五章                  |
| **网络协作** | 角色分工与数据通路设计不当 | 配网失败、BR 失联、App 远程失效  | 第五章、第十章（thread 系列） |

取证之前先画**互拖矩阵**：行是被害协议、列是嫌疑协议，逐格问「它开着我什么时候会疼」——这是全系列反复用到的思维工具。

```text
同板共存的三个灵魂拷问：
Q1 物理上几颗射频芯片？（决定片上共存的形态与工具）
Q2 它们在时间上怎么互相让？（决定性能互拖的边界）
Q3 它们在网络上怎么分工？（决定故障会不会跨协议传播）
```

## 目标读者与承诺

- 读过三部曲中至少一部（推荐 WiFi + Thread 或 WiFi + BLE 组合），懂各自系列的分层取证框架
- 手上有至少一块多协议开发板（ESP32-C6/H2 或 nRF5340/nRF54 级）更佳，纯路由器+ dongle 组合也能走完大部分实验
- **承诺**：读完能判断共存问题归哪一层、看懂并验证 PTA/分时调度的实际行为、给多射频产品做信道与天线布局决策、用「电流+空口+日志」三通道对齐法定位互拖根因
- **不承诺**：不教多协议协议栈的驱动开发、不教 RF 前端共享电路设计（只到设计与排查层）、不覆盖 5G Hz Wi-Fi 与 802.15.4 的频谱问题（不相交，仅一笔带过）

## 学习节奏建议

- **先修科目**：至少读完 [[wifi-hw-debug|WiFi 硬件调试实战]] 与 [[thread-debug|Thread 调试实战]]（或 [[ble-debug|蓝牙调试实战]]）的 Part I，否则本系列的名词表过载。
- **按需跳读**：做 WiFi+BLE 产品的读第三章，做 Matter 边缘网关的读第四、五章；第二章频谱地图是所有人的公共底座。
- **第六章是全系列的方法论核心**：哪怕只读一章，读它——三通道对齐法适用于一切「互拖」类疑难。
- **收官**：第八章的知识地图把四个系列串成一张图，适合当整个无线调试 tracks 的总复习入口。
