## 7.1 设计侧共存：取证解决「已经坏了」，布局解决「还没坏」

第六章的方法论再好，也是在病灶形成之后动刀。共存问题有一个对设计者极不友好的特性：**布局层面的病灶在单板测试阶段几乎全部隐身**——净空被挤占、隔离度不足、噪声源贴脸，这些在实验室桌面上都测得过去，要到整机装配态、真实家庭环境、多射频同开的负载下才现形。而现形之后的整改手段，往往就是「改板」两个字：一次流板以周计，牵动结构与产能。

两条战线的分工因此明确：

| 战线   | 回答的问题         | 时间点        | 手段                                 | 成本曲线                     | 本章位置 |
| ------ | ------------------ | ------------- | ------------------------------------ | ---------------------------- | -------- |
| 取证侧 | 已经坏了，根因在哪 | 量产后/测试中 | 三通道对齐 + 矩阵实验（第六章）      | 小（按天计），但治标后仍需改 | 第六章   |
| 设计侧 | 还没坏，怎么不坏   | 原理图/布局期 | 隔离度预算、净空、摆位、信道规划联动 | 大（改板按周计），但一次到位 | 本章     |

设计侧的全部工作，本质是给第六章 checklist 里的每类病灶**预先发一张不存在的许可证**：

| 第六章的病灶（取证侧发现）     | 本章的预防（设计侧规则）               |
| ------------------------------ | -------------------------------------- |
| 频谱层互扰：信道重叠、邻道干扰 | 信道规划与天线方案联动决策（7.5）      |
| 空间隔离不足：互相听得太多     | 天线间距与排布方案（7.2）              |
| 共享链路的额外损耗没算够       | 插损入链路预算（7.3）                  |
| 噪声源污染接收灵敏度           | 净空与噪声源距离规则（7.4）            |
| 灵敏度「莫名」比评估板差       | 链路预算制度与传导口径验收（7.6 案例） |

> [!note] 本章证据口径
> 本章为设计章，不涉及实测读数；间距、隔离度、插损等数值均为**经验口径或概念量级**，逐处标注；精确数值以天线仿真/整机实测为准（标「待核对」）。布局规则的完整展开在 [[ch13-pcb-layout|射频入门（十三）]] 与 [[wifi-hw-debug-ch08-antenna-structure|WiFi 调试（八）]]，本章只写多射频共存特有的增量；dB 与链路预算语言见 [[ch03-decibel-family|射频入门（三）]]。

## 7.2 天线隔离度：间距与排布

### 7.2.1 隔离度的直觉

隔离度（isolation）回答一个问题：**A 天线发射时，B 天线的馈电口能「听到」多少**。隔离度越高，一颗射频的发射在另一颗射频接收带内留下的信号越小。两条直觉先建立起来：

- **距离是第一杠杆**：2.4 GHz 自由空间波长 λ ≈ 122 mm。板间多天线间距以 **λ/2 ≈ 61 mm 起步**（经验口径）；远场条件下距离每翻倍隔离度约 +6 dB（20log 口径）。但 PCB 上的耦合以近场与板面波为主，实际隔离度与地板、走线、结构件强相关，**具体 dB 值以仿真/实测为准，待核对**——经验数字只用来画红线，不用来做承诺。
- **间距不够，靠方向图与极化补**：小型产品塞不下 λ/2 是常态。可用手段：两颗天线极化正交（典型可带来十余 dB 量级的额外隔离，经验口径，待核对）、方向图主瓣错开（一颗朝上一颗朝侧）、天线之间加隔离墙/开槽切断板面波。每一项都是「缓解」而非「解决」，最终以整机实测收口。

判读口径沿用第二、三章的视角：隔离度决定的是**空间层**的互扰下限，频谱层（信道错开，[[radio-coexist-ch02-24ghz-spectrum-map|第二章]]）与片上层（调度让路，[[radio-coexist-ch03-wifi-ble-coexistence|第三章]]）是在这个下限之上继续加的保险。三层都薄的产品，就只剩祈祷。

把可用的隔离手段按「设计期→调试期」排成一张杠杆表（量级均为经验口径，逐板实测收口）：

| 杠杆        | 动作                               | 典型量级（经验口径，待核对） | 设计期/调试期 | 代价              |
| ----------- | ---------------------------------- | ---------------------------- | ------------- | ----------------- |
| 间距        | 天线间距做到 λ/2 起步              | 基础盘，距离翻倍约 +6 dB     | 设计期        | 摆位面积          |
| 极化正交    | 相邻天线极化方向错开               | 十余 dB 量级的额外隔离       | 设计期        | 天线选型/姿态受限 |
| 方向图错开  | 主瓣朝向错开（一颗朝上一颗朝侧）   | 与安装姿态相关，无统一数字   | 设计期        | 结构/外观约束     |
| 隔离墙/开槽 | 天线间加隔离墙或地板开槽切断板面波 | 数 dB 到十余 dB 量级         | 设计期        | 结构复杂度        |
| 地板完整度  | 射频下方地板回流完整、不走信号线   | 属于「不做必坏」项           | 设计期        | 布线自由度        |
| 信道错开    | 频谱层错开主冲突信道               | 频谱层保险，见第二章         | 设计期+部署期 | 频谱规划自由度    |
| 调度让路    | PTA/分时保证互斥                   | 片上层保险，见第三、四章     | 固件期        | 各协议可用时间    |

### 7.2.2 同板三射频的天线排布方案对照

三种典型排布，覆盖了从旗舰网关到成本敏感产品的谱系：

| 方案            | 形态                                                                        | 隔离来源          | 优点                       | 代价                                                               | 调试含义（取证侧）                             | 典型产品          |
| --------------- | --------------------------------------------------------------------------- | ----------------- | -------------------------- | ------------------------------------------------------------------ | ---------------------------------------------- | ----------------- |
| **三独立天线**  | WiFi(+BLE 组合芯) 一颗、802.15.4 一颗、（BLE 独立芯时）再一颗，各走各的馈线 | 空间距离 + 方向图 | 隔离最好；各射频互不设卡   | 面积/成本/结构摆位压力大                                           | 互拖问题以频谱层为主，片上调度余量最大         | 中枢/网关/企业 AP |
| **双天线+开关** | 组合芯片（WiFi+BLE）独占一颗；802.15.4 与 BLE（或备用射频）经开关共享另一颗 | 空间 + 开关互斥   | 面积折中；主射频性能不受损 | 开关插损 + 切换互斥落在次要射频上                                  | 被共享方性能与开关时序强相关，抓包重点在共享侧 | 路由器/机顶盒     |
| **共享天线**    | 全部射频经开关网络挂同一颗天线                                              | 开关互斥（唯一）  | 最省面积与成本；一处净空   | 插损全射频共担；**同一时刻只有一颗射频能用天线**，完全依赖片上调度 | 调度异常直接变成全协议事故（7.6 案例）         | 成本敏感 IoT 主控 |

三条选型直觉。其一，**共享度与调度依赖度成正比**：天线越共享，越离不开片上共存机制（第三、四章）可靠工作——共享天线方案里 PTA/多协议调度不是「优化项」，是「生命线」。其二，**组合芯片先内部共享**：WiFi+BLE 同芯片时天线通常芯片内部已复用（厂商方案口径，Espressif/Nordic 文档为准），板级「三独立」实际是「组合芯一颗 + 15.4 一颗」的双天线起步，三独立只出现在三颗独立射频芯片的板子上。其三，**摆位即隔离**：同一方案下，两颗天线隔着电池/屏蔽罩/金属支架，和并排裸露在净空区，隔离度可以差出量级——摆位审查比方案选型更常救场。

```text
三种排布的「谁卡谁」视角：
三独立   WiFi▓▓▓▓▓▓▓▓  15.4▓▓▓▓▓▓▓▓  BLE▓▓▓▓▓▓▓▓   ← 各发各的，互不设卡
双天线+开关   WiFi▓▓▓▓▓▓▓▓   [开关]▓▓▓▓▓▓   ← 次要射频轮流用第二颗
共享     [开关]▓▓▓▓▓▓▓▓  ← 谁拿到调度权谁说话，其余排队
（▓ = 可用空口时间；示意图，非实测）
```

## 7.3 共享天线方案：开关、双工与合路

### 7.3.1 三种「把多颗射频接上一颗天线」的电路概念

概念级介绍（电路设计不在本系列范围，到「能看懂方案、能排查后果」为止）：

| 器件                           | 分合原理                                                  | 同频段多射频适用性                                                                         | 调试含义                                              |
| ------------------------------ | --------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| **射频开关**（SPDT/SP3T 一类） | 时分：控制信号决定任一时刻哪颗射频接到天线                | **同频段共享的主力**：配合片上调度保证互斥，不会两颗同时上天线                             | 插损计入两端预算；控制信号与协议栈联动是故障高发点    |
| **双工器**                     | 频分：按频段把信号分走（如 2.4G/5G 双频 WiFi 的频段分路） | 双频段场景适用；**同频段不适用**——频段相同就分不开                                         | 各频段各亏一份带内插损；对共存本身是「分层不互抢」    |
| **合路器/功率分配器**          | 把多路合成一路共同馈电                                    | 同频段**慎用**：合成存在约 3 dB 的理论分配损耗，且路间隔离有限，一颗发射会灌进另一颗接收口 | 同频段多射频几乎都改用「开关+时分调度」，而不是硬合路 |

一句话记忆：**频段不同用频分（双工），频段相同用时分（开关），硬合路是设计事故的种子**。

### 7.3.2 插损入链路预算

开关与双工器不是免费的：信号每多过一节器件，就亏一份插损（insertion loss，典型 0.3~0.5 dB 量级每节，经验口径，具体以器件 datasheet 为准，待核对）。dB 语言的账在 [[ch03-decibel-family|射频入门（三）]] 已经教过，这里只算共存的增量账：

```text
共享天线方案的链路预算账（dB 语言，量级示意）：
独立天线：  TX ─────────────────── 天线      ← 链路上只有走线损耗
共享天线：  TX ── 走线 ── 开关 ──（网络）── 天线
                         ↑ 插损 L_ins
发射端：EIRP 直降 L_ins
接收端：灵敏度等效恶化 L_ins（信号要过的还是同一条路）
双向合计：同一条无线链路的预算被吃掉约 2 × L_ins
```

这解释了 7.6 案例的现象：**方案从独立改共享后「灵敏度变差」，第一嫌疑不是天线坏了，是预算里没记插损这笔账**。设计期的正确动作：天线方案定稿时重算一遍链路预算（发射端与接收端各减插损），对照 [[wifi-hw-debug-ch07-phy-measurements|WiFi 调试（七）]] 的判据确认余量仍然够——余量不够就提前换方案，而不是等整机测试来揭晓。

开关还有一笔**时序账**：切换不是瞬时的，控制信号到位到射频通路稳定需要时间（量级以器件 datasheet 为准，待核对）；片上调度的让路窗口必须把这段时间算进去，窗口算小了的表现是「切换边界上的帧丢失」——取证时在空口 pcap 里表现为紧邻切换事件的零星重传。

### 7.3.3 共享方案的故障模式对照

共享天线把「射频物理层」和「片上调度」焊在了一条船上，它的故障模式有固定套路，第六章的取证方法照单使用：

| 故障模式              | 用户可见表现                               | 空口/电流特征（第六章口径）                                                       | 对应设计规则   |
| --------------------- | ------------------------------------------ | --------------------------------------------------------------------------------- | -------------- |
| 插损没入预算          | 全体射频灵敏度都「差一点」，远点先塌       | 传导口径链路损耗超预算；空口无异常帧                                              | 7.3.2          |
| 调度互斥失效          | 两颗射频同时「哑」或剧烈互踩               | 电流上发射台阶重叠（6.2.1 的共存读法）；开关状态与调度日志矛盾                    | 7.2.2 选型条目 |
| 切换窗口算小          | 切换边界零星重传，业务侧表现为周期性小卡顿 | pcap 里紧邻切换事件的重传；波形正常                                               | 7.3.2 时序账   |
| 控制信号极性/时序错误 | 一颗射频永远没天线（完全连不上）           | 该射频空口完全静默，电流有发射台阶却无空口帧                                      | 原理图审查     |
| 开关网络走线穿净空    | 装配态性能塌、裸板正常                     | 装配态对比法（[[wifi-hw-debug-ch08-antenna-structure\|WiFi 调试（八）]]）差异显著 | 7.4.1          |

这张表的使用方法：共享天线方案的板子出问题时，先按行对号入座，再决定取证顺序——「全体射频都差一点」直接查预算账，「某一颗彻底没天线」直接查开关控制信号，都能省掉大段弯路。

## 7.4 布局规则：净空、噪声源与屏蔽分区

单射频布局规则的全集在 [[ch13-pcb-layout|射频入门（十三）]] 与 [[wifi-hw-debug-ch08-antenna-structure|WiFi 调试（八）]]（净空、馈线、接地、结构影响），本节只写**多射频共存特有**的三条增量规则。

### 7.4.1 净空：一颗天线，一份净空，互不侵占

每颗天线的净空区（天线周围不铺铜、不放件、不被结构遮挡的区域）独立成立；共存增量是**共享天线方案的所有开关/合路网络走线同样需要保护带**——7.6 案例里，正是开关网络的走线挤进了原净空区。审查动作：把「天线净空」从「一块区域」升级成「一条链路」——天线本体、馈线、开关、直到射频引脚，整条链路上不得有新增导体与强干扰源。

### 7.4.2 敏感接收与噪声源的距离

| 噪声源               | 噪声特征                                                                                      | 摆位原则                                                         | 依据                                                               |
| -------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| DCDC 开关节点        | 开关频率及其谐波的宽谱辐射，能量随电流走                                                      | 远离天线净空与射频接收链路；开关节点面积最小化                   | [[ch12-power-supply\|射频入门（十二）]] 的「电源性格」             |
| USB3 接口/线缆       | 8 Gbps 数据的谐波噪声落在 2.4 GHz 频段（业界共识问题，量级与整改见 Intel 相关白皮书，待核对） | 远离天线；接口屏蔽与接地按 [[ch13-pcb-layout\|射频入门（十三）]] | 业界共识，逐板实测                                                 |
| 屏幕排线（高速串行） | 高速差分对的共模谐波可落入 2.4G 频段                                                          | 排线不穿天线净空区；必要时加共模抑制                             | [[ch14-interference-coexistence\|射频入门（十四）]] 的 2.4G 邻居观 |
| 第二颗射频的发射     | 同频段强信号直灌                                                                              | 这正是隔离度问题：按 7.2 排布，不靠运气                          | 本章 7.2                                                           |

共存特有的一句提醒：**你的接收敏感区，同时是另一颗射频的发射强区**——同板射频之间的距离摆位，按「接收链路对强信号的容忍度」审查，而不是只按「天线对天线的距离」。

```text
            │  │天线 A │   │ 开关网络  │←──│净空保护带│   │
            │  └──┬───┘   └──────────┘    └─────────┘   │
            │  天线A净空区（无铜/无件/无排线）             │
            └────────────────────────────────────────────┘
要点：噪声源全部压在数字区并罩住；开关网络按射频链路待遇
     （保护带 + 纳入射频侧屏蔽）；每颗天线一份独立净空。
```

### 7.4.3 屏蔽罩分区

数字区与射频区各自罩住的思路不变（规则见 [[ch13-pcb-layout|射频入门（十三）]]），共存增量两条：其一，**共享天线方案里开关网络建议纳入射频侧屏蔽**——它是射频链路的一部分，却常常被画到「模组外面」而失去保护；其二，**屏蔽罩不要罩成新的耦合腔**：罩体与天线的距离、开缝方向会改变方向图，多天线方案的罩体摆位要在整机态复测（口径见 [[wifi-hw-debug-ch08-antenna-structure|WiFi 调试（八）]] 的装配态对比法）。

## 7.5 信道规划与天线方案的联动决策

空间层（7.2~7.4）与频谱层（[[radio-coexist-ch02-24ghz-spectrum-map|第二章]]）不是二选一，是**乘法关系**：两端都留余量，产品才稳。决策表把两种手段组合起来（信道错开的具体地图见第二章与 [[thread-debug-ch09-802154-rf-phy|Thread 调试（九）]]，本节不重复信道号）：

| 空间条件 \ 频谱条件             | 频谱可错开（信道自由）                    | 频谱受限（信道被锁/邻居挤占）                        |
| ------------------------------- | ----------------------------------------- | ---------------------------------------------------- |
| **隔离好**（三独立/摆位佳）     | 双保险：随手感错开即可                    | 靠隔离硬扛：同频共存可接受，互拖比验证（第六章 6.4） |
| **隔离中**（双天线+开关）       | 标准组合：错开主冲突 + 开关调度兜底       | 加强片上调度核查：PTA/分时配置逐项过（第三章）       |
| **隔离差**（共享天线/紧凑摆位） | **最低配置**：必须错开，且留 AFH/调度兜底 | 红线：方案重审或接受性能折扣，按互拖比定级           |

读表三条。其一，**右下角是事故象限**：隔离差 + 频谱锁死 = 靠片上调度独自扛空口互扰，调度风暴场景（[[radio-coexist-ch05-scheduling-storms|第五章]]）下必翻车——评审时直接要求改方案。其二，**信道规划要留「逃逸信道」**：邻居是活的，今天的空信道明天可能被占，AFH（[[ble-debug-ch08-ble-rf-phy|蓝牙调试（八）]]）与 Thread 的信道选择策略（[[thread-debug-ch09-802154-rf-phy|Thread 调试（九）]]）是频谱层的动态保险。其三，**决策表是评审工具**：新板评审时把「空间条件 × 频谱条件」落格，落在哪一行就执行哪一行的动作，不靠个人手感。

## 7.6 教学案例：双天线改共享天线后灵敏度劣化

> 教学复盘案例，取材自常见故障模式综述。现象与根因类型具有普遍性，具体数值不给虚构读数，损耗以「量级」表述。

| 环节           | 内容                                                                                                                                                                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **现象**       | 成本优化改板：原「组合芯片 + 802.15.4 各配一颗天线」改为「开关网络共享一颗天线」。改板后整机远点测试明显变差：同点位吞吐下降、弱信号下重传与掉线增多；Thread 侧远端节点也报链路质量下滑。评估板（裸模组接参考天线）无此现象                                                                       |
| **弯路一**     | 先怀疑软件：回退驱动与固件版本、核对发射功率配置——无效。改板前后软件包一致，本应第一时间排除，**教训：改板类问题先列「这次改了什么」清单**                                                                                                                                                        |
| **弯路二**     | 用辐射法对比新旧板灵敏度，读数跳动大、新旧板差距时大时小——第七、八章讲过的口径问题：辐射法在整机态离散大，不适合作为天线方案对比的主证据                                                                                                                                                          |
| **转折点**     | 切到**传导口径**（[[wifi-hw-debug-ch07-phy-measurements\|WiFi 调试（七）]] 的口径切换方法）：把射频口引出，逐段核算「模组引脚 → 走线 → 开关 → 馈线 → 天线」的链路损耗，与旧板的「引脚 → 馈线 → 天线」对比。新板链路损耗比旧板**多出一份与开关插损同量级的差值**——预算里没记这笔账，这是全案转折点 |
| **补充证据一** | 矢网扫开关两条通路：插损与 datasheet 量级相符，但共用网络走线的一段穿过了原 WiFi 天线的净空区边缘，装配态下失配加重——净空被挤占的第二处病灶                                                                                                                                                       |
| **补充证据二** | 空口复测（第六章双 sniffer）：开关切换边界伴随零星重传——切换时序没算进调度窗口，属于次要病灶                                                                                                                                                                                                      |
| **根因**       | 三处叠加：① 共享网络的插损**双向**吃掉链路预算（7.3.2 的账），发射端 EIRP 与接收端灵敏度同亏；② 开关网络走线挤占净空，装配态失配加重；③ 切换时序未入调度预算，边界丢帧                                                                                                                            |
| **对策**       | ① 链路预算补账：插损计入收发两端，余量不足处恢复双天线；② 开关网络走线移出净空并加保护带；③ 切换窗口按器件时序放宽（以厂商文档口径核对 PTA/调度参数）；④ 验收口径固定为传导对比 + 装配态整机复测两段                                                                                              |
| **预防**       | 天线方案变更必须重走两步：链路预算重算（含新增器件逐项记账）+ 净空链路审查（7.4.1 的「整条链路」口径）；改板评审清单把「这次改了什么」列为第一项                                                                                                                                                  |

**证据链复盘**：软件侧无效（改板清单意识缺席）→ 辐射口径离散（口径识别迟了半步）→ **转折点：传导口径下链路损耗核算，新板多出一份与插损同量级的差值**（把「灵敏度玄学」变成「预算欠账」）→ 矢网与净空审查补齐第二处病灶 → 空口补齐第三处 → 预算制度收口。本案与 [[wifi-hw-debug-ch12-casebook-checklist|WiFi 调试（十二）]] 案例二共享同一个转折点形态——**口径切换**：辐射法的离散里没有答案，传导法的账本里全是答案。

三处病灶与本章规则的对应关系（也是防复发的验收清单）：

| 病灶                 | 违反的规则               | 验收动作                  | 复发防线           |
| -------------------- | ------------------------ | ------------------------- | ------------------ |
| 插损未入预算         | 7.3.2 的链路预算记账     | 传导口径逐段核算损耗      | 方案变更重走预算   |
| 走线挤占净空         | 7.4.1 的「整条链路」口径 | 净空链路走查 + 装配态复测 | 净空审查进评审清单 |
| 切换时序未入调度窗口 | 7.3.2 的时序账           | 切换边界空口复测          | 器件时序入参数表   |

## 本章小结

- **两条战线**：取证解决「已经坏了」（第六章，按天计），布局解决「还没坏」（本章，改板按周计）——设计侧每条规则对应一类已知病灶（7.1）。
- **隔离度直觉**：λ/2 间距起步、距离翻倍约 +6 dB（经验口径）；间距不够用极化与方向图补；隔离度是空间层的下限，频谱与片上在其上加保险（7.2）。
- **共享天线 = 时分互斥**：同频段用开关不用合路；插损双向吃链路预算，切换时序要计入调度窗口——共享度越高，片上调度越接近生命线（7.3）。
- **布局三增量**：净空按「整条射频链路」审、接收敏感区按「对强信号的容忍」审、屏蔽罩别罩成新耦合腔（7.4）。
- **联动决策表**：空间与频谱是乘法关系，右下角象限（隔离差+频谱锁死）是评审红线（7.5）；教学案例的转折点再次是**口径切换**——辐射法没答案时，传导法的账本里全是答案（7.6）。
