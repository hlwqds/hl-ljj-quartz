## 目标（先结论）

## 1. 原理：BCM2711 GPIO 控制器寄存器图

BCM2711 的 GPIO 控制器基址 **0xFE200000**（注意每代 SoC 都挪过家：BCM2835 是 0x20200000、
BCM2837 是 0x3F200000——地址是「这一代」的事实，换板要重查手册）。本节用到的寄存器（偏移与
位布局以《BCM2711 ARM Peripherals》手册为准，下表是公开的手册事实）：

> 📖 **术语卡：寄存器（Register）**
> **是什么**：芯片内部一排可读可写的存储格子，每格 32 bit（BCM2711 GPIO 控制器如此），其中每个位或位组控制外设的一个状态——某个引脚是输入还是输出、当前是高还是低。
> **怎么访问**：CPU 不给寄存器单独发指令，而是把每格寄存器编上一个内存地址，读/写这个地址就是读/写这格寄存器。
> **类比**：楼宇配电箱——一排开关（寄存器），每个开关（位）管一路（一个功能），动开关不用进机房，在固定位置摸得到。

> 📖 **术语卡：MMIO（Memory-Mapped I/O，内存映射 I/O）**
> **是什么**：把外设控制器的寄存器编进统一内存地址空间的手法——GPIO 控制器占 `0xFE200000` 起的一段，访问外设 = 往某地址读写，与访问内存同一套 CPU 指令。
> **为什么存在**：免去专用 I/O 指令，编译器/语言无需特殊语法；代价是「这段地址不是真内存，写它有副作用」。
> **类比**：写字楼门牌——访客（CPU）只需认门牌号（地址），不需要知道门后是办公室（内存）还是设备间（寄存器）。
> ⚠️ 类比边界：对真内存，写完再读回一样；对 MMIO，写入会触发硬件动作，读回的可能是随时变化的引脚电平——别用「普通内存」的直觉优化它（重排/合并访问都危险，ch04 内核侧代码会看到 `volatile` 的用武之地）。

基址（base address）+ 偏移（offset）= 实际地址：`0xFE200000 + 0x04 = 0xFE200004` 就是 GPFSEL1——下文所有地址都按这个加法算出来。

| 寄存器    | 偏移      | 作用                                           |
| --------- | --------- | ---------------------------------------------- |
| GPFSEL0–5 | 0x00–0x14 | 功能选择：每脚 3 bit，每 32 bit 寄存器管 10 脚 |
| GPSET0/1  | 0x1C/0x20 | 写 1 置位对应引脚（写 0 无副作用）             |
| GPCLR0/1  | 0x28/0x2C | 写 1 清零对应引脚                              |
| GPLEV0/1  | 0x34/0x38 | 读回引脚实际电平                               |

GPIO17 的位算术推导（这套算术就是 F429 的 `pin % 16 * 4` 换了个进制）：

- 功能：GPIO17 → `GPFSEL1`（0xFE200004，管 GPIO10–19），位区间 `[(17−10)×3 … +3) = [21..23]`，`001` = 输出
- 置位：`GPSET0`（0xFE20001C）bit 17 → 写 `0x1 << 17 = 0x00020000`（`<<` 是左移：把二进制 1 挪到第 17 位，其余位为 0——「第 17 格开」的机器写法）
- 清零：`GPCLR0`（0xFE200028）bit 17 → 同一个数写到另一个地址
- 读回：`GPLEV0`（0xFE200034）bit 17

> 📖 **术语卡：RMW（Read-Modify-Write，读-改-写）**
> **是什么**：寄存器一格 32 bit 里挤着多根引脚的配置，只想改其中 3 位时，必须「先读出整格 → 掩码改这几位 → 整格写回」，三步合称 RMW。
> **为什么危险**：三步之间若被别的事件插进来改了同一格，你的写回会把别人的修改覆盖掉（丢失更新）。
> **为什么还离不开**：像 GPFSEL 这种「一格多主」的寄存器，专用置位/清零寄存器没覆盖到的场合只能 RMW——所以本实验第一步对 GPFSEL1 规规矩矩 RMW，第二三步的 GPSET/GPCLR 才能一步直达。
> **类比**：合租房告示板——你只想改自己那行字，也得把整块板子抄下来、改一行、整块贴回去；抄与贴之间室友改了别的行，就被你无意覆盖了。

### 与 F429 寄存器的同构对照

| BCM2711       | 语义                | STM32F4（RM0090）  | 语义                  |
| ------------- | ------------------- | ------------------ | --------------------- |
| GPFSELn       | 3 bit 选功能        | MODER              | 2 bit 选模式          |
| GPSET0/GPCLR0 | 原子置位/清零       | BSRR（BS/BR 两半） | 同一思想的两种排布    |
| GPLEV0        | 读实际电平          | IDR                | 读输入                |
| —             | （无整口 ODR 直写） | ODR                | 整口直写，需 RMW 拼位 |

（表头注：RM0090 是 STM32F4 系列官方《参考手册》的文档编号，MODER/BSRR/IDR/ODR 都是它的 GPIO 寄存器名——F429 侧老朋友，语义见右列。）

两家硬件工程师在「如何原子地动一根脚」上殊途同归：**都提供写 1 生效的置位/清零寄存器**，
让「置位」不需要读-改-写三步曲——RMW 是可以被中断/被抢占打断的，专用置位寄存器天然原子（原子 atomic：一次完成、不可被打断再插队的操作单位，别人要么看到它没发生、要么看到它已完成）。
这个伏笔在 [[ch05-request-irq-vs-nvic|ch05（中断）]] 会再收一次。

## 2. 工具与门禁：/dev/mem 与 CONFIG_STRICT_DEVMEM

Debian 源里**没有 devmem2 包**（Ubuntu 有，Debian 一直没打包）。两条路：

1. **busybox devmem**（本系列主用；busybox：把上百个常用命令精简后塞进单个二进制的「瑞士军刀」，嵌入式救场神器）：`sudo apt install busybox`，用法
   `busybox devmem ADDR [WIDTH [VALUE]]`，WIDTH 以字节计，32 位寄存器用 `4`（确切语义以
   `busybox devmem --help` 实测为准）。
2. devmem2 源码自编译（单文件约 100 行）。推荐读一遍源码再编译——它就是
   `open("/dev/mem") + mmap + 一次访存`（mmap：把文件/设备映射进本进程地址空间的系统调用，之后直接当内存指针访问——你的主场），把「用户态碰物理地址」的全部秘密摊开。

devmem2 的全部魔法就这三步（代码走读，伪码）：

```c
int fd = open("/dev/mem", O_RDWR | O_SYNC);     // ① 打开「物理内存」这个设备文件
void *p = mmap(0, 4096, PROT_READ|PROT_WRITE,   // ② 把目标物理页映射进自己进程
               MAP_SHARED, fd, 0xFE200004 & ~0xFFF);  //    mmap 只认页对齐地址，低 12 位先抹掉
printf("%x\n", *(volatile uint32_t *)(p + 4));  // ③ 指针解引用一次 = 访问一次物理寄存器
```

①是「申请门禁」，②是「把远处的门牌挂到本进程墙上」，③之后读写这个指针就是读写寄存器——`volatile`（告知编译器：此地随时自己会变，禁止缓存/重排对它的访问）是 MMIO 的标配前缀。

`/dev/mem` 是把整个物理地址空间文件化的字符设备。现代内核对它有两道锁：

> 📖 **术语卡：字符设备（Character Device）**
> **是什么**：Linux 设备模型三大类之一——按**字节流**顺序读写的设备（另一大类块设备按块/扇区随机寻址，如磁盘；第三类网络设备无设备文件）。
> **为什么 /dev/mem 属于它**：/dev/mem 没有块结构，`read()/write()/mmap()` 逐字节/逐段透明搬运，行为最像「一条流」。
> **类比**：串口终端是标准字符设备；/dev/mem 则是一条「通向全物理地址」的流——你的主场（`ls -l` 首位的 `c` 即字符设备标志）。

> 📖 **术语卡：/dev/mem**
> **是什么**：一个设备文件，打开并读写/mmap 它 = 直接读写**物理地址**（真实 RAM 与 MMIO 区都在其中）。
> **为什么存在**：调试、取证、以及 pigpio 这类「绕过内核自己动手」的用户态库需要一条直达物理层的后门。
> **代价**：拿着它就是「内核之外的第二权力中心」——所以才有了下面两道配置锁。
> ⚠️ 类比边界：它不是「另一份内存」，而是同一份物理地址空间的**另一个入口**；经它写坏内核数据结构与直接写坏没有区别。

- **CONFIG_STRICT_DEVMEM**：禁止经 /dev/mem 访问 **RAM**（防 root 借它直接改内核内存提权绕过审计）。
- **CONFIG_IO_STRICT_DEVMEM**（更严）：连 MMIO 区也禁。

（CONFIG\_ 前缀是内核**编译期**配置项（Kconfig 体系）的名字：编内核时逐项决定某功能要不要编进去，成品内核的能力在编译那一刻就定死——改它等于重编内核，跟改运行时配置文件是两回事。）

树莓派官方内核历史上保留 /dev/mem 对 MMIO 的访问能力（pigpio（老牌树莓派 GPIO 用户态库，大量功能直接吃 /dev/mem）整个库靠它吃饭），预期 GPIO
区可读写；本机内核的实际配置用 `zgrep -E 'STRICT_DEVMEM|IO_STRICT' /proc/config.gz` 或
`grep STRICT_DEVMEM /boot/config-$(uname -r)` 核对（待核对）。

**命令拆解：** 查内核配置的两条路

| 命令                                                  | 作用                                                                                                       |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `zgrep -E 'STRICT_DEVMEM\|IO_STRICT' /proc/config.gz` | `/proc/config.gz`：内核把**自己编译时的完整配置**压缩后挂进 /proc；zgrep = 直接在压缩流里 grep，免手动解压 |
| `grep STRICT_DEVMEM /boot/config-$(uname -r)`         | 备选路：boot 分区里随内核安装的配置文本；`$(uname -r)` 就地展开成当前内核版本号，拼出对应文件名            |

**你会看到**：形如 `CONFIG_STRICT_DEVMEM=y`（开锁）或 `# CONFIG_STRICT_DEVMEM is not set`（没编）的行。
**失败了先查**：/proc/config.gz 不存在（该内核没开 CONFIG_IKCONFIG_PROC），走 boot 分区备选路。

（/proc：内核把自身状态伪装成文件挂出的虚拟目录——你的主场。）

用系统侧的话说：Linux 把「谁能写物理地址」从一个特权态问题，改写成**文件权限 + 内核配置**
的审计问题——能力没有被删除，而是被装进了可管理的门。

## 3. 实验：三步点亮 LED

接线回顾（ch01 规约）：GPIO17 → 330Ω → LED → GND。先共地、再接信号线。

### 第一步：GPFSEL1 读-改-写，把 GPIO17 设为输出

```bash
sudo busybox devmem 0xFE200004 4     # 先读旧值（预期形如 0x???????，默认值待实测）
# RMW 纪律：new = (old & ~(0x7 << 21)) | (0x1 << 21)，只动 [23:21] 三个位
# 若旧值为 0x00000000，则直接写 0x00200000：
sudo busybox devmem 0xFE200004 4 0x00200000
```

**命令拆解：** `sudo busybox devmem 0xFE200004 4 [VALUE]`

| 部分             | 作用                                                        |
| ---------------- | ----------------------------------------------------------- |
| `sudo`           | root 权限（/dev/mem 默认只归 root——你的主场）               |
| `busybox devmem` | 经 /dev/mem 读写物理地址的小工具（借宿在 busybox 工具箱里） |
| `0xFE200004`     | 目标物理地址 = GPIO 基址 0xFE200000 + GPFSEL1 偏移 0x04     |
| `4`              | 访问宽度，**字节**数——4 = 一次读写 32 bit（整格寄存器）     |
| （末位）`VALUE`  | 给了 = 写入该值；不给 = 只读并打印旧值                      |

**掩码算式拆解：** `new = (old & ~(0x7 << 21)) | (0x1 << 21)`

| 片段               | 意思                                                         |
| ------------------ | ------------------------------------------------------------ |
| `0x7 << 21`        | 二进制 111 挪到 [23:21]——GPIO17 的三个功能位                 |
| `~(...)`           | 按位取反：除了这三位，其它位全变 1                           |
| `old & ~(三位的1)` | 掩码清零：三个功能位归 0，其余位**原样保留**                 |
| `\| (0x1 << 21)`   | 按位或：把 001 写进刚清出的三位 = 「输出」；其余位仍不受影响 |

**你会看到**：第一次命令打印旧值（形态待实测）；写入命令打印的就是写入值；LED 尚无反应（只改了方向，还没输出电平）。
**失败了先查**：`Permission denied`（不是 root）；地址打错（打印的值驴唇不对马嘴时先怀疑抄错位）。

RMW 纪律不是洁癖：GPFSEL1 里还住着 GPIO10–19 的其他脚（例如 GPIO14/15 可能默认是串口
alt0 功能——alt0 即 alternate function 0：引脚复用的第 0 号角色，此时这根脚被当作串口数据线而非 GPIO 用），一把梭写 0 会顺手改掉邻居的复用状态。裸机老手的肌肉记忆，原样平移。

交叉验证（Bookworm 自带的官方工具，包名待核对）：`pinctrl get 17` 应显示 GPIO17 已是 output
（`pinctrl get 编号`：官方小工具的「查这根脚现在什么状态」子命令，输出复用功能/方向/电平——它走内核正规接口查，正好给 devmem 的野路子做对账）。

### 第二、三步：置位 / 清零 / 读回

```bash
sudo busybox devmem 0xFE20001C 4 0x00020000   # GPSET0 bit17 → LED 亮
sudo busybox devmem 0xFE200034 4               # GPLEV0 读回，bit17 应为 1
sudo busybox devmem 0xFE200028 4 0x00020000   # GPCLR0 bit17 → LED 灭
```

**命令拆解：** 点灯/读回/熄灯三连（参数含义同上表，不再重复 sudo/宽度）

| 命令                             | 硬件效果                                                         |
| -------------------------------- | ---------------------------------------------------------------- |
| `devmem 0xFE20001C 4 0x00020000` | 往 GPSET0 写「bit17=1」→ 引脚输出 3.3V → LED 亮                  |
| `devmem 0xFE200034 4`            | 读 GPLEV0：bit17 应为 1（硬件实际电平，不是你写入的回声）        |
| `devmem 0xFE200028 4 0x00020000` | 往 GPCLR0 写「bit17=1」→ 引脚拉 0V → LED 灭（注意：写 1 才清 0） |

**你会看到**：亮/灭肉眼可辨；读回值 `0x00020000`（bit17 = 1）。
**失败了先查**：第一步方向没设对（读回恒 0）、引脚选错（对照 ch01 接线）。

万用表直流电压档（DC V 档：表笔并联在测量点与 GND 之间读电压）：LED 亮时 GPIO17 对 GND 约 **3.3V**，灭时 0V（表笔先共地，ch01 规约）。

注意一个事实：这些写操作**绕过了内核的 GPIO 子系统**。如果目标引脚正被某个内核驱动占用，
你是在和内核抢方向盘——选 GPIO17 就是为了躲开默认占用（串口在 14/15、I2C/SPI 默认关闭）。

## 4. 考古：sysfs 旧接口（/sys/class/gpio）

老教程里遍地都是的 `/sys/class/gpio`，用法本身很简单：

```bash
ls /sys/class/gpio                     # 预期：export  unexport  gpiochipN
cat /sys/class/gpio/gpiochip0/base     # 预期 0；若非 0，export 的编号要加上 base
echo 17 | sudo tee /sys/class/gpio/export
echo out | sudo tee /sys/class/gpio/gpio17/direction
echo 1  | sudo tee /sys/class/gpio/gpio17/value      # LED 亮
echo 17 | sudo tee /sys/class/gpio/unexport
```

**命令拆解：** sysfs 点灯全套（`echo X | sudo tee 文件` 的组合 = 「把 X 写进需要 root 权限的伪文件」；伪文件本身没有内容，写它 = 触发内核动作）

| 命令                               | 作用                                                    |
| ---------------------------------- | ------------------------------------------------------- |
| `ls /sys/class/gpio`               | 看接口在不在：有 `export`/`unexport`/`gpiochipN` 即活着 |
| `cat .../gpiochip0/base`           | 查这块 GPIO 芯片的**起始编号**，决定 export 用哪个号    |
| `echo 17 \| .../export`            | 向内核申请把全局 17 号线「导出」→ 出现 gpio17/ 目录     |
| `echo out \| .../gpio17/direction` | 设为输出方向（对应 GPFSEL 的活，由内核代写寄存器）      |
| `echo 1 \| .../gpio17/value`       | 写 1 = 输出高电平（内核代写 GPSET）→ LED 亮             |
| `echo 17 \| .../unexport`          | 释放这根线，gpio17/ 目录消失                            |

**你会看到**：export 后目录里长出 `direction`/`value` 等伪文件；value 写 1 后 LED 亮、读回也是 1。
**失败了先查**：`ls` 空的/不存在 = 本内核没开 CONFIG_GPIO_SYSFS（下文讲了，考古降级为纯讲解）；export 报 `Device or resource busy` = 该线已被内核驱动占用。

> 📖 **术语卡：gpiochip 与全局编号（legacy numbering）**
> **是什么**：内核把每块 GPIO 控制器芯片登记为一个 `gpiochipN`，带一个 `base`（起始编号）；sysfs 时代「全局编号」= 芯片 base + 芯片内偏移。BCM2711 的 GPIO 控制器通常是 gpiochip0、base=0，所以全局 17 恰好就是 GPIO17。
> **为什么脆弱**：板上一加**GPIO 扩展器**（经 I2C/SPI 总线外挂的额外 GPIO 芯片），它也会登记成 gpiochip1、base 接在后面——所有编号集体漂移，写死的 17 从此指鹿为马。
> **类比**：全市统一门牌号——城里一插新小区，后半城门牌全部重编，写死门牌的信全送错。

先说现状事实（已核对）：主线内核**至今没有真正删除** sysfs GPIO——GPIO 子系统维护者在
FOSDEM 2025 的报告原话是「用户态没迁完，删不动」（FOSDEM：欧洲最大的开源开发者年度聚会）；树莓派官方 6.6 内核 defconfig（内核「默认配置模板」，发行版/厂商从它出发裁剪出正式内核配置）仍开着
`CONFIG_GPIO_SYSFS=y`。但它在内核 ABI 文档里自 2015 年就从 testing 挪进了 obsolete（ABI：应用二进制接口，内核承诺「永不变卦」的用户态对接面；testing = 观察期、obsolete = 官宣弃用——你的主场）。本机
`ls /sys/class/gpio` 是否出 gpiochipN，以实测为准（出不来就是该内核把配置关了，考古降级为
纯讲解）。

废弃的三宗罪，每一条都对应 libgpiod 的一个设计决定：

| #   | 罪状               | sysfs 的做法                                                      | libgpiod 的对策（[[ch03-libgpiod-userspace-toll\|ch03]]） |
| --- | ------------------ | ----------------------------------------------------------------- | --------------------------------------------------------- |
| 1   | 全局编号空间       | export 的 17 依赖 chip base=0；板上一加 GPIO 扩展器，编号全体漂移 | 芯片名 + 偏移（`gpiochip0 17`），彻底消灭全局号           |
| 2   | 无事件             | value 只能轮询读，没有边沿/中断通知                               | line event + gpiomon（ch05 的用户态伏笔）                 |
| 3   | 无所有权、全局可写 | 谁都能 echo export/value，互相踩                                  | 请求制：谁请求谁持有，fd 关闭即释放                       |

（表内两个生词：边沿 = 电平的跳变瞬间，0→1 叫上升沿、1→0 叫下降沿，按键检测要捕的就是它；轮询 = 反复读值等变化，CPU 空转陪跑。fd（file descriptor，文件描述符）= 进程打开文件/设备后拿到的整数句柄，fd 关闭即自动释放资源是 Unix 的通用回收时机——你的主场。）

接口演化是活教材：**字符设备 + 请求制不是设计出来的，是被这三宗罪逼出来的**。读旧接口的
墓志铭，比直接学新接口更能理解新接口为什么长这样。

## 与 F429/裸机对照

| 动作     | F429 裸机                 | Linux 用户态                           |
| -------- | ------------------------- | -------------------------------------- |
| 设为输出 | `GPIOA->MODER \|= 1<<10;` | root + busybox devmem RMW GPFSEL1      |
| 拉高     | `GPIOA->BSRR = 1<<5;`     | root + devmem 写 GPSET0                |
| 前置条件 | 无——上电即权柄            | root + /dev/mem 存在 + CONFIG 允许     |
| 出错半径 | 整机（反正只有你）        | 仍是整机物理，但**权限可审计、可回收** |

裸机里写寄存器是「能力」，天天干；Linux 里它成了 root 特权动作。这层特权墙在防什么？——
防的是**多进程世界里一个失控进程把所有外设状态当全局变量踩**。F429 单体固件没有这个烦恼，
因为它只有一个执行流；等 FreeRTOS 把第二个任务带进来，「谁的临界区」问题立刻出现（临界区 critical section：必须独占执行、不许他人插入的代码段——你的主场；参见
[[ch18-critical-sections-spinlocks|FreeRTOS 深度解析（十八）：临界区]]）。
Linux 的答案是干脆把 MMIO 关进文件权限的笼子。

而 devmem 同时证明了：墙是策略不是物理。MMIO 终究是 MMIO——内核自己每时每刻都在做同一件事。
[[ch04-kernel-module-mygpio|ch04]] 我们进内核，亲眼看内核版寄存器写入长什么样。
