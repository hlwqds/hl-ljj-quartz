## 9.1 L4 射频证据链：站在肩膀上

前两章的病灶查到「链路质量低、重传占比高」就该往下走了——L4（射频层）是链路的物理地基。方法框架完全复用 [[wifi-hw-debug-ch07-phy-measurements|WiFi 调试（七）]] 的证据链：**症状分型 → 指标测量 → 降级实验 → 根因收束**，仪器使用（频谱仪、功率计、可变衰减器）不再重复。本章补的是 Thread 特有的三块拼图：

```text
        （本章证据链的位置）
 L1~L3：ot-cli 表格/计数器（第七、八章）──┐
 L3.5 ：空口抓包重传分布（第三章）────────┤→ 指向 L4
 L4   ：功率/频偏/灵敏度/占用率（本章）──┘
```

| 上层症状（七八章口径） | 本章要回答的问题                    |
| ---------------------- | ----------------------------------- |
| retry 占比全网均匀偏高 | 信道占用是否被 WiFi 吃掉了？（9.4） |
| 单链路 margin 见底     | 灵敏度/功率/天线是否达规格？（9.3） |
| 强信号仍误码           | 频偏/邻道/调制质量问题？（9.3）     |
| 信道环境复杂           | 该换哪个信道？（9.4.3）             |

## 9.2 物理层速览

### 9.2.1 O-QPSK DSSS：慢而稳的 250 kbps

2.4 GHz 频段的 IEEE 802.15.4 PHY 是 **O-QPSK 调制 + DSSS 扩频**（IEEE 802.15.4-2015 口径）：每个符号 4 bit 映射为 32 片（chip）的伪随机序列扩频，恒定速率 **250 kbps**，2.4 GHz 信道 11~26（每信道 5 MHz，第三章的信道表口径）。设计取向一句话：**不用速率换链路预算**——扩频增益换来更高的接收灵敏度和更强的抗干扰容忍，与 WiFi「速率分级换吞吐」是相反的哲学。

| 协议       | 物理层        | 速率量级       | 设计取向                     |
| ---------- | ------------- | -------------- | ---------------------------- |
| WiFi (11n) | OFDM          | 数十~数百 Mbps | 速率分级，高速率牺牲链路预算 |
| BLE 2M/1M  | GFSK          | 1~2 Mbps       | 低成本低功耗，速率中等       |
| 802.15.4   | O-QPSK + DSSS | 250 kbps 恒定  | 链路预算优先，速率恒定不协商 |

调试含义：Thread **没有速率协商**这回事（对照 [[wifi-hw-debug-ch07-phy-measurements|WiFi 调试（七）]] 的速率诊断思路在此失效）——250 kbps 是常数，所有吞吐类问题都是**时间问题**（信道占用/重传/CSMA 等待）而不是速率问题。这个恒等式反而简化了排障：吞吐低 → 先查空口时间账，不用查调制与编码方案。

时间账可以直接算（教学计算示意）：250 kbps ≈ 31 KB/s 量级，一个 100 字节的 MAC 帧，加上前导/PHY 头的传输时长约几 ms（精确到 µs 级的帧时长公式见 IEEE 802.15.4-2015 的 PHY 段，symbol duration 与各前导长度以标准表为准）。做容量估算时的直觉口径：**一条报文占空口毫秒级，重传一次翻一倍，CSMA 每轮退避再添毫秒级等待**——第八章「重传占比」的每一分都要在这个时间账上付利息。

| 空口事件（教学示意）       | 时间量级            | 来源               |
| -------------------------- | ------------------- | ------------------ |
| 100 B 帧发射               | 数 ms               | 250 kbps 恒速      |
| MAC 确认等待+ACK           | 1 ms 量级           | MAC 时序（标准表） |
| CSMA 一轮退避              | ms 级（随 BE 翻倍） | 9.4.1 机制         |
| 整次失败（4 轮退避后放弃） | 数十 ms 级          | 累计账             |

### 9.2.2 为什么 802.15.4 链路预算更宽裕

接收灵敏度是链路预算的另一个入项（margin = 信号强度 − 灵敏度，第八章 8.2.2 的余额概念）：**IEEE 802.15.4-2015 对 2.4 GHz PHY 的最低灵敏度要求是 −85 dBm**；实际芯片普遍远好于规范底线——以 nRF52840 为例，datasheet 给出的 802.15.4 接收灵敏度为 −97 dBm 量级（nRF52840 Product Specification 口径，**具体值以所用版本为准**；ESP32-H2 等其他芯片查各自 datasheet，待逐项核对）。对照 WiFi（灵敏度典型 −70~−90 dBm 区间、随速率分级，见 [[ch05-rx-chain-sensitivity|射频入门（五）]]）与 BLE（见 [[ble-debug-ch08-ble-rf-phy|蓝牙调试（八）]]），802.15.4 的灵敏度门槛设计就低一档，加上发射功率同在 +8 dBm 规范上限内、速率慢每 bit 能量足，**同场地 Thread 的单跳距离/绕射余量通常优于 WiFi**——这解释了一个现场常见反差：「WiFi 掉线的房间，Thread 传感器还好好的」。

## 9.3 射频指标：判据与典型病灶

指标框架与 [[ble-debug-ch08-ble-rf-phy|蓝牙调试（八）]] 同构（两者同为 2.4 G 短距协议），判据口径换成本章的：

| 指标     | 测什么                     | 判据口径                                                               | 典型病灶（现场表现 → 指纹）                     |
| -------- | -------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------- |
| 发射功率 | 帧的能量                   | 规范上限 +8 dBm（IEEE 802.15.4-2015）；实际值查芯片 datasheet/固件配置 | 功率被固件配低 → 远端 margin 不足（第八章病灶） |
| 频偏     | 载波频率准确度             | 规范容限 ±40 ppm（IEEE 802.15.4-2015 口径）                            | 晶振差/温漂 → 误码随温度时间漂移，信号强也丢包  |
| 灵敏度   | 最低可解调电平             | 规范 −85 dBm 底线；芯片实测远优（9.2.2 口径）                          | 灵敏度劣化 → 同距离邻居 LQ 全面下降             |
| 邻道抑制 | 相邻信道强干扰下的解调能力 | 规范有最低要求（IEEE 802.15.4-2015，具体 dB 值以标准表为准）           | 特定信道组合才坏 → 邻道/共道干扰被误判为硬件病  |

调试读法（沿用 [[ble-debug-ch08-ble-rf-phy|蓝牙调试（八）]] 的「指标 → 病灶」映射法）：**信号强却误码高 → 先怀疑频偏/干扰而不是功率**；**整片设备同向劣化 → 查共道干扰或环境**；**单台劣化 → 查该台硬件与天线**（装配、天线馈点、外壳屏蔽——结构侧细节见 [[wifi-hw-debug-ch08-antenna-structure|WiFi 调试（八）]] 的方法论，同适用于 802.15.4 设备）。频偏类病灶在电池设备上还有一个高发变体：低温下晶振频偏出容限，冬季批量返修的「冬天不好用」先测频偏温度曲线。

### 9.3.2 从表格到动作：一组指标的测量次序

表格给的是「判据是什么」，现场还需要「按什么顺序测」——原则仍是取证成本从低到高（第一章口径）：

| 步骤 | 动作                                  | 成本   | 回答的问题                         |
| ---- | ------------------------------------- | ------ | ---------------------------------- |
| 1    | 双板对测定距 RSSI/LQ（9.5.2）         | 零成本 | 病跟板、跟位置还是跟信道           |
| 2    | ot-cli 能量扫描全信道（9.5.1）        | 零成本 | 信道占用分布                       |
| 3    | 核对固件功率/信道配置 vs datasheet    | 零成本 | 配置性劣化（功率被调低、信道错配） |
| 4    | 抓包统计 retry/CCA 失败（第八章口径） | 低成本 | 时间账流向（9.4.2）                |
| 5    | 频偏/邻道的仪器测量（7 章 7 的方法）  | 需仪器 | 指标级定案                         |

前四步不需要任何专用仪器，能解决现场绝大多数「疑似射频病」——大多数最后落在配置或信道占用上，真到第 5 步的才是指标级硬件问题。这个比例本身就是本章最重要的现场经验：**先怀疑世界（干扰），再怀疑芯片。**

## 9.4 CSMA/CA 与信道占用

### 9.4.1 802.15.4 的退避机制

802.15.4 的 CSMA/CA（IEEE 802.15.4-2015 MAC 口径）：发送前先做 **CCA**（空闲信道评估），忙则**二进制指数退避**后重试——退避窗口由三个 MAC PIB 属性控制：

| 属性                 | 默认值（IEEE 802.15.4 口径） | 作用                                    |
| -------------------- | ---------------------------- | --------------------------------------- |
| `macMinBE`           | 3                            | 首轮退避窗口指数（2^BE−1 个时隙中随机） |
| `macMaxBE`           | 5                            | 退避窗口指数上限，逐轮翻倍到顶          |
| `macMaxCSMABackoffs` | 4                            | 退避重试上限，用尽则本次发送失败        |

（退避的基本时间单位 unitBackoffPeriod 与带信标网络下的额外规则，见标准 MAC 段，以标准表为准。）直观账：默认配置下最多退避 4 轮，**全忙就放弃本次发送**——帧被上层按失败处理，进入重传/端到端兜底，第八章的两层账本又叠一层。

```text
        （格式示意：一次 CSMA/CA 发送）
 想发 → CCA→闲 →发 ✓
      → CCA→忙 →随机退避 BE=3 →CCA→忙 →退避 BE=4 →CCA→闲 →发 ✓
      → 4 轮退避后仍忙 →放弃（本帧失败，MAC 计数器记一笔 → 8.6 的 counters 取证）
```

这解释了第八章 `counters mac` 里两个最值得盯的计数：**TxRetry**（MAC 层自己重传的次数）与 **CCA 失败/忙碌拒绝类计数**（进不了空口的次数）。两者高低的组合还指向不同病灶：

| 组合                   | 解读                         | 方向                       |
| ---------------------- | ---------------------------- | -------------------------- |
| CCA 失败高、TxRetry 低 | 帧挤不进空口（信道被占）     | 共存/占用病 → 9.4.2        |
| TxRetry 高、CCA 失败低 | 发得出去但对方收不好/收不到  | 链路质量/硬件病 → 9.3、9.5 |
| 双双走高               | 恶性循环：挤不进→攒队列→更挤 | 先治占用，再看残余链路问题 |

一把 CSMA 参数表还能反着用：固件若改过 `macMinBE`/重传上限（多见于「救弱链路」的调参），先核对配置再谈病灶——调参不当本身就是病源（与第八章 8.3 的权衡提醒同源）。

### 9.4.2 与 WiFi 共存：谁让谁

2.4 GHz 是 Thread、WiFi、BLE 三家共用（频段图见 [[ch02-radio-and-spectrum|射频入门（二）]]，共存全景见 [[ch14-interference-coexistence|射频入门（十四）]]）。Thread 的处境可以用一句话概括：**流量短小但 CSMA 处于弱势**。

| 维度       | WiFi                               | Thread（802.15.4）                          |
| ---------- | ---------------------------------- | ------------------------------------------- |
| 单帧占用   | 长帧、聚合后毫秒~数十 ms 连发      | 短帧，百 ms 级报文也只占空口零点几 ms       |
| 竞争策略   | 高功率长占，CCA 阈值与 Thread 不同 | CCA 检测得到 WiFi（能量大），反向检测常失效 |
| 被挤占时   | 几乎不退让                         | 只能退避，4 轮后退让失败                    |
| 后果不对称 | WiFi 吞吐略降，几乎无感            | Thread retry/CCA 失败暴涨，设备「变卡」     |

「谁让谁」的机制：Thread 的 CCA 按能量检测，**听得见 WiFi**（WiFi 高功率）→ 忙则退避；WiFi 对低功率的 802.15.4 帧常常**检测不到**（能量低于其 CCA 门限）→ 不让路。所以共存病的流向几乎总是单向的：WiFi 吃掉 Thread 的 airtime，Thread 退让到底。一个对称的干扰案例（教学推演）：微波炉工作时在 2.4 GHz 全段注入宽频噪声，能量扫描上表现为 11 信道附近抬升——与 WiFi 共道病在扫描图上可区分：微波炉是**时间性**的（工作时才有），WiFi 是**常驻**的，分时段两次扫描对比即可判别（判别思路见 [[ch14-interference-coexistence|射频入门（十四）]]）。

### 9.4.3 信道选择策略

对策按性价比排序：

| 策略                  | 做法                                                                                              | 依据/口径                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 避开 WiFi 主信道      | 建网前用 ot-cli 能量扫描（9.5）选安静处；优先落在 WiFi 信道 1/6/11 的齿缝                         | 802.15.4 信道 15/20/25/26 与 WiFi 主信道错位的常用经验（见 [[ch14-interference-coexistence\|射频入门（十四）]]） |
| 利用 netdata 信道通告 | 信道/信道掩码随 network data 分发，可全网协调迁移（机制以 Thread Specification 版本为准，待核对） | 第八章 network data 的「公告板」视角                                                                             |
| 高信道优先            | 信道 26 频点最高、远离多数 WiFi 流量，但部分芯片高频端灵敏度略降，需实测                          | 查芯片 datasheet 的各信道灵敏度表（待逐项核对）                                                                  |
| 运行时换道            | 依托 pending dataset 做全网信道迁移（第四章 dataset 家族口径）                                    | 迁移窗口安排在业务低峰，防中途分区                                                                               |

### 9.4.4 共存病的工程缓解清单

信道选不动时（现场环境被 WiFi 填满），还有一列缓解手段，按「动谁」分组：

| 动谁   | 手段                                                                    | 代价与边界                                           |
| ------ | ----------------------------------------------------------------------- | ---------------------------------------------------- |
| 动自己 | 降低 WiFi 侧重试与大流量（抓包确认主冲突源）                            | 受制于别人家设备时不可行                             |
| 动参数 | 调大 MAC 重传上限救关键流量（8.3 的权衡提醒）                           | 加剧信道占用，整网视角评估                           |
| 动时序 | 业务错峰（OTA/上报避开 WiFi 高峰时段）                                  | 需要业务侧配合                                       |
| 动硬件 | 选带共存 PTA 引脚的芯片（WiFi+15.4 二合一方案常见，口径以芯片手册为准） | 硬件改版成本；PTA 只在**同一块板**内协调，管不了邻居 |

缓解清单的纪律与第七章功耗优化同构：先做无感知的（错峰、治理自己流量），再谈判判延迟预算的（重传参数），最后才动硬件。

## 9.5 降级估计法：不用频谱仪也能定位

没有频谱仪时的低成本三板斧（方法思想同 [[wifi-hw-debug-ch07-phy-measurements|WiFi 调试（七）]] 的降级实验，工具换成 ot-cli）：

### 9.5.1 ot-cli 扫描：能量与 beacon 两把尺

```console
> scan energy 11 26      ## 能量扫描（示意输出格式）
| Ch | RSSI |
| 11 | -88  |
| 15 | -55  |   ← 有常驻能量：大概率 WiFi 共道（示意值，非实测）
| 26 | -90  |
Done
> scan          ## （主动/beacon 扫描，示意格式）
| J | Network Name     | Extended PAN | PAN  | MAC Channel | ...
| 0 | MyThreadNet      | ...          | ...  |          15 | ...
Done
```

读法：**能量扫描看「信道有多吵」**（能量高 = 有别的流量，不区分是谁）；beacon 扫描看「有哪些 Thread 网在空中」（排查 PAN 冲突与邻网干扰）。输出数值随环境时刻变动，样例仅示格式。

三个实操注意：①能量扫描是**瞬时采样**，同一信道不同时刻扫出不同结果，找常驻干扰要多扫几轮取稳定值；②能量扫描不带协议信息，「吵」可能是 WiFi、微波炉或邻网 Thread，定性靠 9.4.2 的分时段对比与抓包；③beacon 扫描发现同区域多网时，记下各网信道与 PAN——邻网流量计入你的「信道占用账」，选信道时要把它当作和 WiFi 一样的占用者对待。

### 9.5.2 定距 RSSI 与双板对测

| 方法      | 做法                                                 | 回答的问题                            |
| --------- | ---------------------------------------------------- | ------------------------------------- |
| 定距 RSSI | 两板固定距离（如 1 m/5 m）对发，读对方测得的 RSSI/LQ | 该台设备的功率/灵敏度是否达同批次水平 |
| 双板对测  | 疑似坏板 × 已知好板互相测，再换角对照                | 坏板跟随「哪一侧」→ 病在哪一侧        |
| 邻道扫描  | 固定位置对 11~26 全信道扫能量+重传对比               | 病是「共道相关」还是「全信道一致」    |

对测的操作细节（影响结论有效性）：两板**固件发射功率配置必须一致**（否则比较无意义，先核对第 3 步配置）；距离固定在近场之外（几米级，避免贴脸时 RSSI 饱和）；每个组合多轮取样取中位——单帧 RSSI 抖动多 dB 很正常。对测的结论是**相对判据**（这台 vs 同批次），不是绝对指标——绝对值留给第 5 步仪器测量。

判读逻辑与 [[ble-debug-ch08-ble-rf-phy|蓝牙调试（八）]] 的对测法一致：**跟板走 → 硬件病；跟位置走 → 环境病；跟信道走 → 干扰病**。

### 9.5.3 三层证据交叉验证

三板斧各自的证据要拼起来看，单份都可能误导（能量扫描把邻网 Thread 流量也计成「吵」，抓包没解密时分不清重传归属）。交叉验证矩阵：

| 组合                      | 一致的结论                 | 矛盾时的下一步                           |
| ------------------------- | -------------------------- | ---------------------------------------- |
| 能量扫描高 + retry 全网高 | 共道占用坐实               | 对抓包确认干扰源类型（WiFi/微波炉/邻网） |
| 能量扫描高 + retry 局部高 | 占用是背景，病灶另有其因   | 回第八章查该链路的 LQ 与非对称性         |
| 扫描安静 + retry 仍高     | 非占用问题：链路余量或硬件 | 双板对测定侧；查频偏温度特性             |
| 双板对测跟板 + 邻道全一致 | 板级发射/接收指标劣化      | 进入 9.6 送测评估                        |

验证闭环的最后一步永远是**复测**：任何对策（换信道/改配置/换板）落地后，重跑同一组扫描与 retry 统计，用同口径数据对比——这条纪律与第七、八章的复测闭环完全一致。

## 9.6 收尾：病灶对照与何时送测

| 症状指纹                      | 高概率根因            | 本章判据/去处                          |
| ----------------------------- | --------------------- | -------------------------------------- |
| 同距离邻居 LQ 全面下降        | 灵敏度/天线劣化       | 双板对测跟板 → 硬件；9.3/9.5           |
| 信号强仍误码、劣化随温度漂    | 频偏出容限            | 测频偏温度曲线（±40 ppm 规范口径）     |
| retry/CCA 失败全网均匀抬升    | 共道占用（多为 WiFi） | 能量扫描 + 抓包同信道 WiFi 流量；9.4.2 |
| 特定信道组合才坏              | 邻道/共道干扰         | 邻道扫描定位组合；换信道验证           |
| 远端 margin 长期不足          | 发射功率被固件配低    | 核对固件功率配置 vs datasheet          |
| 「WiFi 坏的房间 Thread 好用」 | 正常（链路预算差异）  | 9.2.2 的机制解释，非病灶               |

这张表与 [[ble-debug-ch08-ble-rf-phy|蓝牙调试（八）]] 的病灶对照、[[wifi-hw-debug-ch07-phy-measurements|WiFi 调试（七）]] 的测量判读同源——三个 2.4 G 系列在 L4 层共享同一套「指纹 → 根因」骨架，差别只在各协议的物理层参数与判据口径。跨系列排查时先对齐口径再对症状，避免拿 WiFi 的灵敏度直觉判 Thread（后者规范底线低得多，9.2.2）。

三个系列的 L4 职责边界顺带划清：WiFi 系列管「高速率下的速率协商与吞吐」，BLE 系列管「连接事件的射频窗口」，本章管「恒定低速下的时间账与共存弱势」——同一个 2.4 GHz 频段，三种生财之道，三种病谱。判症状前先认协议，判协议前先对口径。

**何时送测**：三板斧定位到「跟板走」的硬件病、或指标接近规范容限边缘（频偏/灵敏度/邻道）时，手工测量已到分辨率极限，应送认证级实验室做传导/辐射全套——流程与预算见 [[thread-debug-ch11-certification-pretest|第十一章：认证与预测试]]，法规框架参见 [[ch17-certification-regulations|射频入门（十七）]]。送测前的自查清单把本章速查表过一遍，能省一轮实验室来回。

送测前自查清单（全绿才送，避免花钱确认自己能免费确认的事）：

| #   | 自查项                                       | 依据       |
| --- | -------------------------------------------- | ---------- |
| 1   | 固件功率/信道配置与设计一致                  | 9.3 步骤 3 |
| 2   | 双板对测已定侧（跟板/跟位置/跟信道）         | 9.5.2      |
| 3   | 能量扫描多时段采样（排除时间性干扰源）       | 9.4.2      |
| 4   | 抓包 retry 归因已完成（哪条链路/什么方向）   | 8.6.2      |
| 5   | 疑似指标已与 datasheet/规范逐项对过口径      | 9.3        |
| 6   | 需要实验室回答的问题写成一句话（测哪个指标） | ——         |

清单第 6 条值得展开：送测请求写得越具体，实验室越省、你也越省——「帮我测测这块板」与「请测 2480 MHz 信道下该板的接收灵敏度并给出 EVM/频偏报告」是两种价格的服务。第八章 8.6 的多轮快照纪律在送测这件事上同样成立：**带着时间线去，而不是带着一句「时好时坏」去。**
