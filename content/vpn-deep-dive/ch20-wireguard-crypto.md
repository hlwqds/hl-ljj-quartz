## 1. WireGuard 加密套件概述

### 1.1 固定加密套件设计

WireGuard 使用**固定的加密套件**，不协商、不妥协：

```
┌─────────────────────────────────────────────────────────────────┐
│                    WireGuard 加密套件                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  用途              │ 算法                    │ 密钥长度  │   │
│  ├─────────────────────────────────────────────────────────┤   │
│  │  身份认证/密钥交换 │ Curve25519 (ECDH)      │ 256 bits  │   │
│  │  对称加密          │ ChaCha20               │ 256 bits  │   │
│  │  消息认证          │ Poly1305               │ 128 bits  │   │
│  │  哈希函数          │ BLAKE2s                │ 256 bits  │   │
│  │  密钥派生          │ HKDF (基于 BLAKE2s)    │ -         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  为什么固定不协商？                                              │
│  ├─ 防止降级攻击（攻击者强制使用弱算法）                       │
│  ├─ 简化实现（无需复杂的协商逻辑）                             │
│  ├─ 减少攻击面（代码量更小）                                   │
│  └─ 确保最高安全性（只使用现代算法）                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 与其他 VPN 的加密协商对比

```
┌─────────────────────────────────────────────────────────────────┐
│                   加密套件协商对比                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  IPsec (可协商):                                                │
│  ├─ IKE 阶段协商加密算法（AES/3DES/ChaCha20）                 │
│  ├─ IKE 阶段协商认证算法（RSA/ECDSA/PSK）                      │
│  ├─ ESP 阶段协商加密算法                                        │
│  └─ 问题：可能协商到弱算法                                      │
│                                                                 │
│  OpenVPN (可协商):                                              │
│  ├─ TLS 握手协商加密套件                                        │
│  ├─ 支持 AES-256-GCM / AES-128-GCM / ChaCha20-Poly1305        │
│  └─ 问题：配置复杂，可能使用弱密码                              │
│                                                                 │
│  WireGuard (固定):                                              │
│  ├─ 无协商，所有通信使用 ChaCha20-Poly1305                     │
│  ├─ 所有密钥交换使用 Curve25519                                 │
│  └─ 优势：简单、安全、可预测                                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 2. Curve25519 椭圆曲线密钥交换

### 2.1 Curve25519 简介

Curve25519 是 **Daniel J. Bernstein** 设计的椭圆曲线 Diffie-Hellman (ECDH) 算法，专门为高性能和安全性优化：

```
┌─────────────────────────────────────────────────────────────────┐
│                       Curve25519 特性                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  数学背景：                                                      │
│  ├─ 椭圆曲线: y² = x³ + 486662x² + x (mod 2^255 - 19)          │
│  ├─ 基础点 G 的阶: 2^252 + 27742317777372353535851937790883648493│
│  └─ 安全性: 相当于 128 位对称加密                                 │
│                                                                 │
│  设计目标：                                                      │
│  ├─ 速度快：比传统 ECC 快 30%                                   │
│  ├─ 实现简单： 无需复杂的曲线参数验证                           │
│  ├─ 常数时间： 天然抗时序攻击                                   │
│  └─ 抗侧信道： 不依赖分支，降低侧信道泄漏                       │
│                                                                 │
│  密钥长度：                                                      │
│  ├─ 私钥: 32 字节随机数                                         │
│  ├─ 公钥: 32 字节（曲线上的点）                                 │
│  └─ 共享密钥: 32 字节                                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 DH 密钥交换过程

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      Curve25519 DH 密钥交换                            │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  数学原理：                                                            │
│                                                                         │
│    Alice 选择私钥 a (32字节随机数)                                      │
│    Alice 计算公钥 A = a*G                                              │
│                                                                         │
│    Bob 选择私钥 b (32字节随机数)                                         │
│    Bob 计算公钥 B = b*G                                                 │
│                                                                         │
│    共享密钥 S = a*B = a*(b*G) = b*(a*G) = b*A                         │
│                                                                         │
│                                                                         │
│  交换过程：                                                             │
│                                                                         │
│    Alice                          Bob                                  │
│    ┌──────────────┐              ┌──────────────┐                      │
│    │ 私钥 a        │              │ 私钥 b        │                      │
│    │ 公钥 A = a*G  │              │ 公钥 B = b*G  │                      │
│    └───────┬──────┘              └───────┬──────┘                      │
│            │                             │                               │
│            │  交换公钥                   │                               │
│            │──────── A ─────────────────▶│                               │
│            │◀──────────────────── B ─────│                               │
│            │                             │                               │
│            ▼                             ▼                               │
│    ┌──────────────┐              ┌──────────────┐                      │
│    │ 共享密钥      │              │ 共享密钥      │                      │
│    │ S = a*B      │   = 相同 =   │ S = b*A      │                      │
│    │ = a*(b*G)    │              │ = b*(a*G)    │                      │
│    └──────────────┘              └──────────────┘                      │
│                                                                         │
│  为什么安全性高？                                                       │
│  ├─ 离散对数问题：已知 G 和 a*G，难以求出 a                           │
│  ├─ 椭圆曲线 DLP 比整数分解难得多                                      │
│  └─ 2^128 次操作才能破解                                               │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 2.3 WireGuard 中的 DH 用法

WireGuard 在握手中使用多次 DH 计算：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    WireGuard 中的 DH 计算                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  WireGuard 使用 4 次 DH 计算：                                          │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  DH1 = DH(e_i, R)        # 发起方临时 × 响应方静态            │   │
│  │     = e_i * R                                                  │   │
│  │                                                                 │   │
│  │  DH2 = DH(i, R)          # 发起方静态 × 响应方静态            │   │
│  │     = i * R                                                  │   │
│  │                                                                 │   │
│  │  DH3 = DH(e_r, E_i)      # 响应方临时 × 发起方临时            │   │
│  │     = e_r * E_i                                               │   │
│  │                                                                 │   │
│  │  DH4 = DH(e_r, I)        # 响应方临时 × 发起方静态            │   │
│  │     = e_r * I                                                  │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  为什么需要 4 次？                                                      │
│  ├─ DH1: 提供前向保密的基础（临时-静态）                              │
│  ├─ DH2: 绑定双方静态身份                                             │
│  ├─ DH3: 临时-临时 DH，确保完美前向保密                               │
│  └─ DH4: 额外的临时-静态 DH，增强安全性                              │
│                                                                         │
│  KDF(DH1 || DH2 || DH3 || DH4) → 会话密钥                            │
│                                                                         │
│  安全性分析：                                                          │
│  ├─ 即使一个 DH 被破解，其他仍安全                                     │
│  ├─ 静态私钥泄露时，DH3 仍保护前向保密                                │
│  └─ 临时私钥泄露时，DH2 仍保护身份认证                                │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 3. ChaCha20-Poly1305 AEAD

### 3.1 AEAD 概念

**AEAD (Authenticated Encryption with Associated Data)** 同时提供加密和认证：

```
┌─────────────────────────────────────────────────────────────────┐
│                       AEAD 工作模式                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  输入：                                                          │
│  ├─ 明文 (Plaintext)                                           │
│  ├─ 密钥 (256 bits)                                            │
│  ├─ Nonce (96 bits, 每次加密必须唯一)                         │
│  └─ AAD (Additional Authenticated Data, 可选，不加密但认证)    │
│                                                                 │
│  输出：                                                          │
│  ├─ 密文 (Ciphertext)                                          │
│  └─ 认证标签 (Auth Tag, 128 bits)                              │
│                                                                 │
│  特性：                                                          │
│  ├─ 机密性: 只有知道密钥才能解密                                │
│  ├─ 完整性: 任何篡改都会导致认证失败                          │
│  ├─ AAD: 不加密但需要认证的数据（如协议头）                    │
│  └─ Auth Tag: 验证完整性的凭证                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 ChaCha20 流加密

ChaCha20 是 **Daniel J. Bernstein** 设计的流加密算法，是 Salsa20 的改进版：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         ChaCha20 算法原理                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ChaCha20 核心：                                                        │
│  ├─ 20 轮 ChaCha20 置换                                               │
│  ├─ 每轮: 4 个 quarter-round 操作                                     │
│  ├─ 输入: 256 位密钥 + 96 位 nonce + 64 位计数器                      │
│  └─ 输出: 512 位的 keystream 块                                        │
│                                                                         │
│  加密过程:                                                              │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │                                                                 │  │
│  │   明文 P[0], P[1], P[2], ...                                   │  │
│  │      │                                                      │  │
│  │      ▼                                                      │  │
│  │   生成 Keystream: S[0], S[1], S[2], ...                      │  │
│  │      │                                                      │  │
│  │      ▼                                                      │  │
│  │   密文 C[i] = P[i] XOR S[i]                                  │  │
│  │                                                                 │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│  为什么 ChaCha20 比 AES 在软件中快？                                     │
│  ├─ 无 S-box 查找（防止缓存时序攻击）                                   │
│  ├─ 只用移位、异或、加法运算                                          │
│  ├─ 无分支依赖（抗侧信道）                                            │
│  └─ 在 ARM 等无 AES-NI 的处理器上更快                                 │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.3 Poly1305 消息认证

Poly1305 是 **Daniel J. Bernstein** 设计的通用 MAC 算法：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         Poly1305 算法原理                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  Poly1305 核心：                                                        │
│  ├─ 基于 GHASH 类似的多项式哈希                                        │
│  ├─ 输入: 256 位密钥 r, 128 位预设值 s, 任意长度消息                   │
│  ├─ 输出: 128 位认证标签                                               │
│  └─ 计算: (r^m + r^(m-1) + ... + r + s) mod (2^130-5)                │
│                                                                         │
│  计算过程:                                                              │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │                                                                 │  │
│  │  1. 将消息分成 16 字节块: M = M[1] || M[2] || ...             │  │
│  │                                                                 │  │
│  │  2. 对每块计算多项式:                                           │  │
│  │     accumulator = accumulator * r + M[i] (mod 2^130-5)        │  │
│  │                                                                 │  │
│  │  3. 最后加上 s:                                                 │  │
│  │     tag = accumulator + s                                      │  │
│  │                                                                 │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│  安全性:                                                                │
│  ├─ 密钥 r 是随机生成的，确保不可预测                                  │
│  ├─ 计算在模 2^130-5 下进行，有良好的代数结构                        │
│  └─ 128 位输出足够抵抗碰撞                                           │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.4 ChaCha20-Poly1305 组合

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      ChaCha20-Poly1305 AEAD                            │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  工作流程:                                                              │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │                                                                 │  │
│  │  加密:                                                          │  │
│  │  ┌─────────────────────────────────────────────────────────┐  │  │
│  │  │  1. 密钥 K, Nonce N                                     │  │  │
│  │  │  2. ChaCha20 生成 64 字节 keystream                     │  │  │
│  │  │  3. 明文 XOR keystream → 密文                           │  │  │
│  │  │  4. Poly1305(K, N || C || AAD) → Auth Tag               │  │  │
│  │  │  5. 输出: 密文 || Auth Tag                              │  │  │
│  │  └─────────────────────────────────────────────────────────┘  │  │
│  │                                                                 │  │
│  │  解密:                                                          │  │
│  │  ┌─────────────────────────────────────────────────────────┐  │  │
│  │  │  1. Poly1305 验证 Auth Tag                              │  │  │
│  │  │  2. 如果验证失败 → 拒绝解密                              │  │  │
│  │  │  3. ChaCha20 解密 → 明文                               │  │  │
│  │  │  4. 输出: 明文                                          │  │  │
│  │  └─────────────────────────────────────────────────────────┘  │  │
│  │                                                                 │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│  Nonce 使用规则:                                                        │
│  ├─ 96 位 (12 字节) Nonce                                            │
│  ├─ WireGuard 中: 发送方 Counter 作为 Nonce 高 64 位                   │
│  └─ 同一密钥下的 Nonce 必须唯一                                       │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 4. BLAKE2s 哈希函数

### 4.1 BLAKE2s 简介

BLAKE2s 是 **Jean-Philippe Aumasson** 等人设计的哈希函数，是 BLAKE (SHA-3 候选) 的优化版本：

```
┌─────────────────────────────────────────────────────────────────┐
│                        BLAKE2s 特性                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  基本参数:                                                        │
│  ├─ 输出长度: 256 bits (BLAKE2s-256)                           │
│  ├─ 密钥长度: 最长 256 bits                                     │
│  ├─ 块大小: 64 bytes                                           │
│  └─ 速度: 比 SHA-256 快 3-5 倍                                 │
│                                                                 │
│  安全性:                                                         │
│  ├─ 与 SHA-3 同级别                                             │
│  ├─ 通过 NIST SHA-3 竞赛评估                                   │
│  └─ 无已知实际攻击                                              │
│                                                                 │
│  优势:                                                           │
│  ├─ 专为软件实现优化                                            │
│  ├─ 无需复杂硬件支持                                            │
│  ├─ 抗侧信道攻击（常数时间实现）                                │
│  └─ 支持密钥哈希 (HMAC 模式内置)                               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 WireGuard 中的 BLAKE2s 用法

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    WireGuard 中的 BLAKE2s 用法                          │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. MAC 计算 (Message Authentication Code):                             │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  MAC(Key, Data) = BLAKE2s-256(Key || Data)                     │   │
│  │                                                                 │   │
│  │  用于:                                                          │   │
│  │  ├─ MAC1/MAC2: 握手消息认证                                     │   │
│  │  └─ Cookie 计算: MAC(ServerKey, IP || Timestamp)               │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  2. 哈希计算:                                                           │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  HASH(Data) = BLAKE2s-256(Data)                                 │   │
│  │                                                                 │   │
│  │  用于:                                                          │   │
│  │  ├─ 握手消息内容的哈希                                          │   │
│  │  └─ 链式密钥派生中的中间值                                       │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 5. HKDF 密钥派生

### 5.1 HKDF 简介

HKDF (HMAC-based Key Derivation Function) 是基于 HMAC 的密钥派生函数：

```
┌─────────────────────────────────────────────────────────────────┐
│                         HKDF 原理                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  HKDF 两个步骤:                                                  │
│                                                                 │
│  1. Extract (提取):                                              │
│     ├─ 输入: 原始密钥材料 IKM + 可选盐值 salt                    │
│     └─ 输出: 伪随机密钥 PRK                                      │
│                                                                 │
│     PRK = HMAC-Hash(salt, IKM)                                  │
│                                                                 │
│  2. Expand (扩展):                                               │
│     ├─ 输入: PRK + 可选上下文 info + 输出长度                    │
│     └─ 输出: 派生的密钥序列                                      │
│                                                                 │
│     OKM = HMAC-Hash(PRK, info || 0x01) ||                       │
│            HMAC-Hash(PRK, info || 0x02) || ...                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 WireGuard 中的 HKDF 用法

WireGuard 使用 **HKDF-BLAKE2s** 作为密钥派生函数：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    WireGuard 中的 HKDF 用法                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 中间密钥派生 (Initiation 消息中):                                   │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  C_i = KDF(DH1 || DH2)                                          │   │
│  │                                                                 │   │
│  │  其中:                                                          │   │
│  │  ├─ DH1 = e_i * R (发起方临时 × 响应方静态)                    │   │
│  │  └─ DH2 = i * R (发起方静态 × 响应方静态)                      │   │
│  │                                                                 │   │
│  │  用于加密发起方的静态公钥                                        │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  2. 会话密钥派生 (双方各自计算):                                       │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  T = KDF(DH1 || DH2 || DH3 || DH4)                             │   │
│  │                                                                 │   │
│  │  Split(T) →                                                    │   │
│  │  ├─ Send_Key: 用于加密发送的数据                                │   │
│  │  ├─ Recv_Key: 用于解密接收的数据                               │   │
│  │  ├─ Send_Nonce: 发送方 Nonce                                   │   │
│  │  └─ Recv_Nonce: 接收方 Nonce                                   │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  3. 链式密钥更新:                                                      │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  用于密钥轮换时更新会话密钥                                      │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 6. WireGuard 密钥体系详解

### 6.1 三层密钥架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      WireGuard 三层密钥架构                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  Layer 1: 静态密钥 (Static Key) - 长期                          │   │
│  │  ├─ 私钥: 32 字节，存储在配置文件中                             │   │
│  │  ├─ 公钥: 32 字节，用于身份标识                                 │   │
│  │  ├─ 用途: 身份认证                                               │   │
│  │  └─ 生命周期: 长期存在，需安全存储                              │   │
│  │                                                                 │   │
│  │  Layer 2: 临时密钥 (Ephemeral Key) - 每次握手                  │   │
│  │  ├─ 私钥: 32 字节，每次握手随机生成                            │   │
│  │  ├─ 公钥: 32 字节，在握手消息中传输                            │   │
│  │  ├─ 用途: 确保完美前向保密                                      │   │
│  │  └─ 生命周期: 握手完成后立即销毁                                │   │
│  │                                                                 │   │
│  │  Layer 3: 会话密钥 (Session Key) - 每会话                     │   │
│  │  ├─ 发送密钥: 加密发送的数据                                    │   │
│  │  ├─ 接收密钥: 解密接收的数据                                    │   │
│  │  ├─ 用途: 实际数据传输加密                                      │   │
│  │  └─ 生命周期: 定期轮换 (2-3 分钟)                              │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  密钥流程图:                                                            │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │   [Static Private] ──×── [Static Public] ──── 身份标识          │   │
│  │        │                                         │              │   │
│  │        │  DH(e_i, R), DH(i, R)                   │              │   │
│  │        ▼                                         ▼              │   │
│  │   [Ephemeral Private]                      [Ephemeral Public]   │   │
│  │        │           × (销毁)                        │              │   │
│  │        └───────────────┬─────────────────────────────┘          │   │
│  │                          │                                          │   │
│  │                          ▼                                          │   │
│  │                   [Session Keys]                                   │   │
│  │                   [Send] [Recv] [Nonce]                             │   │
│  │                          │                                          │   │
│  │                          ▼ × (定期轮换)                             │   │
│  │                   [New Session Keys]                               │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 7. 密码学安全性分析

### 7.1 WireGuard 固定加密套件的安全性

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      WireGuard 安全性分析                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  Curve25519 (ECDH):                                                    │
│  ├─ 安全等级: ~2^128 (相当于 AES-128)                                 │
│  ├─ 无已知实际攻击                                                   │
│  ├─ 常数时间实现，抗时序攻击                                          │
│  └─ 广泛审查，被 TLS 1.3、SSH 等采用                                 │
│                                                                         │
│  ChaCha20-Poly1305:                                                   │
│  ├─ 安全等级: AEAD 认证，256 位密钥                                  │
│  ├─ 无已知实际攻击                                                   │
│  ├─ IETF RFC 8439 标准                                               │
│  └─ TLS 1.3 支持                                                     │
│                                                                         │
│  BLAKE2s:                                                              │
│  ├─ 安全等级: 256 位输出                                              │
│  ├─ SHA-3 候选， NIST 评估通过                                       │
│  └─ 比 SHA-256 快 3-5 倍                                             │
│                                                                         │
│  HKDF:                                                                 │
│  ├─ 基于 HMAC-BLAKE2s                                                │
│  ├─ 标准: RFC 5869                                                    │
│  └─ 密钥派生安全可靠                                                  │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 7.2 已知限制与未来风险

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      已知限制与未来风险                                  │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  后量子安全风险:                                                        │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  问题: Curve25519 可被量子计算机破解                            │   │
│  │                                                                 │   │
│  │  影响:                                                          │   │
│  │  ├─ 量子计算机出现后，当前握手中的 DH 可被破解                 │   │
│  │  ├─ 历史流量可能被解密（"store now, decrypt later")            │   │
│  │  └─ 量子计算机需约 4000 逻辑量子比特破解 RSA/ECC              │   │
│  │                                                                 │   │
│  │  解决方案 (未来):                                               │   │
│  │  ├─ 后量子密钥交换: Kyber (ML-KEM), Dilithium (ML-DSA)        │   │
│  │  ├─ WireGuard 可能添加混合模式                                  │   │
│  │  └─ 目前无标准后量子 WireGuard                                   │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  其他限制:                                                              │
│  ├─ 静态公钥暴露: 虽加密传输，被动攻击者可能识别身份模式              │
│  ├─ 时间侧信道: 密钥轮换时间可能暴露流量模式                        │
│  └─ 实现质量: 依赖具体实现的常数时间实现                            │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 8.2 性能与安全权衡

```
WireGuard 选择 ChaCha20 而非 AES 的理由：

┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  AES 在无硬件加速时的风险:                                        │
│  ├─ AES-NI 可加速，但老设备可能没有                              │
│  ├─ 软件实现 AES 需要 S-box，易受缓存时序攻击                    │
│  └─ 已知缓存时序攻击可泄露 AES 密钥                             │
│                                                                 │
│  ChaCha20 的优势:                                                │
│  ├─ 无 S-box，只用移位、异或、加法                               │
│  ├─ 自然常数时间，无缓存依赖                                     │
│  ├─ 在移动设备 (ARM 无 AES-NI) 上更快                           │
│  └─ 同样安全级别 (256 位)                                       │
│                                                                 │
│  现代设备上的选择:                                                │
│  ├─ 有 AES-NI: AES-GCM 更快                                     │
│  ├─ 无 AES-NI: ChaCha20 更快更安全                              │
│  └─ WireGuard 选择 ChaCha20 是保守安全的选择                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 9. 总结

### 9.1 密码学核心要点

```
┌─────────────────────────────────────────────────────────────────┐
│                   WireGuard 密码学核心要点                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. Curve25519 (密钥交换):                                      │
│     ├─ 256 位安全级别                                            │
│     ├─ 4 次 DH 计算确保完美前向保密                              │
│     └─ 常数时间实现，抗时序攻击                                  │
│                                                                 │
│  2. ChaCha20-Poly1305 (加密认证):                               │
│     ├─ AEAD，同时加密和认证                                      │
│     ├─ 256 位密钥，96 位 Nonce                                   │
│     └─ 无硬件加速时优于 AES-GCM                                 │
│                                                                 │
│  3. BLAKE2s (哈希):                                             │
│     ├─ 256 位输出，比 SHA-256 快 3-5 倍                         │
│     ├─ 用于 MAC 和哈希                                          │
│     └─ NIST SHA-3 候选算法                                      │
│                                                                 │
│  4. HKDF (密钥派生):                                            │
│     ├─ 基于 HMAC-BLAKE2s                                        │
│     └─ 用于从 DH 输出派生会话密钥                              │
│                                                                 │
│  5. 固定套件的优势:                                              │
│     ├─ 无降级攻击风险                                            │
│     ├─ 代码量小，易于审计                                       │
│     └─ 强制高安全级别                                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 9.2 未来发展方向

|| 方向 | 当前状态 | 说明 |
||------|---------|------|
| **后量子安全** | 研究中 | Kyber 替代 Curve25519 |
| **硬件加速** | 可选 | ChaCha20 可用 SIMD 加速 |
| **混合模式** | 无 | 同时使用经典+后量子密钥交换 |
| **国密算法** | 无计划 | WireGuard 无中国国密支持 |
