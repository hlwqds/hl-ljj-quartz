## 1. WireGuard 云端生态概述

### 1.1 为什么需要云端方案

原始 WireGuard 的配置痛点：

```
┌─────────────────────────────────────────────────────────────────┐
│                  原始 WireGuard 的配置痛点                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 密钥管理复杂                                                  │
│     ├─ 需要手动生成、分发密钥                                    │
│     ├─ 新设备加入需要更新所有对端配置                           │
│     └─ 密钥轮换需要协调所有节点                                  │
│                                                                 │
│  2. NAT 穿透问题                                                  │
│     ├─ 虽然支持 NAT，但对称型 NAT 可能需要中继                    │
│     ├─ 无内置 DERP (Detour Routing) 服务器                       │
│     └─ P2P 连接失败时无自动回退                                  │
│                                                                 │
│  3. 网络管理                                                      │
│     ├─ 无集中管理界面                                            │
│     ├─ 无用户认证集成                                            │
│     ├─ 无可视化网络拓扑                                          │
│     └─ 难以管理大量设备                                          │
│                                                                 │
│  4. 企业功能缺失                                                  │
│     ├─ 无 SSO/SAML 集成                                          │
│     ├─ 无审计日志                                                │
│     ├─ 无细粒度访问控制                                          │
│     └─ 无多租户支持                                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 云端方案分类

```
┌─────────────────────────────────────────────────────────────────┐
│                    WireGuard 云端方案分类                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 开源自建方案                                                  │
│     ├─ NetBird: Go 语言，gRPC 管理                             │
│     ├─ TailScale: 商业/开源，Go                                │
│     ├─ ZeroTier: SDN 虚拟网络，支持 WireGuard                  │
│     └─ innernet: Rust，开源                                    │
│                                                                 │
│  2. 商业托管方案                                                  │
│     ├─ Tailscale (SaaS)                                        │
│     ├─ ZeroTier Central (SaaS)                                  │
│     ├─ Cloudflare Access (Gateway)                              │
│     └─ NordVPN Teams                                            │
│                                                                 │
│  3. 简化部署工具                                                  │
│     ├─ wg-easy: Docker 部署                                     │
│     ├─ wireguard-ui: Web 管理界面                               │
│     ├─ Woodpecker: WireGuard 管理                               │
│     └─ Cloudflare Warp (代理而非 VPN)                          │
│                                                                 │
│  4. 云市场方案                                                    │
│     ├─ AWS: Cloud WAN + WireGuard                               │
│     ├─ GCP: Cloud VPN + WireGuard (实验性)                      │
│     ├─ Azure: Virtual WAN + WireGuard                           │
│     └─ 各大云商的 WireGuard 托管服务                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 2. Tailscale

### 2.1 简介

Tailscale 是基于 WireGuard 的零信任网络产品，提供 SaaS 管理平面：

```
┌─────────────────────────────────────────────────────────────────┐
│                        Tailscale 概述                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  核心特性:                                                        │
│  ├─ 基于 WireGuard 协议                                         │
│  ├─ 零信任网络访问 (ZTNA)                                      │
│  ├─ 设备身份认证 (基于 OpenID Connect)                         │
│  ├─ NAT 穿透 + DERP 中继                                       │
│  ├─ 多平台支持 (Linux/Windows/macOS/iOS/Android)              │
│  └─ 开源 (Tailscale 客户端开源，控制平面不开源)                │
│                                                                 │
│  架构:                                                           │
│  ├─ 控制平面: Tailscale 托管 (tailscale.com)                  │
│  ├─ 数据平面: WireGuard 隧道                                    │
│  └─ 编排层: DERP 服务器网络                                     │
│                                                                 │
│  定价:                                                           │
│  ├─ Free: 100 设备                                              │
│  ├─ Personal: $48/年，支持更多                                  │
│  └─ Business: 按设备收费，企业功能                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 工作原理

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         Tailscale 工作原理                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 设备注册 (OIDC 认证):                                              │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │                                                                 │  │
│  │   设备 ──▶ Tailscale 控制平面 ──▶ SSO Provider (OIDC)        │  │
│  │        │                        │                               │  │
│  │        │◀─── Device Key ────────┘                               │  │
│  │        │                                                         │  │
│  │        ▼                                                         │  │
│  │   设备获得唯一的 WireGuard 密钥对                                │  │
│  │                                                                 │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│  2. NAT 穿透 (WireGuard + DERP):                                      │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │                                                                 │  │
│  │   Device A ────── NAT ──│◀── P2P ──▶│── NAT ────── Device B   │  │
│  │                    │                                        │   │  │
│  │                    │ DERP Server (中继)                       │   │  │
│  │                    │ (当 P2P 失败时)                         │   │  │
│  │                    │                                        │   │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│  3. 访问控制 (ACL):                                                   │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │                                                                 │  │
│  │   {                                                           │  │
│  │     "acls": [                                                │  │
│  │       {"action": "accept",                                   │  │
│  │        "src": ["tag:frontend"],                             │  │
│  │        "dst": ["tag:backend:22"]}                           │  │
│  │     ]                                                        │  │
│  │   }                                                           │  │
│  │                                                                 │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 2.3 Tailscale 组件

```
┌─────────────────────────────────────────────────────────────────┐
│                      Tailscale 核心组件                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. tailscaled (守护进程)                                       │
│     ├─ 管理 WireGuard 隧道                                      │
│     ├─ 处理用户态 WireGuard                                     │
│     └─ 与控制平面通信                                            │
│                                                                 │
│  2. Tailscale 控制平面                                          │
│     ├─ 设备认证                                                  │
│     ├─ 密钥分发                                                  │
│     ├─ DERP 服务器协调                                          │
│     └─ ACL 策略分发                                              │
│                                                                 │
│  2. DERP (Detour Routing Protocol)                              │
│     ├─ NAT 穿透中继                                              │
│     ├─ 全球分布的服务器                                          │
│     └─ P2P 失败时自动使用                                        │
│                                                                 │
│  3. MagicDNS                                                     │
│     ├─ 自动 DNS 配置                                             │
│     └─ 设备名解析                                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.4 安装与使用

```bash
# Linux 安装
curl -fsSL https://tailscale.com/install.sh | sh

# 启动
tailscaled

# 连接 (OIDC 认证)
tailscale up --accept-dns=false

# 查看状态
tailscale status

# 断开
tailscale down

# ACL 示例
tailscale ACL edit --acl '{"acls": [{"action": "accept", "src": ["*"], "dst": ["*:*"]}]}'

# 子网路由
tailscale up --advertise-routes=10.0.0.0/24
```

```
┌─────────────────────────────────────────────────────────────────┐

```

### 3.2 架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         ZeroTier 架构                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 网络层级:                                                          │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │                                                                 │  │
│  │   ZeroTier PLANET (根服务器)                                   │  │
│  │         │                                                       │  │
│  │    ┌────┴────┐                                                │  │
│  │    │         │                                                │  │
│  │  LEAF     LEAF    (用户自建的根服务器)                       │  │
│  │    │         │                                                │  │
│  │    │    ┌────┴────┐                                           │  │
│  │    │    │         │                                           │  │
│  │  Node  Node    Node    (加入同一网络的设备)                    │  │
│  │                                                                 │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│  2. L2 vs L3:                                                        │
│  ├─ L2 模式: 完整的以太网，可广播/组播                              │

│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.3 安装与使用

```bash
# Linux 安装
curl -s https://install.zerotier.com | sudo bash

# 加入网络
sudo zerotier-cli join <network-id>

# 查看状态
sudo zerotier-cli status
sudo zerotier-cli listnetworks

# 离开网络
sudo zerotier-cli leave <network-id>

# 自定义路由 (管理员分配)
sudo zerotier-cli set <network-id> allowDefault=1
```

### 4.2 自托管部署

```bash
# Docker Compose 部署
mkdir netbird && cd netbird

# 创建配置
cat > config.yaml << 'EOF'
datadir: /var/lib/netbird
letsencrypt-domain: vpn.example.com
email: admin@example.com
EOF

# 启动
docker-compose up -d

# 初始化管理
nbctl setup --admin-url http://localhost:80 --management-url http://localhost:80

# 添加 peer
nbctl peer add
```

### 5.2 Docker 部署

```bash
# docker-compose.yml
version: '3'
services:
  wg-easy:
    image: ghcr.io/wg-easy/wg-easy
    container_name: wg-easy
    environment:
      - WG_HOST=vpn.example.com
      - PASSWORD=your-admin-password
      - WG_PORT=51820
      - WG_DEFAULT_ADDRESS=10.0.0.x
      - WG_ALLOWED_IPS=10.0.0.0/24
      - WG_MTU=1420
    volumes:
      - ./data:/etc/wireguard
    ports:
      - "51820:51820/udp"
      - "51821:51821/tcp"
    restart: unless-stopped
    cap_add:
      - NET_ADMIN
      - SYS_MODULE
    sysctls:
      - net.ipv4.ip_forward=1
      - net.ipv6.conf.all.forwarding=1

# 启动
docker-compose up -d

# 访问 Web UI
# http://your-server:51821
```

### 8.1 Cilium WireGuard

Cilium 支持 WireGuard 加密集群流量：

```yaml
# Cilium WireGuard 配置
apiVersion: v1
kind: ConfigMap
metadata:
  name: cilium-config
  namespace: kube-system
data:
  enable-wireguard: "true"
  # 节点间加密
  encryption-node-network: "true"
```

### 8.2 Talos Linux

Talos Linux 内置 WireGuard 支持：

```yaml
# talosconfig
machine:
  network:
    interfaces:
      - interface: wg0
        wireguard:
          privateKey: <generated>
          peers:
            - publicKey: <server-public-key>
              endpoint: <server>:51820
              allowedIPs:
                - 0.0.0.0/0
```

### 9.2 密钥同步方案

```bash
# 使用 etcd 同步 WireGuard 密钥
# 每个节点运行:
wg-keysync --etcd-endpoints=http://etcd:2379

# 密钥变化时自动同步到所有节点
# Peer 添加时:
wg set wg0 peer <pubkey> allowedips <ip>
# 自动同步到其他节点
```
