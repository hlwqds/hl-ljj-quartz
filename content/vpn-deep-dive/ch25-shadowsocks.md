## 1. 概述：Shadowsocks 设计哲学

**Shadowsocks（影梭）** 是 clowwindy 于 2011 年开发的开源翻墙工具，核心设计理念是**简单、低占用、难检测**。与 VPN 不同，Shadowsocks 本质上是一个**SOCKS5 代理**，客户端需要在本地启动一个 SOCKS5 监听端口，应用流量通过这个端口转发。

```
Shadowsocks 架构：

┌─────────────────────────────────────────────────────────────────┐
│                        翻墙用户环境                              │
│                                                                 │
│   应用 ──▶ 本地 SOCKS5 代理（127.0.0.1:1080）                   │
│                    │                                             │
│                    │ SOCKS5 协议                                 │
│                    ▼                                             │
│            Shadowsocks Client                                   │
│                    │                                             │
│                    │ 加密隧道（AEAD）                            │
│                    ▼                                             │
└────────────────────┼─────────────────────────────────────────────┘
                     │
              国际出口 │
                     │
┌────────────────────┼─────────────────────────────────────────────┐
│                    ▼                                             │
│            Shadowsocks Server                                    │
│                    │                                             │
│                    │ 原始 TCP/UDP                                │
│                    ▼                                             │
│            目标网站/服务                                          │
│                                                                 │
│                        墙外互联网                                  │
└─────────────────────────────────────────────────────────────────┘

设计特点：
├─ 非 VPN：不需要 TUN/TAP 虚拟网卡
├─ 应用层代理：只在应用层面转发流量
├─ 无连接状态：不维护长期连接状态
└─ 轻量级：单进程，内存占用小
```

## 2. SOCKS5 协议基础

### 2.1 SOCKS5 协议工作流程

Shadowsocks 基于 SOCKS5 协议，理解 SOCKS5 是理解 Shadowsocks 的基础：

```
SOCKS5 握手流程：

┌─────────────────────────────────────────────────────────────────┐
│                    SOCKS5 连接建立                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 版本协商（无认证或用户名/密码认证）                             │
│                                                                 │
│  Client ──── VER(0x05) + NMETHODS(0x02) + METHODS[2] ────▶ Server │
│              │                                                 │
│              │ 0x05 = SOCKS5                                    │
│              │ 0x02 = 有 2 个认证方法                            │
│              │ METHODS[0] = 0x00 (无认证)                       │
│              │ METHODS[1] = 0x02 (用户名/密码)                  │
│                                                                 │
│  Server ◀─── VER(0x05) + METHOD(0x02) ─────────────────── Client │
│              │                                                 │
│              │ 选择用户名/密码认证                                 │
│                                                                 │
│  2. 认证阶段（如果 METHOD = 0x02）                               │
│                                                                 │
│  Client ──── VERSION(0x01) + ID_LEN + ID + PW_LEN + PW ────▶    │
│                                                                 │
│  Server ◀─── VERSION(0x01) + STATUS(0x00) ────────────────────  │
│              │                                                 │
│              │ 0x00 = 认证成功                                  │
│              │ 0x01 = 认证失败                                  │
│                                                                 │
│  3. 连接请求                                                    │
│                                                                 │
│  Client ──── VER(0x05) + CMD(0x01) + RSV(0x00) + ATYP ───────▶  │
│              │                                                 │
│              │ CMD: 0x01 = TCP 连接                             │
│              │      0x02 = TCP 绑定                             │
│              │      0x03 = UDP 关联                             │
│              │ ATYP: 0x01 = IPv4                               │
│              │       0x03 = 域名                                │
│              │       0x04 = IPv6                               │
│                                                                 │
│              + DST.ADDR (目标地址)                               │
│              + DST.PORT (目标端口)                               │
│                                                                 │
│  Server ◀─── VER(0x05) + REP(0x00) + RSV(0x00) + ATYP ──────── │
│              │                                                 │
│              │ REP: 0x00 = 成功                                 │
│              │      0x01 = 普通错误                              │
│              │      0x02 = 规则不允许                            │
│              │      0x05 = 地址不可达                            │
│                                                                 │
│              + BND.ADDR (服务端绑定地址)                          │
│              + BND.PORT (服务端绑定端口)                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 SOCKS5 UDP ASSOCIATE

UDP 转发是 SOCKS5 的重要功能，Shadowsocks 支持 UDP 转发：

```
UDP ASSOCIATE 流程：

TCP 信道建立后：

Client ──── UDP ASSOCIATE ──────────────▶ Server
            [DST.ADDR = 0.0.0.0]
            [DST.PORT = 0]

Server ◀─── UDP REPLY ────────────────── Client
            [BND.ADDR = 实际监听地址]
            [BND.PORT = UDP 端口]

后续：
Client ──── UDP 数据报 ────────────────▶ Server ──▶ 目标
         (通过 TCP 建立的 UDP 端口)

UDP 数据报格式：
┌─────────┬─────────┬──────────┬──────────┬────────────┐
│ RSV(2)  │ FRAG    │ ATYP     │ DST.ADDR │ DST.PORT   │
│ 0x0000  │ 1 byte  │ 1 byte   │ Variable │ 2 bytes    │
├─────────┼─────────┼──────────┼──────────┼────────────┤
│                 │          │          │            │
│ TCP 头部        │ UDP Header│ 目标地址  │ 目标端口    │
│ (由代理处理)    │          │          │            │
└─────────────────┴──────────┴──────────┴────────────┘
```

## 3. Shadowsocks 协议详解

### 3.1 协议版本与加密演进

Shadowsocks 协议经历了多个版本的演进：

```
Shadowsocks 协议版本：

┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  原始版（不推荐）：                                               │
│  ├─ 2022.Blake2.AES-128-CFB                                   │
│  ├─ 2022.Blake2.AES-256-GCM                                   │
│  ├─ 2022.Blake2.ChaCha-ietf-Poly-1305                         │
│  └─ 特点：使用 2022 密钥派生函数                                 │
│                                                                 │
│  AEAD 版本（推荐）：                                             │
│  ├─ AES-256-GCM                                               │
│  ├─ AES-128-GCM                                               │
│  ├─ ChaCha20-Poly1305                                         │
│  ├─ XChaCha20-Poly1305                                        │
│  └─ 特点：完整加密 + 认证，抗注入攻击                            │
│                                                                 │
│  旧版 CFB/OFBCFB（已废弃）：                                     │
│  ├─ aes-256-cfb                                               │
│  ├─ aes-128-cfb                                               │
│  ├─ chacha20                                                  │
│  └─ 特点：只加密不认证，容易被攻击                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 AEAD 加密协议

AEAD（Authenticated Encryption with Associated Data）是当前推荐的加密模式：

```
AEAD 数据包格式：

┌─────────────────────────────────────────────────────────────────┐
│                    AEAD Shadowsocks 数据包                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  发送数据包：                                                    │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ 4 bytes       │  variable      │  16 bytes             │   │
│  │  nonce        │  ciphertext    │  tag                  │   │
│  │ (盐)          │  (加密数据)     │  (认证标签)            │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                 │
│  接收数据包：                                                    │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ 16 bytes     │  variable                                  │   │
│  │ tag          │  plaintext                                │   │
│  │ (认证标签)    │  (解密数据)                                │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                 │
│  各字段说明：                                                    │
│  ├─ nonce（盐）：每次加密随机生成，前 12 字节跟随 nonce           │
│  ├─ ciphertext：使用 ChaCha20/AES 加密                          │
│  └─ tag：Poly1305 认证标签，16 字节                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.3 加密初始化流程

```
Shadowsocks AEAD 密钥派生：

┌─────────────────────────────────────────────────────────────────┐
│                       密钥派生流程                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 原始密钥（用户配置）                                          │
│     password = 用户提供的密码                                     │
│                                                                 │
│  2. 使用 HKDF 派生会话密钥                                        │
│     ├─ 输入：password + random salt                             │
│     ├─ 输出：chacha20poly1305_key (32 bytes)                   │
│     └─ HKDF-SHA256: 64 字节输出，取前 32 字节                     │
│                                                                 │
│  3. 加密过程                                                      │
│     ├─ 生成 12 字节 random nonce                                │
│     ├─ 使用 chacha20poly1305 加密                               │
│     │   └─ plaintext: SS 原生数据                                │
│     │   └─ key: 派生的 32 字节密钥                               │
│     │   └─ nonce: 12 字节随机数                                 │
│     │   └─ ad: 协议头（可选的额外数据）                           │
│     └─ 输出：nonce || ciphertext || tag                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 4. shadowsocks-libev 实现

### 4.1 架构组件

shadowsocks-libev 是目前主流的 Shadowsocks 实现：

```
shadowsocks-libev 架构：

┌─────────────────────────────────────────────────────────────────┐
│                      shadowsocks-libev                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  进程模型：                                                      │
│  ├─ ss-local：本地 SOCKS5 代理                                  │
│  ├─ ss-server：服务器端                                         │
│  └─ ss-manager：多用户管理（通过 UDP）                          │
│                                                                 │
│  核心模块：                                                      │
│  ├─ base.c：基础工具函数                                         │
│  ├─ socks5.c：SOCKS5 协议实现                                    │
│  ├─ encrypt.c：加密/解密                                        │
│  ├─ udprelay.c：UDP 转发                                        │
│  ├─ http.c：HTTP 协议支持（可选）                                │
│  └─ tls.c：TLS 混淆（通过插件）                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 端口配置与多用户

```
配置文件示例（shadowsocks.json）：

{
    "server": "0.0.0.0",
    "server_port": 8388,
    "password": "your-password-here",
    "timeout": 300,
    "method": "chacha20-ietf-poly1305",
    "plugin": "obfs-local",
    "plugin_opts": "obfs=tls;failover=example.com",
    "mode": "tcp_and_udp"
}

多用户配置（ss-manager）：

{
    "server": "0.0.0.0",
    "port_password": {
        "8388": "password1",
        "8389": "password2",
        "8390": "password3"
    },
    "method": "aes-256-gcm",
    "manager": "127.0.0.1:6001"
}
```

### 4.3 数据流分析

```
Shadowsocks 数据流：

Client (ss-local)                          Server (ss-server)
    │                                              │
    │  1. 应用连接本地 SOCKS5 (127.0.0.1:1080)      │
    │─────────────────────────────────────────────▶│
    │                                              │
    │  2. SOCKS5 握手与请求                         │
    │◀─────────────────────────────────────────────│
    │                                              │
    │  3. 加密数据（AEAD）                          │
    │─────────────────────────────────────────────▶│
    │  │ nonce || ciphertext || tag              │
    │                                              │
    │  4. 服务器解密                               │
    │  │ 使用相同密钥派生                           │
    │  │ tag 验证完整性                             │
    │                                              │
    │  5. 转发到目标服务器                          │
    │  │─────────────────────────────────────────▶│
    │  │                目标服务器响应               │
    │  │◀──────────────────────────────────────────│
    │  │                                              │
    │  6. 加密响应                                 │
    │◀─────────────────────────────────────────────│
    │  │ nonce || ciphertext || tag              │
    │                                              │
    │  7. 客户端解密                               │
    │◀─────────────────────────────────────────────│
    │                                              │
    │  8. 通过 SOCKS5 返回应用                     │
    │◀─────────────────────────────────────────────│
    │                                              │
```

## 5. 插件系统与混淆

### 5.1 插件机制

Shadowsocks 支持通过插件扩展功能，主要用于混淆和协议模拟：

```
Shadowsocks 插件架构：

┌─────────────────────────────────────────────────────────────────┐
│                      Shadowsocks + 插件                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  无插件：                                                        │
│  Client ─────── 原始 SS 流量 ──────────▶ Server                 │
│                [加密但可识别]                                     │
│                                                                 │
│  有插件：                                                        │
│  Client ─────── obfs 混淆 ─────────────▶ Server                │
│                │                                      ▲          │
│                ▼                                      │          │
│  ┌─────────────────────┐    ┌─────────────────────┐│          │
│  │   obfs-local         │    │   obfs-server       ││          │
│  │   (TLS/HTTP 混淆)    │    │   (解混淆)           ││          │
│  └─────────────────────┘    └─────────────────────┘│          │
│                │                                      │          │
│                ▼                                      │          │
│  ┌─────────────────────┐    ┌─────────────────────┐│          │
│  │   ss-local          │    │   ss-server          ││          │
│  │   (加密)             │    │   (解密)              ││          │
│  └─────────────────────┘    └─────────────────────┘│          │
│                │                                      │          │
└────────────────┼──────────────────────────────────────┘          │
                 │                                             │
                 │ TLS 隧道                                     │
                 └─────────────────────────────────────────────▶│
                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 simple-obfs 插件

simple-obfs 是最经典的混淆插件：

```
simple-obfs 混淆模式：

1. TLS 混淆模式：

   原始流量：
   ┌──────┬─────────────────────────────┐
   │ SS   │ 加密数据 (nonce+cipher+tag)  │
   │ Header│                             │
   └──────┴─────────────────────────────┘

   TLS 混淆后：
   ┌──────────────────────────────────────────────────┐
   │         TLS ClientHello                          │
   │  SNI: failover.example.com                       │
   │  证书: example.com                                │
   │  指纹: 类似 Chrome                                 │
   └──────────────────────────────────────────────────┘
   │         实际数据（加密）                          │
   │  ┌──────┬─────────────────────────────┐         │
   │  │ SS   │ 加密数据                     │         │
   │  │Header│                             │         │
   │  └──────┴─────────────────────────────┘         │
   └──────────────────────────────────────────────────┘

   插件选项：
   plugin_opts="obfs=tls;failover=example.com;mode=client"

   ├─ obfs=tls：使用 TLS 混淆
   ├─ failover=example.com：连接失败时的备用域名
   └─ mode=client：客户端模式

2. HTTP 混淆模式：

   插件选项：
   plugin_opts="obfs=http;failover=example.com;mode=client"

   伪装成 HTTP 请求：
   GET / HTTP/1.1
   Host: example.com
   ...
```

### 5.3 v2ray-plugin（推荐）

v2ray-plugin 支持更高级的 WebSocket 混淆：

```
v2ray-plugin 混淆模式：

1. WebSocket 模式：

   插件选项：
   plugin_opts="server_plugin=v2ray;path=/ws;host=example.com;tls"

   流量伪装：

   Client                                    Server
    │                                          │
    │  TLS 握手                                 │
    │◀─────────────────────────────────────────▶│
    │                                          │
    │  WebSocket 升级                           │
    │  GET /ws HTTP/1.1                        │
    │  Host: example.com                        │
    │  Upgrade: websocket                       │
    │◀─────────────────────────────────────────▶│
    │                                          │
    │  WebSocket 帧（包含 SS 数据）              │
    │◀─────────────────────────────────────────▶│
    │                                          │

   特点：
   ├─ 使用标准 WebSocket 协议
   ├─ TLS 加密（SNI 可伪装）
   ├─ HTTP 头可以完全模拟正常网站
   └─ CDN 友好（可使用 CDN 加速）

2. QUIC 模式：

   插件选项：
   plugin_opts="server_plugin=v2ray;mode=quic"

   ├─ 使用 QUIC 协议传输
   ├─ 0-RTT 快速恢复
   └─ 原生 UDP 支持
```

## 6. Shadowsocks 的局限性

### 6.1 协议特征

虽然 Shadowsocks 使用加密，但仍有可识别的特征：

```
Shadowsocks 流量特征：

1. 数据包大小分布：
   ├─ 原始 SS：小数据包频率异常
   ├─ 有插件：类似 TLS/HTTP
   └─ 难以完全消除

2. 时序特征：
   ├─ 连接建立模式
   ├─ 心跳间隔
   └─ 重传模式

3. 端口特征：
   ├─ 默认端口 8388
   ├─ 可被端口扫描发现
   └─ 需要配合混淆使用

4. 加密指纹：
   ├─ 特定加密算法的数据包模式
   ├─ nonce 长度
   └─ tag 长度
```

### 6.2 检测与对抗

GFW 可以通过以下方式检测 Shadowsocks：

```
检测方法：

1. 协议指纹检测：
   ├─ 连接建立模式分析
   ├─ 数据包大小分布
   └─ 加密特征识别

2. 主动探测：
   ├─ 向可疑 IP 发送 SS 握手包
   ├─ 分析响应特征
   └─ 确认是否为 SS 服务器

3. 流量分析：
   ├─ 长时间流量采集
   ├─ 行为模式识别
   └─ 机器学习分类

对抗措施：
├─ 始终使用 AEAD 加密（不要用 CFB）
├─ 始终使用混淆插件
├─ 使用 CDN 或代理中转
└─ 定期更换服务器 IP
```

```
Shadowsocks 核心要点：

┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  协议架构：                                                      │
│  ├─ 基于 SOCKS5 代理                                              │
│  ├─ AEAD 加密（推荐 chacha20-ietf-poly1305）                     │
│  ├─ 可选插件混淆（simple-obfs / v2ray-plugin）                   │
│  └─ TCP + UDP 支持                                              │
│                                                                 │
│  优势：                                                          │
│  ├─ 轻量级，资源占用低                                           │
│  ├─ 配置简单，易于部署                                           │
│  ├─ 插件生态丰富                                                │
│  └─ 开源透明                                                     │
│                                                                 │
│  局限性：                                                        │
│  ├─ 协议特征仍可检测                                             │
│  ├─ 单端口单密码，无原生多用户                                   │
│  ├─ 无自动故障转移                                              │
│  └─ 需要额外配置实现高可用                                       │
│                                                                 │
│  最佳实践：                                                      │
│  1. 使用 AEAD 加密                                                │
│  2. 始终启用混淆插件                                             │
│  3. 使用 CDN 或域前置隐藏真实服务器                               │
│  4. 定期更新密码和密钥                                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

Shadowsocks 是翻墙技术的经典之作，其设计理念影响了后续的 V2Ray、Trojan 等项目。虽然单独使用 Shadowsocks 容易被检测，但配合混淆插件和 CDN 仍能提供有效的跨境访问能力。
