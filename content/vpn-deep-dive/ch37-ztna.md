## 1. 概述：零信任基础

**零信任**（Zero Trust）是一种安全范式，其核心原则是「永不信任，始终验证」（Never Trust, Always Verify）。与传统边界安全模型不同，零信任假设网络内部和外部都不可信。

```
零信任核心原则：

┌─────────────────────────────────────────────────────────────────┐
│                    零信任三大原则                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 永不信任（Never Trust）：                                     │
│  ├─ 默认不信任任何用户、设备或流量                                │
│  ├─ 无论来源是内网还是外网                                        │
│  └─ 每次访问都需要验证                                            │
│                                                                 │
│  2. 始终验证（Always Verify）：                                   │
│  ├─ 用户身份（多因素认证）                                       │
│  ├─ 设备状态（补丁、防病毒、证书）                                 │
│  ├─ 上下文（时间、位置、行为）                                    │
│  └─ 最小权限（Just-in-Time 访问）                                 │
│                                                                 │
│  3. 假设已沦陷（Assume Breach）：                                 │
│  ├─ 限制爆炸半径                                                 │
│  ├─ 微分段隔离                                                  │
│  ├─ 持续监控与检测                                              │
│  └─ 快速响应恢复                                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 2. BeyondCorp：Google 的实践

### 2.1 BeyondCorp 概述

BeyondCorp 是 Google 应对内部安全威胁的零信任实践，于 2014 年公开论文：

```
BeyondCorp 核心思想：

┌─────────────────────────────────────────────────────────────────┐
│                    BeyondCorp vs 传统 VPN                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  传统 VPN 模型：                                                │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │                                                          │  │
│  │    员工 ──VPN──>  Unternehmens-VPN  ──> 内部网络 ──> 服务 │  │
│  │                   (完全信任)              (扁平网络)      │  │
│  │                                                          │  │
│  │   问题：一旦接入VPN，整个内网可见，横向移动风险高         │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                 │
│  BeyondCorp 模型：                                              │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │                                                          │  │
│  │    员工 ──> 访问代理 ──> 各类服务（按需授权）              │  │
│  │               │                                          │  │
│  │               └──> 信任引擎（持续评估设备+用户状态）       │  │
│  │                                                          │  │
│  │   特点：无 VPN，基于身份和设备状态动态授权                 │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                 │
│  核心变化：                                                      │
│  ├─ 移除网络位置作为信任依据                                    │
│  ├─ 访问控制基于用户身份 + 设备状态                             │
│  ├─ 所有访问都经过统一入口（访问代理）                          │
│  └─ 细粒度微分段                                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 3. ZTNA 定义与概念

### 3.1 什么是 ZTNA

ZTNA（Zero Trust Network Access，零信任网络访问）是一种安全架构，为用户和设备提供对私有应用的精确访问：

```
ZTNA 定义：

┌─────────────────────────────────────────────────────────────────┐
│                    ZTNA 核心定义                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Gartner 定义：                                                 │
│  「ZTNA 为企业资产（应用、API、数据库）创建基于身份的逻辑                                │
│   访问边界，包含基于端点属性的微分段和大幅减少攻击面。」          │
│                                                                 │
│  Forrester 定义：                                               │
│  「Zero Trust Network Access 将网络安全边界从网络层面移至                                │
│   应用层面，基于身份和上下文提供精确访问。」                      │
│                                                                 │
│  NIST SP 800-207 核心组件：                                     │
│  ├─ 主体（Subject）：用户、设备、服务账号                        │
│  ├─ 资源（Resource）：应用、数据、服务                            │
│  ├─ 策略引擎（Policy Engine）：访问决策                          │
│  ├─ 策略管理员（Policy Administrator）：执行决策                  │
│  └─ 代理（Proxy）：流量控制，强制执行                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 ZTNA 服务模式

```
ZTNA 服务模式：

┌─────────────────────────────────────────────────────────────────┐
│                    ZTNA 部署形态                                 │
├─────────────────────────────────────────────────────────────────┤

│  1. 服务端代理模式（S-Agent）：                                 │
│  ├─ 安装在服务端                                                │
│  ├─ 终止来自 Client 的连接                                      │
│  ├─ 验证后转发到应用                                            │
│  └─ 适合保护数据中心应用                                        │
│                                                                 │
│  2. 客户端代理模式（C-Agent）：                                 │
│  ├─ 安装在用户设备                                              │
│  ├─ 设备端流量整形                                              │

│  └─ 适合移动办公场景                                            │
│                                                                 │
│  3. 混合模式（推荐）：                                          │
│  ├─ 客户端 + 服务端联合部署                                     │

│  │        │                    │                    │         │  │
│  │        │              ┌─────┴─────┐              │         │  │
│  │        │              │  Control  │              │         │  │
│  │        │              │  Plane   │              │         │  │

│  │        │                    │                    │         │  │
│  │        │              mTLS  │  (加密隧道)        │         │  │
│  │        │═══════════════════════════════════════════         │  │
│  │        │                    │                    │         │  │
│  │        ▼                    ▼                    ▼         │  │
│  │    用户设备           控制平面           保护的应用          │  │
│  │                                                          │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 4. ZTNA vs VPN

### 4.1 核心对比

```
ZTNA vs VPN 详细对比：

┌─────────────────────────────────────────────────────────────────┐
│                    ZTNA 与 VPN 对比                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌────────────────┬──────────────────┬──────────────────┐        │
│  │     维度        │      VPN        │      ZTNA       │        │
│  ├────────────────┼──────────────────┼──────────────────┤        │
│  │  信任模型      │ 网络边界信任      │ 永不信任         │        │
│  ├────────────────┼──────────────────┼──────────────────┤        │
│  │  可见性        │ 网络层（IP/端口） │ 应用层（URL/API）│        │
│  ├────────────────┼──────────────────┼──────────────────┤        │
│  │  访问单位      │ 子网/网络段       │ 应用/服务        │        │
│  ├────────────────┼──────────────────┼──────────────────┤        │
│  │  设备评估      │ 无/可选          │ 强制/持续        │        │
│  ├────────────────┼──────────────────┼──────────────────┤        │
│  │  横向移动      │ 允许（内网互通）  │ 禁止（微分段）   │        │
│  ├────────────────┼──────────────────┼──────────────────┤        │
│  │  攻击面        │ 较大             │ 极小             │        │
│  ├────────────────┼──────────────────┼──────────────────┤        │
│  │  用户体验      │ 需连接 VPN       │ 始终连接/无感知   │        │
│  ├────────────────┼──────────────────┼──────────────────┤        │
│  │  带宽成本      │ 加密开销较大      │ 可优化           │        │
│  ├────────────────┼──────────────────┼──────────────────┤        │
│  │  合规支持      │ 基础             │ 增强（审计）      │        │
│  ├────────────────┼──────────────────┼──────────────────┤        │
│  │  适用场景      │ 远程接入通用      │ 企业零信任       │        │
│  └────────────────┴──────────────────┴──────────────────┘        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 场景分析

```

│  推荐：ZTNA                                                    │
│                                                                 │
│  最佳实践：                                                     │
│  ├─ ZTNA 作为零信任主体                                          │
│  ├─ VPN 作为过渡/补充                                           │
│  └─ 长期目标：减少 VPN 使用                                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 NIST ZTA 原则

```
NIST ZTA 核心原则（NIST SP 800-207）：

┌─────────────────────────────────────────────────────────────────┐
│                    NIST ZTA 五大原则                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 所有数据源和计算服务都被视为资源                             │
│     → 笔记本、手机、API、云服务都是资源                         │
│                                                                 │
│  2. 无论网络位置，所有通信都需要保护                             │
│     → 位置不作为信任信号                                        │
│     → 所有流量加密（TLS/mTLS）                                  │
│                                                                 │
│  3. 企业资源访问按单次访问授予                                   │
│     → 会话级授权                                                │
│     → 持续评估                                                  │
│                                                                 │
│  4. 资源访问由动态策略决定                                       │
│     → 包括客户端身份、设备状态、请求资产                         │
│     → 可包括 behavioral attributes                              │
│                                                                 │
│  5. 企业监控并测量所有资产的完整性和安全态势                     │
│     → 持续诊断与响应（CDR）                                      │
│     → 设备卫生评分                                              │
│                                                                 │
│  关键概念：                                                      │
│  ├─ PAwS：Proxy, Authorizer, enforcer, Sustainer               │
│  ├─ PDI：Protected Data Incident                                │
│  └─ PL：Policy Rule = {Subject, Asset, Condition, Action}      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 7. Gartner CARTA

CARTA（Continuous Adaptive Risk and Trust Assessment，持续自适应风险与信任评估）是 Gartner 提出的战略方法：

```
CARTA 核心理念：

┌─────────────────────────────────────────────────────────────────┐

│  └─ Just-in-Time 访问                                          │

│  对比传统安全：                                                  │
```

```
ZTNA 核心要点总结：

┌─────────────────────────────────────────────────────────────────┐
│                    ZTNA 关键要点                                 │
├─────────────────────────────────────────────────────────────────┤

│  ├─ 永不信任，始终验证                                          │
│  ├─ 身份作为新的安全边界                                        │
│  ├─ 设备状态持续评估                                            │
│  └─ 动态策略，渐进式授权                                        │

```
