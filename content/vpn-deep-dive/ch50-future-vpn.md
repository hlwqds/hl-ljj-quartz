## 2. 后量子密码学与量子安全 VPN

量子计算机对传统公钥密码学构成威胁：

```
量子计算威胁时间表：

┌─────────────────────────────────────────────────────────────────┐
│                     量子威胁分析                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  RSA/ECC 破解预估：                                            │
│  ├─ 需要 ~4000 逻辑量子比特破解 RSA-2048                      │
│  ├─ 当前最强：~1000 物理量子比特（2024）                       │

│  └─ 后量子迁移窗口：现在开始准备                                │

│  对 VPN 的影响：                                                │
│  ├─ 密钥交换（DH/ECDH）：可被量子算法（Shor）破解              │

│  └─ VPN 作为关键基础设施需优先升级                            │
```

### 2.3 量子安全 VPN 实现

```
量子安全 VPN 架构：

┌─────────────────────────────────────────────────────────────────┐
│                     混合密钥交换                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  概念：结合经典 ECDH + 后量子 Kyber                            │
│                                                                 │
│  WireGuard 混合模式：                                          │
│  ├─ 传统：Curve25519 (ECDH)                                   │
│  ├─ PQ：CRYSTALS-Kyber-1024                                   │
│  └─ 最终密钥：KDF(ECDH_output || PQ_output)                   │
│                                                                 │
│  优势：                                                        │
│  ├─ 即使量子计算机也需同时破解两种算法                         │
│  ├─ 向后兼容（Fallback 传统模式）                              │
│  └─ 仅增加少量计算和带宽开销                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

```bash
# 后量子 WireGuard 原型配置
# 使用 hybridocrates 工具

# 生成后量子密钥对
pq_genkey --kyber-1024 --output kyber.key

# 混合公钥格式
# <curve25519公钥><kyber公钥>
cat curve25519.pub kyber.pub > hybrid.pub

# WireGuard 配置文件示例
# [Peer]
# PublicKey = <hybrid-pubkey>
# PresharedKey = <可选PSK>
```

```c
// WireGuard 混合密钥交换伪代码
struct HybridPublicKey {
    uint8_t curve25519[32];
    uint8_t kyber1024[1568];  // Kyber-1024 公钥
};

struct HybridHandshakeResult {
    uint8_t session_key[32];  // ECDH + Kyber 组合
};

// 握手过程
1. 生成 Curve25519 临时密钥对 (e, E)
2. 生成 Kyber-1024 临时密钥对 (e_pq, E_pq)
3. 发送 E + E_pq 给对端
4. 接收对方 E' + E'_pq
5. 计算 ECDH: s = ecdh(e, E')
6. 计算 Kyber KEM: kyber_s = kem_encaps(E'_pq)
7. 组合密钥: session_key = KDF(s || kyber_s)
```

### 3.3 基础设施即代码

```yaml
# Kubernetes VPN 配置示例（GitOps 风格）
# vpn-crd.yaml

apiVersion: network.example.com/v1
kind: WireGuardVPN
metadata:
  name: cluster-vpn
  namespace: networking
spec:
  interface:
    privateKey: ${WG_PRIVATE_KEY} # 从 Vault 注入
    address: 10.244.0.1/16
  peers:
    - name: cluster-2
      publicKey: ${CLUSTER2_PUBLIC_KEY}
      endpoint: cluster-2.example.com:51820
      allowedIPs:
        - 10.244.1.0/16 # Cluster 2 Pod CIDR
      persistentKeepalive: 25s
  encryption:
    type: WireGuard
    algorithm: ChaCha20-Poly1305
  autoUpdate:
    enabled: true
    schedule: "0 2 * * *" # 每日密钥轮换
```
