# WiFi 空口调度实战（一）：争抢的账本——DCF、退避与碰撞风暴

局域网里两台机器互传图像，吞吐上不去、延迟乱跳、抓包一看重传一片——先给一句话诊断：**这不是「WiFi 缺调度」**。802.11 的 MAC 从第一天起就带调度：CSMA/CA 的 DCF 是一套无中心的分布式随机调度器，双饱和流互相打死是「机制的天性 + 上层没做功」的合谋。本章把这台调度器拆开走读（1.2），用配套仿真的真实数字算清它的账（1.3），解释为什么图传两路经常一边倒（1.4），最后澄清误解并给出整个系列的分层解法路线图（1.5）。

## 1.1 场景与诊断：争的不是带宽，是信道时间

先把场景说精确：同一 AP、同一信道，机器 A 与机器 B 互传图像。Infrastructure 模式下「两台互传」在空口上其实是**两跳**——A 发的每一帧先占一次信道到 AP，AP 再占一次信道给 B；反方向同理。所以你面对的不是「两条流分一个信道」，而是**四段空口转发在抢同一个信道**，图像流量一起步就把信道推向饱和。

与有线的根本差别一张表看清：

|          | 交换以太网               | 同信道 WiFi BSS              |
| -------- | ------------------------ | ---------------------------- |
| 冲突域   | 每端口独立               | 全 BSS 共享一个信道          |
| 双工     | 全双工（线缆收发各一对） | 半双工（同频段，发时不能收） |
| 谁来调度 | 交换机硬件逐帧转发       | 无人集中调度：DCF 分布式仲裁 |
| 稀缺资源 | 端口带宽                 | **信道时间（airtime）**      |

空口唯一硬通货是信道时间：每毫秒信道要么在传有效数据，要么在退避空闲，要么在碰撞里白白烧掉。本系列所有章节做的事只有一件——重新分配这本账。怀疑「是空口而不是别处」时，一条真实命令就能看到信道级账本的入口：

```bash
iw dev wlan0 survey dump   # 信道时间四分类：channel/busy/rx/tx（第二章的主角）
```

## 1.2 DCF 走读：先听、排队、抽号

DCF（分布式协调功能）每次发包走三步：判忙、等帧间间隔、抽退避号。逐步拆开之前，先回答一个「为什么」：以太网的 CSMA/CD 能**边发边检测**碰撞，无线电为什么只能**避免**（CA）？两个物理原因：其一，自己发射时本机信号远强于任何远方来波，发的时候近似全聋；其二，碰撞发生在**接收方**那里，发送方自己未必听得见——经典的隐藏终端问题（A、C 都听得到 B，彼此却互相听不到，于 A/C 各自看来信道都空闲）。所以 802.11 只能两段式：**事前**抽号错峰避撞，**事后**靠 ACK 超时判决撞没撞。下面三小节都是围绕这两段展开的规则。

**载波侦听，一实一虚。** 物理载波侦听是 PHY 层的 CCA——既测能量也识别有效前导（灵敏度与能量检测的硬件背景见 [[wifi-rf-hw|WiFi 射频硬件入门]]）；虚拟载波侦听是 NAV——MAC 解析听到的每一帧（含发给别人的）的 Duration/ID 字段，该字段声明「本次交换还要占信道多久」，据此设 NAV 定时器：**NAV 没清零，PHY 再静也判忙**。两个判忙源取或，谁说忙都算忙。（RTS/CTS 就是主动提前广播 NAV 的保留机制，长帧场景才划算，此处不展开。）

**时间账：三种帧间间隔。** 典型值（以 5 GHz OFDM 系 PHY 为例；2.4 GHz 与 802.11ax 等参数集不同，以规范版本为准）：

| 间隔 | 典型值              | 语义与用途                                  |
| ---- | ------------------- | ------------------------------------------- |
| SIFS | 16 µs               | 一次交换内部的抢占权：ACK、CTS 紧跟着数据回 |
| slot | 9 µs                | 退避计数器的 tick                           |
| DIFS | SIFS + 2×slot ≈34µs | 想发起**新**一次发送前必须空闲等待的门槛    |

SIFS 故意比 DIFS 短：ACK 靠它在任何退避者之前插队——802.11 把「数据 + ACK」绑定成一个不可分割的原子事务，第三方插不进来。另外收到坏帧后要等更长的 EIFS 才能重新竞争，惩罚「没听清还想发」的一方。

**抽号与二进制指数退避（BEB）。** 规则五条：

1. 侦听信道，从忙转闲并保持空闲满 DIFS 后，才获得抽号资格；
2. 从 `[0, CW]` 均匀抽一个整数作为退避计数器（CW 即竞争窗口）；
3. 此后每空闲一个 slot，计数器减 1；信道一忙立即**冻结**计数，转闲后再继续；
4. 计数器减到 0 的那个 slot 立刻发射；没有等到 ACK 即判碰撞；
5. 碰撞后 CW 翻倍（精确式 `CW ← 2×(CW+1) − 1`，封顶 CWmax），成功后回 CWmin。

CWmin/CWmax 的典型值为 15/1023（DCF 尽力而为流在 OFDM 系 PHY 的常见默认，具体以 PHY 参数表为准）。把两站撞车画成时序：

```text
信道   |<-忙->|<-DIFS->|<-slot->|<-slot->|<-slot->|<-slot->|<-slot->|<--- A/B 同发 = 碰撞 --->|
                          (退避只在空闲时隙递减；信道一忙，计数器冻结)

A: CW=15 抽到 4     →      4        3        2        1        0 →发射 ┐
B: CW=15 抽到 4     →      4        3        2        1        0 →发射 ┘
                                                            双方都等不到 ACK → 判定碰撞
碰撞后：双方 CW 翻倍（15→31），各自重抽退避
A: CW=31 抽到 17    →     17       16       15     ……窗口更大，平均更晚出手
B: CW=31 抽到  9    →      9        8        7  …  0 → B 先数到 0，独占信道发射；A 冻结旁观
再撞再翻倍：31→63→127→…… 封顶 CWmax；谁成功谁回 CWmin
```

两个容易漏看的细节：**碰撞是事后判决**——PHY 层听不出「撞了」，双方都是等 ACK 超时才知道白发了；**冻结比递减更伤**——站越多信道越忙，计数器走走停停，同一个退避号要等更久才数完，等待被系统性拉长。

## 1.3 时隙账本：碰撞风暴是「账被吃掉」，不是「网速慢」

把信道时间轴按 slot 归一，任何时刻只处于三种时隙之一：**空闲**（全员在数数）、**成功**（恰有一站数到 0）、**碰撞**（≥2 站同时到 0）。竞争直觉一句话：N 个站独立抽号，同一 slot 出现 ≥2 个 0 的概率随 N 上升；而碰撞时隙一个比特有效载荷都没传，电波时间却实打实烧掉，涉事各站还要 CW 翻倍重抽——**一次碰撞收三重税**。

这套账不用猜，配套的离散时隙仿真把它跑成了可复现的数字：

> [!tip] 🧪 配套实验：ch01-dcf-sim
> ~300 行 C11 零依赖仿真器（饱和站抽退避、空闲递减、忙冻结、碰撞翻倍封顶 CWmax=1023、成功回 CWmin），四组实验各跑 100 万时隙，`run.log` 即真实输出。
> 源码直达：[dcf_sim.c（代码浏览）](/static/code/#/wifi-airtime-labs/ch01-dcf-sim/dcf_sim.c)、
> [完整工程](/static/code/#/wifi-airtime-labs/ch01-dcf-sim/README.md)。复现：
> `~/zig/zig cc -O2 -o dcf_sim dcf_sim.c && ./dcf_sim > run.log`（C11 零依赖，gcc/clang 亦可）。

E1 实验：竞争站从 2 加到 16（CWmin=15），逐项变化（数字摘自 run.log）：

| N 站 | thr（成功/总时隙） | idle% | coll% | tryc%（每次尝试撞率） | jain 公平指数 |
| ---- | ------------------ | ----- | ----- | --------------------- | ------------- |
| 2    | 0.1780             | 81.03 | 1.17  | 11.63                 | 1.0000        |
| 4    | 0.2189             | 74.82 | 3.29  | 23.73                 | 0.9999        |
| 8    | 0.2431             | 69.79 | 5.90  | 34.12                 | 0.9997        |
| 16   | 0.2528             | 65.80 | 8.93  | 43.75                 | 0.9994        |

读法：站点翻 8 倍，吞吐只升 42%（0.1780→0.2528），碰撞时隙占比却涨 7.6 倍（1.17%→8.93%），每次发射尝试的碰撞概率逼近一半（43.75%）——**多出来的竞争者主要记在碰撞账上**。注意 idle% 仍高达六成以上：DCF 不是撞到崩溃，而是把越来越多时间花在「大家一起数数 + 撞车重抽」里；但真实空口上一次成功传输动辄数百 µs、远大于 9 µs 的 slot，竞争开销按传输次数摊派，账只会更难看。

一个诚实的脚注：仿真把「发一包」归一成 1 个时隙，所以 thr 读数是**时隙利用率**而非 Mbps，跨配置的相对比较才有意义；模型与标准 DCF 的差异（退避抽自 `[0,CW)` 而标准为 `[0,CW]`、无 SIFS/ACK 计时）在工程 README 里有完整交代。E1 表里最有用的不是绝对值，而是三条曲线的**方向**：吞吐缓升、碰撞急涨、公平不动。

CWmin 是这台调度器唯一的静态旋钮，E2 实验扫它（N=8，摘三档）：

| CWmin | thr    | idle% | coll% |
| ----- | ------ | ----- | ----- |
| 3     | 0.4202 | 51.06 | 6.92  |
| 15    | 0.2431 | 69.79 | 5.90  |
| 63    | 0.1457 | 84.04 | 1.38  |

窗口大→撞得少但信道空得慌（idle 涨到 84%）；窗口小→串得快但撞得多。最优 CWmin 随竞争站数变化，而 DCF 的 CWmin 是写死的静态值——这就是后面第四章 EDCA 要把窗口与间隔做成「每类流量一套」的原因。

## 1.4 公平性悖论：赢家先手、捕获效应、一边倒

E1 里对称饱和站的 Jain 公平指数始终 ≥0.9994，长跑近乎完美公平。那为什么图传两路经常一边倒？三个机制叠出来：

**其一，赢家先手是 BEB 的结构属性。** 成功者立刻回 CWmin（小窗，下一个号平均很短）；碰撞者 CW 翻倍（大窗，出手更晚）。先赢的站更容易连赢一串，输家在深退避里排队——长程对称、短期突发成串，观察起来就是「一路顺一路卡」。

**其二，捕获效应让碰撞不总是双输。** 两帧在空口叠上时，接收机可能锁定先到或显著更强的一帧（capture effect）：强者照常解调、ACK 照回，弱者白烧一次发射。功率差门限经验上在 10 dB 量级、随接收机实现而异。离 AP 近、天线好的那台机器天然占优——信号差驱动的马太效应。

**其三，BEB 的公平只发给「持续在场竞争」的站。** E4 实验把一站改成限速（每 50 时隙醒来竞争一次，模拟被应用层或接收端限速的一路）：

| 场景            | thr_A  | thr_B  | coll% | jain   |
| --------------- | ------ | ------ | ----- | ------ |
| 双饱和          | 0.0889 | 0.0891 | 1.17  | 1.0000 |
| A 饱和 + B 限速 | 0.1190 | 0.0150 | 0.22  | 0.6241 |

B 只剩 0.0150——对方份额的 1/8，公平指数从 1.0000 崩到 0.6241；但碰撞率降到 1/5、A 吞吐反升 34%。现实里「两路饱和」很少真对称：编码器输出节奏、传输层窗口（TCP 的行为在 [[lwip-deep-dive|lwIP 深度解析系列]]有实现层拆解）、接收端处理速度，任何一环都会把某一路变成「限速站」——空口层面它就是偶尔来一趟的访客，份额随之崩塌，图传两端看起来就是一边倒。

还有一层窗口效应：Jain 指数是**长跑成绩**（E1/E4 都是百万时隙的累计），而 BEB 的公平只存在于这个长跑意义上——把观察窗口收窄到一次突发内，赢家先手造成的短期失衡会直接露出来。体感上这就是「一阵顺一阵卡」而非稳定的对半分：平均公平与每一秒都公平，是两本不同的账。

## 1.5 「没有调度」的真相：DCF 就是调度基线，缺的是杠杆

常听到的说法是「WiFi 没有调度、全靠抢」。不成立：DCF 就是一台调度器——分布式、随机、无中心，IFS/CW/BEB 就是它的调度策略。它的真正问题不是「不存在」，而是**策略太钝**，每一处钝都有对应的杠杆：

- **不认识开销大小**：每次接入都要重付一遍「DIFS + 数数 + 碰撞风险」的固定成本。聚合（A-MPDU）把一次胜出摊到几十个包上——仿真 E3：每次接入连发 k 包从 1 加到 64，有效吞吐 0.2431→0.7780（3.2 倍），每包摊到的竞争开销从 3.114 降到 0.285 个时隙（第三章）。
- **不认识业务**：图像帧与后台扫描抢同一个号池。WMM/EDCA 给流量分类配不同的 AIFS/CW/TXOP（第四章）。
- **不认识占用成本**：低速率、窄带宽的站发同样比特占更久信道。速率与信道宽度直接改写每比特的空口价（第五章；802.11ax 的上行 MU 也只是把竞争换成了 AP 触发的受控并发，竞争仍是底座）。
- **公平按发射机会而非信道时间计**：让「占得久的站少占、占得慢的多给」的是 airtime fairness / ATF（第六章）。
- **随机调度对突发不设防**：上层不配合空口节奏，就永远在撞与等之间摇摆——pacing 与结构化发送是应用与驱动侧的做功（第七章）。

系列路线图：

| 章  | 杠杆                    | 回答的问题                 |
| --- | ----------------------- | -------------------------- |
| 2   | 先看见：iw survey 实测  | 信道时间到底被谁、怎么花掉 |
| 3   | 聚合 A-MPDU             | 一次接入摊薄固定竞争开销   |
| 4   | WMM/EDCA 优先级         | 图像帧与背景流量分道行驶   |
| 5   | 速率与信道宽度          | 同样比特占更少信道时间     |
| 6   | airtime fairness（ATF） | 按时间而非机会分配公平     |
| 7   | pacing 与结构化发送     | 上层配合空口节奏做功       |
| 8   | playbook                | 场景化组合拳与排障清单     |

注意这些杠杆的**归属各不相同**：聚合与速率住在驱动/固件里，WMM 标记要在发送端打、策略在 AP 上生效，ATF 纯粹是 AP 侧功能，pacing 则全在应用与传输层。没有一个需要重写 MAC——全部是在既有基线上拧旋钮，这也是本系列的立足点：不换硬件、不改协议，把可用旋钮逐个拧到位。

## 1.6 小结

- 两台互传 = 同一信道上四段空口转发；稀缺资源是信道时间，不是「带宽」。
- DCF 三件事：判忙（CCA 实侦听 + NAV 虚拟预约取或）、按帧间间隔排队（SIFS 保 ACK 原子事务、DIFS 是新发送门槛）、抽号退避（`[0,CW]` 均匀抽、空闲递减忙冻结、碰撞 CW 翻倍封顶 CWmax、成功回 CWmin；间隔典型值 16/9/34 µs 量级，以 PHY 参数表为准）。
- 账本三种时隙：空闲/成功/碰撞。仿真实测（CWmin=15）：竞争站 2→16，吞吐仅 +42% 而碰撞时隙 ×7.6、尝试撞率逼近一半；CWmin 是静态旋钮，撞得多与空得慌不可兼得。
- 公平悖论：赢家先手（成功回小窗）、捕获效应（强信号通吃，门限约 10 dB 量级）、限速站份额崩塌（Jain 1.0000→0.6241）——图传一边倒三个来源。
- DCF 不是「没有调度」，是调度基线；聚合、WMM、速率、ATF、pacing 是逐层加杠杆，最终落到 playbook。

账本的框架有了，下一步是把这本账**实测出来**——不插仪器，用 `iw` 的 survey 接口读芯片在信道上记的时间分类账，看 busy 到底是谁吃掉的：[[ch02-measuring-airtime|下一章]]，先看见，再动手。
