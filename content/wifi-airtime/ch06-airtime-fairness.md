# WiFi 空口调度实战（六）：AP 出手——Airtime Fairness 调度

[[ch01-dcf-contention-basics|第一章]]到 [[ch05-rate-and-channel-width|第五章]]的所有机制有一个共同前提：**空口由分布式的竞争规则分配**，谁赢了竞争谁发，没有裁判。这个前提在「两台机器互传图像、同 AP 下还有别的业务」的现场会显形：一台信号差、速率低的机器，会把整张网的空口按住不放。这一章回答三个问题：**为什么分配单位要从「包数/队列」换成「空口时长」**（6.1）、**Airtime Fairness（ATF）实现在哪、怎么配**（6.2、6.3）、以及最要紧的——**它对我们两机互传的场景到底管多少**（6.4、6.5）。答案的最后一块会自然引向下一章：应用自己控制发送形状。

---

## 6.1 换一把尺子：从「机会均等」到「时长均等」

DCF 的公平是**统计意义上的机会均等**：每次竞争胜出，发一帧（或一个 A-MPDU，[[ch03-aggregation-ampdu|第三章]]）。它不关心这一帧要占多少微秒——而占多久恰恰由速率决定。先做一笔纯除法的粗账（不是实测，只看比例关系）：

| 发送端 PHY 速率 | 1500 B 载荷发送时长（粗账） | 备注                  |
| --------------- | --------------------------- | --------------------- |
| 54 Mbit/s       | ≈ 0.22 ms                   | 12000 bit ÷ 54 Mbit/s |
| 6 Mbit/s        | ≈ 2.0 ms                    | 12000 bit ÷ 6 Mbit/s  |

（忽略前导码、SIFS/ACK、重传与聚合开销——这些只会让差距更大。）

现在让快站 F（54 Mbit/s）和慢站 S（6 Mbit/s）同时回传图像。两者各拿到约一半的发送机会，但 S 的每次机会烧掉的时长约是 F 的 **9 倍**——于是**一半的机会变成约九成的空口时长**，F 的吞吐被拖到 S 的水平附近。这就是经典的 rate anomaly（性能反常，Heusse 等在 INFOCOM 2003 以 802.11b 为对象正式刻画过）：**网络总吞吐向最慢站塌缩**。WMM/EDCA（[[ch04-wmm-edca-qos|第四章]]）按接入口分了四类优先级，但每一类内部依旧是机会均等——换了赛道，没换尺子。

ATF 的主张一句话：**调度单位从「发帧机会」改成「空口微秒」**。给每个站点一个时长配额，用满了就排队尾，与时钟对齐而不是与帧数对齐：

```text
DCF：机会均等，时长不均（块宽＝空口占用时长，示意）
     F ██         ██         ██          F 拿一半机会，
     S ██████████████ ██████████████     却只占约 1/10 时长

ATF：时长均等，机会不均
     F ████████ ████████ ████████        两站各占一半时长；
     S ████████         ████████         S 用满配额即让位
```

两个推论：**快站拿回吞吐**——它省下的时长直接变成字节，网络总吞吐上升；**慢站被限速**——代价是它的绝对吞吐下降，从「拖垮全网」变成「按配额排队」。

两个工程上的限定：其一，**ATF 的决策发生在「下一次发送机会」的边界上**——一个已经开跑的 PPDU/A-MPDU 不会被中途打断，所以慢站的单次超长占用仍会发生，只是不会连续发生；其二，聚合（[[ch03-aggregation-ampdu|第三章]]）会放大这个问题：低速率下攒出的大 A-MPDU 是一个更长的不可打断块，但 ATF 的记账单位是**实际占用时长**，聚合只改变块的长度，不改变「用满配额即让位」的结论——这也是它比「限包数/限队列长度」一类的代理指标更稳的原因：**直接计量你真正稀缺的资源**。

## 6.2 实现位置：AP 的下行发送调度器

集中式调度只能住在**看得见所有队列的那台设备**上。基础设施网络里这个位置只有一个：AP 的下行发送调度器——AP 持有发往每个 STA 的队列，自然可以在「下一个发谁、发多少」上做文章。这也划定了 ATF 的出厂形态：**它是 AP 侧的下行策略**（6.4 会回到这条边界）。

自建 AP 的事实标准路径是 **mac80211 主线**，实现是一套按空口亏空（deficit）轮转的发送队列调度器，内核源码里直呼其名（以下均为主线当前代码，以所装内核为准）：

- **调度骨架**：`net/mac80211/tx.c` 的 per-STA per-AC deficit 轮转——注释原话即「airtime DRR scheduler」（deficit round robin）；deficit 为负的站排到队尾，每次轮到补一个 `airtime_weight`（默认权重 256，hostapd 上游配置注释的口径）；
- **扣账**：`net/mac80211/sta_info.c` 的 `ieee80211_sta_register_airtime()` 按实际 TX/RX 时长从 deficit 里扣（是否计入收向两侧可配）；发包前另有按帧长/MCS/带宽估算的预扣（`net/mac80211/airtime.c` 的时长估算表），落账后多退少补；
- **能力门控**：驱动须声明 `NL80211_EXT_FEATURE_AIRTIME_FAIRNESS`，调度器才启用 DRR 路径；内核还有配套的 AQL（Airtime Queue Limits）限制在途帧的预计空口量，防队列积压后「配额失效」。

把三件事串起来，一个调度回合的形状大致是：

```text
轮到某站 ─▶ deficit ＋＝ airtime_weight        （按权重补充预算）
        ─▶ 发包前按帧长/MCS/带宽估算时长，预扣 deficit
        ─▶ 发送（该 PPDU 跑完为止，中途不夺）
        ─▶ 完成后按实际 TX/RX 时长落账，多退少补
        ─▶ deficit ＜ 0？排到队尾，让下一站
```

「预算多少」就是权重，「花多少」就是空口时长——ATF 的全部秘密就是这本账。

厂商硬件的现状一句话：**家用档普遍不开或不可见**——个别固件给一个不解释内部语义的 ATF 开关，企业级 AP 各有私有实现、不开放参数；**可审计、可配参的主战场是自建 AP 与软 AP**（hostapd + mac80211 系驱动）。动手前先验能力：

```bash
# 驱动是否点亮 airtime fairness（在 Supported extended features 列表里找）
iw phy | grep -i airtime
#   命中 "airtime fairness scheduling" 即支持；常见伴随 "Airtime Queue Limits (AQL)"

# 关联后看每站当前 airtime 权重
iw dev wlan0 station dump | grep -E "^Station|airtime weight"
```

## 6.3 hostapd 的 airtime 策略：四个模式与配置方向

hostapd 内置了 airtime policy 配置组（较新版本均有；语义照上游 `hostapd.conf` 注释摘录，**具体以所装版本的注释为准**）。核心是 `airtime_mode` 四档：

| airtime_mode | 上游注释语义       | 配什么                                           |
| ------------ | ------------------ | ------------------------------------------------ |
| 0            | disabled（默认）   | 不启用                                           |
| 1            | static config      | `airtime_sta_weight` 按 MAC 静态配每站权重       |
| 2            | per-BSS dynamic    | 多 BSS 场景按 `airtime_bss_weight` 比例动态折算  |
| 3            | per-BSS limit mode | 在比例之上给本 BSS 设上限（`airtime_bss_limit`） |

单 BSS、两机互传的场景用**模式 1** 就够——直接给图传接收端加权重、给后台业务降权重：

```ini
# hostapd.conf —— 方向性示例（权重是相对值，内核默认 256）
airtime_mode=1
airtime_sta_weight=aa:bb:cc:dd:ee:01 512   # 图传接收端：双倍配额
airtime_sta_weight=aa:bb:cc:dd:ee:02 128   # 后台机器：减半配额
# 动态/限额模式（2/3）另有 airtime_update_interval（轮询内核的周期，上游示例 200 ms）
```

多 BSS（同一射频绑多个 SSID/VLAN）才需要模式 2/3：`airtime_bss_weight` 的**比例**才起作用（上游注释原话强调 ratios 而非绝对值），模式 3 的 limit 语义是「本 BSS 超出份额就压，别的 BSS 超发不拦」。不想动 hostapd 也可以直接走 nl80211 的手动通道（hostapd 的静态模式底层就是它）：

```bash
# 对单站直接设 airtime 权重（驱动支持能力位时生效）
iw dev wlan0 station set aa:bb:cc:dd:ee:01 airtime_weight 512
```

两个诚实提醒：其一，**配了不等于生效**——策略最终要落到驱动的 airtime 调度器上，验证要用 [[ch02-measuring-airtime|第二章]]的空口测量法（survey 前后对比），而不是只看吞吐数字；其二，权重只有**相对意义**，512:128 与 4:1 是一回事，绝对值随内核默认（256）缩放。

验证的骨架（改权重前后各采一组，对比 `channel transmit time` 的分配去向）：

```bash
# iw survey dump 的字段名照 iw 源码摘录：channel busy/transmit time 单位为 ms
iw dev wlan0 survey dump | grep -E "frequency|busy time|transmit time"
# 看点：B 加权后，AP 在 B 身上花掉的 transmit time 占比是否如期上升
```

## 6.4 两机互传的能与不能：ATF 的管辖区

回到我们的现场：图传发送端 A 与接收端 B 挂在同一 AP 下。基础设施模式里**STA 之间没有直发路径**——A 到 B 的每一份数据都要走两段：

```text
   A（发送端） ──上行①──▶ AP ──下行②──▶ B（接收端）

   ① A→AP：上行。谁先抢到谁发（DCF/EDCA），ATF 管不到
   ② AP→B：下行。AP 的发送调度器全权决定，ATF 的配额在这里生效
```

于是能与不能一张表看清：

| ATF 对两机互传        | 结论                                                   |
| --------------------- | ------------------------------------------------------ |
| AP→B 下行的配额与公平 | **能**：给 B 加权、给后台站降权，慢站不再拖垮 ② 段     |
| 同 AP 下慢站隔离      | **能**：对 rate anomaly 的网络级矫正就发生在这条腿上   |
| A→AP 上行的争抢       | **不能**：802.11ax 之前的框架里，AP 无权指派上行发送权 |
| A、B 绕开 AP 直发     | **不能**：AP 不在数据路径上，ATF 无处安放              |

上行那条「不能」是框架级的：分布式协调没有留出集中指派上行的口子（802.11ax 的上行 OFDMA 开始由 AP 发 Trigger 帧集中调度上行，但那是另一套机制，且要求双方支持）。而且别以为上行腿只有图像数据——**若传输层走 TCP，B 的反向 ACK 也要挤上行**，与 A 的图像帧在同一套竞争规则下抢；这份反向小包流正是 ch04 EDCA 与下一章 pacing 的用武之地。还有一个容易被忽略的**转发税**：同一信道上，一份数据要占两次空口（①+②），基础设施模式的理论吞吐先打对折，再谈怎么分。

所以真正的分水岭在组网层：**「AP 集中转发」把调度权交给 AP（ATF 有抓手）；「对等直发」把两台机放进一个独立 BSS（AP 消失，回到纯 DCF 对等竞争）**。两条路线怎么选，下一节摆开。

## 6.5 组网视角：集中转发与分信道直发

「对等直发」不是把 A、B 留在原 AP 下硬抢——那是 6.4 表里的第四行（ATF 无处安放）。实践中的直发是**分信道**：让一台机器当软 AP（或 P2P GO），与对端组一个独立 BSS，落在**另一条信道**上，与主网物理隔离。先把两条拓扑摆在一起：

```text
路线一：经 AP 转发（同一信道，调度权集中）
  其他业务 ──┐
  A（发送端）──①上行──▶ AP ──②下行──▶ B（接收端）
                        ▲ ATF/WMM 都住在这个点上

路线二：分信道直发（独立 BSS，另一条信道）
  主网业务 ══▶ 主 AP @ 信道 X
  A（软 AP/GO）══ B @ 信道 Y     ← 与主网零争抢，但没有集中调度者
```

逐项对比：

| 维度       | 路线一：经 AP 转发 + ATF      | 路线二：分信道直发（softAP/P2P） |
| ---------- | ----------------------------- | -------------------------------- |
| 空口占用   | 同信道两次（①+②），有转发税   | 独立信道一次                     |
| 调度权     | 集中在 AP：ATF/WMM 都是抓手   | 无集中点，回到 DCF 对等竞争      |
| 对主网影响 | 同池争抢，但可配额控制        | 信道级隔离，主网零争抢           |
| 设备要求   | 两台普通 STA 即可             | 一台具备软 AP/GO 能力            |
| 信道预算   | 一份                          | 两份（5 GHz 有富余时才可行）     |
| 运维       | 统一管理、统一观测            | 多一套独立网络要维护             |
| 适合       | 无富余信道、需要统一 QoS 策略 | 点对点大流量、频谱有干净空隙     |

路线二的软 AP 并不要求大机器：嵌入式 WiFi 模组普遍带软 AP 能力，ESP32 一类即可胜任（[[esp32-s3-box-3|ESP32-S3-BOX-3 工程实战]]就是现成的实验场）。路线二有个**前提性 caveat**：隔离是信道级的，不是魔力——直发 BSS 落的那条信道得真的干净（先做 [[ch05-rate-and-channel-width|第五章]]那套速率/信道功课，邻道重叠与 2.4 GHz 的拥塞见 [[wifi-rf-hw|WiFi 射频硬件入门]]），否则只是把争抢换了个场地。路线一则受 6.4 的边界约束：ATF 只能保 ② 段，① 段上行的争抢要靠 [[ch04-wmm-edca-qos|第四章]]的 EDCA 参数与应用自律。

给两机图传的决策顺序：**有干净信道、流量以点对点为主 → 路线二**（把争抢连根拔掉）；**没有富余信道、或两机还要同时上网 → 路线一**（ATF 保下行配额 + EDCA 分级 + 应用侧自律）。

## 6.6 小结

- DCF 给「机会」不给「时长」：速率低的站每次机会占用 9 倍时长（1500 B 载荷 6 vs 54 Mbit/s 的粗账），一半机会变九成空口——rate anomaly 让网络吞吐向最慢站塌缩。
- ATF 换尺子：按空口微秒给每站配额，快站恢复吞吐、慢站限速让位；粒度是「下一次发送机会」，正在发送的 PPDU 不可中途打断。
- 实现位置在 **AP 的下行发送调度器**：mac80211 主线是 airtime DRR（deficit 轮转 + 时长估算扣账，`NL80211_EXT_FEATURE_AIRTIME_FAIRNESS` 门控）；hostapd 用 `airtime_mode`（0 关/1 静态/2 per-BSS 动态/3 限额）+ `airtime_sta_weight`（内核默认权重 256）配置；家用档普遍不开或不可见，自建/软 AP 是主战场。
- 两机互传的边界：ATF 管 AP→B 下行配额，管不了 A→AP 上行（802.11ax 前框架无集中上行指派），更管不了绕开 AP 的直发；基础设施模式还有一份数据占两次空口的转发税。
- 组网分水岭：「经 AP 转发 + ATF」调度权集中、统一管理、受上行边界约束；「分信道直发」零争抢但吃掉两份信道预算、前提是目标信道干净。

但请注意两条路线的共同盲区：**它们都默认应用把包倒进网卡时形状是对的**。路线二里没有 AP、没有 ATF，路线一里上行腿本来就没人管——此时最后一层、也常常是杠杆最高的一层，是应用自己控制发送的形状：pacing 的节奏、burst 的大小、报文结构怎么贴合聚合。[[ch07-pacing-and-structure|下一章]]就把这最后一块拼图放上去。
