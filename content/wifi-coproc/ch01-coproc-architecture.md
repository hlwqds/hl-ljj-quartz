# F429 × Korvo-1（一）：架构决策——三档方案与 SPI 路线的由来

目标一句话：**F429 上跑一个能联网的应用，WiFi 能力全部来自 SPI 对面的 Korvo-1**。动手前这一章把三件事定死：协议栈怎么分（1.1 的三档架构与选型）、物理链路为什么是 SPI（1.2 的硬件事实）、两块板的引脚预算怎么审（1.3 的方法论）——这三件事定错，后面每章都在还债。读完它，六根线的系统图应该在你脑中成型。

---

## 1.1 三档架构：WiFi 能力的三个"贩卖粒度"

协处理器方案的灵魂问题是：**S3 把什么形态的能力卖给 F429**。三档选择，粒度由粗到细：

### 档位一：文本命令（ESP-AT 模式）

S3 侧跑完整 WiFi + lwIP，socket 也活在 S3 里；F429 发 `AT+CWJAP`、`AT+CIPSEND` 这类文本命令，收文本应答与透传数据。

- 优点：宿主零网络知识，串口就能调试；
- 缺点：文本协议解析啰嗦、无结构化错误、命令集固定、透传大文件的转义开销——而且这是"用现成的"，学不到里面。

### 档位二：socket 代理（本系列的选择）

S3 侧跑 WiFi + lwIP + 一组 socket 服务；F429 通过**二进制 RPC**（open/connect/send/recv/close）远程调用这些 socket，数据在专用数据通道上流。**IP 栈仍在 S3，但 socket 的"使用权"搬到了 F429**——F429 的应用代码写起来像在本地调 BSD API。

- 优点：结构化、可扩展（命令是我们自己定义的）、不需要在 F429 上养协议栈、任何 MCU 都能接；
- 缺点：每步操作都过一次 RPC（延迟比本地 socket 高），流控要自己做。

### 档位三：netif 隧道（ESP-Hosted 模式）

S3 侧只跑 WiFi 驱动与关联管理，**把 Ethernet 帧递给 F429**；F429 本地跑完整 lwIP（[[f429-lab|F429 实验室]]ch21 已就位），对它而言 S3 就是一块"远程网卡"。

- 优点：F429 拿到真正的网络接口，全套 socket/DNS/协议自由；
- 缺点：F429 必须养协议栈（RAM/ROM 预算）、隧道内是裸帧（丢失/乱序要处理）、复杂度最高。

```text
档位一（AT）      F429 ──文本命令──▶ [ WiFi+lwIP+socket │ S3 ]
档位二（本系列）  F429 ──socket RPC─▶ [ WiFi+lwIP │ S3 ]      ← socket 在哪用，不在哪活
档位三（Hosted）  F429 ──Eth 帧隧道─▶ [ WiFi 驱动 │ S3 ] + [ lwIP │ F429 ]
```

**选档位二的理由**：它与 F429 裸机路线的资源账最匹配（不养协议栈）、教学颗粒度最好（每一层都自己写、都看得见）、且向上兼容——第十章给出把它升级成档位三的路线。由浅入深的路径也顺：先协议后应用，先控制后数据。

## 1.2 硬件事实：为什么是 SPI，而不是 SDIO/UART

三条候选链路的判定，一章说清：

| 链路           | 判定          | 原因                                                                                                                       |
| -------------- | ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| SDIO           | ❌ 走不通     | **ESP32-S3 没有 SDIO slave 外设**（经典款 ESP32 的专属配置，S3 砍掉了）；F429 倒是有 SDMMC 主机，但对不上                  |
| UART           | ⚠️ 仅兜底     | 波特率天花板低（921600 ≈ 90 KB/s），WiFi 吞吐喂不饱；但协议层做成字节流无关后，它可以当调试通道与低速后备（ch03 顺路获得） |
| **SPI 全双工** | ✅ 本系列主线 | S3 的 GPSPI 从机 + F429 的 SPI 主机（带 DMA），10–20 MHz 档位即可支撑 Mbps 级数据通道                                      |

SPI 主线的一个先天约束从第一天就要记住：**时钟由主机出，从机永远"被读"不能主动发起**。所以链路需要一根额外的握手线（S3 的"我有数据"通知，ch02 §2.3），这根线是整个时序设计的支点。

## 1.3 板卡资源审计：先查账，再选脚

教程最容易翻车的不是协议，是**引脚撞车**。两块板各有"住户"，动手前先记账：

**挑战者 F429-V2（宿主）**：板载以太网 PHY 走 RMII——`PA1/PA2/PA7/PC1/PC4/PC5/PB11/PB13` 一排默认脚被占（[[f429-lab|F429 实验室]]ch20 的主场）；TF 卡槽若走 SDMMC 则占 `PC8–PC12/PD2`。**结论：SPI1 的默认脚 PA5/PA6/PA7 里 PA7 与 RMII 相撞**——要么用 SPI1 重映射（PB3/PB4/PB5），要么换 SPI2/SPI3，本章审计表留给你按原理图勾选。这是"每个引脚先查住户再签合同"的现成教案。

**ESP32-S3-Korvo-1（协处理器）**：板上住着 ES8311 编解码器、ES7210 采麦、LCD/触摸、TF 槽、功放使能等，各占一组 GPIO。好消息：WiFi 协处理器不需要这些外设工作，**只需要从剩余空闲 GPIO 里挑出四个给 SPI 从机**（S3 的 GPIO 矩阵允许把 SPI 从机信号映射到多数空闲脚），外加一根握手输出。审计方法与 F429 同款：开官方原理图 → 标出住户 → 剩余脚做"点亮-回环"逐一验证 → 锁定并记录。

> [!tip] 六根线预算（全系列的物理合同）
> `SCK`（F429→S3 时钟）、`MOSI`（F429→S3 数据）、`MISO`（S3→F429 数据）、`CS`（F429 片选）、`DRDY`（S3→F429 "我有数据"握手）、`GND`（共地，必接）。可选第七根 `RESET`（F429 复位 S3，救活挂死的从机——建议留）。**全部 3.3V 逻辑，可直连**；S3 的供电独立（WiFi 发射峰值电流 0.5A 量级，别指望 F429 板的 3V3 扛）。

## 1.5 小结

- 三档架构按"贩卖粒度"分：文本命令（AT）/ socket 代理 / netif 隧道；本系列选 socket 代理——F429 不养协议栈，socket 用权在手，每层都可亲手写。
- S3 无 SDIO slave 是硬事实：主线 SPI 全双工（10–20 MHz + DMA），UART 做协议兼容的调试后备；SPI 从机不能发起 → DRDY 握手线是时序支点。
- 引脚先审计后签约：F429 侧 RMII 撞 PA7 的现成案例、Korvo-1 侧音频/LCD 住户排查；六根线合同 + 可选 RESET。
- 路线五层递进：链路 → 帧 → 控制/数据 → 应用 → 性能与对照。

下一章把六根线点亮：F429 的 SPI 主机怎么配 DMA、S3 的 SPI 从机怎么挂队列、模式与极性怎么对表，以及 DRDY 握手把"主机轮询"变成"从机可发起"的完整时序——最后用一次回环传输验收这条线。[[ch02-spi-link|第二章：SPI 全双工链路]]。
