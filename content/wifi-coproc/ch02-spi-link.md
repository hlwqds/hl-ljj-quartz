# F429 × Korvo-1（二）：SPI 全双工链路——DMA、握手与"从机不能发起"

ch01 定了六根线的合同，这一章让字节在线上跑起来。四个工程问题逐一解决：双方怎么配出同一套时序（2.1 模式与配置）、一次"事务"到底交换了什么（2.2 固定长度双缓冲语义）、S3 有数据时怎么让 F429 知道（2.3 DRDY 握手时序）、F429 怎么不把 CPU 烧在搬运上（2.4 DMA）。收尾用回环验收（2.5）。寄存器级代码沿用 [[f429-lab|F429 实验室]]的裸机风格，S3 侧骨架按 IDF 的 `spi_slave` 驱动设计。

---

## 2.1 模式与配置：先把四个词对齐

SPI 的 CPOL/CPPHA 组合出四种模式，双方必须完全一致。本系列定 **Mode 0（CPOL=0，CPHA=0）**：时钟空闲低、双沿都在下降沿前的第一个边沿采样——两侧驱动都原生支持，也是最省心的默认。

```text
F429（主机，SPI2 重映射脚示例——按 ch01 审计结论替换）
  SPI_CR1: MSTR=1, SSM/SSI 软件片选（或硬件 NSS）、BR 波特率分频起步 /256（≈0.33MHz）
  帧格式 8-bit、MSB first；DFF=0
  DMA: TX/RX 通道各一，优先级高、FIFO 阈值 1/2
S3（从机，GPSPI2 经 GPIO 矩阵到审计选定的空闲脚）
  IDF spi_slave：mode 0、队列深度 4、DMA 使能（max transfer 512B 对齐）
```

两个新手坑先钉死：**CS 必须包住整段事务**（S3 从机在 CS 上升沿交还总线，中途拉高等于把帧腰斩）；**首字节前留一点时钟稳定时间**（F429 软件片选拉低后立即发第一个字节，某些从机首字节会错位——间隙从 0 调到几百 ns 即愈）。

## 2.2 事务语义：一次交换，双向各 512B

SPI 全双工的物理事实：主机发 N 字节的**同时**必然收到 N 字节。所以协议不定义"读"和"写"，只定义**交换（exchange）**：F429 每次事务固定交换 512 字节，MOSI 上是它的 TX 缓冲（没内容就填空闲字节），MISO 上是 S3 预先挂到从机队列里的 TX 缓冲（没内容也是空闲字节）。

```text
F429 发起一次 512B 交换：
  MOSI ──▶ [F429 的 TX 缓冲：要发给 S3 的帧，或 IDLE 填充]
  MISO ◀─ [S3 挂在队列里的缓冲：要发给 F429 的帧，或 IDLE 填充]
  两侧同时在写、同时在读——"全双工"落到工程上就是这两个缓冲永远成对存在
```

固定 512B 的好处：DMA 好配（对齐、长度恒定）、S3 侧 `spi_slave_queue_trans` 的缓冲可以静态分配、空闲开销可预算（10 MHz 下一笔 512B 交换 ≈ 41 µs，即使一半是填充也不贵）。上层帧协议（ch03）负责在这 512B 里装可变长帧，传输层不关心内容。

## 2.3 DRDY 握手：把"从机不能发起"翻过来

SPI 的时钟霸权在主机：S3 有数据想发，只能等 F429 来交换。轮询是最笨的解法（空转填充字节），**DRDY 中断线**才是正解：

```text
S3 侧：TX 队列里出现待发帧 → DRDY 拉高
       交换完成、队列为空   → DRDY 拉低
F429 侧：DRDY 上升沿触发 EXTI 中断 → 调度一次 512B 交换
       自身有数据要发时     → 主动发起交换（顺手把 S3 的待发数据一起带回来）
```

```text
   S3 应用产生数据     组帧入 TX 环        DRDY↑            被交换带走       DRDY↓
        │                 │                  │                  │              │
   ─────┴─────────────────┴────────┬─────────┴─────────┬────────┴──────────────┴──
                                    │         │         │
   F429                             │  EXTI 唤醒        │
   ─────────────────────────────────┴──DMA 交换 512B────┴───────────────────────
```

这张时序图是本系列的"协议第一页"：S3 的事件世界（WiFi 收包、命令应答）与 F429 的时钟世界（DMA 事务）靠一根 GPIO 完成了跨域通知。第三个状态别忘了：**F429 自己要发数据时无需等 DRDY**——主动交换即可，双向顺路捎带，链路利用率立刻翻倍。

## 2.4 DMA：F429 侧的搬运账

512B × 每秒几百次交换，若用 CPU 逐字节轮询，主频再高也烧不起。F429 的 DMA2（SPI2 挂 DMA1——按具体总线手册核对通道映射）配成：内存侧递增、外设侧固定、半字/字节按 DFF。双缓冲用**循环模式 + 半满/全满中断**或两块乒乓缓冲，保证 DMA 在搬第 N+1 笔时 CPU 在解析第 N 笔。这些手法与 [[f429-lab|F429 实验室]]ch10/ch11（USART/ADC 的 DMA 环）一脉相承，本章把同一套思想平移到 SPI 而已。

S3 侧对称地用 `spi_slave_queue_trans` + 回调（post-setup callback 在 DMA 挂好缓冲后、事务开始前触发——正好在这里决定 DRDY 电平），收发各一个任务，帧层用队列与它解耦。

## 2.5 验收：三层回环

链路好不好的判据分层测，逐层放行：

1. **物理层**：F429 发递增字节序列（0..255 循环），S3 原样回投——验证模式/时钟/位序全对（错一位立刻雪崩成乱码，很好认）；
2. **交换层**：S3 主动产生 1000 笔随机长度数据（触发 DRDY 路径），F429 统计收到的字节数与触发次数，零丢失为过；
3. **压力层**：时钟从 0.33 MHz 爬到 10 MHz 重跑 ①②，记录首个出错档位——那就是本条杜邦线 + 面包板实物的真实极限（接线长、地线细都会压低它，实测数据 ch08 见）。

## 2.6 小结

- Mode 0 + 8-bit MSB 起步；CS 包住整段事务、首字节留稳定间隙，两个新手坑先钉死。
- 协议只有"交换"没有读写：固定 512B 双向成对，帧层装内容、传输层认填充。
- DRDY 是跨域通知线：S3 有货拉高、清空拉低；F429 EXTI 响应或主动交换顺路捎带——时钟霸权与事件世界握手言和。
- 两侧都上 DMA 与乒乓/队列：DMA 搬第 N+1 笔、CPU 解析第 N 笔；手法与 f429-lab 的 DMA 环同宗。
- 三层回环（字节序列 → 事件路径 → 时钟爬坡）逐层放行，最后一级的出错档位就是实物链路的物理极限。

线通了，但线上还是裸字节。下一章给它们立规矩：COBS 透明打包（任何字节都能装）、CRC32 查错（杜邦线接触不良当场现形）、序号与重传窗口（交换层丢了帧怎么办）——这套帧协议同时天然兼容 UART，调试后备通道顺手白拿。[[ch03-framing|第三章：帧协议]]。
