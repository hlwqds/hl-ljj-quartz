# F429 × Korvo-1（八）：性能——时钟爬坡、双缓冲与吞吐-延迟曲线

第七章的应用"能跑"，这一章追问"能跑多快、多稳"。四个抓手：时钟阶梯爬坡找出实物极限（8.1）、把每笔交换的固定开销拆开记账（8.2）、用两种负载画像吞吐-延迟（8.3）、把断链剧本排成戏（8.4）。方法比数字重要——同一套测量模板适用于任何 MCU × 无线模组组合。

---

## 8.1 时钟爬坡：阶梯法与归因

SPI 能跑多快不是芯片手册说了算，是**你的杜邦线说了算**。阶梯法：0.33 → 2 → 4 → 6.6 → 8 → 10 → 13.2 → 16 → 20 MHz（F429 的 APB 分频档），每档跑 ch02 的三层回环 + ch07 的 HTTP 下载各三遍：

```text
每档记录：错误率（CRC 帧错/总帧）、吞吐、现象描述
首个出错档位 → 降一档运行 → 归因三连：
  ① 线长：杜邦线 >15cm 是原罪，换短线常白捡一档
  ② 地：只接一根 GND 时高频回流路径差，补一根地线（与信号并行）再试
  ③ CS/时钟质量：示波器看 CS 包裹完整性与时钟过冲（有 rpi-lab 的仪器正好开工）
```

经验锚点：面包板 + 长杜邦通常倒在 6.6–10 MHz；焊线/短排线能上 20 MHz 档。**记录"倒下的档位和原因"比记录成功档位更有价值**——换板复现时它是排查的第一张地图。

## 8.2 每笔交换的账：固定开销拆解

链路有效吞吐 = 512B × 帧效率 ÷ 每笔总时间。账要拆到项：

```text
每笔 512B 交换 @10MHz：
  位传输      512×8 ÷ 10MHz        ≈ 410 µs   ← 不可压缩
  CS 间隙/建立                      ≈ 2–10 µs  ← 软件片选时可压
  DMA 启动/完成中断                  ≈ 5–15 µs  ← 乒乓可藏
  任务队列/回调往返（两侧 RTOS）      ≈ 20–80 µs ← 最大可压缩项
  帧协议头尾 + COBS 开销             ≈ 3–8 %    ← 结构性
有效数据占比 = payload/512，批量负载下 ≈ 0.9+
```

两个结论性抓手：**乒乓双缓冲**把"DMA 启动/完成"藏进下一笔的传输时间里（第 N 笔在线上跑时，第 N+1 笔的缓冲已挂好）；**批量合并**（小帧攒批过河）把任务往返开销摊薄——但会伤延迟，8.3 的曲线就是这对矛盾的可视化。

## 8.3 吞吐-延迟曲线：两种负载画像

单一"吞吐"数字会骗人，两种负载各画一条：

- **批量负载**（HTTP 下载：满 512B 帧、单向为主）：吞吐逼近 512B/410µs ≈ 1.2 MB/s @10MHz（≈9.6 Mbps）量级，再乘帧效率；延迟不重要；
- **交互负载**（NTP/MQTT：小帧、一来一回）：**单次 RTT** 才是指标——DRDY 中断响应 + 交换 + 两侧任务唤醒的总和，典型落在 1–5 ms 档；攒批合并会把它成倍推高。

把两轴画成曲线（吞吐↑时钟档位 / 延迟↑合并批大小），**工作点选在曲线膝部**：批 4–8 帧通常同时保住九成吞吐与个位数毫秒延迟。这套画法与 [[f429-lab|F429 实验室]]ch22 的对照实验同一方法论，只是对象从以太网换成了代理链路。

## 8.4 断链剧本：把故障排成戏

稳定性不是"没出过事"，是"出了事都有剧本"。三个剧本各演一遍，记录恢复时间线：

| 剧本     | 注入方式           | 预期恢复链                                                                                                              |
| -------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 物理拔线 | 中途拔 MOSI/DRDY   | F429 侧 PING 三次超时 → 链路断判定 → 按键/自动重试 → 插回后 PING 恢复                                                   |
| AP 消失  | 关路由器           | S3 事件帧 LINK_DOWN → F429 停数据层 → S3 退避重连 → LINK_UP → 应用续传（HTTP 支持 Range 断点续传是加分项）              |
| S3 挂死  | S3 侧断点/喂狗超时 | F429 发现 PING 失联但 DRDY 呆高/呆低 → 拉 RESET 线硬重启 S3 → 完整启动时序重走 → 会话重建（sock_id 全部失效，应用重连） |

第三个剧本专门验证 ch01 的第七根线（RESET）与 ch04 的看门狗——**协处理器模式的终极问题就是"它死了怎么办"，答案是宿主握着它的复位键**。

## 8.5 小结

- 时钟极限由实物决定：阶梯爬坡 + 降一档运行 + 归因三连（线长/地/信号质量），倒下的档位要归档。
- 每笔交换四项开销拆账：位传输不可压、CS/任务往返可压、乒乓藏 DMA、合并摊固定——批大小与延迟是同一枚硬币。
- 两种负载两根曲线，工作点选膝部（批 4–8 帧：九成吞吐 + 个位数毫秒 RTT）。
- 三剧本保稳定：拔线/断 AP/杀 S3 各有恢复链；RESET 线与看门狗兑现"宿主握着协处理器复位键"的终极兜底。
- 测量模板通用：换任何 MCU × 模组组合，这章的方法照跑。
