# F429 × Korvo-1（九）：对照官方——ESP-AT、ESP-Hosted 与我们的轮子

手搓的轮子跑通了，现在照镜子：Espressif 官方在同一道题上交过两份标准答案，它们怎么解、与我们差在哪、什么时候应该弃用自己的轮子。最后一段把同一块 Korvo-1 换到树莓派宿主上走一遍官方路径——ch01 里"多宿主"的伏笔在此收线。

---

## 9.1 ESP-AT：文本 NCP 的哲学与天花板

官方档位一（对应 ch01 的档位一）：固件预置、命令是文本、调试是串口终端。它对"我们的六条命令"的映射一目了然：

| 我们（ch05） | ESP-AT                  | 语义差异                             |
| ------------ | ----------------------- | ------------------------------------ |
| PING         | （心跳靠 AT 本身的 OK） | 我们有 RTT，它是回显                 |
| STATUS       | AT+CWJAP?               | 结构化 vs 解析文本                   |
| SCAN         | AT+CWLAP                | 它的 +CWLAP:<sec>,… 格式要字符串切   |
| JOIN         | AT+CWJAP=…              | 等价；它支持 WPA3/企业网（我们没做） |
| DNS          | （藏在连接里）          | 我们显式可测                         |
| SOCK\_\*     | AT+CIPSTART/SEND/…      | 透传 vs 我们的二进制分帧             |

AT 的真正强项在**成熟度**：多年打磨的边角（重连、SmartConfig 配网、低功耗、多连接管理）都是我们自己要一步步踩的坑。天花板同样清楚：文本协议的解析负担、无结构化错误码、命令集封闭（改协议要重刷 S3 的 AT 固件——而改我们自己的 control.c 只是一行编译）。

## 9.2 ESP-Hosted：netif 隧道的官方实现

官方档位三（对应 ch01 档位三）：S3 跑 WiFi 驱动与关联，宿主拿到虚拟网卡 + 完整协议栈。两个值得偷师的零件：

- **控制面/数据面分离**：它的控制接口（配网、扫描）与数据通路（Ethernet 帧过河）是两条独立通路——与我们"控制帧/数据帧"的 type 分离同构，但它的控制协议是序列化的结构体/TLV 体系，比我们的六条命令完备一个数量级；
- **缓冲环与信用**：它的传输层在 SPI 上实现了带"信用返还"的环形缓冲（收方消费后归还缓冲额度，发方有额度才能发）——比我们"三闸门"更精细的背压形态，值得 ch10 的升级清单收录。

S3 上的传输现实：ESP-Hosted 对 ESP32 经典款首选 SDIO，对 S3 提供 **SPI 模式**（同款"无 SDIO slave"的硬件约束，殊途同归）——这佐证了 ch01 的链路判定，也意味着**官方方案与我们手搓方案跑在同一根物理线上，对照才公平**。

## 9.3 三方对照表

| 维度       | 手搓（本系列）       | ESP-AT            | ESP-Hosted                 |
| ---------- | -------------------- | ----------------- | -------------------------- |
| 协议形态   | 二进制 TLV（自定义） | 文本命令          | 结构化控制 + 帧隧道        |
| 协议栈位置 | S3（socket 代理）    | S3（全栈+socket） | 宿主（netif 虚拟网卡）     |
| 宿主需求   | 最低（无需栈）       | 最低              | 需完整协议栈（lwIP/Linux） |
| 吞吐站位   | 中（代理开销）       | 中低（文本+透传） | 高（隧道近裸帧）           |
| 协议可改   | 源码在手，随便改     | 封闭（刷固件）    | 开源但体量大               |
| 可观测性   | 每层自己 printf      | 串口日志          | 驱动日志+抓包              |
| 成熟度边角 | 自己踩               | 量产级            | 工程级                     |
| 教学价值   | ★★★（全透明）        | ★                 | ★★（读得懂改不动）         |

一句话站位：**手搓方案是"教学最优 + 小规模自用可用"；产品化要么 AT（省事）要么 Hosted（要吞吐与多宿主）**。造轮子的目的从来不是替换它们，而是让你在它们出问题时看得懂里面。

## 9.4 树莓派宿主：官方路径一次走通

同一块 Korvo-1（同一份 Hosted 从机固件，SPI 模式）接树莓派的路径：树莓派侧开 SPI（`raspi-config` + 设备树覆盖使能 spi0）→ 编译 esp-hosted 的宿主驱动 → 得到虚拟网卡与控制工具，协议栈用 Linux 自家的。与 F429 路线对照的启示：

- **宿主越强，越该往档位三走**——Linux 白送一个世界级协议栈，没理由让 socket 活在 S3 里；
- 我们手搓的**帧层与控制层经验完全复用**——COBS/CRC/TLV/背压这些零件，在阅读 Hosted 的传输层源码时全是熟面孔；
- F429 与树莓派共用一块 S3 从机做实验，交叉验证两侧宿主的差异——这是多宿主教学的完整闭环。

## 9.5 小结

- AT = 成熟度天花板 + 协议封闭；Hosted = 吞吐与多宿主站位 + 需要宿主持栈；手搓 = 全透明可改 + 教学最优——三方是光谱不是排名。
- 值得偷师两个零件：Hosted 的控制/数据面分离细节与带信用返还的缓冲环背压。
- S3 上官方同样走 SPI——物理线与我们一致，对照公平。
- 宿主越强越往 netif 隧道走；树莓派路径让多宿主伏笔收线，手搓经验在官方源码里全是熟面孔。
