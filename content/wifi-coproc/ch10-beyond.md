# F429 × Korvo-1（十）：收束——netif 隧道、链路加密与设计清单

## 10.1 升级路线：从 socket 代理到 netif 隧道

档位二升档位三，改动被分层隔离得很好——这正是九章分层的红利：

| 层      | 改动                                                                                                                                      | 工作量                                                                                                                  |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | --- |
| S3 侧   | 删 socket 服务；改挂一个"虚拟网桥"：从 WiFi station 接口抓 Ethernet 帧（IDF 的 esp_netif 有现成的帧层挂点）封装成 DATA 帧；反向解包后注入 | 中                                                                                                                      |
| 帧层    | 不动（ch03 的 DATA 帧载荷从"socket 数据"换成"Ethernet 帧"）                                                                               | 零                                                                                                                      |
| 控制层  | JOIN/STATUS/EVENT 保留；SOCK\_\* 段废弃；新增 ARP/路由配置类命令                                                                          | 小                                                                                                                      |
| F429 侧 | 删 ws\_\* API；把帧层递出的 Ethernet 帧接进 [[f429-lab                                                                                    | F429 实验室]]ch21 的裸机 lwIP——本质上就是再写一个 `ethernetif` 移植层，只是 input/output 的对端从 MAC-DMA 换成 SPI 链路 | 中  |

对照启发：**这恰好是 ESP-Hosted 在 S3 上做的事**（9.2）——升级完成后，你等于手搓了它的迷你版，再读它的传输层源码就是"对答案"。

## 10.2 链路加密：把 vpn-labs 的信封直接搬来

SPI 是板级总线，通常不考虑窃听——但排针外露的开发台、共享实验环境、或链路经过排线/连接器扩展时，**物理可接触 = 链路可注入**。[[diy-vpn|手写 VPN 系列]]的零件在此直接复用：

```text
现状帧： [magic|ver|len|seq|type|payload|crc32]
升级帧： [magic|ver|len|seq|type|Enc(payload)|HMAC-SHA256(header‖ct)]
           密钥：两侧共享 64B（KDF 双向分钥，ch06 的 vpn 做法）
           seq：帧头现成的序号就是防重放计数器——字段从第一天就没白留
```

改造点三处：帧层 seal/unseal 加密包装（`chacha20.c/hmac.c/sha256.c` 从 vpn-labs 原样拷入两侧工程）；握手期一次 KEY_EXCHANGE（可以先用静态密钥，后续接 DH——vpn-labs 的 dh.c 现成）；CRC32 保留（它管链路误码，HMAC 管篡改，两者不可互相替代——**误码检测与身份认证是两个问题**）。开销账：每帧 +36B 与两次哈希/加密，批量负载下个位数百分比——买"排针世界里的端到端干净"，值。

## 10.3 设计清单：十章收束

1. **先审引脚再签合同**（ch01）：RMII 撞 PA7 的案例说明，引脚账是第一张要平的账；
2. **传输层只认字节流**（ch02/03）：SPI/UART 可换、协议零改——分层在第一天就为第十天付账；
3. **帧头为未来留位**（ch03）：magic 防失步、ver 留演进、seq 从第一天就在——后来防重放/加密白拿；
4. **可靠性与安全性分级**（ch03/10.2）：控制帧 ACK、数据帧不重传、CRC 管误码、MAC 管篡改——**分级是设计不是默认**；
5. **两侧共用同一份协议源码**（ch03/05）：联调省命法则，一次写处处编译；
6. **协处理器三义务**（ch04）：能连、状态变化必报、挂了能被 RESET——宿主握着复位键是终极兜底；
7. **背压逐级回传到源头**（ch06）：三闸门 + 借 TCP 窗口之力——慢消费者问题的通用解法；
8. **启动先对表**（ch07）：版本协商、状态对齐，跨芯片协议的第一课；
9. **测不出来的极限不存在**（ch08）：时钟阶梯、双负载曲线、断链三剧本——稳定性是被排练出来的；
10. **造轮子是为了看得懂轮子**（ch09）：三方光谱上各有站位，全透明是我们方案的位置。
