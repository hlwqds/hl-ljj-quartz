# F429 × Korvo-1（十三）：官方路径与多宿主收束

续篇最后一章做两件事：把**官方 ESP-Hosted** 在 RPi4B 上走通（13.1–13.2），然后三方同台对照、给整个系列的多宿主主题收口（13.3–13.4）。

---

## 13.1 从机侧：还是那块 Korvo-1

刷 ESP-Hosted 的从机固件（S3 走 SPI 传输——ch09 说过的硬件现实）：固件内部同样是"SPI 从机队列 + 缓冲环 + WiFi 驱动"三件套，只是协议换成了它的（控制面结构化命令 + Ethernet 帧隧道，ch09 §9.2 拆过）。**接线与手搓版完全相同**（五线 + 共地 + DRDY 换成它的握手线定义）——物理层不动，换的只是固件与宿主软件，这让三方对照天然公平。

## 13.2 宿主侧：模块、虚拟网卡与控制面

RPi4B 上的安装路径（命令随版本演进，以官方文档为准，步骤骨架不变）：

```bash
# ① 内核模块（虚拟网卡 + 控制接口；随内核版本编译）
make -C esp-hosted-ng/host/linux … && insmod esp_wifi.ko
# ② 网卡现身：ip link（一个 Ethernet 形态的虚拟接口）
# ③ 控制面：配网/扫描走它家的控制工具（对应我们 ch05 的六条命令的"全家桶版"）
# ④ 之后就是标准 Linux 联网：dhclient / ip route / 正常 TCP/IP 世界
```

与手搓版最深的差别在这一步显形：**官方方案把 F429 版需要自己写的三层（帧/控制/数据）全部下沉进模块与固件**，宿主拿到的是一块"普通网卡"——门槛最低、吞吐最高（近内核路径），代价是协议封闭在我们已经熟悉的黑盒里。**读懂这个黑盒的每一层，正是主线十章做过的事。**

## 13.3 三方对照大表

| 维度         | F429 手搓（主线）  | RPi 手搓 spidev（ch12）  | RPi 官方 ESP-Hosted（本章） |
| ------------ | ------------------ | ------------------------ | --------------------------- |
| 协议层       | 全自研（三层）     | **同一份源码零改动**     | 官方（模块+固件内）         |
| 传输层       | 裸寄存器 + DMA     | spidev 用户态 ioctl      | 内核 SPI 驱动               |
| 宿主得到什么 | ws\_\* API         | ws\_\* API（Linux 进程） | 虚拟网卡（Linux 原生联网）  |
| 吞吐站位     | 裸机最高效         | syscall 差价             | 内核路径最优                |
| 观测/调试    | printf + 示波器    | strace/poll/日志全家桶   | dmesg/抓包                  |
| 工程投入     | 全手写（教学最优） | 只写传输层（移植验收）   | 安装配置（产品位）          |

三个站位各自成立的条件：**学协议选 F429 手搓，验可移植选 RPi 手搓，要联网能力本身选官方**——本系列三章全走了一遍，切换的只是视角。

## 13.4 交叉实验：一块 S3，两个宿主

多宿主的验收实验设计（真机回填时的标准流程）：

1. **同应用双跑**：NTP 校时 + HTTP 下载（ch07 的两个应用）分别在 F429 与 RPi4B 上对同一块 Korvo-1 跑——两侧的帧序列、分片行为、水位曲线应当**同构**（协议层相同则行为必然相同，任何差异都指向传输层实现）；
2. **对拍观测**：RPi4B 侧开 `strace -e ioctl` 看交换节奏，与 F429 侧的逻辑分析仪/DMA 计数对拍——两个世界观的同一协议，时序上互为镜像；
3. **故障注入移植**：ch08 的三剧本（拔线/断 AP/杀 S3）在 RPi 侧重演——恢复逻辑长在协议层与 S3 固件里，宿主侧只换"怎么发现链路断了"（EXTI 超时 → poll 超时）。

这套实验跑完，"传输无关分层"从设计承诺变成被两台机器背书的事实——**这就是多宿主的全部含义**。

## 13.5 小结（续篇收束）

- 官方路径 = 安装配置拿到虚拟网卡：三层全在黑盒里，而主线十章正是这个黑盒的逐层解剖。
- 三方大表定站位：学协议 / 验可移植 / 要联网，三个需求三种选法，全部亲自走过。
- 交叉实验三件套（同应用双跑、观测对拍、故障注入移植）把"协议层相同则行为相同"变成可验证命题。
- 多宿主的第一功臣是传输无关分层（ch03 的白纸黑字）——续篇四篇是对它的完整兑现。

至此主线十章 + 续篇三章全部完成：一块没有 WiFi 的 F429、一台 Linux 单板机、一根 SPI 线、一块 Korvo-1——从裸字节到官方方案，这条"给任何宿主装上 WiFi"的路完整走了一遍。真机点亮之日，run.log 里见。
