# WiFi 硬件调试实战系列：从看得懂到查得动

> [!tip] 系列说明
> 本系列是 [[wifi-rf-hw|WiFi 射频硬件入门]] 的实战续作。入门系列回答「这东西是什么、为什么这样设计」，终点是**看得懂、测得出、问得准**；本系列回答「**坏了怎么查**」——当你面对一台连不上、掉线、吞吐拉不起来、功耗超标或过不了认证的设备时，手上有一套可执行的排障路径。
>
> 写法延续仓库传统：**现象驱动**。每章从一个具体故障现场出发，按「现象 → 分层定位 → 取证手段 → 根因 → 对策」推进；软件侧命令（`iw`/`wpa_cli`/`tcpdump`/`iperf3`/Wireshark）全部可直接复制执行，需要真机或仪器的实验明确标注实测口径，不虚构读数。装备遵循入门系列的零成本优先原则：手机 App + 路由器后台 + Linux 笔记本 + 一块支持监听模式的 USB 网卡，就能走完前半程。

## 方法论：症状五分类 × 分层下钻

WiFi 故障千变万化，但落到用户可感知的现象只有五类。每类对应一条主排查路径，本系列的章节地图就按这条路径展开：

| 症状分类        | 典型表现                              | 首选取证手段                     | 对应章节 |
| --------------- | ------------------------------------- | -------------------------------- | -------- |
| **连不上**      | 扫不到、认证失败、关联失败、卡在 DHCP | 空口抓包 + 站端日志对齐          | 第四章   |
| **掉线/漫游差** | 用着用着断、跨房间断、漫游乒乓        | deauth 原因码 + 漫游事件时间线   | 第五章   |
| **慢**          | 连上了但吞吐/延迟差                   | iperf3 + 抓包联动 + 信道占用观测 | 第六章   |
| **功耗/电源类** | 发射时复位、电池续航与规格差一个量级  | 电流波形 + 事件对齐              | 九、十章 |
| **认证不过**    | 预测试 fail：功率/杂散/带宽           | 传导测试 + 预测试清单            | 第十一章 |

每一类症状再用「分层下钻」定位。入门系列的四问下钻是**认知框架**，这里是**取证顺序**——从信息最便宜的一层开始，每层回答一个问题再往下：

```text
L1 观测层 —— 用户看得到什么？RSSI、速率、断连频次、重连时间点
L2 协议层 —— 空口发生了什么？beacon/认证/关联/4-way/deauth 逐帧看
L3 驱动固件层 —— 站端日志怎么说？事件、错误码、重试计数、固件断言
L4 射频电路层 —— 物理层健康吗？功率、EVM、频偏、VSWR、电源毛刺
```

原则：**取证成本从低到高，改板子永远放最后**。多数现场问题死在 L2/L3，根本轮不到动烙铁；反过来，电源和天线问题在 L1/L2 只有间接症状，越早识别越少走弯路。

## 目标读者与承诺

- 读过（或在跟）[[wifi-rf-hw|射频硬件入门]] 系列，或具备同等概念量级（懂 dBm、知道 PA/LNA/天线各是什么）
- 有一台 Linux 笔记本（WSL2 亦可，监听模式实验需原生 Linux 或虚拟机直通网卡）
- **承诺**：读完能独立完成空口抓包定位断连根因、用 `iw`/`iperf3` 完成链路质量评估、看懂认证预测试报告、判断「这锅归软件还是硬件」
- **不承诺**：不教射频电路设计与 layout、不教天线仿真、不替代正式认证实验室——预测试的终点是「送测前自己先排掉 80% 的低级 fail」

## 学习节奏建议

- **顺序推进 Part I → II**：工具链与抓包手感是后面所有案例的取证基础，跳过去只能「看故事」。
- **案例章（四、五、六）可按需跳读**：手头正卡哪类症状，直接翻对应章，遇到工具盲区回第一、二章补课。
- **Part III 起动手门槛上升**：第七~九章按「先看懂判据、再攒装备」的节奏来；每章末尾的「降级方案」保证没有仪器也有事可做。
- **每章一个可复制的取证脚本**：能软件侧做的给完整命令；需要硬件的给步骤与预期观察点，标注实测口径——这也是本系列与入门系列的分工：入门看懂设计，实战拿回证据。
