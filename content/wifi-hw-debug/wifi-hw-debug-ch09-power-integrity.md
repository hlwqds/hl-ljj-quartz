## 9.1 现场：三类「电源病」

电源问题在 WiFi 设备上的出场方式出奇地一致。先把三类最常见的现场摆出来——如果你手头的故障能对上号，本章就是为你写的：

| 编号 | 现场描述                                             | 表面症状                         | 第一直觉（往往是错的）       |
| ---- | ---------------------------------------------------- | -------------------------------- | ---------------------------- |
| A    | OTA 升级到固件解压/写入+联网校验阶段，设备复位       | 「升级必失败」「闪存坏了？」     | 先怀疑 Flash、先怀疑固件 bug |
| B    | 大流量上传（摄像头推流、文件上传）跑几分钟后随机重启 | 「跑负载就死」「驱动内存泄漏？」 | 先怀疑 lwIP、先怀疑驱动      |
| C    | 换了一个电源适配器，问题消失                         | 「玄学」「心理作用？」           | 归档为「不可复现」           |

三个现场的共同点：**故障与「发射/大电流」强相关，与代码逻辑弱相关**。A 现场里升级流程恰好伴随密集的 HTTPS 交互与 CPU 满载；B 现场里上传让 WiFi 长时间处于高占空比发射；C 现场里唯一变化的变量是供电本身。这不是巧合——WiFi 发射是这类嵌入式设备上**最猛的瞬时负载**，没有之一。

> [!tip] 一条现场经验
> 「换个电源就好了」从来不是玄学，它是成本最低的一次**电源变量对照实验**。遇到可疑的随机复位，先做这个零成本实验，再决定要不要动示波器。

电源性格的概念（电源不是理想电压源，它有内阻、有响应速度、有脾气）在 [[ch12-power-supply|射频入门（十二）]] 已经建立。那一章回答「为什么电源会这样设计」；本章回答「怎么**证明**你手头这台设备的病根在电源，以及怎么**归因**到具体哪一环」。

## 9.2 WiFi 电流画像：先知道你在找什么

测电源之前，得先知道 WiFi 芯片的电流长什么样。三个稳态 + 一个瞬态：

### 三态电流量级

以乐鑫 ESP32 系列 datasheet 典型值为口径（**具体数值以对应芯片 datasheet 为准**，不同型号/频段/速率/发射功率档差异很大）：

| 状态                            | 典型量级（ESP32 系列口径） | 说明                                   |
| ------------------------------- | -------------------------- | -------------------------------------- |
| 空闲（modem sleep，关联但省电） | 十几~几十 mA               | 依赖 DTIM 周期醒来收 beacon            |
| 空闲（active，不省电）          | 数十~一百 mA 量级          | CPU 与射频均常开                       |
| 接收（RX，持续收流）            | 约几十~一百 mA 量级        | datasheet 给 RX 典型值                 |
| 发射（TX，802.11b 高功率档）    | 二百~三百 mA 量级          | datasheet 给 TX 典型值，功率档越高越大 |

> [!warning] 量级 vs 精确值
> 本章只承诺**量级**——「发射比接收大数倍、瞬时可达数百 mA」。做设计余量计算时必须翻你手上那颗芯片的 datasheet 射频功耗表，按实际速率与功率档取值，不要拿本章的约数当设计输入。

### TX 突发的形状：关键不在平均值

三态平均值骗不了人但也帮不了你——真正把电源打趴下的是 **TX 突发的形状**。802.11 的发射是包驱动的：每个 PPDU 发射期间 PA 满血工作，包间隔回落。示意如下：

```text
WiFi TX 电流画像（示意，非实测，量级参考 datasheet 典型值）

电流
300mA ┤      ┌─┐        ┌─┐   ┌───┐
      │      │ │        │ │   │   │      ← TX 突发（数百 mA 量级）
100mA ┤ ┌─┐  │ │  ┌─┐   │ │   │   │      ← RX/空闲基线（几十 mA 量级）
      │ │ │  │ │  │ │   │ │   │   │
      ──┴─┴──┴─┴──┴─┴───┴─┴───┴─┴──→ 时间
        ms 级包周期，突发间隔随流量模式变化

关键特征：
- 上升沿 di/dt 大：PA 从关到开在 µs 级完成
- 突发高度：从基线到数百 mA 的跳变
- 突发宽度：单个 PPDU 数百 µs 到 ms 级（取决于包长与速率）
```

两个对电源最不友好的属性：

| 属性                   | 为什么致命                                       | 对应的硬件敏感点                 |
| ---------------------- | ------------------------------------------------ | -------------------------------- |
| 突发性（数百 mA 跳变） | 电源要在 µs 级补上这个缺口，储能电容先顶上       | 输出电容的容值与 ESR             |
| 大 di/dt               | 电流快速变化 × 走线电感 = 瞬间压降 `V = L·di/dt` | 供电走线的电感（长度/宽度/过孔） |

这就是为什么「平均电流没超标，设备照样复位」：万用表看到的是平均值（几十 mA，安安稳稳），示波器看到的是数百 mA 的毛刺流。**平均电流是给续航计算用的，瞬时电流才是给电源设计用的。**

## 9.3 因果链三级表现：同一个病，三种脸

电源跌落的伤害按深度分三级。同一块板子、同一个病根，负载轻重不同会表现出完全不同的症状——这也是电源问题难查的原因之一：它擅长伪装成软件问题。

```text
因果链（示意）：
TX 突发大电流 → 电源内阻/走线阻抗上的压降 → 芯片供电电压跌落
                                                  │
        ┌─────────────────────────────────────────┼──────────────────────┐
        ▼ 跌得很深                                 ▼ 跌到临界但不触发      ▼ 跌得浅
   第一级：brownout 复位                      第二级：无复位但丢包     第三级：仅性能抖动
```

| 级别 | 表现                     | 机理                                            | 现场特征                                        |
| ---- | ------------------------ | ----------------------------------------------- | ----------------------------------------------- |
| 一级 | brownout 复位 / 硬件复位 | 电压跌破芯片 brownout 检测阈值，复位电路动作    | 重启时间点与发射高峰对齐；复位原因寄存器有记录  |
| 二级 | 不复位，但丢包/掉线      | 电压跌到射频/晶振能勉强工作但裕量尽失的区间     | RF 性能劣化：EVM 变差、接收灵敏度下降、偶发丢包 |
| 三级 | 仅性能抖动               | 电压跌落轻，尚未伤及功能，但时钟/偏置被轻微扰动 | 吞吐锯齿、延迟抖动，抓包看到重传率升高          |

### 三级甄别方法

| 级别 | 取证手段                                                                                                           | 看什么                                                                                      |
| ---- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 一级 | 复位源日志：ESP32 侧读 `esp_reset_reason()` / bootloader 启动日志（`rst:` 行）；Linux SBC 侧看内核日志供电相关报错 | 复位原因是否为 brownout / power-on；时间是否与 OTA、上传等大电流活动对齐                    |
| 二级 | 空口抓包（第三章方法）：观测是否有异常 deauth/disassoc，还是仅丢数据帧；站端 `iw dev <if> station dump`            | deauth 特征 vs 吞吐锯齿的区别：电源性丢包通常是**重传增多、速率自适应下调**，而非认证层断链 |
| 三级 | `iw station dump` 的重传计数器前后对比；iperf3 打流时观察吞吐锯齿形态                                              | 重传率随流量增大而上升、空闲时恢复——与干扰的差别在于干扰不跟你设备的负载正相关              |

> [!tip] 一个强判别信号：负载相关性
> 把「症状是否随 WiFi 发射占空比变化」当作第一甄别轴。打流就犯病、空闲就正常 → 强烈指向电源/射频物理层；空闲也犯病、与流量无关 → 优先查协议层（第四章、第五章的领地）。这个判断零成本，先做它。

一级甄别的 ESP32 侧具体动作：复位后立刻读启动日志，乐鑫 bootloader 会打印复位原因（brownout 复位在日志中有明确标记）；运行中的应用可调用 ESP-IDF 的复位原因 API 持久化记录。**注意**：如果复位原因显示的是 SW CPU reset 或 panic，那病根大概率不在电源，别急着冤枉它。

## 9.4 示波器实测：把毛刺抓出来

定性判断做完，实锤要靠示波器。目标只有一个：**拍到复位/丢包瞬间的供电电压波形**。

### 探头与接地：先不引入假象

| 要点         | 为什么                                                                      | 做法                                                        |
| ------------ | --------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 接地线尽量短 | 长地线的地环路电感在大幅 di/dt 场合会引入振铃假象，让你「测到」不存在的毛刺 | 用探头自带的接地弹簧/短接地夹，接地端点选被测芯片就近的地   |
| 带宽够用即可 | 毛刺边沿在 µs~百 ns 级，普通 100 MHz 示波器足够；带宽越高越容易拾取环境噪声 | 100 MHz 级台式示波器/手持示波表均可                         |
| 探头衰减档   | 1× 档信噪比好但输入电容大，10× 档更常见                                     | 用 10× 探头时记得把示波器通道设置为 10×，否则电压读数差十倍 |
| 测点选择     | 测「芯片看到」的电压，不是「电源输出」的电压                                | 探针顶在 WiFi 芯片/模组的供电引脚或最近的去耦电容焊盘上     |

### 触发：用 GPIO 翻转与 TX 事件对齐

毛刺是随机的，靠单次捕获碰运气效率太低。标准做法是**软件打标**：在 ESP32 侧的 WiFi 事件回调里翻转一个空闲 GPIO，示波器用这个 GPIO 边沿做触发，另一通道测供电——这样示波器图上每一屏都「知道」TX 事件在哪，电压跌落与发射的因果关系一目了然。

```c
/* 思路示意：在 TX 事件回调中翻转 GPIO 作为示波器触发标记 */
#define PIN_TX_MARK GPIO_NUM_4

static void tx_mark_toggle(void)
{
    gpio_set_level(PIN_TX_MARK, !gpio_get_level(PIN_TX_MARK));
}
/* 在 esp_wifi 事件处理（如 TX 完成事件）或发送热路径中调用 tx_mark_toggle()；
   具体挂接点随项目的事件模型而定，见本仓库 ch16-wifi-events 的事件章节 */
```

配置要点：

| 配置项           | 建议                                                                               |
| ---------------- | ---------------------------------------------------------------------------------- |
| 示波器触发源     | GPIO 所在通道，边沿触发                                                            |
| 触发方式         | Normal（单次/ repetition 均可），先 Normal 等事件                                  |
| 供电通道垂直档位 | 按电源轨设置（如 3.3 V 轨用 100 mV~200 mV/div 交流耦合看纹波，直流耦合看绝对跌落） |
| 时基             | 先 ms 级看整体，抓到后再收缩到 µs 级看单次跌落                                     |

### 要捕获的两个数：幅度与持续时间

拍到之后，从波形上量两个数，它们就是后续归因的输入：

| 观测量       | 定义                     | 归因用途                                                                       |
| ------------ | ------------------------ | ------------------------------------------------------------------------------ |
| 跌落幅度     | 供电从稳态掉到谷值的深度 | 对照芯片 brownout 阈值与 LDO dropout（见 9.5）                                 |
| 跌落持续时间 | 跌到谷值再恢复的时长     | 对照 DCDC 环路响应速度：几 µs 级恢复 → 电容问题；几百 µs 不恢复 → 电源响应问题 |

### 便宜替代：采样电阻 + 普通示波器

没有电流探头（电流探头往往是全套装备里最贵的一件）时，串一只小阻值采样电阻，用普通电压探头看电阻上的压降来反推电流：

| 项       | 建议                                         | 压降代价                                                          |
| -------- | -------------------------------------------- | ----------------------------------------------------------------- |
| 阻值     | 0.1 Ω ~ 1 Ω 量级（封装功率要够）             | 300 mA × 1 Ω = 300 mV 压降——**对 3.3 V 轨已是不可忽视的额外跌落** |
| 位置     | 串在电源轨进入 WiFi 模组之前                 | 注意采样电阻自身会让问题更容易复现，见下方警告                    |
| 读数换算 | 通道电压 ÷ 阻值 = 电流（看清楚探头档位倍率） | —                                                                 |

> [!warning] 采样电阻会改变被测系统
> 串入电阻相当于人为增加电源内阻，可能让原本「临界不复发」的板子稳定复现——这说明它本来就临界，但要意识到**加电阻后看到的跌落深度 ≠ 原板真实跌落深度**。定性看电流形状可以，定量归因要折算并注明。

再降一档的零成本观察法（定性）：USB 功率计/串口电流表看平均值是否异常，手机慢动作摄像 + LED 指示灯捕捉复位瞬间时序——这些替代只能回答「有没有异常」，回答不了「毛刺多深多宽」。

## 9.5 判据：跌多深算深

拍到了跌落波形，怎么判断「这就是病根」？两个参照物：

### 参照物一：芯片 brownout 阈值

芯片复位与否由 brownout 检测阈值决定。以 ESP32 系列为口径：brownout 检测阈值由芯片技术参考手册/ESP-IDF 配置项定义，且**部分型号可分级配置**；确切电压值随芯片型号与配置而不同，**以对应芯片 datasheet / 技术参考手册为准**——具体典型电压值本章标注「待核对」，避免以讹传讹。

定性结论不受影响：**跌落谷值逼近 brownout 阈值（无论该阈值具体是多少伏），就是一级表现的直接证据**。若复位日志同时给出 brownout 标记，因果链闭合。

### 参照物二：LDO dropout 与 DCDC 占空比极限

即使没触发 brownout，供电网络里的每一环也有自己的极限：

| 环节 | 极限参数                                                         | 口径                                                                                   |
| ---- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------ |
| LDO  | dropout voltage：输入-输出压差低于它就不再稳压，输出跟随输入下跌 | 以所用 LDO 的 datasheet 为准（典型值零点几伏量级，负载越大越大）                       |
| LDO  | 电流上限 / 热限制                                                | datasheet 给的输出电流与功耗预算；TX 峰值电流要算进去                                  |
| DCDC | 瞬态响应：负载阶跃时输出偏差与恢复时间                           | datasheet 瞬态响应曲线；环路慢则跌落深且恢复久                                         |
| 走线 | `V = L·di/dt` 与 `I·R` 压降                                      | 走线电感/电阻随长度、宽度、过孔数变化，无统一判据，layout 章节口径见 [[ch13-pcb-layout | 射频入门（十三）]] |

### 余量设计直觉

调试视角的余量直觉，三条够用：

1. **电压余量**：稳态工作点离 brownout 阈值的距离，要大于最坏 TX 突发造成的跌落深度。稳态 3.3 V 看着健康，跌 0.4 V 就可能踩线。
2. **电流余量**：LDO/DCDC 的额定输出要对 TX 峰值留出裕量（工程惯例常取 50% 以上裕度，具体项目自定口径），且 DCDC 的「额定」要看瞬态而不是只看连续电流。
3. **时间余量**：储能电容撑住的时间要大于电源环路响应时间。电容提供的电荷 `Q = C·ΔV`，反过来说 `ΔV = I·t/C`——突发电流越大、环路越慢，电容就要越大。

> [!note] 判据来源纪律
> 本章故意不给出「跌 0.3 V 算深」这类具体数字判据——它依赖具体芯片与电源器件。正确的取证习惯是：**跌落深度 vs 该芯片 brownout 阈值（datasheet 口径）、vs 该电源器件 dropout/瞬态规格（器件 datasheet 口径）**，两个对照都查原文，查不到就在调试记录里标「待核对」，而不是抄网上经验值。

## 9.6 常见根因逐个过

波形到手，归因开始。四类根因覆盖了绝大多数现场，逐一对照：

| #   | 根因                                   | 波形指纹                                                                        | 定位实验                                                                    |
| --- | -------------------------------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 1   | LDO 电流余量不足                       | 电压跌落后**不恢复**或恢复缓慢，像被拖住；严重时 LDO 过热                       | 换大电流 LDO 或改 DCDC 对照；摸 LDO 温度；核 datasheet 电流规格与峰值负载比 |
| 2   | DCDC 瞬态响应慢                        | 跌落深、恢复时间长（数百 µs 级平台）；轻载正常、重载跌落                        | 查器件 datasheet 瞬态规格；试补偿/更大输出电容对照                          |
| 3   | 走线阻抗大 / 大电容位置远              | 芯片引脚处跌落深，但电源输出端跌落浅——**两点测压差**就是走线证据                | 分别探电源输出端与芯片引脚，压差大即走线问题                                |
| 4   | 共电源干扰（电机/屏幕/继电器拉低母线） | 跌落时间点与 WiFi 发射**不**对齐，反而与外设动作对齐；GPIO 打标图上一眼看出错位 | 关停外设逐一对照；打标图上比对事件时间线                                    |

几条归因备注：

- **根因 1 的隐蔽形态**：LDO 热限制是慢变量——冷机正常、跑十分钟才犯病，温度相关性是最强的指向。这个现场与 9.1 的 B 现场高度相似，别误判成内存泄漏。
- **根因 3 的几何解释**：射频入门系列讲过供电走线要短粗、去耦电容要贴着芯片引脚放（[[ch13-pcb-layout|射频入门（十三）]]、[[ch08-passives-in-rf|射频入门（八）]]）。调试阶段能做的是**证明**，改板才是修复。
- **根因 4 最常被冤枉**：电机/背光在另一条「无关」的电源轨上，但它们共母线。很多「WiFi 玄学」最终归因到一块 LCD 背光或一颗舵机——GPIO 打标对齐实验（9.4）是揭穿它的最快路径。

## 9.7 对策与验证

归因完成，按根因选对策。原则不变：**先软后硬、先板级后改版**。

| 对策             | 针对根因 | 做法                                                                                                                  | 验证方法                         |
| ---------------- | -------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| 加储能电容       | 2、3     | WiFi 芯片供电引脚就近加大容值（如百 µF 级电解/钽/陶瓷并联，按空间与 ESR 需求选型，具体值按 9.5 的 `ΔV = I·t/C` 估算） | 复测波形：跌落深度变浅、恢复更快 |
| 换 DCDC / 调补偿 | 1、2     | 换更大电流、更快瞬态响应的 DCDC；或调整已有器件的补偿/频率设置（以器件 datasheet 设计指南为准）                       | 复测瞬态波形对比                 |
| 独立供电域       | 4        | WiFi 芯片单独一路 LDO/DCDC，与大电流外设的母线解耦                                                                    | 外设满载时 WiFi 轨波形不再受扰   |
| 走线/铺铜改版    | 3        | 加宽供电走线、增加铺铜、去耦电容贴近引脚                                                                              | 改版后 A/B 波形对比              |

### 软件侧临时缓解：是止血，不是修复

等板子改版期间，软件侧可以临时压低 TX 突发的猛烈程度，让设备先能用：

| 手段                             | 机制                                               | 代价                                                    |
| -------------------------------- | -------------------------------------------------- | ------------------------------------------------------- |
| 降低 TX 功率                     | PA 电流与发射功率正相关，降功率直接削突发峰值      | 链路预算变小：远距离/遮挡场景 RSSI 下降，可能引入真丢包 |
| 限速（降 MCS/带宽）              | 包发送时间变长、速率降，di/dt 变缓但总能量未必变少 | 吞吐直接受损                                            |
| 关闭省电（提高常供电稳定性需求） | 消除唤醒突发电流，电流曲线更平                     | 平均功耗上升——与第十章的省电目标直接冲突                |

> [!warning] 明确边界
> 以上三条全部是**临时缓解**：它们改变的是症状的触发概率，不是电源的承载能力。降功率可能把「电源病」伪装成「信号病」（RSSI 掉了、真丢包出现了），让归因复杂化。**缓解措施要记录在案并设定回退计划**，改版验证通过后立即撤销——把止血药当饭吃，是电源问题最常见的烂尾方式。

## 9.8 教学案例复盘：从「上传就重启」到电源归因

> [!note] 案例口径
> 教学复盘案例，取材自常见故障模式综述，不对应任何具体真实项目；时间线与判据为方法论演示，不虚构仪器读数。

**现象**：一台 ESP32 系列电池供电设备，功能是本地采集 + 周期性上传云平台。现场反馈：大多数时候正常，但上传较大数据块时偶发重启，重试后有时能成功。固件日志无 panic、无看门狗触发记录。软件侧已排查：内存水位正常、任务栈无溢出、lwIP 无断言。

**取证链，按成本从低到高：**

1. **零成本对照**：换电源适配器（设备同时支持 USB 供电调试）→ 故障频率明显下降但未消失。电源进入嫌疑名单，但不能定罪（还存在电池与 USB 供电轨不同的变量）。
2. **复位源取证**：重启后读复位原因 → brownout 复位标记。一级因果链的「果」坐实：是电源跌落触发的复位，不是软件崩的。此时归因还差一半——跌落可能来自电池内阻、走线、LDO 或 DCDC。
3. **负载相关性确认**：对比「上传小包」与「上传大块数据」的故障率 → 大块数据（TX 占空比更高）故障率显著更高。与 9.3 的判别轴一致：负载相关 → 物理层/电源方向。
4. **GPIO 打标 + 示波器**（9.4 方法）：GPIO 翻转对齐 TX 事件，探针顶在模组供电引脚 → 捕获到与 TX 突发对齐的电压跌落，谷值逼近该芯片 brownout 阈值口径（具体电压值查对应 datasheet，调试记录中标注待核对）。跌落后恢复缓慢，呈「被拖住」的形态。
5. **两点测压差**（9.6 根因指纹法）：电源输出端跌落浅、模组引脚端跌落深 → 压差显著 → 中间环节（走线 + 电源自身响应）共同承责。
6. **根因收束**：核对电源器件 datasheet：LDO 额定电流对 TX 峰值电流的裕量不足，且该 LDO 在压差边缘工作。指纹与根因 1（LDO 余量不足）吻合，走线压差为次要放大因素。

**对策与验证**：临时缓解——软件限制单次上传块大小并错峰（写入缓解记录，附回退条件）；硬件——换更大电流余量的电源器件 + 模组供电引脚就近补储能电容。改版后用同一套打标 + 示波器流程复测：跌落谷值明显抬升、远离 brownout 阈值，长时间上传压力测试不再复位。撤销临时限流后复测，故障未回归——闭环。

**复盘要点**：这条链上每一步都是可复制的——零成本对照实验、复位源日志、负载相关性、打标对齐、两点测压差。没有一步依赖昂贵仪器，示波器只在第 4 步才出场。**归因的功夫在测量之外：每一步都先缩小嫌疑范围，再花下一分钱。**

## 9.9 收尾：电源问题 checklist

遇到「疑似电源病」，按顺序过这张表：

| #   | 检查项                            | 方法                                          | 结果判读                                 |
| --- | --------------------------------- | --------------------------------------------- | ---------------------------------------- |
| 1   | 症状是否与发射/大流量负载相关     | 空闲 vs 打流/上传对照                         | 负载相关 → 电源嫌疑 ↑；无关 → 回协议层查 |
| 2   | 换电源/供电方式故障率变化         | 零成本对照实验                                | 变化明显 → 电源嫌疑 ↑↑                   |
| 3   | 复位原因寄存器/启动日志           | `esp_reset_reason()` / bootloader `rst:` 日志 | brownout 标记 → 一级表现坐实             |
| 4   | TX 峰值电流 vs 电源器件额定       | 查芯片与电源器件 datasheet，算裕量            | 裕量不足 → 根因 1 方向                   |
| 5   | LDO 温度（如适用）                | 手摸/热像，冷热机对比                         | 温度相关 → 热限制方向                    |
| 6   | 示波器拍供电跌落（GPIO 打标对齐） | 9.4 方法，量幅度与持续时间                    | 谷值逼近 brownout 阈值 → 实锤            |
| 7   | 电源端 vs 芯片引脚两点测压差      | 双探针对比                                    | 压差大 → 走线/去耦方向                   |
| 8   | 外设动作与跌落时间对齐            | 打标图时间线比对                              | 错位对齐 → 共电源干扰（根因 4）          |
| 9   | 临时缓解是否在案                  | 缓解记录 + 回退计划                           | 缺记录 → 补上，防止止血药当饭吃          |
| 10  | 修复后同流程复测                  | 打标 + 示波器 + 压力测试                      | 不复位且撤销缓解后不回归 → 闭环          |
