## 1.1 软件工程师为什么需要认识硬件

从一个所有写代码的人都遇过的场景说起：**WiFi 满格，但上不了网**。图标四格，`ping` 却丢包三成，视频转圈。你的排障路径大概率是这样的：重启大法 → 查 DNS → 查路由表 → 抓包看重传 → 升级驱动。每一步都在软件栈里打转，而真正的病因可能在软件的视野之外——天线被新买的金属摆件挡了、电源适配器老化导致发射瞬间电压跌落、2.4 GHz 频段被邻居和微波炉挤爆。这不是玄学，是**你的调试栈缺了最底下的两层**。同一个症状，两个世界的病因对照：

| 症状                         | 软件侧你已经排查过的      | 硬件侧可能的真相                           | 本系列哪章       |
| ---------------------------- | ------------------------- | ------------------------------------------ | ---------------- |
| 信号满格但上不了网           | DNS、路由表、TCP 重传抓包 | 信噪比差（干扰挤占）、天线净空被遮挡、频偏 | 第五、六、十一章 |
| 大流量下载时整机掉线         | 驱动、固件版本、缓冲区    | 发射瞬间电流毛刺拉低电压（电源余量不足）   | 第十二章         |
| 深夜高峰延迟恶化             | 重启、固定信道、QoS       | 邻居 2.4 GHz 信道占用高峰、同频干扰        | 第十四章         |
| 设备「看着好好的」就是连不上 | 密码、认证方式、DHCP      | 晶振频偏导致解调失败——硬件没有任何可见损伤 | 第十一章         |

左边这些坑，本仓库的软件系列都排过；排到最后剩下的那一部分，就是本系列的领地。本仓库的三条线恰好把软件栈从上到下钻了个通透，但各自停在一条边界上：

| 系列                                                                         | 停在哪条边界                                                     |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| [[2026-08-26-lwip-deep-dive-ch18-esp32-wifi-lwip-integration\|lwIP（十八）]] | WiFi **驱动之上**的协议栈：netif、pbuf、TCP/IP 全链路            |
| [[2026-08-26-esp32-s3-box-3-ch16-wifi-events\|BOX-3（十六）]]                | 连接管理层：WiFi 事件、断连重连、省电                            |
| 本系列                                                                       | 再往下：**射频 PHY、芯片、电路、天线**——电磁波出发前的最后一厘米 |

软件工程师对底层的认知停在「驱动」这一层，就像运维对机房的认知停在「ssh 进去」——知道机器在哪，但没见过机架长什么样。本系列的解法很直接：**把机器拆开看**。

方法论沿用索引里的「四问下钻」，拿「满格却上不了网」当例子先走一遍：

```text
Q1 现象层 —— RSSI 到底多少、邻居占着哪些信道？（手机 App 就能看）
Q2 协议层 —— 802.11 怎么定义信号质量与速率协商？
Q3 芯片段 —— SoC 里哪段链路把信号弄丢了？
Q4 电路层 —— 板上哪个元件、哪段走线决定了它？
```

软件系列的终点是源码行号；本系列的终点是 **datasheet 参数与元件符号**。到不了「会设计」，但到得了「看得懂、测得出、问得准」。

**本系列承诺**：读完能看懂 ESP32-WROOM-1 模组 datasheet 的射频章节、能用地摊级装备做 RSSI/信道实测、能和硬件工程师有效对话。

**本系列不承诺**：不教天线设计与仿真（史密斯圆图只到概念级）、不教射频电路计算与 layout 实操、不做 6 GHz 实测（实验全部 2.4 GHz）、不教仪器操作。每个硬件概念都会配一个你已懂的**软件类比**——但类比只是脚手架，真值永远以 datasheet 为准。

> [!note] 本章的证据口径
> 硬件事实（模组构成、天线净空、功率、晶振、电源峰值）均标注官方出处：乐鑫官网产品页、ESP-FAQ 仓库（GitHub master，中文版 rst 原文逐条核对）、esp-idf 源码头文件、esp-box 仓库硬件资料；查不到出处的数值一律标「待核对」。路由器拆解是**文字 walkthrough**——本章不虚构照片与仪器读数，外观描述均为定性文字；建议读者按 1.2 的指引拿一台旧路由器亲手对照（拆机有电气风险，见安全提示）。

## 1.2 拆解一台典型家用路由器：七个部件认脸

### 1. 拆机三步

典型家用路由器的开壳流程，一把十字螺丝刀就够了：

1. **断电拔线**：电源、网线、天线（可拆的）全部移除。
2. **找螺丝**：底部橡胶脚垫和保修贴纸下面通常藏着 2~4 颗螺丝，掀开拧下。
3. **开壳**：剩下的外壳靠卡扣咬合，沿缝隙用指甲或塑料撬片分离一圈再掀开，金属工具容易留痕。

开壳后常见的形态：一块主板，中间一到两块金属屏蔽罩，边缘焊着内置天线（或馈线接到外置天线座），网口集中在一侧，电源入口在另一侧。双频路由器通常有**两套 RF 前端**（2.4 GHz 与 5 GHz 各一套）——一个可以自查的定性观察：**馈线/天线走线的组数大致对应频段与天线数量**。

> [!warning] 待实践：拆机安全提示
> 拆机前务必断电并拔掉所有线缆。路由器的开关电源部分有大容量电解电容，**断电后仍可能储能**，不要用手指或金属工具同时触碰电容两极；拆下的螺丝按位置收好。本节为通用安全指引，非实测记录——你第一次动手时请保守操作。

### 2. 部件总表：是什么 / 干什么 / 软件类比 / 在哪能找到

开壳后，PCB 上认得出七个角色。这是本章的核心表，逐列读：

| 部件           | 是什么                                    | 干什么                                                       | 软件类比                                                   | 在哪能找到                                                 |
| -------------- | ----------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- | ---------------------------------------------------------- |
| 主控 SoC       | 一颗高集成芯片（博通/高通/联发科/瑞昱等） | WiFi MAC+基带、路由协议栈、NAT、Web 管理界面，通常单芯片全包 | 片上整机：把 CPU+网卡+交换芯片塞进一颗芯片                 | 板上最大的一颗芯片，常盖散热片或屏蔽罩，丝印型号           |
| RAM            | 一两颗小封装 DRAM 芯片                    | 跑固件运行时（转发表、缓存、Web 后台）                       | 内存条                                                     | SoC 旁边的小黑芯片，丝印容量可查                           |
| Flash          | 一颗 NOR/NAND 芯片                        | 存放固件本体（bootloader+系统+配置）                         | 磁盘 + /boot 分区；固件升级就是写 Flash                    | 与 RAM 相近的另一颗小芯片，有时与 RAM 叠封                 |
| RF 前端+屏蔽罩 | PA/LNA/收发开关/滤波器，藏在金属罩下      | 把基带交付的数字帧变成能上天线的模拟射频信号（发），反向亦然 | 网卡的 PHY 与线路驱动器：MAC 交付帧，它负责「上物理介质」  | 天线馈线或 PCB 走线汇入的那块金属罩（见 1.4）              |
| 天线           | 外置棒状（橡胶天线）或内置 PCB 走线       | 导线里的电信号与空气里的电磁波互相翻译                       | 对外的「最后一米网线+端口」：再好的协议栈也要从这段出去    | 外置：拧在壳上的几根棒子；内置：PCB 边缘的蛇形/倒 F 走线区 |
| 网口变压器     | RJ45 座后方一排小方块                     | 电气隔离、防雷、共模抑制、以太网线缆耦合                     | 协议网关前的「防雷隔离带」：让两个电气世界互相通话但不共地 | WAN/LAN 口一排 RJ45 后面整齐排列的小黑块                   |
| 电源           | DC 输入座 + DCDC/LDO + 一圈电容           | 把适配器电压降到 SoC 内核与 3.3 V；扛住发射瞬间的电流毛刺    | 限流器+缓冲池：瞬时流量洪峰不能打挂服务                    | 电源线入口处，最大的那颗电容和电感附近                     |

**整机类比**：一台路由器就是一台「1U 微型服务器机架」——SoC 是主板与计算，RAM/Flash 是内存与磁盘，RF 前端与天线是上联网卡与外线，网口是下联交换口，电源是 PSU。把这条类比展开成一张机架对照表，今天认的每个部件都能在机房里找到同名亲戚：

| 路由器里的部件 | 机房里的对应物     | 职责层     |
| -------------- | ------------------ | ---------- |
| 外壳/卡扣/螺丝 | 机柜与机架         | 结构与容纳 |
| 主控 SoC       | 主板（CPU+芯片组） | 计算       |
| RAM 芯片       | 内存条             | 运行态     |
| Flash 芯片     | 磁盘+/boot 分区    | 持久化     |
| RF 前端+天线   | 网卡+网线/配线架   | 上行链路   |
| 网口与交换     | 机架交换机         | 下行/内网  |
| DCDC/LDO/电容  | PSU/PDU            | 供电与缓冲 |

这张表也解释了为什么软件工程师看路由器「眼熟」：你运维过的每一层职责，在这块巴掌大的板上都有对应的物理器官——只是全部折叠进了 1U 都不到的塑料壳里。

### 3. 逐件补几句（带出处的事实）

- **电源——最被低估的部件**。WiFi 发射是「瞬时大电流负载」。ESP-FAQ 给 ESP8266 的官方数字：模拟电源峰值 350 mA、数字电源峰值 200 mA，模拟部分极限电流可达 500 mA，电源设计需满足 500 mA；若用 LDO，输出电流要大于 500 mA（出处：ESP-FAQ 硬件设计篇，原文核对）。同一 FAQ 还有一组对照：ESP32 裸片供电窗口 2.3~3.6 V，而 ESP32-WROOM-32 模组收窄为 3.0~3.6 V——模组里多了 Flash，电压下限水涨船高。「电压差一点，WiFi 就丢包」的机理第十二章展开。
- **天线——性价比最高的升级点**。官方 FAQ 的摆放指引：天线附近不能有金属或遮挡物、天线背面不能有 PCB，并让辐射较强的方向指向接收设备（出处：ESP-FAQ 射频篇）。一个有出处的参照数字：乐鑫模组手册给 WROOM-1U 认证时的外接天线增益上限是 2.33 dBi（模组手册 v1.8 §1.4，见第七章核对）；家用路由器外置天线增益常见标称在 2~5 dBi 量级（待核对；第六章教你读懂这个数的含义）。
- **RAM/Flash**。路由器固件升级的本质是把新固件写进 Flash——类比 `dd` 写镜像；运行时的转发表与 NAT 会话住在 RAM 里，断电即失。所以「恢复出厂设置」清的是 Flash 里的配置分区，不是 RAM。
- **网口变压器**。RJ45 座后面那排小方块负责电气隔离与共模噪声抑制，让路由器的地与你电脑的地不直接相连——类比光耦隔离的电气版。注意路由器的主业是无线，有线口是 backhaul 与配置入口。
- **RF 前端**。屏蔽罩下通常是 PA（发射放大）、LNA（接收放大）、收发开关与滤波器——第四章、第五章沿「比特→天线」「天线→比特」各漫游一遍，第十章专门拆 FEM。

### 4. 对照实物图指引（文字版）

- **找到天线**：外置棒状天线的路由器，开壳后顺着天线根部的馈线（细同轴线）走，另一端焊在 PCB 上——这就是 RF 的出口。内置天线的机型，看 PCB 边缘一大片**没有铺铜、没有元件**的走线区（为什么必须净空见 1.4）。
- **找到屏蔽罩**：馈线汇入处那块焊在板上的金属盖，覆盖的区域就是 RF 前端与 SoC 的敏感部分。
- **找到存储**：SoC 周围找丝印含容量信息的芯片（如 `128M`、`256M` 字样），那就是 Flash/RAM。
- **找到晶振**：SoC 旁边的小椭圆/小圆柱金属件（比米粒大不了多少），它是全系统的节拍器（1.4 细讲）。
- **数一数馈线**：从天线根数能反推这台机器的基本规格——几组馈线、几个天线座，大致就是几个频段/几条空间流的规模。
- **找到电源**：DC 圆孔入口向后看，电感（黑色小方块/圆柱）与电解电容（圆柱、顶部有刻痕）聚集处。

每颗芯片的型号丝印都可以拿手机拍照后搜 datasheet——这是比读十篇科普更快建立「硬件坐标」的办法。

## 1.3 对照实验：BOX-3 的「最小 WiFi 硬件」

路由器是「全家桶」，ESP32 模组是「最小系统」——把 WiFi 硬件砍到不能再砍。本系列后续真机实验的主力是 BOX-3，它的核心是一颗 **ESP32-S3-WROOM-1 N16R8V 模组**（16 MB Quad Flash + 8 MB Octal PSRAM，本仓库 [[2026-08-26-esp32-s3-box-3-ch1-quick-start\|BOX-3（一）]] 的实测记录）。

为什么拿它对照而不是拿路由器：三个理由——资料全公开（原理图/BOM/PCB 随手可查，路由器拿不到）、就在手边（后续章节的实验对象）、规模最小（部件少到每一个都能讲清楚，路由器多出的交换机/USB/多路 FEM 都是噪声）。

### 1. 模组内部有什么

依据乐鑫官网 ESP32-S3-WROOM-1 模组产品页与模组手册：

| 项目             | 事实（官方页原文口径）                                                      | 出处                      |
| ---------------- | --------------------------------------------------------------------------- | ------------------------- |
| 核心芯片         | 基于 ESP32-S3（双核 Xtensa LX7 @240 MHz，512 KB 片上 SRAM）                 | 乐鑫 ESP32-S3 SoC 产品页  |
| 无线规格         | "2.4 GHz Wi-Fi (802.11 b/g/n)"、"Bluetooth 5 (LE)"                          | 同上                      |
| 模组内 Flash     | 4/8/16 MB 可选（N16 = 16 MB Flash）                                         | WROOM-1 模组产品页        |
| 模组内 PSRAM     | 0/2/8/16 MB 可选（R8 = 8 MB PSRAM）                                         | 同上                      |
| 天线             | WROOM-1 为「PCB Antenna」（板载）；WROOM-1U 为「Antenna Connector」（外接） | 同上                      |
| 外形尺寸         | WROOM-1：18×25.5×3.1 mm；WROOM-1U：18×19.2×3.2 mm                           | 同上                      |
| 主晶振           | 40 MHz（`SOC_XTAL_FREQ_40M = 40`）                                          | esp-idf `clk_tree_defs.h` |
| 认证天线增益     | 1U 外接天线认证增益上限 2.33 dBi                                            | 模组手册 v1.8 §1.4        |
| 默认最大发射功率 | 20 dBm（menuconfig：Component config → PHY → Max Wi-Fi TX power）           | ESP-FAQ RF-related        |

三条读表注意：其一，双核与 512 KB SRAM 在本机 esp-idf 也有佐证（`soc_caps.h` 的 `SOC_CPU_CORES_NUM = 2`）；其二，20 dBm 那行出自 ESP-FAQ 的模组功率问答（原文语境是 ESP32-WROVER-E 条目），ESP32-S3 的软件可配范围 2~20 dBm 已在[[ch03-decibel-family|第三章]]用 `esp_wifi.h` 注释单独核实，两处口径一致；其三，模组手册 v1.8 的系统框图显示模组内就是 SoC+Flash/PSRAM+晶振+RF 匹配网络+天线，**没有外置 PA/LNA**（第七章逐项核对）——这条在下面 1.3.3 的对照表里马上要用。

一个直观的对比藏在尺寸里：板载 PCB 天线版比外接天线版**长了 6.3 mm**（25.5 − 19.2）——那截多出来的板子就是天线本体。天线不是「一根可选的棒子」，它是印在 PCB 上的、有形状有尺寸的电路。拆一台路由器时看到的每根橡胶天线里，也藏着同样讲究的一截金属。

另一个乐鑫官方 FAQ 的数字先立此存照：**模组 PCB 天线区域及外扩 15 mm 需净空（严禁铺铜、走线、摆放元件）**（ESP-FAQ 硬件设计篇）。天线周围那一圈「什么都没有」不是浪费板材，是射频性能的保命空间。

### 2. 模组 = 预装好的服务器整机

软件类比，本章最重要的一条：**裸片是散件，模组是整机**。

- **ESP32-S3 裸片**（DIE）就像自己攒机房：你要自己焊 Flash、配晶振负载电容、设计天线匹配网络、过 FCC/CE/SRRC 认证——相当于从内核开始自己维护操作系统。
- **WROOM-1 模组**是云上的预配主机：芯片 + Flash/PSRAM + 晶振 + PCB 天线（或天线座）封装在一小块做了认证的板子上，焊到你的板子、接上电源就能跑 WiFi。datasheet 就是它的「云主机规格清单」。

这就是索引里那句「软件工程师永远用模组」的硬件依据——不是能力问题，是**认证与射频调校的成本问题**（第七章展开）。

把这条类比拉成一条「集成度光谱」，今天认的每个对象都能放进去：

| 层级                         | 里面有什么                                 | 软件类比               |
| ---------------------------- | ------------------------------------------ | ---------------------- |
| 裸片（DIE）                  | 只有 SoC 本体，Flash/晶振/天线全要自己配   | 从内核开始自建操作系统 |
| 模组（WROOM-1）              | 裸片 + Flash/PSRAM + 晶振 + 天线，认证已过 | 云上预配主机，开箱即用 |
| 开发板/整机（BOX-3、路由器） | 模组 + 电源 + 接口 + 外壳 + 天线布局       | 托管机房全家桶         |

买模组多花的钱，买的是别人已经趟平的射频坑与已经付费的认证——和「买云主机比自己运维便宜」是同一笔账。

> [!warning] 待真机验证
> BOX-3 到货后对照实物核验：模组表面金属屏蔽罩的覆盖范围、板载天线的净空区域、模组丝印的 N16R8V 字样。另有一处口径差异待核对：esp-box 仓库官方硬件概述写 BOX-3 模组带「16 MB 八线 PSRAM」，而本仓库 BOX-3（一）的实测丝印是 N16R8V（8 MB）——乐鑫官网变体表里 N16R8V 与 N16R16V 两种模组都存在，到手配置以丝印为准。本节官方规格以乐鑫产品页为准，实物观感待回填。

### 3. 路由器 vs BOX-3：全家桶砍成了什么

拿 1.2 的部件总表对照 BOX-3，能看清「最小 WiFi 硬件」到底砍掉了什么、留下了什么：

| 部件角色  | 家用路由器                      | BOX-3（最小 WiFi 硬件）     |
| --------- | ------------------------------- | --------------------------- |
| 计算核心  | 高通/博通/联发科等多颗大芯片    | 一颗 WROOM-1 模组           |
| RAM/Flash | 板上独立 DRAM/NAND 颗粒         | 全部藏进模组（N16/R8）      |
| RF 前端   | 外置 FEM：独立 PA/LNA，双频两套 | SoC 片内 PA/LNA，无外置 FEM |
| 天线      | 外置棒状多根，或高增益阵列      | 模组板载 PCB 天线一根       |
| 网口      | WAN+LAN 交换芯片+变压器         | 没有（Type-C 只管供电）     |
| 电源      | 外置适配器+板上多路 DCDC        | Type-C 供电+板上电源树      |

（BOX-3 用 Type-C 做供电与下载/调试的出处：esp-box 仓库硬件概述文档；「无外置 FEM」的出处见 1.3.1 读表注意第三条。）

砍掉的都是「服务别人」的部件——交换、多天线、多路放大；留下的正好是 WiFi 的**最小完备集**：一颗收发一体的 SoC、一块存固件的 Flash、一根天线、一路稳压。反过来读这张表也成立：路由器比 BOX-3 贵出来的部分，大半花在你现在看不见的外置 FEM、多天线与散热上——第十章会算这笔账。

## 1.4 屏蔽罩与「黑盒」：为什么盖金属、什么不能碰

### 1. 为什么 RF 部分要盖金属罩

拆机时你最先看到的「芯片」其实多半是**屏蔽罩**——焊在 PCB 上的马口铁小盒，真正的芯片藏在下面。它不是装饰，主要也不是散热片。乐鑫官方 FAQ 的说法（硬件设计篇）：屏蔽罩应采用**导电材质并接地**，能有效减少外界干扰和 PCB 板上各电路之间的互相干扰；当板上存在 WiFi/蓝牙/Zigbee 等无线电路时建议加上。

**软件类比：机房的电磁屏蔽与接地**。一个满机柜的服务器房间，如果墙不屏蔽、设备不接地，交换机的灯都在互相感应噪声。屏蔽罩就是给 RF 电路修的「独立机房」：自身的发射不漏出去干扰别人（过认证的关键），外面的噪声也进不来干扰接收灵敏度。它是**法拉第笼**，而「接地」是让这个笼子生效的前提——这层依赖关系很像软件里的隔离边界必须配合权限边界，只隔离不收权等于没隔离。

为什么偏偏 RF 部分盖罩：因为 RF 是板上「嗓门最大、耳朵最灵」的电路——PA 发射时是噪声源，LNA 接收时最怕噪声，两者天生需要和其他电路隔开。

顺带回答一个拆机现场问题：**罩子能不能撬开看**？看清罩下是什么没问题，但撬开后就焊不回原样——FAQ 的措辞是屏蔽罩「导电并接地」才有效，业余回焊很难保证四周焊缝的接地连续性，罩子等于白盖。想看罩下的结构，去看 1.3 那些公开的原理图与装配图，比撬罩子看得更清楚。

### 2. 拆机时千万别碰的三样东西

| 别碰            | 原因                                                                 | 碰坏的后果                                                 |
| --------------- | -------------------------------------------------------------------- | ---------------------------------------------------------- |
| 天线馈线/同轴线 | 它是按 50 Ω 阻抗设计的传输线，弯折、拉扯、焊点移位都会改变其电气特性 | 信号反射、灵敏度下降、连不上网                             |
| 晶振            | 全系统的节拍器；机械应力与过热会改变其频率精度                       | 频偏导致「看着好好的设备连不上」（第十一章的真实故障模式） |
| 天线净空区      | 那是刻意留空的射频性能空间（外扩 15 mm 净空要求）                    | 在净空区贴标签/堆线缆 = 亲手劣化天线                       |

顺带一个 FAQ 佐证的行为准则：乐鑫官方明确建议模组天线区域**附近不能有金属或遮挡物、天线背面不能有 PCB**；天线朝向应让「辐射较强的方向指向接收设备」。换成路由器语言：路由器别塞进金属弱电箱、别靠墙角、天线别折叠——这些「玄学建议」背后全是天线物理（第六章展开）。

还有一个容易踩的实操细节：U 系列模组（带天线座）不能直连 SMA 天线，官方口径是**请使用 IPEX 转 SMA 转接线**（ESP-FAQ）。想给设备换「大天线」时，先想清楚第九章会讲的线损与失配账。

### 3. 顺带认识晶振：全系统的节拍器

别碰清单里的晶振值得单独看一眼：它是 SoC 全系统的时钟源头，WiFi 的载波频率就从它倍频而来。乐鑫 FAQ 对 ESP8266 的要求是 26 MHz 晶振、自身精度 ±10 ppm（出处：ESP-FAQ 硬件设计篇）；ESP32-S3 的主晶振是 40 MHz（出处：esp-idf `clk_tree_defs.h` 的 `SOC_XTAL_FREQ_40M`，见 1.3 的表）。ppm 级的频偏足以让对端的解调器「听不清」你的载波——「设备看着好好的就是连不上」的经典硬件病，第十一章专门拆解。软件类比：晶振之于 SoC，就像单调时钟之于内核——所有「时间相关的正确性」都押在它的稳定上，坏了不报错，只是所有人都开始犯错。

**屏蔽罩下面到底有什么**：以模组为例，罩下是裸片、Flash/PSRAM 与供电去耦电容（模组手册 v1.8 系统框图口径）；在路由器上，RF 罩下则是 PA/LNA/收发开关和一小撮指甲盖大小的匹配元件（第七、八章起逐个认）。把它当「黑盒」不是坏事——本系列的目标不是开盖，而是知道黑盒的规格书上写着什么、问出专业的问题。

## 1.6 常见误区表与小结

| 误区                         | 真相                                                                  | 详见           |
| ---------------------------- | --------------------------------------------------------------------- | -------------- |
| 天线越粗/越长信号越好        | 增益由天线设计决定，粗不等于增益高；高增益往往伴随方向图变窄          | 第六章         |
| 屏蔽罩是装饰或散热片         | 主职是 EMI 屏蔽，且必须导电并接地才生效（ESP-FAQ）                    | 1.4、第十三章  |
| 信号满格 = 网络一定好        | 满格只说明 RSSI 高；信噪比、信道占用、协商速率是另一回事              | 第五章         |
| 拆机看到的金属方块都是芯片   | 多数是屏蔽罩，芯片在罩下；「开盖」需要专业工具，别硬撬                | 1.2、1.4       |
| 主频高的路由器 WiFi 快       | CPU 主频决定 NAT/转发吞吐；WiFi 速率由 RF 链路、调制阶数与协商决定    | 第四、十六章   |
| 5 GHz 一定比 2.4 GHz 好      | 5 GHz 频段更干净但衰减更快、穿墙更差，频段是取舍不是升级              | 第二章         |
| WiFi 不稳先怪固件            | 电源电压跌落、晶振频偏、天线净空被破坏，都是典型硬件病                | 第十一、十二章 |
| 加根天线延长线总有收益       | 线损与阻抗失配可能吃掉全部增益；U 系列还需 IPEX 转 SMA 转接线（FAQ）  | 第九、第十八章 |
| 模组和裸片差不多，能省则省   | 模组预先解决了天线、匹配、认证三大难题；软件工程师永远用模组          | 第七章         |
| 金属弱电箱里信号差是固件问题 | 金属包围直接劣化天线辐射（FAQ：天线附近不能有金属遮挡）               | 1.4、第六章    |
| 天线拧掉也能凑合用           | 发射端天线缺失或严重失配时，PA 可能工作在恶劣负载下（待核对风险边界） | 第六章         |

**小结**：

- **WiFi 硬件的部件坐标已建立**：主控 SoC（片上整机）、RAM/Flash（内存/磁盘）、RF 前端与屏蔽罩（网卡 PHY+机房屏蔽）、天线（最后一米网线）、网口变压器（电气隔离带）、电源（限流器+缓冲池）——整机即一座 1U 微型服务器机架（对照表见 1.2.2），每个部件今天起不再是无名的黑色方块。
- **模组 = 预装好的服务器整机**：WROOM-1 把 ESP32-S3 裸片、Flash/PSRAM、40 MHz 晶振、PCB 天线封装成做过认证的最小 WiFi 硬件；板载天线版比外接版长出的 6.3 mm 就是天线本体。BOX-3 则示范了「全家桶砍到最小完备集」：计算、存储、天线、电源四件套，其余全是可砍的服务性部件。
- **两条拆机纪律**：断电后电解电容仍储能，别短路；天线馈线、晶振、天线净空区三样东西别碰——15 mm 净空是官方写进 FAQ 的硬要求。
- **三条线索通向后续**：功率类数字（20 dBm、2.33 dBi）第三章换算；「满格却上不了网」第五章用 SNR 解释；拆机看到的每个部件在 1.5 的地图里都有专属章节。
- **一条元方法**：四问下钻从 Q1（手机 App 就能看的现象）走到 Q4（板上元件）——每往下一层，证据就从「日志」换成「datasheet 参数」，但「先取证再下结论」的纪律不变。
