# WiFi 射频硬件入门（三）：dB 家族——硬件世界的十六进制

> [!info] WiFi 射频硬件入门系列 0. [[wifi-rf-hw|系列索引]]

> **第三章：dB 家族——硬件世界的十六进制**（当前章）
> 下一章：[[ch04-tx-chain|第四章：发射链路漫游]]

这一章只解决一件事：**看懂 dB/dBm/dBi，并且会心算**。它是全系列的「单位制」章——后面每一章的 datasheet 表格、API 注释、法规条文，全用这套单位写。学不会它，就像不懂十六进制就去读内核的内存布局代码：每个字都认识，连起来不知道在说什么。

核心类比先立起来：**dB 家族之于射频，等于十六进制之于程序员**。程序员看到 `0x10000000` 秒懂是 256 MB，看到 `268435456` 却要数三位才知道量级；射频工程师看到 `-67 dBm` 秒懂是「中等信号」，看到 `0.0000002 mW` 同样要数零。人类读大数费劲，工程界的解法一致：**换刻度**。十六进制把 2 的幂压成一位十六进制数，dB 把 10 的幂压成一个加法。

## 3.1 为什么不用毫瓦：线性数字装不下这个动态范围

### 1. 同一件事的两种写法

一台 2.4G 路由器满功率发射（中国法规上限），与 ESP32-S3 在最低速率下的接收灵敏度，用毫瓦写出来是这样的：

| 说的事                    | 用 mW 写           | 用 dBm 写 |
| ------------------------- | ------------------ | --------- |
| 路由器满功率（EIRP 上限） | 100 mW             | 20 dBm    |
| 基准功率                  | 1 mW               | 0 dBm     |
| S3 最低速率灵敏度         | 0.0000000001445 mW | -98.4 dBm |
| FCC 允许的传导功率上限    | 1000 mW            | 30 dBm    |

（灵敏度数值出处：ESP32-S3 datasheet v2.2 §6.3 表 6-4，802.11b 1 Mbps 典型值 -98.4 dBm；法规限值出处见 3.4 节。）

线性写法的两个问题一目了然：**零要靠数**（那个 0.0000000001445 你刚才是逐个数过去的），**比值要靠除法**（100 mW 是灵敏度的多少倍？心算直接放弃）。而 dBm 写法里，跨了约 118 dB——约七千亿倍的动态范围——只是一条 120 个刻度的数轴。

### 2. 你早就用过同款解法

程序员对「线性数字不好读」的回应是十六进制与 2 的幂：

- `1 << 20` 是 1 MB——你不会写成 `1048576`；
- 地址空间用 `0x80000000` 说 2 GB——不会写 `2147483648`；
- 授权费用「四个 9 的可用性」——不会写 99.99%。

dB 是射频界的同款回应，还多赚了一层：**对数把乘法变成加法**。功率放大 1000 倍、再衰减一半，线性世界要乘除，dB 世界就是 `+30 - 3`。你已经熟悉的 log 域运算（频谱图的纵轴、FFT 幅度、信号强度条）全是这个道理。

定义只有两行，这是全系列仅有的两行必须记住的公式：

```text
dBm = 10 × log10( P / 1mW )      # P 换算成 dBm：绝对功率，1 mW 是 0 点
dB  = 10 × log10( P2 / P1 )      # 两个功率的比值：增益/损耗，没有基准
```

一个立即可得的好性质：**dBm 相减 = dB**（20 dBm 与 17 dBm 差 3 dB，即功率差约 2 倍）；**dBm 与 dB 相加减 = dBm**（20 dBm 衰减 3 dB 是 17 dBm）。这一条正是 3.3 节链路加减法的全部合法性来源。

## 3.2 三兄弟辨析：dBm 是值，dB 是差，dBi 是参照物账

### 1. 一张表分清

| 单位 | 本质                     | 参照物       | 软件类比                                 | 例子                         |
| ---- | ------------------------ | ------------ | ---------------------------------------- | ---------------------------- |
| dBm  | 绝对功率                 | 1 mW         | 带单位的时间戳（`int64_t` 纳秒）         | 发射 20 dBm、灵敏度 -98 dBm  |
| dB   | 两个功率的比值，无量纲   | 无（纯比值） | 两个时间戳的差（offset/delta）           | 线损 3 dB、放大器增益 10 dB  |
| dBi  | 天线增益（相对全向天线） | 理想全向天线 | 相对 baseline 的性能百分比，必须注明基线 | PCB 天线约 2 dBi、外置 5 dBi |

用「单位即类型」的类型系统直觉读这张表：

- `dBm ± dB = dBm`——时间戳加时差还是时间戳，合法；
- `dBm ± dBm` 非法——两个时间戳相加没有物理意义，这是新手最高频的类型错误（见 3.6 误区表）；
- `dB + dB = dB` 合法——差值叠加还是差值。

dBi 的 i 是 isotropic（全向）：一个假想的、向所有方向均匀辐射的天线。天线增益的单位用 dBi 而不是 dB，是为了**钉死参照物**——「增益 5 dBi」= 在最强方向上，比理想全向天线强 5 dB。你还会见到 dBd（相对半波振子 dipole），换算恒等：dBi = dBd + 2.15（半波振子相对全向天线的增益是 10×log10(1.64) ≈ 2.15 dB，由振子方向图积分而来，标准天线学结论）。本系列一律用 dBi。

天线那笔账先按下不表，只立一句防误导的定论：**天线是无源器件，不产生能量**，增益是把能量从「四面八方」重新分配到「某些方向」换来的——细节是第六章的主场。

### 2. 换算速查表（背锚点，不背表）

| dBm | mW       | 记忆锚点                                 |
| --- | -------- | ---------------------------------------- |
| -30 | 0.001 mW | 1 µW，-30 = 1 mW 缩小 1000 倍            |
| -20 | 0.01 mW  |                                          |
| -10 | 0.1 mW   |                                          |
| 0   | 1 mW     | 基准点：一切从 1 mW 起算（类比 2^0 = 1） |
| +10 | 10 mW    | +10 dB = ×10                             |
| +20 | 100 mW   | 中国/欧盟 2.4G EIRP 上限（3.4 节核实）   |
| +30 | 1000 mW  | FCC 传导功率上限 1 W                     |

锚点就三个：**0 dBm = 1 mW**、**+10 dB 十倍**、**+3 dB 翻倍**（10×log10(2) = 3.01，工程口诀抹掉小数）。其余全部由口诀现场推出，见下节。

## 3.3 心算术：三个口诀打天下

### 1. 口诀与二进制直觉

| 心算   | 结果         | 你熟悉的同款直觉               |
| ------ | ------------ | ------------------------------ |
| +3 dB  | ×2（×1.995） | 左移一位 `<<1`                 |
| +6 dB  | ×4（×3.98）  | 左移两位 `<<2`                 |
| +10 dB | ×10          | 十进制升一位（hex 升一位=×16） |
| +20 dB | ×100         | 两个数量级                     |
| -3 dB  | ÷2           | 右移一位 `>>1`                 |
| -10 dB | ÷10          | 降一个数量级                   |
| +7 dB  | ×5           | +10 与 -3 组合：10×10÷2        |
| +13 dB | ×20          | +10 与 +3 组合：10×2           |

验算两例，建立信心：

- WiFi 速率从 MCS7 掉到 MCS0，灵敏度从 -74.2 dBm 放宽到 -92.6 dBm（ESP32-S3 datasheet 表 6-4），放宽 18.4 dB——最低速率能解调的信号比高速率弱约 70 倍（10^1.84 ≈ 69）；
- FCC 与中国的 EIRP 上限差 16 dB（36 对 20，见 3.4 节）≈ ×40——美区法规允许的辐射强度约是中国的 40 倍。

### 2. 链路加减法：一笔预算账

dB 域的乘法变加法，直接给射频工程师送了一套**预算追踪**流程——和你给一条数据处理管道逐级记账延迟完全同构：每级的 gain/loss 是增量，起点是绝对值，终点是绝对值：

```text
接收电平 = 发射功率 + 发射天线增益 - 线损 - 自由空间损耗 + 接收天线增益
```

代入一笔真实的账（每个数的出处都在 3.4/3.5 节核实过）：

```text
  20    dBm   路由器 EIRP（中国法规上限）
+  0    dBi   笔记本内置天线增益（保守取 0）
- 60    dB    2.4G 自由空间损耗，10 米（由 FSPL 公式算出，见下）
------
= -40    dBm   笔记本处的接收电平
```

拿它对比接收端的灵敏度：-40 dBm 对 ESP32-S3 的 -74.2 dBm（HT20 MCS7），**裕量 34 dB**——信号比解调门限强约 2600 倍（10^3.42），这是一间房内 WiFi 应该有的样子。整套算法的名字叫**链路预算（link budget）**，第五章（接收链路与灵敏度）正式展开，这里先记住一句话结论：**链路预算就是 dB 域的逐级记账，最后一行永远是「接收电平 − 灵敏度 = 裕量」**。

顺带一条从 FSPL 公式（自由空间损耗，第五章推导）直接掉出来的距离规律，心算时极其好用：2.4G 下距离每 ×10，损耗 +20 dB；每 ×2，+6 dB。反过来读就是**功率翻倍（+3 dB）只买到 √2 ≈ 1.41 倍距离；想把距离翻倍，功率要 ×4（+6 dB）**。「加 3 dB 不如挪半米」的工程直觉从此有出处。

## 3.4 WiFi 世界的典型值速查表

### 1. 法规限值：同一台路由器的三种人生

2.4G 免许可频段的发射上限按地区不同，这是「美版路由器信号猛」的制度原因：

| 地区 | 依据                               | 限值原文口径                                                            | 换算与备注                                  |
| ---- | ---------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------- |
| 中国 | 信部无〔2002〕353 号               | 天线增益 <10 dBi 时 EIRP ≤ 100 mW                                       | 20 dBm EIRP；≥10 dBi 天线另有扣减           |
| 美国 | 47 CFR §15.247(b)（eCFR 现行文本） | 数字调制最大传导功率 ≤ 1 W，基于 ≤6 dBi 天线；增益每超 3 dB 功率扣 1 dB | 30 dBm 传导 + 6 dBi = 36 dBm 有效 EIRP 上限 |
| 欧盟 | ETSI EN 300 328                    | EIRP ≤ 100 mW（20 dBm）                                                 | 与中国同档                                  |

认证与法规是什么、SRRC/FCC/CE 对选型的实际影响，第十七章展开；本章只要锚点：**20 dBm（中/欧）对 36 dBm（美），差 16 dB**。

### 2. ESP32 的发射功率：datasheet 口径与软件口径

ESP32-S3 芯片发射功率典型值（datasheet v2.2 §6.3 表 6-2 节选，天线口测量、含前端损耗、前端为 0 Ω 电阻条件）：

| 模式         | 速率    | TX 功率典型值 |
| ------------ | ------- | ------------- |
| 802.11b DSSS | 1 Mbps  | 21.0 dBm      |
| 802.11g OFDM | 54 Mbps | 19.0 dBm      |
| 802.11n HT20 | MCS0    | 19.5 dBm      |
| 802.11n HT20 | MCS7    | 18.5 dBm      |

三个读表收获：

1. **发射功率也不是一个数**：速率越高、调制越密（第四章讲 QAM），放大器越难保持线性，功率就越低——11b 1 Mbps 到 HT20 MCS7 差 2.5 dB；
2. datasheet 首页写「11b 最高 +21 dBm、11n 最高 +19.5 dBm」，就是这张表的上沿；
3. **软件口径更低**：ESP-FAQ 记载「ESP32 的 Wi-Fi RF 功率输出最高可以配置为 20 dBm，取值范围 2-20 dBm」，`esp_wifi.h` 注释同样给出 [8, 84]（0.25 dBm 单位）对应 2-20 dBm（3.5 节原文）。datasheet 的 21 dBm 是芯片在理想条件下的典型值，软件栈让你配到的上限是 20 dBm——两份文档口径不同，引用时别混。

### 3. 灵敏度不是一个数

ESP32-S3 接收灵敏度典型值（datasheet v2.2 §6.3 表 6-4 节选，PER 判据：11b 为 8%，11g/n 为 10%）：

| 模式         | 速率/MCS | 灵敏度典型值 |
| ------------ | -------- | ------------ |
| 802.11b      | 1 Mbps   | -98.4 dBm    |
| 802.11g      | 54 Mbps  | -76.5 dBm    |
| 802.11n HT20 | MCS0     | -92.6 dBm    |
| 802.11n HT20 | MCS7     | -74.2 dBm    |
| 802.11n HT40 | MCS7     | -71.4 dBm    |

跨度 27 dB（约 500 倍）。「灵敏度 -97 dBm」这种单值说法要么是最低速率的极限值，要么没写清条件——正确姿势是**谈灵敏度必带速率/MCS**。为什么高速率需要更强信号（SNR 与调制阶数的关系）是第五章的主题。

同表附近还有一条容易被忽略的行：**最大接收电平**（表 6-5）——11b 1 Mbps 时 +5 dBm，54 Mbps/MCS7 时 0 dBm。信号强过这个数，接收机饱和，同样解不出。类比：麦克风贴着嘴喊话，录出来的只会是爆音。

### 4. 手机上的 RSSI 分档：经验约定，无官方标准

| RSSI      | 主观评价 | 经验解读                                    |
| --------- | -------- | ------------------------------------------- |
| -50 以上  | 极好     | 贴脸水平，再强无意义                        |
| -50 ~ -65 | 好       | 满速运行的正常区间                          |
| -65 ~ -75 | 中       | 开始掉速率，看 3.4.3 的灵敏度表就知道为什么 |
| -75 ~ -85 | 差       | 高速率挡位陆续解不出，断流边缘              |
| -85 以下  | 很差     | 掉线候选，仅剩最低速率勉强维持              |

必须交代的事实：**ESP-FAQ 明确说「我们没有对 RSSI 信号强度进行等级划分」**，只给了换算建议（RSSI 范围 [0, -96] 映射五格信号），并转引 Android AOSP `WifiManager` 的 MIN_RSSI = -100 / MAX_RSSI = -55。上表分档是手机 App 与社区的经验约定（不同厂商分级不同，**待核对**：以你手头 App 的说明页为准），量级判断够用，别当标准引用。

## 3.5 软件入口：工程师最先遇到的三个 dB 场景

三个场景都来自本机 `~/esp/esp-idf`（v6.0.2）`components/esp_wifi/include/` 的一手头文件注释，逐条 grep 核实过。

### 1. 场景一：esp_wifi_set_max_tx_power 的单位是 0.25 dBm

`esp_wifi.h` 的注释原文（关键句）：

```c
 * @attention 4. Param power unit is 0.25dBm, range is [8, 84] corresponding to 2dBm - 20dBm.
 * @attention 5. Relationship between set value and actual value. As follows:
 *   {set value range, actual value} = {{[8, 19], 8}, {[20, 27], 20}, {[28, 33], 28},
 *   {[34, 43], 34}, {[44, 51], 44}, {[52, 55], 52}, {[56, 59], 56}, {[60, 65], 60},
 *   {[66, 71], 66}, {[72, 79], 72}, {[80, 84], 80}}.
```

三层信息，一层比一层容易踩坑：

1. **单位不是 dBm，是 0.25 dBm**——想设 20 dBm 要传 `80`，想设 19 dBm 传 `76`。这是定点数（放大 4 倍的整数 dBm），也是经典单位陷阱的同款：时间 API 的 ms 对 µs、`esp_timer` 的 µs 对 ms。传错单位差 4 倍，编译器不会替你发现——`int8_t` 不携带单位；
2. **上限 84 但实际封顶 80**：attention 5 的映射表说 [80, 84] 区间的设置值统统落到 80（20 dBm），与 3.4.2 节「软件口径 20 dBm」互相印证；
3. **设置值会被吃进离散档位**：传 68（想设 17 dBm）落在 [66, 71] 档，实际值 66 = 16.5 dBm。ESP-FAQ 记载的「menuconfig 配 17 dBm 时 ESP32 实际最大发射功率为 16 dBm」就是同一现象的配置入口版本——PHY 按 2 dBm 起步的档位量化，你给的值会被吸附到最近的档。

注释还有一句伏笔：attention 1「WiFi 启动前的最大功率受 PHY init data bin 限制」——PHY 初始化数据是芯片校准链路的入口，第七章（SoC 解剖）再展开。

### 2. 场景二：esp_wifi_get_max_tx_power 读回同单位

```c
 * @param power Maximum WiFi transmitting power, unit is 0.25dBm.
```

读回 `80` 就是 20 dBm。set/get 一对 API 单位一致，这正是它俩的价值：**用 get 验证 set**（尤其在档位吸附和法规配置介入之后）。日志里同时打 set 值和 get 值，是排查「为什么实际功率和我设的不一样」的第一步。

### 3. 场景三：wifi_ap_record_t.rssi——你日志里的第一个 dBm

`esp_wifi_types_generic.h` 中的字段与注释原文：

```c
int8_t rssi;  /**< Signal strength of AP. Note that in some rare cases
                   where signal strength is very strong, RSSI values can be slightly positive */
```

两个宝藏细节：

1. **RSSI 可以为正**——头文件官方注释亲口说的：信号极强时 RSSI 可能是小的正数（设备贴着路由器时）。这呼应 3.2 节：dBm 只是刻度，正负只代表比 1 mW 强或弱；
2. **RSSI 是滑动平均，不是瞬时值**——ESP-FAQ 给出了滤波器本体：`rssi_avg = rssi_avg * 13/16 + new_rssi * 3/16`，每 ≥100 ms 更新。你一眼就能认出这是一阶 IIR 低通（EMA），而且系数 13/16、3/16 是**定点数实现**——16 是 2 的幂，除法退化成移位，免浮点单元。嵌入式信号处理的教科书手法长在了 WiFi RSSI 上。工程后果：日志里 RSSI 变化迟钝、拐弯平滑，是滤波后的产物；真机实验（第十五章）读数时按此预期。

另有一个 API 命名口径：v6.0.2 头文件里只有 `esp_wifi_sta_get_ap_info()`（本机 grep 无 `esp_wifi_get_ap_info` 匹配，后者是旧版名，老教程里常见）。扫描结果里 `wifi_ap_record_t.rssi` 与连接后读到的 `rssi` 同字段，后者按上述 EMA 语义平均。

### 4. 一段可以直接抄的最小代码

```c
#include "esp_wifi.h"

int8_t raw = 0;
esp_wifi_get_max_tx_power(&raw);      // 读回 80 → 80 × 0.25 = 20 dBm
ESP_LOGI(TAG, "max tx power = %.2f dBm", raw * 0.25);

wifi_ap_record_t ap = {0};
esp_wifi_sta_get_ap_info(&ap);        // v6 名称；旧代码见 esp_wifi_get_ap_info
ESP_LOGI(TAG, "rssi = %d dBm", ap.rssi);  // 典型 -30 ~ -80；极近场可为小正数
```

## 3.6 常见误区表

| 流传说法                         | 错在哪                                                   | 正确姿势                              |
| -------------------------------- | -------------------------------------------------------- | ------------------------------------- |
| 「20 dBm 加 10 dBm 等于 30 dBm」 | 两个绝对功率相加无物理意义（时间戳加时间戳）             | dBm ± dB = dBm；dBm 相减得 dB（比值） |
| 「天线增益把功率放大了」         | 无源器件不产生能量；增益是把能量重新分配到特定方向换的   | 增益是方向性的账，单位 dBi（第六章）  |
| 「灵敏度是 -97 dBm 一个数」      | 灵敏度按速率/MCS 分档，S3 跨 -98.4 ~ -71.4 dBm           | 谈灵敏度必带速率条件（第五章）        |
| 「RSSI 可以跨设备精确对比」      | 各芯片 RSSI 口径不同，且是 EMA 滤波后的均值              | 同设备看趋势可以；跨设备只比量级      |
| 「+3 dB 就是精确两倍」           | 10×log10(2) = 3.0103，口诀是取整                         | 心算用口诀，正式计算用公式            |
| 「功率翻倍，距离翻倍」           | 距离 ×2 需 +6 dB（功率 ×4）；+3 dB 只买 √2 ≈ 1.41 倍距离 | 用链路预算算，别用直觉（第五章）      |
| 「信号越强一定越好」             | 接收机有最大电平（S3 表 6-5：+5 dBm/0 dBm），过强饱和    | 过强同样解不出，像麦克风贴嘴爆音      |

## 3.7 小结

- **单位制**：dBm 是绝对功率（1 mW 为 0 点），dB 是比值（差值），dBi 是相对全向天线的增益。单位即类型：dBm ± dB = dBm 合法，dBm ± dBm 非法。
- **心算**：+3 dB 翻倍、+10 dB 十倍，组合出 +7（×5）、+13（×20）；链路预算 = dB 域逐级记账，末行恒为「接收电平 − 灵敏度 = 裕量」。
- **典型值锚点**（均已注明出处）：中/欧 EIRP 上限 20 dBm 对美国 36 dBm（差 16 dB）；ESP32-S3 发射典型 18.0 ~ 21.0 dBm 分速率、软件上限 20 dBm；灵敏度 -98.4 ~ -71.4 dBm 按速率；RSSI -50/-70/-85 是经验分档，无官方标准。
- **软件入口**：`esp_wifi_set/get_max_tx_power` 的 0.25 dBm 定点单位与档位吸附（[8, 84] → 2-20 dBm），`wifi_ap_record_t.rssi` 的「可为正」与 13/16+3/16 定点 EMA。
- **一个再确认的类比边界**：dB 与十六进制的共同点是「对数刻度压缩数量级、把大数变可读」，差异是 dB 底数为 10 且把乘法变加法——类比帮记忆，计算请回到公式。

下一章顺着发射功率这条线往下钻：一个比特从 MAC 层出发，经过调制（OFDM/QAM）、上变频、功率放大器到天线口的完整旅程——那也是「为什么速率越高发射功率越低」在 3.4.2 埋下的疑问的答案。见[[ch04-tx-chain|第四章：发射链路漫游]]。
