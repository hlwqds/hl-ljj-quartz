# WiFi 射频硬件入门（五）：接收链路与灵敏度

> [!info] WiFi 射频硬件入门系列 0. [[wifi-rf-hw|系列索引]]

> **第五章：接收链路与灵敏度**（当前章）
> 下一章：[[ch06-antenna-basics|第六章：天线入门]]

上一章的发射链路把比特调制成波形、放大、从天线推了出去；本章走反方向：天线里感生出来的是**微伏级的模拟波形**，信号、热噪声、邻居干扰泡在同一根导线上，接收链路的全部工作是「在噪声里把比特听回来」。发射拼的是「说得响」，接收拼的是「听得清」——两者考的科目完全不同。

软件类比先行：接收链路是一座**信号还原栈**。像协议栈的接收路径（PHY 校验 → 解码 → 拆分 → 交付上层），每一级只干一件事、并让下一级更好干；发射是层层包装，接收是层层拆包加纠错，互为镜像。本章回答三个问题：噪声的底在哪里、为什么避不开；灵敏度为什么**不是一个数**；以及「信号满格却上不了网」的完整因果链。

## 5.1 接收链路总览：发射的镜像

先把整条链画出来。对照上一章的发射方向（比特 → 调制 → 上变频 → PA → 天线），接收是逐级倒着走：

```text
[天线] → [带通滤波] → [LNA] → [下变频] → [AGC+ADC] → [解调/均衡] → [FEC] → 还原出的比特
  信号+噪声+干扰   │ 只留 2.4G   │ 低噪放大  │ 卸载波   │ 采样数字化 │  星座判决    │ 纠错
  一起进来         └──────────── 模拟域：定噪声下限 ─────────────┴──────── 数字域：从这里开始
```

这张图不是教科书空想。ESP32-S3 数据手册对片内接收机的描述原文（§4.3.1.1）：接收机把 2.4 GHz 射频信号解调为正交基带信号，用**两个高速高分辨率 ADC** 转入数字域；为适应变化的信道条件，芯片集成了 **RF 滤波器、自动增益控制（AGC）、直流偏移消除电路与基带滤波器**——滤波、放大、变频、AGC、ADC 全在这一颗 SoC 里。ESP32 数据手册 §4.6.1 是几乎同款的一段。

每一级干什么、和发射侧如何镜像、软件类比是什么，一张表说清：

| 接收级 \| 职责 \| 发射侧的镜像（上一章） \| 软件类比                                                         |
| ------------------------------------------------------------------------------------------------------------ |
| 带通滤波 \| 只放 2.4G 频段进来，挡住带外噪声 \| 发射末级滤波：压住带外杂散 \| 入口白名单校验：先拦住无关流量 |
| LNA \| 第一级低噪声放大，定整机噪声下限 \| PA：末级功率放大 \| 第一级运放/低噪前端：整机底噪由它定           |
| 下变频 \| 卸掉 2.4 GHz 载波，搬到基带 \| 上变频：把基带搬上载波 \| 剥信封：先去传输层包装再解析载荷          |
| AGC + ADC \| 自动增益把信号装进 ADC 满量程 \| DAC：数字变波形 \| 自动量程：动态范围横跨百倍也装得下          |
| 解调/均衡 \| 星座判决，补偿信道造成的失真 \| 调制：画星座图 \| 音频 EQ：把被房间削掉的频段补回来             |
| FEC \| 用发射时加的冗余纠错还原比特 \| 信道编码：往里塞冗余 \| ECC 内存/纠删码：错几个也能还原               |

对称美一眼可见：发射链的瓶颈在**末级**（PA 的功率、线性与效率），接收链的瓶颈在**第一级**（LNA 的噪声系数）——一个把最难的事留在出口，一个把最难的事放在入口。为什么接收的胜负手在第一级，5.4 节用级联噪声公式给出定量理由。

按系列方法论把本章钉进四问下钻——现象层的「满格上不了网」，一路问到底就是电路层的前端元件与次序：

| 层次 \| 问什么 \| 本章答案                                                           |
| ------------------------------------------------------------------------------------ |
| Q1 现象 \| 为什么信号满格却上不了网 \| RSSI 只量分子（信号），SNR 才决定能跑哪档速率 |
| Q2 协议 \| 灵敏度怎么定义、怎么变化 \| PER 门限 + MCS 阶梯：灵敏度是一张表（5.3 节） |
| Q3 芯片 \| 片内接收机怎么分工 \| datasheet §4.3.1.1：RF 滤波+AGC+双 ADC 集成片内     |
| Q4 电路 \| 板上什么决定接收好坏 \| 前端次序「小损耗滤波 → LNA」，第一级定噪声下限    |

## 5.2 噪声是避不开的底

接收的一切痛苦都源于一件事：**噪声不用人发，它自己存在**。来源是热运动——任何温度高于绝对零度的导体里，载流子都在乱撞（约翰逊–奈奎斯特噪声），撞出来的噪声功率只取决于温度和带宽：

```text
噪声功率(dBm) = -174 + 10·log10(BW / 1 Hz)      （T = 290 K，匹配负载）
```

-174 这个锚点可以自己核一遍：k = 1.38×10⁻²³ J/K，T = 290 K，算出每 Hz 约 4.0×10⁻¹⁸ mW，取 10·log10 ≈ **-174 dBm/Hz**。这是 1 Hz 带宽里的热噪声功率——不是哪个芯片的参数，是物理学的底线。

把带宽项代进去，噪声底立刻成表。读者不妨拿计算器跟算一遍，以后看任何带宽都能心算：

| 带宽 BW \| 10·log10(BW) \| 噪声底 = -174 + 左列 \| 对应场景 |
| ----------------------------------------------------------- |
| 1 Hz \| 0 dB \| -174 dBm \| 公式的锚点                      |
| 1 MHz \| 60 dB \| -114 dBm \| BLE 信道宽度                  |
| 20 MHz \| 73 dB \| **-101 dBm** \| 11g/n HT20 主信道        |
| 40 MHz \| 76 dB \| -98 dBm \| 11n HT40 信道捆绑             |

类比：**带宽越宽，进来的噪声越多 = 采样窗口越大，采到的抖动越多**。做测量的人都知道，平均窗口拉长，随机抖动按功率累加进来——接收带宽从 1 MHz 开到 20 MHz，等于把观察窗口放大 20 倍，噪声功率也涨 13 dB。想听更弱的信号？把「窗口」开窄（降带宽）是最直接的物理手段。

三个推论必须钉死：

1. **噪声底只跟带宽与温度走，跟芯片贵贱无关**。20 MHz 信道里热噪声就在 -101 dBm 附近，它是物理学，不是采购预算。
2. **增益救不了噪声底**。放大器把信号与噪声一起放大，SNR 在放大前后不变（还会因放大器自身噪声再差一点）。后面 AGC 再努力，也抬不高「信号比噪声强多少」。
3. **干扰是在热噪声底之上再垫一层「人为噪声」**。微波炉、邻居 AP、USB3 泄漏都往这个底座上加料——这就是「信号满格却上不了网」的物理起点（5.5、5.6 节实证）。

### 接收机自己也要交「入场费」：噪声系数 NF

热噪声是「环境税」，接收机自己还要再交一笔：每级电路都会注入额外噪声，用**噪声系数 NF**（Noise Figure，dB）衡量——定义为输入端 SNR 与输出端 SNR 之比，理想接收机 NF = 0 dB，真实的要差几 dB。于是实用版噪声底公式是：

```text
实际噪声底(dBm) ≈ -174 + 10·log10(BW) + NF
```

NF 每差 1 dB，灵敏度就跟着差 1 dB——这是 5.4 节「前端决定一切」的伏笔：整机 NF 由第一级 LNA 主导（Friis 级联公式），而 5.3 节灵敏度表与热噪声底的差值里，藏着的正是「NF + 实现损耗」的合计。顺带一提：ESP32/S3 数据手册的射频表并未直接列出 NF 数值（**待核对**），入门阶段用灵敏度表对账即可，不必追这个数。

## 5.3 SNR 与灵敏度：不是一个数

### 1. SNR 与「有效位」类比

SNR（信噪比）= 信号功率 − 噪声功率，单位 dB。软件类比：**ADC 的有效位（ENOB）**——标称 12 位的 ADC，噪声一大实际只剩 9 位可用；datasheet 写「12 bit」，工程上关心的是「有几位是真的」。接收也一样：**「信号多强」不重要，「信号比噪声强多少」才重要**。信号 -80 dBm 在安静的 -101 dBm 底噪上是 21 dB 的好 SNR；在被干扰抬到 -85 dBm 的底噪上只剩 5 dB，勉强活着。

### 2. 灵敏度的定义：PER 门限

灵敏度 = **在规定误包率（PER）下仍能接收的最小信号电平**。ESP32-S3 数据手册把测试条件写得明白（§6.1.2，表 6-4 前的说明）：RX 测试的 PER 门限，**802.11b 为 8%，802.11g/n 为 10%**；射频在天线端口直接测量，供电 3.3 V、环境温度 25 °C。为什么按「包」不按「比特」：WiFi 以帧为单位，FEC 之后仍错一个比特，整帧作废等重传——类比 UDP 报文，一个比特错整个报文就扔。

### 3. 灵敏度表：同芯差 27 dB

ESP32-S3 的灵敏度阶梯（典型值，datasheet v2.2 表 6-4）：

| 模式 \| 速率/MCS \| 灵敏度 (typ, dBm) |
| ------------------------------------- |
| 802.11b DSSS \| 1 Mbps \| -98.4       |
| 802.11b \| 11 Mbps \| -88.6           |
| 802.11g OFDM \| 6 Mbps \| -93.2       |
| 802.11g \| 54 Mbps \| -76.5           |
| 11n HT20 \| MCS0 \| -92.6             |
| 11n HT20 \| MCS3 \| -85.0             |
| 11n HT20 \| MCS7 \| -74.2             |
| 11n HT40 \| MCS0 \| -90.0             |
| 11n HT40 \| MCS7 \| **-71.4**         |

（HT20 的 MCS1/2/4/5/6 介于 -91.0 与 -75.8 之间单调排列，全表见 datasheet。）ESP32 经典款的对应值（datasheet v4.8 表 5-6）：11b 1M **-98**、11g 54M **-75**、HT20 MCS0 **-93**、MCS7 **-73**、HT40 MCS7 **-70** dBm——两款芯片同一量级、同一规律。

「灵敏度不是一个数」现在有了数字证据：同一颗 ESP32-S3，最灵敏的 -98.4 dBm 与最迟钝的 -71.4 dBm 差 **27 dB——五百倍的功率**。原因在调制：11b 低速率用扩频（DSSS 处理增益），星座点稀疏，信号淹得深也能捞回来；MCS7 用 64-QAM，64 个星座点挤在一起，错一点就判到邻居家，必须高 SNR 伺候。

### 4. 拿噪声底对账：所需 SNR 的近似账

把 5.2 的噪声底和灵敏度表相减，每档调制「要多少 SNR」就自己冒出来了：

| 场景 (ESP32-S3) \| 灵敏度 \| 对应带宽噪声底 \| 差值 ≈ 所需 SNR |
| -------------------------------------------------------------- |
| 11b 1 Mbps \| -98.4 dBm \| -101 dBm (20M) \| 约 2.6 dB         |
| 11n HT20 MCS0 \| -92.6 dBm \| -101 dBm (20M) \| 约 8.4 dB      |
| 11n HT20 MCS7 \| -74.2 dBm \| -101 dBm (20M) \| 约 26.8 dB     |
| 11n HT40 MCS7 \| -71.4 dBm \| -98 dBm (40M) \| 约 26.6 dB      |

（真实接收机自身还有几 dB 噪声系数加在底座上，所以解调器实际需要的 SNR 比表中差值再低一些——这笔账看量级即可，别较真到小数点。）这张表解释了两件日常事：**信号变差时不是立刻断网，而是先降速**——速率自适应就是在灵敏度阶梯上找「当前 SNR 撑得住的最高一级」（第十六章对照路由器后台做实验）；以及**低速率=传得远**的硬件根据——极端如 S3 的 BLE 125 kbps coded PHY，灵敏度低至 **-104.5 dBm**（PER 30.8% 口径，出处同表 6-4），比 WiFi 最低速率还再低 6 dB：速率压到底、冗余拉满，换来的就是可听下限的继续下探。

另外注意 datasheet 的测试条件是**天线端口直测、理想环境**；实际板子有匹配损耗与失配，现场比表值再差几个 dB 属正常，别把 datasheet 值当现场承诺。

## 5.4 LNA 与「前端决定一切」

### 1. Friis 级联噪声公式：第一级为什么是胜负手

接收链是一串级联的模块，每级都有自己的噪声。整机噪声因子由 Friis 级联公式（概念级）给出：

```text
F_total = F1 + (F2 - 1)/G1 + (F3 - 1)/(G1·G2) + …
```

F 是各级噪声因子，G 是各级增益。看结构就够了：**只有第一项不带除号**——后面每一级的噪声贡献，都被它前面攒下的增益「除掉」了。只要第一级增益 G1 够大，整机噪声就几乎等于第一级的噪声。这就是「前端决定一切」的定量版本。

类比回到**第一级运放/低噪前端**：做过传感器调理的人都知道，整条模拟链路的底噪由第一级仪表放大器决定，后面级数再多、增益再大，只是把「已经被污染的信号」继续放大。耳机里听到的沙沙声来自第一级，不是末级功放。

### 2. 为什么滤波器不放在 LNA 前面省噪声

常见错觉：先滤波再放大，把噪声滤掉不是更好？不行——前置的带通滤波器是无源有损耗器件，插在 LNA 之前的每 1 dB 插损会 1:1 变成整机噪声系数的恶化（衰减量直接加进 F1 的位置）。所以链路次序铁律是：**小损耗滤波 → LNA → 大量后续处理**。入口那个滤波器只为挡带外大干扰（2.4G 之外的世界），指望它「滤噪声」是错位的——热噪声在带内，滤不掉。

### 3. LNA 与 PA 的对称美

| 维度 \| PA（发射末级） \| LNA（接收第一级）                    |
| -------------------------------------------------------------- |
| 位置 \| 链路最后一级 \| 链路第一级                             |
| 核心指标 \| 输出功率、线性度、效率 \| 噪声系数、增益           |
| 失败模式 \| 带外杂散、EVM 恶化 \| 噪声劣化 → 灵敏度直接掉      |
| 设计矛盾 \| 效率 vs 线性度 \| 增益 vs 噪声 vs 功耗             |
| 软件类比 \| 总线驱动器：把信号推上长线 \| 前端运放：定整机底噪 |

一颗 ESP32 上这对镜像共用一个射频口：ESP32 数据手册 §2.2 引脚定义里，**LNA_IN 的描述就是「RF input and output」**——收发复用同一引脚。为什么能复用、什么时候需要外接 FEM（带收发开关与独立 LNA/PA 的前端模组），第十章展开；这里记住入口即可。

## 5.5 RSSI 到底是什么

### 1. esp_wifi 的 rssi：一手证据

软件工程师摸得到的「接收质量」入口就是 RSSI。IDF 侧的取法（本机 ESP-IDF v6.0.2 源码）：

```c
wifi_ap_record_t ap;
esp_wifi_sta_get_ap_info(&ap);   // esp_wifi.h：「Get information of AP to which
                                 // the device is associated with」
printf("rssi=%d dBm\n", ap.rssi);
```

字段定义原文（`esp_wifi_types_generic.h`，`wifi_ap_record_t`）：

```c
int8_t  rssi;   /**< Signal strength of AP. Note that in some rare cases
                     where signal strength is very strong, RSSI values
                     can be slightly positive */
```

三个可读出的事实：它是**有符号 8 位、以负值为主**的量，按 **dBm 语义**使用；IDF 全栈拿它比大小（扫描结果按 `WIFI_CONNECT_AP_BY_SIGNAL` 排序、快速扫描按它设门限）；快速扫描的门限字段注释写明 **缺省 -127**（`threshold.rssi`，Defaults to -127 if set to >= 0）——-127 当「不设门限」的哨兵值，恰好也旁证了它的量纲：比任何真实 dBm 读数都低。

「近似」关系要说透：RSSI 是芯片对**成功解调的帧**（含 beacon）做的功率估计，标定成 dBm。它天生有两个盲区——强干扰下收不到帧时读数不刷新（RSSI 无法告诉你噪声多高）；标定有批次与频段偏差（头文件都承认极强信号可能读出 +1）。

### 2. 为什么不同设备的 RSSI 不能直接比

802.11 标准并没有统一 RSSI 的标度与原点（有的厂商内部是 0~255 的指数、有的映射成 dBm、手机信号格更是厂商自定义的分段）。所以「A 设备 -60、B 设备 -70」不构成「A 处信号更好」的证据——两把刻度不一样的尺子，读数没有可比性；**同一台设备、时间序列上的相对变化**才有严格意义。这是业界通识，而 ESP32 头文件那句「可能略为正值」正是标定差异存在的小证据。

### 3. 共存插曲：另一种「听不见」

接收质量的天敌不止噪声。ESP32 系列只有一套 RF，BLE/BT 与 WiFi 分时共用——esp_coex.h 的枚举注释原文（v6.0.2 源码）：

```c
ESP_COEX_PREFER_WIFI = 0,  /*!< Prefer to WiFi, WiFi will have more
                                 opportunity to use RF */
```

「用 RF 的机会」是字面意义的时隙分配。对发射是排队；对接收是**整段帧窗被让出去——BT 占用 RF 的那些时间里，WiFi 该收的帧根本没进接收机**。这不抬噪声底，但等效丢包、PER 变差。第十四章专门展开；BOX-3 的 BLE+WiFi 应用就活在这个机制下（[[ch16-wifi-events|BOX-3（十六）]] 讲连接事件层，本系列第十四章讲共存层）。

### 4. 「信号满格上不了网」的完整解释链

把本章串成一条因果链：

```text
RSSI 好（信号功率够）
   ≠ SNR 好（干扰抬了噪声底 / 共存分走了接收窗）
   ≠ 可用速率好（速率自适应降 MCS、重传吃掉空口时间 → 测速塌）
```

| 症状 \| 卡在哪一环 \| 修法方向                                              |
| --------------------------------------------------------------------------- |
| 满格、测速低 \| SNR：底噪被干扰抬高 \| 换信道、挪走干扰源、看 5G            |
| 满格、ping 抖/丢包 \| 共存或竞争：没轮到你听 \| 复现时关 BLE 对照、错开设备 |
| 格数低但能用 \| RSSI 低而 SNR 尚可 \| 正常状态，别急着「加放大器」          |
| 格数低且测速塌 \| RSSI 与 SNR 双低 \| 缩距离/换天线（下一章的主题）         |

满格只说明「分子」（信号功率）够大；上不了网是「分母」（噪声+干扰+抢不到接收窗）出了问题。5.6 节在厨房里实证这条链。

## 5.6 实践观察（待真机验证）

> [!warning] 待真机验证
> 以下两个实验的步骤与预期均为设计稿，BOX-3 到货后实测回填数据；不预设具体读数。

### 实验一：RSSI 同源对照（约 10 分钟）

1. ESP32（STA 模式）连上家里 2.4G AP，在任意已连接的工程里加一段每 2 秒读取打印的循环（API 见 5.5 节代码，编译依据 `esp_wifi.h`/`esp_wifi_types_generic.h` 原型核实）。
2. 手机 WiFi 分析仪 App 紧挨 ESP32 放置，观察**同一个 AP** 的 RSSI。
3. 挪动一两米、换个握持方向，再各记录几组，共约 10 组。
4. 预期：两者**趋势与量级一致**（同向涨跌、同在 -40 ~ -70 dBm 这类量级），但不必逐 dB 相等——App 读的是手机 WiFi 芯片，esp 读的是 ESP32，标定不同（5.5 节）。差值应近似恒定（偏移型偏差）；若差值忽大忽小，先怀疑位置与天线姿态变了。
5. 结论口径：RSSI 的绝对值只在**同一台设备内**可比；跨设备只比趋势。

### 实验二：微波炉毁 SNR 实证（约 15 分钟）

器材：微波炉、一杯水（**必须放**——空载运行伤磁控管）、ESP32 跑 `examples/wifi/iperf`（本机 IDF 仓库实测存在该示例）、手机分析仪 App。

| 步骤 \| 操作 \| 记录什么                                             |
| -------------------------------------------------------------------- |
| 1 \| 基线：炉关，跑 iperf 60 s \| RSSI 均值、吞吐、丢包率            |
| 2 \| 炉内放水，最高档，同位置再跑 60 s \| 同上三项                   |
| 3 \| （可选）手机 App 看 2.4G 整段底噪变化 \| 信道图是否整体「变亮」 |

预期与解释：**RSSI 几乎不动（±1~2 dB），吞吐显著塌、丢包率上升**。微波炉泄漏是 2.4G 频段内的宽带噪声（磁控管工作在 2.45 GHz 附近，业界通识）——它不碰分子（信号功率，RSSI 测的），专抬分母（噪声功率）：SNR 掉 → 解调器沿灵敏度阶梯降 MCS → 重传吃掉空口时间。这就是 5.2 的公式和 5.3 的阶梯表在厨房里的样子，也是「满格 ≠ 能用」最家庭友好的实证。

## 5.7 常见误区表与小结

| 误区 \| 错在哪 \| 正确姿势                                                                                     |
| -------------------------------------------------------------------------------------------------------------- |
| 「信号满格 = 网一定好」 \| RSSI 只量信号功率，不含噪声与干扰 \| 看 SNR/吞吐/重传，格数只当粗定位               |
| 「灵敏度 = -98 dBm 一个数」 \| 同一颗芯片按 MCS/带宽差 27 dB（表 6-4） \| 灵敏度是一张表，问「哪一档的灵敏度」 |
| 「选模块取灵敏度绝对最小值」 \| 最小值出自 1M/11b，正常流量根本不在那档速率 \| 看常用 MCS（如 MCS7）的灵敏度   |
| 「加放大器能救弱信号接收」 \| 放大器信号噪声一起放大，SNR 不变还更差 \| 接收侧要低噪前端（LNA），不是增益      |
| 「不同设备 RSSI 可以比大小」 \| 802.11 未统一 RSSI 标度，各厂标定不同 \| 同设备时间序列自比才有效              |
| 「微波炉一开是信号被屏蔽」 \| 通常是 RSSI 不掉、底噪抬——坏的是 SNR 不是信号 \| 做 5.6 实验二，看吞吐而不是格数 |
| 「AGC 能把淹没的信号捞回来」 \| AGC 调的是量程，信号低于噪声底就没了 \| 先看噪声底账（5.2），再谈增益          |

**小结**：

- 接收链路是发射的镜像、一座**信号还原栈**：天线 → 带通滤波 → LNA → 下变频 → AGC+ADC → 解调/均衡 → FEC → 比特；发射的胜负手在末级 PA，接收的胜负手在第一级 LNA。
- 噪声底 = **-174 dBm/Hz + 10·log10(BW)**，来自载流子热运动；20 MHz ≈ **-101 dBm**、40 MHz ≈ -98 dBm。它是物理底线：增益救不了，芯片贵贱无关；干扰是在这底座上再加的人为噪声。
- **灵敏度不是一个数**：ESP32-S3 从 -98.4 dBm（11b 1M）到 -71.4 dBm（HT40 MCS7）差 27 dB（datasheet v2.2 表 6-4，PER 门限 11b 8%、11g/n 10%）；信号变差先降速后断网，速率自适应就是在这张阶梯表上找级。
- Friis 级联公式说明**整机噪声系数 ≈ 第一级的**：LNA 就是接收链的「第一级运放」，它之前每 1 dB 插损都 1:1 变成灵敏度恶化——所以前端小损耗滤波、LNA 紧随其后是铁律次序。
- RSSI 是按 dBm 语义的信号功率估计（`esp_wifi_sta_get_ap_info()` → `wifi_ap_record_t.rssi`，int8_t，门限哨兵 -127），它**只量分子不量分母**：满格 ≠ SNR 好 ≠ 可用速率好；共存分走 RF 时隙（esp_coex「more opportunity to use RF」）是另一种听不见。

下一章换主角：这一章所有 dBm 的起点都是那根天线——RSSI 在它身上开始衰减，SNR 在它身上决定入口。天线是性价比最高的硬件升级，见[[ch06-antenna-basics|第六章：天线入门]]。
