# WiFi 射频硬件入门（十）：射频前端 FEM

> [!info] WiFi 射频硬件入门系列 0. [[wifi-rf-hw|系列索引]]
> 上一章：[[ch09-impedance-matching|第九章：阻抗与匹配]]
> **第十章：射频前端 FEM**（当前章）
> 下一章：[[ch11-crystal-clock|第十一章：晶振与时钟]]

一句话结论：**FEM（Front-End Module，射频前端模块）是 WiFi 芯片的「外接显卡/独立声卡」**。SoC 片内射频像核显与板载声卡，日常够用、省事、便宜；要大功率远距离高吞吐，就把 PA、LNA、收发开关、滤波器打包成一颗芯片外挂到天线旁边——性能上强度，代价是更贵的 BOM、更刁的电源和更难的布局。这就是「带外置 FEM 的板子贵且信号好」的全部因果。

本章按四问下钻：**Q1 现象**（信号好/差差在哪几 dB）→ **Q2 协议**（半双工 TDD 为什么逼出收发开关）→ **Q3 芯片**（FEM 四件套各自的关键参数）→ **Q4 电路**（一条发射/接收链路的完整 dB 账，BOX-3 到底有没有 FEM）。它继续站在电路层：[[ch18-esp32-wifi-lwip-integration|lwIP（十八）]] 讲驱动之上的软件栈，[[ch16-wifi-events|BOX-3（十六）]] 讲连接管理与事件——本章往下钻到天线旁边那颗芯片。

> [!note] 本章的证据口径
> 数值事实来自三类来源，文中逐一标注：厂商规格页（Skyworks SKY85331-11、Qorvo QPF4200，2026-08-28 官网核对）；乐鑫官方文档（ESP32-S3-WROOM-1/1U Datasheet v1.4，官网 PDF）；本地仓库与社区（`~/esp/esp-box` 硬件目录实测存在、esp32.com 官方论坛讨论）。凡标注「典型值示例」的数字是自洽的教学算例，不是任何具体产品的规格；标注「待核对」处需打开对应文档确认。

## 10.1 为什么要有 FEM：片内射频的物理极限

先回答「SoC 里不是已经有 PA 和 LNA 了吗，为什么还要外挂」。两个原因，一个物理、一个系统。

**物理原因一句话**：WiFi SoC 是数字 CMOS 工艺，而 CMOS 晶体管击穿电压低、衬底损耗大，做「高功率 + 高线性」的末级功放先天吃亏——高功率 PA 的主场在砷化镓（GaAs）这类化合物工艺。所以工程分界线很清晰：片内做「够用的 +20 dBm 级」，要「上强度的 +24 dBm 级以上」，外挂 FEM。

**系统原因**是第五章 Friis 公式的直接推论：级联链路的噪声系数由第一级主导，**前端决定系统性能**——发射端看末级 PA 的功率与线性，接收端看第一级 LNA 的噪声系数。SoC 把「够用」的收发放进片内；路由器这类要覆盖整层楼的产品，就得在天线旁边堆上更强的专用前端。第九章讲过天线附近那一小撮元件是匹配网络，本章讲天线附近的另一颗芯片：FEM。

### 类比总表：外接显卡的世界观

| 射频侧       | PC 世界对照            | 一句话共同点               |
| ------------ | ---------------------- | -------------------------- |
| SoC 片内射频 | 核显、板载声卡         | 能跑、省事、够日常用       |
| 外挂 FEM     | 独立显卡、独立声卡     | 要上强度就得外挂，贵且费电 |
| PA           | 扩音器的末级功放       | 决定「喊多响」             |
| LNA          | 高保真话放（话筒前放） | 决定「听得清不清」         |
| 收发开关     | 单车道桥的信号灯       | 同一通道分时复用           |
| 带通滤波器   | 只放行自己端口的防火墙 | 别人的频段一律挡在门外     |

这张表就是本章地图：四件套（PA/LNA/开关/滤波）在 10.2 逐个建档，10.3 连起来算账，10.4 讲开关为什么最「娇气」，10.5 讲怎么在真实板子上认出它们。

### 片内前端的真实水平：ESP32-S3-WROOM-1 实测口径

拿 BOX-3 上的模组当「无外挂 FEM」的标尺——ESP32-S3-WROOM-1/1U Datasheet v1.4 的模组框图里，SoC 与天线之间只有一个 RF 匹配网络，模组上再无其他射频器件；发射功率表（表 16）与灵敏度表（表 18）都标明是「模组天线口」的实测口径，也就是**片内前端的真实成绩单**：

| 项目                    | 数值      | 出处  |
| ----------------------- | --------- | ----- |
| 发射 802.11b @ 1 Mbps   | +20.5 dBm | 表 16 |
| 发射 11n HT20 MCS7      | +17.5 dBm | 表 16 |
| 发射 11n HT40 MCS7      | +17 dBm   | 表 16 |
| 灵敏度 802.11b @ 1 Mbps | -98.2 dBm | 表 18 |
| 灵敏度 11n HT20 MCS7    | -74.2 dBm | 表 18 |

两个读表要点，后面都要用到：

- **功率与灵敏度都必须连着速率口径读**：+20.5 dBm 是 1 Mbps 老 11b 的数字，到了 HT20 MCS7 只剩 +17.5 dBm——速率越高、调制越密，PA 越要「留余量防失真」，能给的功率越少。灵敏度同理：-98.2 dBm 换到 MCS7 就只有 -74.2 dBm，差了 24 dB。
- 同一份表的发射电流（表 12）：11b 满功率瞬间约 355 mA（模组实测口径），这是第十二章电源话题的伏笔。

## 10.2 FEM 四件套档案

### 1. PA：功率放大器，扩音器的末级

发射链路的最后一级放大，「喊多响」由它定。看规格书先抓三个数：增益、EVM 合格输出功率、P1dB。

| 参数          | 含义                               | 类比               |
| ------------- | ---------------------------------- | ------------------ |
| 增益          | 多少 dB 放大倍数，dB 相加直接算账  | 音量旋钮           |
| P1dB 压缩点   | 输出开始压不动的临界功率           | 失真前的最大音量   |
| EVM 合格输出  | 失真不超标时真正可用的功率         | 唱歌不破音的最大声 |
| Psat 饱和功率 | 压满的极限输出，指标好看但失真已爆 | 音量开满的破音状态 |

EVM（误差矢量幅度，第四章）衡量「发出去的星座点歪了多少」，习惯用 dB 表示：-35 dB 约等于 1.8%（对数换算是第三章的账）。**PA 的真实工作点是「EVM 合格输出功率」，不是 Psat**——这四个字的区别是 10.6 误区表的重灾区。

### 2. LNA：低噪声放大器，高保真话放

接收链路的第一级放大，「听得清不清」由它定。它赚的不是「把信号放大」这一点，而是第五章级联公式 `F_total = F1 + (F2 - 1) / G1 + ...` 的位置红利：**第一级的噪声系数和增益几乎决定整条链路的底噪**，所以它必须又低噪又放在最前面——和高保真系统里「话放定音质」一个道理。

| 参数           | 含义                          | 类比                 |
| -------------- | ----------------------------- | -------------------- |
| 增益           | 对天线来的微弱信号放大多少 dB | 话放的放大倍数       |
| 噪声系数（NF） | 自己掺多少噪声，越低越好      | 前级定整条链路的底噪 |
| 旁路模式       | 强信号时跳过放大，保护后级    | 大嗓门不用话放       |

旁路模式（bypass）是实用细节：信号强时 LNA 反而会把后级撑爆，FEM 允许把 LNA 短路掉，吃一点插损换不饱和——像大嗓门的人直接说话、不用话放。

### 3. 收发开关：半双工的方向阀

WiFi 收发不同时进行（10.4 展开），一根天线两个方向，中间必须有开关选路。SPDT（单刀双掷）在硬件里就是 `if (tx_enabled) 走PA; else 走LNA;`。

| 参数     | 含义                         | 类比             |
| -------- | ---------------------------- | ---------------- |
| 切换时间 | TX 转 RX 要几微秒，越快越好  | 信号灯变灯要快   |
| 插入损耗 | 导通也吃掉一点功率，dB 计损  | 过路口总要刹一脚 |
| 隔离度   | 关断方向漏过去多少，越大越好 | 关掉的门不能偷看 |

### 4. 带通滤波器：只放自己频段进门的保安

把 2.4 GHz 之外的信号挡在门外：既不让 5 GHz 的邻居串进接收链，也不让自己的谐波杂散漏出去惹法规（第十七章）。「双工器」不在此列——WiFi 是 TDD 分时制，用开关就够；双工器是 FDD 同时收发制（蜂窝 LTE）才需要的器件。

| 参数     | 含义                     | 类比             |
| -------- | ------------------------ | ---------------- |
| 通带插损 | 自己频段过闸也要交过路费 | 自家包也要查一遍 |
| 带外抑制 | 隔壁频段被压多少 dB      | 防火墙默认拒绝   |
| 通带范围 | 盖住 2.4 GHz 全部信道    | 放行端口别写太窄 |

### 5. 真实 FEM 长什么样：两家旗舰规格对照

四件套通常集成在一颗 3×5 mm 级的屏蔽 QFN 里。两家代表型号（2.4 GHz、面向路由器/网关）：

| 参数           | SKY85331-11（Skyworks）         | QPF4200（Qorvo）                |
| -------------- | ------------------------------- | ------------------------------- |
| 定位           | 2.4 GHz 802.11ax 高功率 FEM     | 2.4 GHz Wi-Fi 7 FEM             |
| 集成内容       | PA、LNA（可旁路）、开关、检测器 | PA、LNA（可旁路）、稳压、检测器 |
| TX 增益（typ） | 33 dB（typ）                    | 33 dB（typ）                    |
| 线性输出功率   | +24 dBm @ -35 dB DEVM（MCS9）   | 待核对（完整表）                |
| LNA 增益       | 15 dB                           | 15.5 dB                         |
| LNA 噪声系数   | 待核对                          | 2.1 dB（typ）                   |
| 接收旁路损耗   | 待核对                          | 6 dB（typ）                     |

（出处：Skyworks、Qorvo 官网产品页，2026-08-28 核对；标「待核对」处需查完整 datasheet。）

SKY85331-11 的产品页还给了两条后面要用的数：供电 5 V 时典型电流 **470 mA**（发射瞬间），以及集成对数功率检测器、可做约 20 dB 动态范围的闭环功控——功率输出不再靠「开了多大声」估计，而是拿实测回读。QPF4200 的接收路径还带 25 dB 的 5 GHz 抑制（同页），滤波器四件套角色直接体现在指标里。

## 10.3 一条完整链路的 dB 账：从 SoC 到 EIRP

第三章说过 dB 是这个世界的十六进制，这里把第三、四、五、九章的账连成一条线算给你看。**所有未标出处的数字都是「典型值示例」**——自洽的算例，不是某块具体板子的规格。

### 1. 发射账：带 FEM 的路由器

| 环节           | 数值    | 说明                          |
| -------------- | ------- | ----------------------------- |
| SoC 射频输出口 | -9 dBm  | 示例：由 +24 - 33 反推        |
| FEM PA 增益    | +33 dB  | SKY85331-11 typ               |
| FEM 额定输出   | +24 dBm | -35 dB DEVM @ MCS9            |
| 板级走线损耗   | -1 dB   | 示例：匹配与走线              |
| 天线增益       | +3 dBi  | 示例：外置天线                |
| EIRP 合计      | +26 dBm | 约 400 mW；法规限值见第十七章 |

```text
EIRP = SoC 输出 + FEM 增益 - 走线损耗 + 天线增益
     = -9 dBm + 33 dB - 1 dB + 3 dBi
     = +26 dBm   （约 400 mW，典型值示例）
```

三个读账要点：

- **SoC 只出 -9 dBm 这种「耳语级」驱动**：放大全部交给 FEM，这正是「外接显卡」的分工——SoC 的射频口只负责把调制做干净，力气活外包。
- **FEM 的额定输出 +24 dBm 已经扣掉它内部开关的插损**（标称在 ANT 口测得），所以表里没有单独一行「开关插损」。
- **+26 dBm 不是想发就发**：各国法规对 2.4 GHz 的 EIRP 有上限，FEM 给的余量会被合规配置钳回来——限值与测试口径是第十七章的主题。

### 2. 对照组：无 FEM 的 ESP32

| 环节               | 数值       | 说明                  |
| ------------------ | ---------- | --------------------- |
| 片内 PA 天线口输出 | +20.5 dBm  | 11b 口径（模组表 16） |
| PCB 天线增益       | +2 dBi     | 示例：PCB 天线典型    |
| EIRP 合计          | +22.5 dBm  | 约 180 mW             |
| 与 FEM 板差距      | 约 -3.5 dB | 高速率口径差距更大    |

**「带外置 FEM 的板子信号好」的发射端账**：11b 低速口径下差距只有 3.5 dB；但更公平的高阶调制对照是——模组 HT20 MCS7 只有 +17.5 dBm（表 16），SKY85331-11 在更密的 MCS9 上仍有 +24 dBm，差距拉到 6~7 dB 量级（11n 与 11ax 口径不完全对齐，精确差值待核对）。速率越高，片内 PA 越早「没劲」，FEM 的优势越大。

### 3. 接收账：LNA 的收益不写在增益里

| 环节            | 数值     | 说明                     |
| --------------- | -------- | ------------------------ |
| 天线收到信号    | -75 dBm  | 示例：MCS7 可用边缘附近  |
| 天线增益与线损  | +1 dB    | 示例：+2 dBi - 1 dB      |
| FEM LNA 增益    | +15 dB   | SKY85331-11 typ          |
| 交给 SoC 的电平 | -59 dBm  | 放大本身不改善 SNR       |
| 真正的收益      | 约 +2 dB | 假设片内 NF 4 dB，待核对 |

关键在最后一行：LNA 的 15 dB 增益只是把 -74 抬到 -59，**信号和噪声一起抬，SNR 不变**；真正的收益来自级联公式——第一级 NF 从片内前端的假设值 4 dB 换成 FEM 的 2.1 dB，整链路噪声系数跟着降约 2 dB，等效灵敏度就好约 2 dB。这笔账换算成体感：发射端 +6 dB 加接收端 +2 dB，链路预算 +8 dB，按自由空间每 6 dB 距离翻倍的规律（第十五章实测验证），**同一速率的可用距离大约翻 2.5 倍**——这就是「贵几美元 FEM，信号好一大截」的全部数学。

## 10.4 半双工与开关时序：谁在拨方向阀

### 1. WiFi 为什么必须有开关

软件工程师最容易带入以太网的直觉，所以先摆对照：

| 对比项         | 以太网 100BASE-TX            | WiFi 2.4 GHz             |
| -------------- | ---------------------------- | ------------------------ |
| 传输介质       | 两对双绞线，收发各一对       | 一段共享频谱，空气       |
| 双工方式       | 全双工，收发同时进行         | 半双工，收发分时进行     |
| 冲突处理       | 交换机逐端口交换，基本无冲突 | CSMA/CA，先听再说加退避  |
| 需要收发开关？ | 不需要，物理通道本来就分开   | 必须，还要微秒级完成切换 |

以太网全双工靠的是**物理通道分开**——收和发各占一对线，同时进行互不干扰。WiFi 没这个奢侈：2.4 GHz 就一段频谱、一根天线，同一个信道上要么发要么收（TDD，时分双工），还叠加 CSMA/CA 的「大家轮流讲话」。于是物理上必然存在一个问题：**天线后面这一条路上，PA 的输出口和 LNA 的输入口不能同时接上去**——PA 发射时若 LNA 还挂在线上，大功率直接把接收端烧了；反过来 PA 常挂线上，它自己的噪声就把微弱的入射信号淹了。方向阀（收发开关）因此而生：TX 时隙接 PA、断 LNA；RX 时隙反之。

### 2. PA_EN/LNA_EN：GPIO 世界观的接入点

FEM 的开关和放大器由两个使能引脚控制，语义就是电平高低：

```text
TX 时隙：PA_EN = 1，LNA_EN = 0   （扩音器开，话放关）
RX 时隙：PA_EN = 0，LNA_EN = 1   （话放开，扩音器关）
空闲：   PA_EN = 0，LNA_EN = 0   （全关，省电）
```

这就是软件工程师最熟悉的「外设使能脚」世界观——和 RS-485 收发器的方向脚 DE/RE 一个套路：同一条总线，方向脚说了算。真正的问题不在「怎么驱动」，而在「**什么时候**翻转」：WiFi 每个包的收发边界以 802.11 规定的 SIFS（2.4 GHz 为 10 μs，标准值）为节拍，方向切换必须塞进这些微秒级缝隙里，而且必须与实际发包精确同步——发早了信号被掐头，翻晚了烧接收端。

结论也和软件世界同构：**时序关键的东西必须下沉到硬件**。路由器 SoC 的 WiFi MAC 硬件在每个包边界自动翻转这些脚；通用 CPU 上跑的软件（哪怕实时 GPIO 直写寄存器）既不知道包何时发出，也赶不上 10 μs 的节拍——相当于用轮询去赶硬件中断。

### 3. ESP32 为什么不外挂：生态的定位差异

把上面的时序结论套到乐鑫生态，就明白了两种产品哲学：

- **乐鑫**：把「够用的前端」（片内 PA/LNA/收发开关）做进 SoC，配合模组把天线和匹配也做好——软件工程师买一颗模组就得到完整可用的射频，收发切换由片内硬件自动完成，软件完全无感。
- **路由器厂**：SoC 只出「耳语级」驱动，外挂 FEM 上强度，换取覆盖整层楼的链路预算。

一个佐证：ESP-IDF 的 WiFi 组件没有外置 PA/FEM 的收发控制接口（与天线选择相关的 GPIO API 只用于外接天线选择开关，见 ESP-IDF 文档），esp32.com 官方论坛上「ESP32 外挂 FEM」的讨论也卡在「驱动不暴露收发时序钩子」这一步。所以在 ESP32 生态里，想加强度，官方路径是**选片内前端更强/带更好天线的模组**，而不是自己焊 FEM。

### 4. 一根天线上挤着 WiFi 和蓝牙：BOX-3 的现场

BOX-3 的模组 ESP32-S3-WROOM-1 只有一根天线，WiFi 和蓝牙（BLE）都从它走。模组 datasheet 明说：Wi-Fi 与蓝牙共享同一根天线的**片内共存机制**——翻译成本章语言：片内那套收发开关/路径选择还兼职「WiFi 与 BT 的分时调度」，让两种无线电在同一根天线上轮流上镜。这是第十四章（干扰与共存）的主菜，BOX-3 的 BLE+WiFi 配置在那里用共存视角重讲；软件层的连接管理事件见[[ch16-wifi-events|BOX-3（十六）]]。

## 10.5 选购与识别：屏蔽罩下面那颗芯片

### 1. 规格书里挑什么

| 要挑的参数    | 怎么挑                 | 为什么                          |
| ------------- | ---------------------- | ------------------------------- |
| 频段与制式    | 2400~2500 MHz、11ax    | 5 GHz FEM 装不上 2.4 GHz 板     |
| 线性输出功率  | 标了 EVM 条件的 dBm 值 | Psat 不算数，EVM 合格才是工作点 |
| TX 增益       | 与 SoC 驱动电平配平    | 推不到额定输出就白搭            |
| LNA 增益与 NF | 15 dB 上下、2 dB 上下  | 接收端一半收益在这              |
| 供电与电流    | 电压轨与峰值电流先看好 | 5 V 470 mA 不是小板能养的       |

最后一行展开就是「贵」的账单：SKY85331-11 那类高功率 FEM 要 5 V 轨、发射瞬间 470 mA（约 2.4 W），3.3 V 小板根本供不起（第十二章讲 WiFi 的电源性格）；还要 50 Ω 走线、完整地平面和屏蔽罩伺候（第十三章）；功率上去了，认证测试（第十七章）也更贵。**BOM、电源、布局、认证四张账单，就是「带外置 FEM 的板子贵」的全部构成**——而它们换来的，是 10.3 算出来的那几 dB 和翻倍的覆盖。

### 2. 板子上怎么认出它：零装备观察实验

不用拆机就能看清楚自家路由器里的 FEM，全程浏览器：

1. 翻路由器底面标签，找 **FCC ID**（形如「厂商代码-产品代码」两段）。
2. 到 FCC 设备授权数据库（fcc.gov 的 FCC ID Search）查这个 ID，或直接用搜索引擎搜「FCC ID + 编号」。
3. 打开该设备文档里的 **Internal Photos（内部照片）**：主板上天线馈点或 IPEX 座附近、屏蔽罩边缘，那颗 3×5 mm 上下的方形多脚芯片就是 FEM 的标准体位。
4. 照片里若有**丝印**（芯片顶上的短代号），可反查型号：厂商 datasheet 附录一般有「schematic marking」对照表，拿丝印去 Skyworks/Qorvo 官网搜即可对号入座。

这就是「屏蔽罩下面那颗芯片」识别法：**位置（天线旁）+ 封装（3×5 mm 屏蔽 QFN）+ 丝印（短代号反查）**三连。FEM 通常还是板上发射时最热的芯片之一——470 mA 不是白吃的。

### 3. BOX-3 有没有 FEM：判定与证据链

结论：**BOX-3 主板上没有外置 FEM，射频全靠片内前端**。证据链：

1. BOX-3 用 ESP32-S3-WROOM-1（N16R8V），器件清单见[[ch1-quick-start|BOX-3（一）]]的到货验货表。
2. 该模组的 datasheet 框图（v1.4）里，SoC 与天线之间只有 RF 匹配网络——模组内无 PA/LNA/开关等外置器件。
3. 官方硬件仓库在本地已克隆：`/home/huanglin/esp/esp-box/hardware/`（实测存在），其中 BOX-3 主板原理图为 `SCH_ESP32-S3-BOX-3_V1.0/SCH_ESP32-S3-BOX-3-MB_V1.1_20230808.pdf`（2023-08-08 版）。该 PDF 本工具环境读不了，**待核对**：打开后确认 RF 部分只有「模组天线口到天线/馈点的走线」，无 FEM 器件位号。

第 1、2 条已足够支撑「模组内无 FEM」的结论；主板再外加 FEM 的做法在这种「模组即完整射频」的设计里没有先例动机（驱动时序也过不去，见 10.4.3），故整体判定置信度高，最终以原理图人工核对为准。

## 10.6 常见误区

| 常见误区                      | 错在哪                          | 正确姿势                       |
| ----------------------------- | ------------------------------- | ------------------------------ |
| FEM 只放大发射                | 它收发都管，LNA 管接收          | 链路预算要收发两头一起算       |
| 两颗 PA 并联功率翻倍          | 直接并联阻抗全乱，会互相抵消    | 功率合成要用合路器，先亏 3 dB  |
| 增益 33 dB 就能出 33 dBm      | 到额定输出时已压缩，失真超标    | 看标了 EVM 条件的线性输出      |
| 给 ESP32 外挂 FEM 就变强      | 收发切换时序软件跟不上          | 官方路径是选片内前端更强的模组 |
| 灵敏度 -98 dBm 所以很远也能连 | 那是 1 Mbps 的口径              | 灵敏度必须连着速率一起读       |
| 2.4 GHz 也该配双工器          | WiFi 是 TDD，收发分时，开关就够 | 双工器是 FDD 蜂窝的方案        |

逐条快评：第一条源于以太网全双工直觉；第二条忘了功率合成需要相位一致与阻抗匹配，合路器每路理论上先损失 3 dB；第三条混淆了「增益」与「能线性输出的功率」；第四条是时序问题不是焊接问题；第五条忘了灵敏度是速率的函数（-98.2 对 -74.2，差 24 dB）；第六条把 FDD 的器件错装到 TDD 的系统上。

## 10.7 小结

- **FEM 是 WiFi SoC 的外接显卡**：PA 管喊多响（EVM 合格输出 +24 dBm 级）、LNA 管听多清（前级定底噪，NF 约 2 dB）、收发开关管半双工方向（微秒级切换）、带通滤波器当只放自家频段的保安（带外抑制数十 dB）。
- **dB 账连成线**：EIRP = SoC 驱动 + FEM 增益 - 走线损耗 + 天线增益；示例链路 +26 dBm 对无 FEM 的 ESP32 +22.5 dBm，高阶调制口径差距拉到 6~7 dB；接收端 LNA 赚的是级联噪声的位置红利，不是增益本身。
- **半双工是开关存在的根因**：以太网全双工靠物理通道分开，WiFi 一根天线收发分时，方向阀必须由 MAC 硬件在 SIFS（10 μs）节拍内拨动——软件 GPIO 赶不上，这就是 ESP32 片内集成而不外挂的底层原因。
- **BOX-3 无外置 FEM**：模组框图与 datasheet 实测口径已证；主板原理图 PDF 路径已留，待人工核对收尾。
- 贵的账单：BOM + 5 V/470 mA 电源 + 布局屏蔽 + 认证，换来的是发射 6 dB、接收 2 dB 与约 2.5 倍的可用距离（典型值示例口径）。
