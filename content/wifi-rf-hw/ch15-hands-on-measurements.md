## 15.1 实验哲学：零仪器的边界与记录纪律

先立总类比：**零仪器测量 = 只用日志和内置 metrics 排障**。后端工程师没有火焰图和示波器时，靠进程自带计数器、结构化日志、上下游交叉验证也能定位大部分问题——WiFi 芯片同样自带一套免费遥测：RSSI 就是它的性能计数器，扫描列表就是它的 `netstat`，ping 就是它的探活。先榨干免费遥测，剩下的再谈买仪器（15.7）。

零仪器的能与不能，一张表划清边界：

| 能测           | 靠什么             | 边界在哪                 |
| -------------- | ------------------ | ------------------------ |
| RSSI 相对变化  | 扫描 API、手机 App | 标定各异，只能同设备自比 |
| 信道邻居分布   | 三方扫描对照       | 看不见非 WiFi 占用者     |
| 延迟与丢包     | ping、日志时间戳   | 受系统调度抖动影响       |
| 功率绝对值/SNR | 需仪器             | 只能用吞吐、丢包间接推   |

（RSSI 跨设备不可比是第五章 5.5 的结论；「看不见非 WiFi 占用者」是第十四章的档案——微波炉和 USB3 不说 802.11 语言，永远不出现在扫描列表里。）

记录纪律五条，**与压测纪律同款**，五个实验通用：

1. **一轮只改一个变量**：距离、姿态、遮挡、干扰源，一轮动一样，其余全固定并在表里注明；
2. **同设备自比**：绝对值没有意义（标定差异），差值和趋势才有意义；
3. **多读取中位**：RSSI 是 EMA 滤波后的均值（`rssi_avg = rssi_avg × 13/16 + new × 3/16`，至少 100 ms 才刷新一次，ESP-FAQ 口径），每个测点停 10 秒、读 5 次取中位，别拿第一眼读数填表；
4. **记录环境**：时间、有人走动、门窗开闭、板子姿态——多径环境随时间漂移，两轮数据隔了一小时就没法对比；
5. **当场填表**：模板都在各节里，现场填，别靠回忆补。

两个本章核心类比先挂出来，后面各节反复用：**RSSI 距离衰减 = 信号强度对数账**（距离每翻一倍，账本上记一笔 −6 dB，实验二是拿真机读数去对账）；**方向图手绘 = 压测采样**（绕一圈记 12 个点，就是对「角度」这个维度做性能采样，采样密度决定能分辨多窄的凹陷）。

## 15.2 实验一：信道扫描与占用——三个独立观察者

**目的**：把第二章的信道地图和第十四章「换到最空信道」的对策落到实测；同时验证三个互相独立的信息源说法一致——这就是**双实现交叉验证**：用两个独立工具复现同一个现象，比任何单一来源都可信。

**器材**：手机 WiFi 分析仪 App（Android 用 WiFiAnalyzer 等；iOS 受系统限制拿不到 RSSI，用路由器后台替代——索引装备约定）、路由器管理后台、ESP32（下方骨架）。

**API 事实**（本机 v6.0.2 头文件逐条核实）：`esp_wifi_scan_start(const wifi_scan_config_t *config, bool block)`，`config` 传 `NULL` 即默认参数——主动扫描、每信道 0~120 ms、被动 360 ms、回驻主信道 30 ms（`esp_wifi.h` 注释原文口径）。`wifi_scan_config_t`（`esp_wifi_types_generic.h`）全字段：

- `ssid` / `bssid`：只扫指定 AP，其余过滤掉；
- `channel`：只扫指定信道，0 为全信道；
- `show_hidden`：是否包含隐藏 SSID 的 AP；
- `scan_type`：`WIFI_SCAN_TYPE_ACTIVE`（主动发 probe 请求）或 `WIFI_SCAN_TYPE_PASSIVE`（只听 beacon）；
- `scan_time`：每信道驻留时间，单信道上限 1500 ms，超限可能掉线（`esp_wifi.h` attention 原文）；
- `home_chan_dwell_time`：扫完一个信道回驻主信道（已连接时）的停留时间；
- `channel_bitmap`：按位指定要扫哪些信道；
- `coex_background_scan`：共存场景下扫描时定期回主信道。

结果有两种取法：阻塞模式（`block = true`）扫完才返回；非阻塞模式等 `WIFI_EVENT_SCAN_DONE` 事件（附带 `wifi_event_sta_scan_done_t{status, number, scan_id}`）。无论哪种，都必须调 `esp_wifi_scan_get_ap_records()`（或 `esp_wifi_clear_ap_list()`）释放驱动内部缓存——注释原文明说。另一个坑：正在连接时发起扫描会返回 `ESP_ERR_WIFI_STATE`，所以骨架里扫描任务**等拿到 IP 才起跑**。

**代码骨架**（基于 station 例程裁剪，事件骨架与 BOX-3 十六 16.6 完全一致，此处只列增量）：

```c
/* app_main 里、进入观察循环前：xTaskCreate(scan_task, "scan", 4096, NULL, 5, NULL); */
static void scan_task(void* arg)
{
    /* 等拿到 IP 再扫：连接过程中并发扫描会被拒（ESP_ERR_WIFI_STATE） */
    xEventGroupWaitBits(s_ev, BIT_GOT_IP, pdTRUE, pdFALSE, portMAX_DELAY);

    for (;;) {
        vTaskDelay(pdMS_TO_TICKS(10000));
        esp_err_t r = esp_wifi_scan_start(NULL, true);   /* NULL=默认参数；true=阻塞到扫完 */
        if (r != ESP_OK) {
            ESP_LOGW(TAG, "scan failed: %s", esp_err_to_name(r));
            continue;
        }
        uint16_t n = 20;                                 /* 进：缓冲上限；出：实际条数 */
        wifi_ap_record_t aps[20];
        ESP_ERROR_CHECK(esp_wifi_scan_get_ap_records(&n, aps));  /* 取结果并释放缓存 */
        ESP_LOGI(TAG, "==== %u APs ====", (unsigned)n);
        for (int i = 0; i < n; i++) {
            ESP_LOGI(TAG, "ch=%2u rssi=%4d b/g/n=%u/%u/%u %s",
                     (unsigned)aps[i].primary, aps[i].rssi,
                     (unsigned)aps[i].phy_11b, (unsigned)aps[i].phy_11g,
                     (unsigned)aps[i].phy_11n, (char*)aps[i].ssid);
        }
    }
}
```

（`wifi_ap_record_t` 里 `primary` 是信道号、`rssi` 就是第三章见过的那个 int8_t 字段、`phy_11b/g/n` 是 AP 的能力位，`bandwidth` 还能看出谁开了 40 MHz。）

**步骤**：① 手机 App 开信道视图，数每个信道的 AP 数与最强信号；② 路由器后台记下自家信道、带宽，以及「周边 AP/信道分析」页（有则记，无则跳过）；③ ESP32 刷骨架，`idf.py flash monitor` 看扫描输出；④ 三份读数**在同一分钟内**完成，填进记录表；⑤ 判读并决策。

> [!warning] 待真机验证
> 以上步骤与输出均为设计稿，真机到货后实测回填。预期现象：三方对**信道分布趋势**一致（哪个信道挤、哪个空，三家说法应该吻合）；条数与数值不必逐个相等——手机扫描时机不同、隐藏 SSID 双方表现不同、ESP32 与手机的标定不同（第五章 5.5），差值近似恒定即算合格。

**记录表模板**：

```text
信道   App 上 AP 数   ESP32 扫到条数   App 最强(dBm)   esp rssi(dBm)   备注
1      待填           待填             待填            待填            自家 AP 所在信道？
6      待填           待填             待填            待填
11     待填           待填             待填            待填
其他   待填           待填             待填            待填
结论：1/6/11 里最空的是信道 __；同信道最强邻居是 __（rssi __ dBm）
```

**看到什么说明什么**：若某信道（常见是 6 或自动信道的 1/11）挤着最多 AP 且信号强——第十四章的「同信道抢时间」就在你家上演，换到最空的那个不重叠信道是最便宜的对策；若三方某一家明显与众不同，先怀疑它的观察条件（手机在兜里扫的？路由器后台是启动时的快照？），再怀疑数据——这也是交叉验证的价值：**单一来源的异常读数会在对照里自动暴露**。

## 15.3 实验二：距离-RSSI 曲线——对一笔「信号强度对数账」

**目的**：验证第三章的距离规律不是课本台词：距离每 ×2，接收功率 −6 dB。核心类比：RSSI 随距离的变化是**对数账**——账本上每一笔都是 dB，距离翻倍记一笔 −6 dB，功率翻倍只买 √2 倍距离。本实验就是拿真机读数**对账**。

**理论回收**（第三章 3.3 的口诀 + 教材通识公式）：

```text
FSPL(dB) = 20·log10(d_km) + 20·log10(f_MHz) + 32.44     （d 用 km、f 用 MHz）
代入 f = 2450 MHz 化简：FSPL(dB) ≈ 40.2 + 20·log10(d_m)  （d 改用 m）
互核锚点：d = 10 m → 40.2 + 20 = 60.2 dB ≈ 第三章链路预算里的「60 dB @ 10 m」
口诀：距离每 ×2 损耗 +6 dB；每 ×10 损耗 +20 dB
```

**器材**：ESP32（连上家里 2.4G AP）+ 手机 App + 卷尺；一段无遮挡的直线空间（走廊/楼下空地最理想，4~8 m）。

**读数循环**（同样只是 station 骨架的增量）：

```c
/* 连上后建议先关 modem sleep，读数更跟手（官方 antenna 例程同款做法） */
ESP_ERROR_CHECK(esp_wifi_set_ps(WIFI_PS_NONE));  /* 默认是 WIFI_PS_MIN_MODEM（esp_wifi.h 注释） */
for (;;) {
    wifi_ap_record_t ap = {0};
    if (esp_wifi_sta_get_ap_info(&ap) == ESP_OK) /* v6 名称；旧名 esp_wifi_get_ap_info 已不存在 */
        ESP_LOGI(TAG, "rssi = %d dBm", ap.rssi);
    vTaskDelay(pdMS_TO_TICKS(1000));
}
```

**步骤**：① 路由器位置固定，从 AP 天线起量 1/2/4/8 m 四个测点（同一条直线上，高度一致约 1 m）；② 每点停 10 秒，ESP32 与手机 App 各读 5 次取中位；③ 全程同一姿态持板（实验四会证明握姿本身就是变量）；④ 若 8 m 处必须穿墙，单独标注——墙损是账本外的另一笔扣减。

> [!warning] 待真机验证
> 预期现象：**相邻测点的差集中在 −4 ~ −8 dB 区间**（理想自由空间是 −6 dB，室内多径会让个别点偏离）；RSSI 绝对值大概率对不上任何理论值——你家 AP 的 EIRP、天线增益、环境修正都是未知数，**绝对值本来就不该对上，对得上的只有差值**。若某个测点读数突跳（比两侧邻居低十几个 dB），那是多径零点，不是仪器坏了。

**记录表模板**：

```text
测点   理论 FSPL(dB)   esp rssi 中位(dBm)   手机 App(dBm)   与上一测点差(dB)
1 m    40.2            待填                 待填            —（基准）
2 m    46.2            待填                 待填            待填
4 m    52.2            待填                 待填            待填
8 m    58.2            待填                 待填            待填
环境记录：路径上有无墙/家具 ___；板子高度 ___ m；测点间是否有人走动 ___
```

**看到什么说明什么**：相邻差落在 −6 dB 附近，说明**对数账成立**——你已经亲手复现了「加 3 dB 不如挪半米」的物理出处；读数不单调、有深坑，说明多径在起作用——这正是第六章天线分集要救的场景，也是「同一地点信号差、挪半米就好」的机制；ESP32 与手机两列的差值若近似恒定，又一次验证第五章「跨设备只比趋势」的口径。多径之于无线，就是 flaky 测试环境之于 CI：时过时不过，病因是隐藏变量（反射径的相位），对策也同款——多采样、记录环境、看趋势不看单点。

## 15.4 实验三：天线方向图手绘（12 点版）——压测采样画波瓣

**目的**：把第六章的理想「甜甜圈」（方位面近似圆、俯仰面 8 字）变成**你手里那块板**的实测图，亲眼看「全向天线其实不圆」。第六章 6.6 给过 8 点初版（45° 一点），本章把它标准化为 **12 点（30° 一点）**——压测采样直觉：**采样密度决定能分辨的最窄凹陷**，8 点只能看出 45° 级的特征，12 点能分辨 30° 级的凹坑，成本只是多走四步。

**器材**：ESP32 刷 softAP 例程（`examples/wifi/getting_started/softAP`，固定 SSID）、手机 App、卷尺加粉笔（或 12 张纸条）、非金属支架（纸箱即可）、一张极坐标纸（打印或手画同心圆）。

**步骤**：① 空旷场地，ESP32 架在非金属支架上约 1 m 高，姿态固定为模组天线区朝上水平放（与第六章 6.6 一致，便于日后对照回填）；② 以板子为圆心画半径 2 m 的圆，每 30° 一个标记，共 12 个测点；③ 每个测点：站位、手机高度与板子一致、屏幕朝板、握姿每次相同（下一实验会证明为什么）；④ 等 10 秒，读该 SSID 的 RSSI 10 次取均值填表；⑤ 整圈完成后，把板子立起来（板面竖直）再测一圈，得第二张图。

> [!warning] 待真机验证
> 预期现象：水平圈的图**大致是圆但起伏若干 dB**（理想全向的「圆」被板子地平面、外壳、支架啃出缺口——第六章说 PCB 倒 F 的方向图天然不规则）；立板那圈不仅形状变，整体电平也会变（方向图与极化两个变量叠加，这正是第六章「收发天线姿态保持平行」的实测依据）。已知陷阱沿用第六章：距离太近读数饱和不随角度变化；测点间握姿不一致会造出假凹陷；场地金属物反射造成局部异常。

**画图与判读**：极坐标纸上每圈 2 dB（或 5 dB），全圈最强读数定为最外圈，12 个点按角度标点、平滑连线，就是你的第一张实测方向图。判读三问：① 相对最强方向起伏多少 dB（「圆度」）；② 最深凹坑在哪个角度、深多少 dB——**那是摆设备要避开的死区**，也是 ESP-FAQ「让辐射较强方向对准接收设备」这句话的实测版；③ 与第六章 6.3 的理论图对照：方位面近圆但缺口的，缺口的账记在地板与外壳头上。看到什么说明什么：**一张手绘方向图 = 把「天线增益是方向性的账」从名词变成你板子上的事实**；今后设备信号差，先转 90° 再谈别的。

## 15.5 实验四：手挡天线与人体遮挡——吸收与反射的体感课

**目的**：直观体验两种效应：**吸收**（人体大半是水，2.45 GHz 对水做功正是微波炉加热的原理——第十四章的档案在可见光之外同一物理）与**反射**（身体是导体-ish 的反射面，多径可能反而让信号变强）。第六章实验纪律里那句「人体是 2.4G 的吸波体，站位本身就是变量」在这里兑现。

**器材**：ESP32（沿用实验二的读数循环）+ 手机 App 对照，一个空旷位置。

**步骤**：AP 与板子位置全程不动，依次做五种状态，每种停 10 秒读 10 次取均值：① 无遮挡（基线）；② 手掌完全盖住模组天线区；③ 手掌贴在板子背面（不盖天线）；④ 整个身体站在板与 AP 的视线路径上；⑤ 身体站在板子背后（不在视线路径上）。

> [!warning] 待真机验证
> 预期现象（方向性，不预设数值）：② 掉得最狠（数 dB 到十数 dB，吸收直达路径）；③ 变化较小；④ 掉数 dB（视线被人体挡住）；⑤ 变化很小、**偶尔反而 +1~2 dB**（反射径叠加）。若 ⑤ 出现「变强」，别怀疑人生——那正是多径的签名。

**记录表模板**：

```text
状态                     rssi 10 次均值(dBm)   相对基线(dB)
无遮挡（基线）           待填                 0
手掌盖住模组天线区       待填                 待填
手掌贴在板背面           待填                 待填
身体站在板-AP 视线上     待填                 待填
身体站在板背后           待填                 待填
结论：遮挡损失主要来自 ___；有没有反而变强的状态 ___
```

**看到什么说明什么**：遮挡不是单调变弱——吸收削路径、反射造多径，两者叠加才是你读到的数。三条工程推论：**手持设备的 RSSI 预算必须算人体**（可穿戴/物联网产品的实测规范都要人手在场）；**拿在手里的读数别跟架在桌上的比**（姿态+遮挡两个变量都变了，违反 15.1 纪律第一条）；**信号差时挪半米、换个面**的民间智慧，物理机制全在本实验里。

## 15.6 实验五：微波炉与 USB3 干扰对照——分子不动的证据

**目的**：把第十四章的干扰档案在自家复现一遍，并统一「分子不动、分母塌」的读数口径。该章 14.6 已给过两个实验的完整设计与安全线（**微波炉内必须放一杯水、不拆机**），本节不重复，只把它们纳入本章的记录框架，作为实验套装的收官对照。

**器材**：微波炉 + 一杯水、USB3 移动硬盘（或任意 USB3 外设）、同网电脑、ESP32（已连 AP）、手机 App。

**步骤**：位置与距离全程固定，跑三个相位：① 基线（干扰源全关）；② 微波炉最高档运行 60 秒（炉内有水）；③ USB3 硬盘贴着 ESP32 拷大文件。每个相位同时采三样：手机 App 的信道图形态、ESP32 的 RSSI（实验二循环）、电脑对 ESP32 的 300 个 ping（Linux/macOS：`ping -c 300 <ip>`；Windows：`ping -n 300 <ip>`——读输出末行的 min/avg/max/mdev 与丢包率即可）。

> [!warning] 待真机验证
> 预期现象（方向与第十四章 14.6、第五章 5.6 一致，不预设数值）：**RSSI 全程基本不动（±1~2 dB）**；ping 的 avg 轻微上升、**max/mdev 与丢包明显恶化**；App 信道图上微波炉相位 2.4G 中高频段整段变亮（宽带噪声的形态是「一片亮」），USB3 相位 2.4~2.5 GHz 整段抬亮、挪开 1 m 后回落（Intel 白皮书实测抬底噪近 20 dB 的量级，第十四章 14.3 转引）。

**记录表模板**：

```text
相位                  RSSI(dBm)   ping min/avg/max/mdev(ms)   丢包   App 信道图形态
基线                  待填        待填                        待填   ___信道亮
微波炉开（炉内有水）  待填        待填                        待填   ___信道变亮
USB3 硬盘贴脸拷贝     待填        待填                        待填   ___
设备距离：ESP32-干扰源 ___ m；ESP32-AP ___ m；ping 主机 ___
```

**看到什么说明什么**：这张三相对照表就是一张**排障决策树**：「信号强度不动、延迟丢包塌」→ 干扰抬分母，去第十四章找噪声源（换信道、挪干扰源）；「信号强度也塌」→ 分子出了问题，回实验二（距离）和实验四（遮挡）。第五章那句「RSSI 只量分子、不量分母」，至此从结论变成了你自己的测量记录。

## 15.7 进阶装备一瞥：RTL-SDR 与万用表

免费遥测榨干之后，钱该往哪花？两个入门档：两百元级的 RTL-SDR 和几十元级的万用表。

### RTL-SDR：是什么，以及一个必须先纠正的口径

RTL-SDR 是**被逆向成通用接收机的电视棒**：2012 年有人发现 RTL2832U 解调芯片能输出原始 IQ 采样，配上开源软件（SDR#/GQRX/SDRangel 等）就成了「低成本频谱仪」——屏幕上是横轴频率、纵轴时间的瀑布图。**但系列索引装备表里那句「RTL-SDR 约 ¥200，能看 2.4G 频谱占用」经核实需要修正**：RTL-SDR Blog 官方 datasheet 写明 V3（R820T2 调谐器）与 V4（R860）的接收范围均为 **500 kHz – 1.766 GHz**——够不着 2.4 GHz；老款 E4000 调谐器上限约 2.2 GHz，同样差一口气。两百元档能看的是 1.7 GHz 以下的世界：FM 广播、400/470 MHz 对讲机、1090 MHz 航空 ADS-B（经典入门项目）、137 MHz 气象卫星。

那想看 2.4G 频谱怎么办？两条路：**加预算**买覆盖到 6 GHz 的设备（HackRF One 一类，正版贵、克隆板数百元——价格**待核对**）；或者用**土法**：¥10 的 nRF24L01 模块配 ESP32，利用其接收功率检测位（RPD，datasheet 口径约 −64 dBm 门限）以 1 MHz 步进逐信道扫出「有无信号」的一比特读数，终端里打字符直方图——分辨率和动态范围都极粗，但「2.4G 信道占用热力图」这件事十块钱就成立了（社区成熟玩法），正是本章零仪器哲学的延伸。

**2.4G 瀑布图的文字预告**（在有装备时你会看到什么，不编造截图）：把中心频率设在 2.44 GHz、带宽拉满，瀑布图上——深色底是热噪声底（第五章 −174 dBm/Hz + 带宽的账，仪器世界里它就是屏幕的「黑」）；**一簇周期性竖直亮线**是各 AP 的 beacon，约每 102.4 ms 一条（100 个 TU 的默认 beacon 间隔），稳定得像心跳——BOX-3 十六讲的 TBTT 节拍在频谱上的样子；**某信道整块亮起又熄灭**是有人传大文件（20 MHz 数据突发）；**微波炉一开**，2.45 GHz 附近一大片持续亮带罩住高频信道（第十四章档案的宽带噪声形态）；**随机位置的小闪点**是蓝牙跳频（每秒 1600 跳）。频谱图就是那章干扰档案表的可视化版。

### 万用表：管「电」，不管「波」

万用表在 WiFi 场景的角色第十二章 12.6 已经给全：测 3.3 V 轨、测入口电流、记 Vmin，把「WiFi 时好时坏」的第一嫌疑人（供电账）量化。能干与不能干一张表收口：

| 能                                         | 不能                             |
| ------------------------------------------ | -------------------------------- |
| 测 3.3 V 轨 DC、入口电流、Vmin（12.6）     | 测射频功率与频谱（不是功率计）   |
| 查 IPEX 座与天线馈点通断（第六章机械弱点） | 看微秒级 TX 毛刺（每秒只采几次） |
| 换线换口前后的量化对照                     | 替代示波器做任何波形判断         |

一句话定位：**万用表量的是供电与连接，射频信号本身它一个字节都看不见**——测「波」的最低门票是上面那台 SDR。

## 15.8 常见误区表与小结

| 说法                       | 错在哪                                  | 正确姿势                         |
| -------------------------- | --------------------------------------- | -------------------------------- |
| 「App 的 RSSI 是精确值」   | 标定因芯片而异，且是 EMA 后的均值       | 同设备看趋势，跨设备比量级       |
| 「距离翻倍信号减半」       | 减半是 -3 dB；距离翻倍 -6 dB（剩 1/4）  | 对数账：问差多少 dB（3.3 实验）  |
| 「扫不到就是没人用」       | 隐藏 SSID 与微波炉/USB3 都不进扫描列表  | 占用 = 扫描 + App 形态 + ping    |
| 「几个点画不出方向图」     | 采样密度决定分辨率，12 点可辨 30 度级坑 | 12 点起步，疑点区加密（15.4）    |
| 「手挡一下不算测量」       | 它是吸收/反射的定性对照，方向可靠       | 定量归仪器，定性归人手（15.5）   |
| 「ping 高就是信号弱」      | 干扰抬分母时 RSSI 不动、ping 塌         | 先跑实验五分诊（14.2 的账）      |
| 「两百元 RTL-SDR 看 2.4G」 | 主流调谐器上限 1.766 GHz                | 土法 nRF24 或加预算（15.7）      |
| 「读数抖是板子坏了」       | EMA、多径、人体移动都在抖               | 多读取中位，抖动也是数据（15.1） |

**小结**：

- **实验哲学**：零仪器测量 = 只用日志和内置 metrics 排障——RSSI 是芯片的免费遥测、扫描列表是它的 `netstat`；一轮一个变量、同设备自比、多读取中位、记录环境，五条纪律与压测同款。
- **实验一（扫描与占用）**：三个独立观察者交叉验证；`esp_wifi_scan_start(NULL, true)` 全字段与默认参数（主动 0~120 ms/被动 360 ms/1500 ms 上限）核对自 v6.0.2 头文件；扫描要等拿到 IP（`ESP_ERR_WIFI_STATE`），结果必须用 `esp_wifi_scan_get_ap_records` 释放。
- **实验二（距离-RSSI）**：对「信号强度对数账」——理论 FSPL ≈ 40.2 + 20·log10(d/m)，与第三章 60 dB @ 10 m 锚点互核；实测对的是**相邻测点 −6 dB 的差**，不是绝对值；深坑是多径，flaky 环境的无线版。
- **实验三（方向图 12 点）**：压测采样画波瓣——12 点分辨 30° 级凹陷；两张图（水平/竖直）对照第六章甜甜圈，缺口是地板与外壳的账，死角是摆位的禁区。
- **实验四（人体遮挡）**：吸收与反射叠加，遮挡不单调变弱、偶尔回血；手持设备的 RSSI 预算必须算人体。
- **实验五（干扰对照）**：分子不动（RSSI ±1~2 dB）、分母塌（ping 尾部与丢包）——第五章与第十四章的核心结论变成自己的测量记录；这张三相对照表就是排障决策树。
- **装备边界**：两百元 RTL-SDR 上限 1.766 GHz（官方 datasheet，索引口径已在本章修正），2.4G 频谱要土法 nRF24L01 或加预算；万用表管「电」不管「波」。全部实验与预期**待真机验证**，到货后按表回填。
