## 真机发现与代码修正（已落盘）

1. **Zig 0.17 API 迁移**（ch02–ch11）：
   - `b.addStaticLibrary` → `b.addLibrary(.{ .linkage = .static, … })`；
   - `Build.args` 移除 → ch03 的运行参数改为 `-Dfile=<path>`；
   - `[_]u8{0} ** N` / `[_]?*Task{null} ** N` → `@splat(0)` / `@splat(null)`；
   - `align` 成为关键字（ch03 局部量改名 `align_bytes`）；
   - `export fn` 不再隐式 `pub`（跨模块引用处统一 `pub export fn`）；
   - `@fence(.seq_cst)` 移除 → `asm volatile ("fence rw, rw" ::: .{})`；
   - `std.process.argsAlloc`、`std.fs.File` 移除 → `main(init: std.process.Init)` + `std.Io.Dir/File.Writer`；
   - 禁止直接调用 `callconv(.naked)` 函数 → 经 `*const fn () callconv(.c) void` 指针调用；
   - naked asm 引用的模块级变量必须 `export var`，否则符号被改名、链接期 undefined。
2. **S31 启动链硬约束**（ch04–ch11 链接脚本 + start.zig）：
   - `unpack_load_app` 断言 `rom_index == 2`：镜像必须正好有两个落在 `0x40000000..0x44000000` 的段。原「SRAM-only」布局直接 `Assert failed … (rom_index == 2)`。改为 `.flash.text` → `irom`（`0x40000020`）、`.flash.rodata` → `drom`（`0x40020020`），`.data/.bss/栈` 留在 SRAM。
   - **RTC/LP 看门狗**：bootloader 交接时仍使能，裸机不喂狗约 9 s 后 `rst:0x10 (CHIP_LP_WDT_RESET)`。`_start` 增加一段：解锁 `RTC_WDT_WPROTECT`（键 `0x50D83AA1`）→ feed → 清 `CONFIG0.EN`/`STG0` → 恢复写保护。
3. **SYSTIMER 需要两级时钟门控**（ch05/ch07/ch08）：`HP_SYS_CLKRST + 0x120` 的 bit0（APB）与 bit4（计数器时钟）复位值均为 0。只开 bit0 时寄存器可读但恒为 0，`measure` 的忙等永不结束；只开 bit0+bit31/bit30（SYSTIMER CONF）不足以让计数器走动。修正后 ch05 量到 `cycles=16000012 / ticks=3200030 → CPU 80 MHz`。
4. **trap 向量必须放 SRAM**（ch06–ch11）：向量位于 flash（IROM）时，异常投递直接 `rst:0x1a (CPU_LOCKUP_RESET)`，连 `mtvec` 里的死循环都执行不到。改为 `.trap_ram` 段（链接脚本放 SRAM，`ALIGN(4)`）后，ch06 的非法指令演示能完整打印 `mcause/mepc/ra/mtval/sp` 并 `wfi` 停机（无复位）。
5. **mcause 高位带 CLIC 字段**：实测 `mcause=0x30000002`，异常码只在低 5 位；`causeName` 先 `raw & 0x1F` 再查表，否则一律落到 "reserved"。
6. **ch02 任务看门狗**：`app_main` 用 `esp_rom_delay_us` 忙等 1 s 会饿死 CPU0 的 IDLE，10 s 后 `task_wdt` 报警并打印寄存器。因 SPEC §4.2 要求 Zig 侧只调 ROM 符号，处理放在 IDF 侧：`sdkconfig.defaults` 关闭 `CONFIG_ESP_TASK_WDT_EN/INIT`；日志恢复为 `hello s31` + 每秒 `tick`。
7. **ch03 校验和偏移**：IDF 的规则是「镜像长度 + 1 个校验和字节」补齐到 16 字节块，校验和是该块**最后一个字节**（即 `align16(pos+1)-1`），16 字节对齐的是其后的 SHA256 起始地址。原实现对不齐，报 "only 31 bytes remain"。
8. **ch06 hex 打印缺换行**：`putHex32` 补 `\n`，否则 `mcause=…mepc=…` 挤成一行。

## 仍未闭环（下一轮的工作项）

1. **ch07 中断不投递**：`mtvec=0x2f000003`（CLIC 模式）、`MIE=1`、输入 19 `IE=1 / IP=0 / prio=1 / SHV=0`、阈值 0 全部读回正常；`raise(19)` 后 ISR 不执行，SYSTIMER 1 kHz 也不进。怀疑点：CLIC 模式下 `mstatus.MIE` 之外还需要 `mintthresh`/`mintstatus` 或 `mtvt` 相关配置；需对照 `csr_clic.h` 与 IDF `interrupt_clic_ll.h` 逐项核对。
2. **ch08 DMA 内容不匹配**：`chunks=2 first_bad=0 bad=2040`（DONE 置位、数据没落地）。
   对照 IDF `async_memcpy_gdma.c` 后确认工程少了三件事：① M2M 触发号应取 `gdma_get_free_m2m_trig_id_mask()`
   的 `ctz`（0..3 一类），不是硬编码 9/15（试过 15 仍失败）；② 两个通道都要 `owner_check`、
   `auto_update_desc`、`eof_till_data_popped` 策略（`gdma_apply_strategy`）；③ `gdma_config_transfer`
   给两个通道设 `max_data_burst_size` 与 `access_ext_mem`。下一步按这三条重写 `dma.zig` 的 CONFn/策略位。
3. **ch10/ch11 的换栈锁核（已闭环）**：根因是 Zig 0.17 下经 C 约定函数指针调用 naked `switchRaw`，LLVM 按 C ABI 加序言/尾声破坏 64 B 帧；改 `pub export fn switchRaw` + `asm volatile ("call switchRaw")` 后，ch10 打出 `all tasks done, switches=13`，ch11 打出 hi/loA/loB 全部 beat 与 `idle: wfi`。
4. **ch11 伴生的队列缺陷（已修）**：任务在时间片到期时被重新入队、随后才标 `done`，`pickNext` 直接返回会让已结束任务复活；改为循环 `dequeue` 丢弃 `done` 项。另需记住两条：`mcause` 高位带 CLIC 脏位（先 `& 0x1F`）；TIMG 的 `INT_ENA_TIMERS(+0x70)` 必须置位，否则 `INT_RAW` 出不了 TIMG。
5. **章节证据边界已回写（2026-11-13）**：ch04–ch13 开头的「本工程尚未在真机运行」已按实测逐章替换（ch07/ch08/ch12 如实写部分通过），ch05 的 320 MHz 口径改为实测 80 MHz；各工程目录内的 README 口径以本报告与各章状态表为准。
6. `ch01-board-id/board-id.md` 需要按实测值填写（本报告「环境与板卡」一节即字段来源）。

ch12 的崩溃点收敛到「从任务上下文里第一次真正切走」这一步：supervisor 打印完两行 `cfg:` 后创建 spinA/spinB 并 `sem.wait`，

两个 sp 传递变量 `export var`。真机复测：ch10 A/B/C 全部跑完（`all tasks done, switches=13`）；
ch11 hi 6 beat + loB 4 + loA 4 + `sched: all tasks done ticks=183 switches=5` + `idle: wfi`；

## 关键结论（全系列）

1. **换栈原语是这套模板 B 的唯一硬骨头**：`switchRaw` 必须 `pub export` + `asm volatile ("call switchRaw")`；
   任何经 C 约定指针的调用都会破坏 64 字节帧（ch10–ch12 的锁核全部由此而来）。
2. **异常/中断入口进 SRAM**、**mcause 先掩码**、**`_start` 关 RTC WDT**、**`mie.MEIE` 重开** 是四条与章节无关的启动期硬约束。
3. 双核（ch14）是当前最完整的一章：core1 启动、IPI、跨核负载迁移、延迟统计全部在真机跑通。

**ch17 的下一步**（第二轮的读数已经把方向钉死了，别再猜写序）：

1. 已经排除的：写序（与 IDF `emac_ll_reset`/`emac_ll_is_reset_done` 逐字等价）、
   总线时钟门控（`hp_sys_clkrst+0xc8 bit0` = 1）、内部存储时钟
   （`GMAC_MEM_CLK_FORCE_ON` bit5 已写，`gmac_ctrl0=0x00000124` 回读为 1）、
   AXI 时钟请求（`cactive=1`）。`busmode=0x00020101` 除 bit0 SWR 外只有
   bit8/bit17（PBL/RPBL，上电默认），不是写错位。
2. 剩下的是 **TX/RX 复位时钟仍为 0**（`rst_clk_tx_n=0`、`rst_clk_rx_n=0`，写 SWR
   前后都一样）。SWR 的文档原话是「在所有 ETH_MAC 时钟域完成后才自清」。
   第三轮把 `pins.initRgmii()`（GPIO13 的 TXC 路由）提到时钟阶段之前，读数
   **一字未变**（`logs/ch17c-boot.log`），所以 pad 顺序已被排除。
3. **第四轮已排除“GMAC 存储低功耗”这条分支**：`GMAC_MEM_LP_CTRL` 复位值 `0x6`
   （`lp_mode=2` shutdown + `lp_en=1`），强写 `lp_mode=3 / lp_en=0 / force_ctrl=1`
   后读回 `0xb`，但只读的 `GMAC_MEM_PRDYN`(bit12) **仍是 0**，SWR 照旧超时
   （`logs/ch17d-boot.log`）。软件能关低功耗、存储却不上电，说明卡的还是时钟域。
4. **第四轮新证据（不再 SWR 后停机，一路跑到第 9 阶段）**：`BUSMODE` 的写生效
   （读回 `0x06001080`），但 `TXDESC_LIST`/`RXDESC_LIST` 写后读回 **0**；
   MDIO 全扫 `0x0000`/`0xffff`（无 PHY 应答）；TX 一帧 `Timeout after 10006us
(des0=0xf0100000)`。DMA 寄存器块“只有部分写生效”与“某时钟域没放行”同源，
   MDIO 无应答则把矛头同时指向 PHY 供电/MDC-MDIO 脚号。
5. 剩下的最可疑是 **ref clock 的源**：IDF 先用 `esp_clk_tree_src_set_freq_hz(MPLL, 500 MHz)`
   把源配出来、再使能输出时钟；本章直接假设「MPLL = 500 MHz」写 `div=3`。
   下一轮判据仍是 `rst_clk_tx_n` / `rst_clk_rx_n` 变 1；验证手段优先级：
   ① 读 MPLL 配置/校准/上电状态（`LP_AONCLKRST.MSPI_DIV`、`HP_SYS_CLKRST.ANA_PLL_CTRL0`、
   `PMU_HP_ACTIVE_HP_CK_POWER`）；② 频率计量 GPIO13；③ 换 CPLL 源对照。
   同时用原理图核 MDC/MDIO 到底接哪两个脚（当前 GPIO20/21 是占位默认值）。
