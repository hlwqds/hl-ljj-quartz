# ch06-mini-chord —— 一致性哈希定宿主 + finger 路由 + churn 自愈

把 [[ch06-dht-chord|第六章：分布式哈希表——一致性哈希与 Chord]] 的路由核心做成单文件
模拟器：m=8 位环、16 节点、finger[i]=successor(n+2^i)、查找走 closest-preceding-finger
逐跳计数、后继链（r=5）承担容错。模拟边界：算法与协议语义保真，真实传输层（丢包/
延迟/RPC 重试）折算成"超时回退"计数（见套件 SPEC §2）。

## 实验设计

1. **健康网络**：200 个 sha1 哈希 key 从随机起点路由，验证结果 = 真值函数
   （环上第一个活节点 ≥ key），统计跳数（期望 O(log N)≤4）；
2. **churn 注入**：随机杀 6/16 节点 → 3 轮 stabilize（后继链修复 + 随机 fix_fingers）
   → 再跑 200 次查找，统计成功数与"超时回退"（跳到的 finger 已死、换次优候选——
   真实实现里的一次 RPC 超时重选）。

## 编译运行

```bash
zig cc -o chord chord.c sha1.c    # Linux/macOS 同样一行（无平台依赖）
./chord 16 200 6                  # 节点数 键数 杀掉数
```

固定随机种子（srand(42)），输出可逐字节复现。实测（run.log）：健康网络平均
1.78 跳 / 最大 4 跳 / 零错判；杀 37% 节点后 200/200 全部成功、23 次超时回退——
**正确性挂在后继链上兜底，慢但不断服**，正是章末"快速路径允许脏，正确性挂在
慢速路径"的数值形态。

完整真实输出见 `run.log`（含"key 砸在自己 ID 上绕环一圈"的排错实录）。
