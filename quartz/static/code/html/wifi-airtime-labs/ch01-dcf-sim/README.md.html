# ch01-dcf-sim：DCF 竞争的离散时隙仿真

> 配套章节：[[ch01-dcf-contention-basics|第一章：争抢的账本]]

## 定位

把 802.11 DCF 的"抽退避 → 空闲递减 → 撞了翻倍 → 成了归零"这套争抢规则，压成一个
~300 行的宿主端离散时隙仿真（C11、零依赖、单文件），用四组实验把第一章的三种时隙账
（空闲 / 成功 / 碰撞）跑成可复现的数字。不碰固件、不依赖任何 SDK，`run.log` 即真实输出。

本工程属于 `practice/wifi-airtime-labs/` 套件（公约见套件内 SPEC.md）。SPEC 中 `fixtures/`
与 `collect.sh` 是 iw 文本解析工程（ch02）的必备件；本工程是纯仿真器，输入只有随机种子，
故不适用，特此说明。

## 模型说明

- **饱和站点**：N 个站始终有包可发；每站从 `[0, CW)` 均匀抽退避计数器。
- **递减规则**：只在**空闲时隙**递减，忙时隙（有人发送/碰撞）冻结；某时隙恰 1 站计数到 0
  即成功发送，≥2 站同时到 0 即全部碰撞。
- **BEB**：碰撞后 CW 翻倍（封顶 CWmax=1023），成功后回 CWmin；无重传上限。
- **时隙归一**：发送 1 包 = 碰撞 1 次 = 空闲退避 1 步 = 1 时隙。E3 聚合时每次胜出连发
  k 包、占 k 时隙，碰撞双方同样烧掉 k 时隙（整条 A-MPDU 报废）。
- **E4 限速站**：每 50 时隙醒一次，醒来抽 `[0,CWmin)` 退避正常竞争，完成一次尝试
  （无论成败）即继续睡，不做 BEB 重试。
- **随机数**：xorshift32，固定种子 42，每个配置重新播种——同机重跑输出逐字节一致
  （已实测 `diff` 为空；另用种子 20261030 复核过 E2 结论不依赖具体种子）。
- **指标**：`thr`=成功包/总时隙（归一化吞吐）；`idle%`/`coll%`=空闲/碰撞时隙占比；
  `tryc%`=每次发射尝试的碰撞概率；`jain`=各站按成功包数的 Jain 公平指数。

与真实 802.11 DCF 的主要简化：不区分 aSlotTime（9µs）与包长（百 µs 量级），所以 `thr`
读数是**时隙利用率**而非 Mbps，跨配置相对比较才有意义（例如 E4 混合场景总吞吐下降就是
归一化效应——真机上包长远大于 aSlotTime，少一个竞争者总 Mbps 通常反而上升）；退避抽自 `[0,CW)`
（标准是 `[0,CW]` 共 CW+1 个值）；无 DIFS/SIFS/ACK/重传上限计时。

## 复现

```bash
~/zig/zig cc -O2 -o dcf_sim dcf_sim.c
./dcf_sim > run.log        # 全部输出重定向；每配置 100 万时隙（≥5 万）
```

Windows（Git Bash）下 zig cc 产出无扩展名的 `dcf_sim`（可直接 `./dcf_sim` 运行）及
`dcf_sim.pdb` 调试文件，两者均已按入库规则删除；Linux/macOS 同命令。运行耗时 <1s。

## 四组实验结果（数字摘自 run.log，均为真实输出）

### E1 站点数 N（CWmin=15, CWmax=1023）

```text
   N      thr    idle%    coll%    tryc%     jain
   2   0.1780    81.03     1.17    11.63   1.0000
   4   0.2189    74.82     3.29    23.73   0.9999
   8   0.2431    69.79     5.90    34.12   0.9997
  16   0.2528    65.80     8.93    43.75   0.9994
```

**结论**：竞争站从 2 加到 16，吞吐只升 42%（0.1780→0.2528），而碰撞时隙占比涨 7.6 倍
（1.17%→8.93%）、每次尝试的碰撞概率从 11.63% 涨到 43.75%——站点翻 8 倍的代价主要记在
碰撞账上，但对称饱和站的长跑公平性几乎完美（Jain 始终 ≥0.9994）。

### E2 CWmin（N=8, CWmax=1023）

```text
 CWmin      thr    idle%    coll%    tryc%     jain
     3   0.4202    51.06     6.92    25.55   0.9948
     7   0.2852    62.99     8.49    39.10   0.9994
    15   0.2431    69.79     5.90    34.12   0.9997
    31   0.1987    76.89     3.24    25.46   0.9999
    63   0.1457    84.04     1.38    16.35   0.9999
```

**结论**：CWmin 从 7 加到 63，碰撞率单调降 6 倍（8.49%→1.38%），代价是空闲时隙涨到
84%、吞吐掉一半——窗口越大越不撞、信道也越空；CWmin=3 是非单调例外：胜者抽到 0 的
"立即连发"把信道串行化，碰撞率（6.92%）反而低于 CWmin=7（该形态已用第二种子复核）。

### E3 A-MPDU 聚合（N=8, CWmin=15, 每次胜出连发 k 包）

```text
   k      thr       wins        att       coll         pkts    ovh/win    ovh/pkt
   1   0.2431     243101     368982     125881       243101       3.11      3.114
   4   0.5103     127583     193647      66064       510332       3.84      0.960
  16   0.7035      43971      66767      22796       703536       6.74      0.421
  64   0.7780      12157      18406       6249       778048      18.26      0.285
```

**结论**：k=1→64 有效吞吐涨 3.2 倍（0.2431→0.7780）、每包摊到的竞争开销从 3.114 时隙
降到 0.285 时隙（1/11），成功接入次数从 243101 降到 12157（少 95%）——聚合的本质是把
一次接入的固定竞争开销摊到更多包上，省下的就是信道时间。

### E4 用户场景（N=2, CWmin=15：双饱和 vs A 饱和 + B 限速 50 时隙/次）

```text
scenario            thr_A    thr_B  thr_all    coll%    tryc%     jain
both-saturated     0.0889   0.0891   0.1780     1.17    11.63   1.0000
A-sat+B-lim50      0.1190   0.0150   0.1340     0.22     3.24   0.6241
```

**结论**：一站退成限速后碰撞率降到 1/5（1.17%→0.22%）、留下的饱和站吞吐 +34%
（0.0889→0.1190），但限速站只剩 0.0150（对方的 1/8，每 ~58 时隙才轮到一次尝试），
Jain 从 1.0000 崩到 0.6241——BEB 的公平只给"在场竞争"的站，不发言就没有份额。
